# 常见问题与故障排查

## **我应该使用 `generate` 还是 `push`？**

从逻辑上讲，这是两个不同的命令。`generate` 用于创建一个 sql 文件，以及 `drizzle-kit`（或任何其他迁移工具）所需的附加信息。

生成这些迁移后，它们不会自动应用到数据库。
你需要在下一步手动应用。你可以在 **[这里](/docs/migrations)** 阅读更多内容

另一方面，`push` 不需要生成任何迁移。它
只是将你的 schema 与数据库 schema 同步。使用时请务必小心；
我们仅建议在本地开发和本地数据库中使用它。要了解更多内容，请查看 **[`drizzle-kit push`](/docs/drizzle-kit-push)**

## `push` 和 `generate` 如何处理 PostgreSQL 索引

### 限制

1. **如果索引建立在至少一个表达式上，你应该手动为索引指定名称**

示例

```ts
index().on(table.id, table.email) // 可以正常工作，名称会自动生成
index('my_name').on(table.id, table.email) // 可以正常工作

// 但是

index().on(sql`lower(${table.email})`) // 报错
index('my_name').on(sql`lower(${table.email})`) // 可以正常工作
```

2. **如果以下字段（见下方列表）在现有索引中发生变化，push 不会生成语句：**

- `.on()` 和 `.using()` 中的表达式
- `.where()` 语句
- 列上的运算符类 `.op()`

如果你使用 `push` 工作流，并且想要修改索引中的这些字段，你需要：

1. 注释掉该索引
2. 执行 push
3. 取消注释该索引并修改这些字段
4. 再次执行 push

对于 `generate` 命令，`drizzle-kit` 会被新的 drizzle 索引 API 中任意属性的任何变更所触发，因此这里没有限制。
