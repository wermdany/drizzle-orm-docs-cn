# `drizzle-orm@0.32.0` 和 `drizzle-kit@0.23.0` 的发布说明

> 并非必须同时升级这两个包，但如果你想在查询和迁移中都使用新特性，则需要同时升级这两个包

## 新特性

### 🎉 MySQL `$returningId()` 函数

MySQL 本身并不原生支持在 `INSERT` 之后使用 `RETURNING`。对于 `autoincrement`（或 `serial`）类型的`主键`，只有一种方式可以实现，即通过 `insertId` 和 `affectedRows` 字段。我们为你准备了一种使用 Drizzle 自动处理此类情况的方式，自动以独立对象的形式接收所有插入的 ID

```ts
import { boolean, int, text, mysqlTable } from 'drizzle-orm/mysql-core';

const usersTable = mysqlTable('users', {
  id: int('id').primaryKey(),
  name: text('name').notNull(),
  verified: boolean('verified').notNull().default(false),
});


const result = await db.insert(usersTable).values([{ name: 'John' }, { name: 'John1' }]).$returningId();
//    ^? { id: number }[]
```

此外，在 Drizzle 中，你可以使用 `$default` 函数指定一个`主键`，它会在运行时生成自定义主键。我们也会在 `$returningId()` 调用中为你返回这些生成的键

```ts
import { varchar, text, mysqlTable } from 'drizzle-orm/mysql-core';
import { createId } from '@paralleldrive/cuid2';

const usersTableDefFn = mysqlTable('users_default_fn', {
  customId: varchar('id', { length: 256 }).primaryKey().$defaultFn(createId),
  name: text('name').notNull(),
});


const result = await db.insert(usersTableDefFn).values([{ name: 'John' }, { name: 'John1' }]).$returningId();
//  ^? { customId: string }[]
```

> 如果没有主键 -> 这类查询的类型将是 `{}[]`

### 🎉 PostgreSQL 序列

你现在可以在 Postgres 中、任何你需要的 schema 内指定序列，并定义所有可用属性

##### **示例**

```ts
import { pgSchema, pgSequence } from "drizzle-orm/pg-core";

// 未指定参数
export const customSequence = pgSequence("name");

// 带参数的序列
export const customSequence = pgSequence("name", {
      startWith: 100,
      maxValue: 10000,
      minValue: 100,
      cycle: true,
      cache: 10,
      increment: 2
});

// 自定义 schema 中的序列
export const customSchema = pgSchema('custom_schema');

export const customSequence = customSchema.sequence("name");
```

### 🎉 PostgreSQL 标识列

[来源](https://wiki.postgresql.org/wiki/Don%27t_Do_This#Don.27t_use_serial)：如前所述，Postgres 中的 `serial` 类型已过时，应被废弃。理想情况下你不应使用它。`标识列`（Identity columns）是在 schema 中指定序列的推荐方式，因此我们引入了`标识列`特性

##### **示例**

```ts
import { pgTable, integer, text } from 'drizzle-orm/pg-core' 

export const ingredients = pgTable("ingredients", {
  id: integer("id").primaryKey().generatedAlwaysAsIdentity({ startWith: 1000 }),
  name: text("name").notNull(),
  description: text("description"),
});
```

你可以在 `.generatedAlwaysAsIdentity()` 函数中指定序列所有可用的属性。此外，你还可以为这些序列指定自定义名称

PostgreSQL 文档[参考](https://www.postgresql.org/docs/current/sql-createtable.html#SQL-CREATETABLE-PARMS-GENERATED-IDENTITY)。

### 🎉 PostgreSQL 生成列

你现在可以在 PostgreSQL 支持的任何列上指定生成列，以便与生成列一起使用

##### 使用 `tsvector` 生成列的 **示例**

> 注意：我们将在最新版本之前添加 `tsVector` 列类型

```ts
import { SQL, sql } from "drizzle-orm";
import { customType, index, integer, pgTable, text } from "drizzle-orm/pg-core";

const tsVector = customType<{ data: string }>({
  dataType() {
    return "tsvector";
  },
});

export const test = pgTable(
  "test",
  {
    id: integer("id").primaryKey().generatedAlwaysAsIdentity(),
    content: text("content"),
    contentSearch: tsVector("content_search", {
      dimensions: 3,
    }).generatedAlwaysAs(
      (): SQL => sql`to_tsvector('english', ${test.content})`
    ),
  },
  (t) => ({
    idx: index("idx_content_search").using("gin", t.contentSearch),
  })
);
```

如果你不需要引用表中的任何列，可以只使用 `sql` 模板或一个 `string`

```ts
export const users = pgTable("users", {
  id: integer("id"),
  name: text("name"),
  generatedName: text("gen_name").generatedAlwaysAs(sql`hello world!`),
  generatedName1: text("gen_name1").generatedAlwaysAs("hello world!"),
}),
```

### 🎉 MySQL 生成列

你现在可以在 MySQL 支持的任何列上指定生成列，以便与生成列一起使用

你可以同时指定 `stored` 和 `virtual` 选项，更多信息可查看 [MySQL 文档](https://dev.mysql.com/doc/refman/8.4/en/create-table-generated-columns.html)

此外 MySQL 对此类列的用法有一些限制，[这里](https://dev.mysql.com/doc/refman/8.4/en/alter-table-generated-columns.html)有相关描述

Drizzle Kit 在 `push` 命令上也会有限制：

1. 你不能通过 `push` 更改生成约束表达式和类型。Drizzle-kit 会忽略此更改。要使其生效，你需要`删除该列`、`push`，然后`添加一个带有新表达式的列`。这样做是由于数据库侧的复杂映射，schema 表达式会在数据库侧被修改，而在内省时我们会得到一个不同的字符串。我们无法确定是你修改了这个表达式，还是它被数据库修改并格式化了。由于这些是生成列，而 `push` 主要用于在本地数据库上进行原型设计，因此`删除`和`创建`生成列应该很快。由于这些列是`生成的`，所有数据都会被恢复

2. `generate` 应该没有限制

##### **示例**

```ts
export const users = mysqlTable("users", {
  id: int("id"),
  id2: int("id2"),
  name: text("name"),
  generatedName: text("gen_name").generatedAlwaysAs(
    (): SQL => sql`${schema2.users.name} || 'hello'`,
    { mode: "stored" }
  ),
  generatedName1: text("gen_name1").generatedAlwaysAs(
    (): SQL => sql`${schema2.users.name} || 'hello'`,
    { mode: "virtual" }
  ),
}),
```

如果你不需要引用表中的任何列，可以在 `.generatedAlwaysAs()` 中只使用 `sql` 模板或一个 `string`

### 🎉 SQLite 生成列

你现在可以在 SQLite 支持的任何列上指定生成列，以便与生成列一起使用

你可以同时指定 `stored` 和 `virtual` 选项，更多信息可查看 [SQLite 文档](https://www.sqlite.org/gencol.html)

此外 SQLite 对此类列的用法有一些限制，[这里](https://www.sqlite.org/gencol.html)有相关描述

Drizzle Kit 在 `push` 和 `generate` 命令上也会有限制：

1. 你不能更改现有表中 stored 类型的生成约束表达式。你需要删除该表并重新创建。这是由于 SQLite 对此类操作的限制。我们将在未来的版本中处理这种情况（这将涉及创建新表并进行数据迁移）。

2. 由于与上述相同的原因，你不能向现有列添加 `stored` 生成表达式。不过，你可以向现有列添加 `virtual` 表达式。

3. 由于与上述相同的原因，你不能更改现有列中的 `stored` 生成表达式。不过，你可以更改 `virtual` 表达式。

4. 由于与上述相同的原因，你不能将生成约束类型从 `virtual` 更改为 `stored`。不过，你可以从 `stored` 更改为 `virtual`。

## Drizzle Kit 新特性

### 🎉 为所有新的 ORM 特性提供迁移支持

适用于所有方言的 PostgreSQL 序列、标识列和生成列

### 🎉 `drizzle-kit push` 的新标志 `--force`

你可以在 push 命令中使用该标志自动接受所有数据丢失语句。它仅在 CLI 参数中可用。如果你能接受在数据库上运行数据丢失语句，请确保始终使用它

### 🎉 新增 `migrations` 标志 `prefix`

你现在可以自定义迁移文件前缀，使格式适合你的迁移工具：

- `index` 是默认类型，会生成 `0001_name.sql` 文件名；
- `supabase` 和 `timestamp` 相同，会生成 `20240627123900_name.sql` 文件名；
- `unix` 会生成 unix 秒数前缀的 `1719481298_name.sql` 文件名；
- `none` 将完全省略前缀；


##### **示例**：Supabase 迁移格式
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  migrations: {
    prefix: 'supabase'
  }
});

```
