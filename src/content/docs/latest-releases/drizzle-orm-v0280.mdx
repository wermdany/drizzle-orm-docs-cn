## 破坏性变更

### 移除了按嵌套关系过滤的支持

当前示例在 `0.28.0` 中将不再生效：

```ts
const usersWithPosts = await db.query.users.findMany({
  where: (table, { sql }) => (sql`json_array_length(${table.posts}) > 0`),
  with: {
    posts: true,
  },
});
```

`where` 回调中的 `table` 对象将不再包含来自 `with` 和 `extras` 的字段。我们移除了它们，以便构建更高效的关系查询，从而改进行读取和性能。

如果你之前曾在 `where` 回调中使用过这些字段，有几种变通方法：

1. 在获取到行之后，在代码层面手动应用这些过滤器；
2. 使用核心 API。

### 为 `mysql2` 驱动添加了 Relational Queries `mode` 配置

Drizzle 关系查询总是生成恰好一条要在数据库上执行的 SQL 语句，这有其特定的注意事项。为了针对市面上各种数据库提供一流的支持，我们引入了模式（modes）。

Drizzle 关系查询在底层使用子查询的 lateral join，而目前 PlanetScale 不支持它们。

当将 `mysql2` 驱动与常规 MySQL 数据库一起使用时——你应该指定 mode: "default"。
当将 `mysql2` 驱动与 PlanetScale 一起使用时——你需要指定 mode: "planetscale"。

```ts copy {9}
import { drizzle } from 'drizzle-orm/mysql2';
import mysql from 'mysql2/promise';
import * as schema from './schema';

const client = await mysql.createConnection({
  uri: process.env.PLANETSCALE_DATABASE_URL,
});

const db = drizzle({ client, schema, mode: 'planetscale' });
```

## 提升了大型 schema 的 IntelliSense 性能

我们在一个包含 85 张表、666 个列、26 个枚举、172 个索引和 133 个外键的数据库 schema 上运行了诊断。我们优化了内部类型，使 IntelliSense 的速度提升了 **430%**。

## 提升了 Relational Queries 的性能与读取用法

在此版本中，我们彻底改变了为 Relational Query API 生成查询的方式。

总结起来，我们在查询生成策略上做了以下一组改动：

1. Lateral Joins：在新版本中，我们利用由 "LEFT JOIN LATERAL" 子句表示的 lateral join，来高效地从相关表中检索特定数据。对于 PlanetScale 中的 MySQL 和 SQLite，我们使用了简单的子查询 select，这改进了查询计划和整体性能

2. Selective Data Retrieval：在新版本中，我们只从表中检索必要的数据。这种有针对性的数据检索减少了获取的不必要信息量，从而得到更小的数据集进行处理，并加快执行速度。

3. Reduced Aggregations：在新版本中，我们减少了聚合函数（例如 COUNT、json_agg）的数量。通过在 lateral join 中直接使用 json_build_array，drizzle 以更精简的方式聚合数据，从而改进了查询性能。

4. Simplified Grouping：在新版本中，移除了 GROUP BY 子句，因为 lateral join 和子查询已经能更高效地处理数据聚合。

## 支持为所有列插入带有默认值的行

你现在可以提供一个空对象或空对象数组，Drizzle 会将所有默认值插入数据库。

```ts copy {2,5}
// 插入 1 行，全部使用默认值
await db.insert(usersTable).values({});

// 插入 2 行，全部使用默认值
await db.insert(usersTable).values([{}, {}]);
```
