# 新特性

## MSSQL 方言 

Drizzle 现在在 `drizzle-orm`、`drizzle-kit` 和 `drizzle-seed` 包中支持 MSSQL。它支持大多数列、查询构建器能力、迁移策略等。

唯一尚不支持的特性是 `RQBv2`

```ts
// 请确保安装了 'mssql' 包 
import { drizzle } from 'drizzle-orm/node-mssql';

const db = drizzle(process.env.DATABASE_URL);
 
const result = await db.execute('select 1');
```
```ts
// 请确保安装了 'pg' 包 
import { drizzle } from 'drizzle-orm/node-mssql';

// 你可以指定 mssql 连接选项中的任意属性
const db = drizzle({ 
  connection: { 
    connectionString: process.env.DATABASE_URL,
    ssl: true
  }
});
 
const result = await db.execute('select 1');
```

## CockroachDB 方言

Drizzle 现在在 `drizzle-orm`、`drizzle-kit` 和 `drizzle-seed` 包中支持 MSSQL。它支持大多数列、查询构建器能力、迁移策略等。

唯一尚不支持的特性是 `RQBv2`

```ts
// 请确保安装了 'pg' 包 
import { drizzle } from 'drizzle-orm/cockroach';

const db = drizzle(process.env.DATABASE_URL);
 
const result = await db.execute('select 1');
```
```ts
// 请确保安装了 'pg' 包 
import { drizzle } from 'drizzle-orm/cockroach';

// 你可以指定 node-postgres 连接选项中的任意属性
const db = drizzle({ 
  connection: { 
    connectionString: process.env.DATABASE_URL,
    ssl: true
  }
});
 
const result = await db.execute('select 1');
```

## 关系查询部分

如果你需要将关系配置拆分为多个部分，可以使用 `defineRelationsPart` 辅助函数

```ts
import { defineRelations, defineRelationsPart } from 'drizzle-orm';
import * as schema from "./schema";
export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));
export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

然后你可以将它提供给 db 实例

```ts
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })
```

## Folders v3 迁移

> 相关讨论：https://github.com/drizzle-team/drizzle-orm/discussions/2832

我们通过以下方式更新了迁移文件夹结构：
- 移除了 journal.json
- 将 SQL 文件和快照分组到独立的迁移文件夹中
- 移除了 `drizzle-kit drop` 命令

这些变更消除了与 journal 文件可能产生的 Git 冲突，并简化了删除或修复冲突迁移的过程

在即将发布的 beta 版本中，我们将引入可交换性检查，以帮助你应对团队迁移冲突、检测可能的冲突，并给出解决建议
> 可交换性讨论：https://github.com/drizzle-team/drizzle-orm/discussions/5005

要将之前的文件夹迁移到新格式，你需要运行
```
drizzle-kit up
```

## `drizzle-kit` 完全重写

架构重写，以解决 kit 和迁移的主要问题。我们完成了一系列有价值且必要的更新，以帮助我们更快迭代、提高测试覆盖率并增强整体稳定性。

已完成工作总结：
- 从数据库快照迁移到数据库 DDL 快照
- 重新设计了用于检测和应用 diff 的整个架构
- 为默认值、表达式和类型检测添加了重大改进
- 通过最小化数据库调用和查询复杂度，将 schema 内省时间从 10 秒缩短到 1 秒以内
- 为 push 添加了查询提示和 explain 支持
- 扩展了测试覆盖率 - 每个测试用例现在最多运行 6 种不同的场景（例如 push+push、pull+generate 等）

## 新增 `drizzle-kit pull --init`

此标志将在数据库中创建一个 drizzle 迁移表，并将第一个拉取的迁移标记为已应用，这样你就可以从那里继续迭代

## `schemaFilter` 行为更新

`drizzle-kit` 将开始管理你代码中定义的所有 schema。如果你想过滤它们，可以使用 `schemaFilter` 
以前，除非你显式向 `schemaFilter` 添加更多 schema，否则只会管理 public schema。

现在它还支持 glob 模式，允许你以任意方式过滤 schema

## `.enableRLS()` 弃用

以前，要将 PostgreSQL 表标记为启用 RLS，你需要：

```ts
// 旧语法
pgTable('name', {}).enableRLS()
``` 

我们将这个选项移到了另一个位置

```ts
pgTable.withRLS('users', {});
```

## 直接在列上使用别名

你现在可以通过简单的方式为列添加 `as` 别名：

```
const query = db
	.select({ age: users.age.as('ageOfUser'), id: users.id.as('userId') })
	.from(users)
	.orderBy(asc(users.id.as('userId')));
```
