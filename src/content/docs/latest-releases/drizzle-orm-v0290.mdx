> Drizzle ORM 版本 `0.29.0` 将要求 Drizzle Kit 最低版本为 `0.20.0`，反之亦然。因此，当升级到更新版本的 Drizzle ORM 时，你还需要升级 Drizzle Kit。这可能会在各版本之间带来一些破坏性变更，尤其是当你需要升级 Drizzle Kit 而你的 Drizzle ORM 版本早于 `<0.28.0` 时

## 新功能

### 🎉 MySQL bigint 的 `unsigned` 选项

你现在可以指定 `bigint unsigned` 类型

```ts copy {2}
const table = mysqlTable('table', {
  id: bigint('id', { mode: 'number', unsigned: true }),
});
```

### 🎉 改进的查询构建器类型

从 `0.29.0` 开始，默认情况下，由于 Drizzle 中的所有查询构建器都尽可能遵循 SQL，你只能调用大多数方法一次。例如，在 SELECT 语句中可能只有一个 WHERE 子句，因此你只能调用 .where() 一次：

```ts copy {5}
const query = db
  .select()
  .from(users)
  .where(eq(users.id, 1))
  .where(eq(users.name, 'John')); // ❌ 类型错误 - where() 只能被调用一次
```

这种行为对于常规的查询构建很有用，即当你一次性创建整个查询时。然而，当你想要动态构建查询时会成为一个问题，即如果你有一个接收查询构建器并对其进行增强的共享函数。为了解决这个问题，Drizzle 为查询构建器提供了一个特殊的 'dynamic' 模式，它移除了只能调用一次方法的限制。要启用它，你需要在查询构建器上调用 .$dynamic()。

让我们通过实现一个简单的 withPagination 函数来看看它是如何工作的，该函数根据提供的页码和可选的页大小向查询添加 LIMIT 和 OFFSET 子句：

```ts copy {12,13}
function withPagination<T extends PgSelect>(
  qb: T,
  page: number,
  pageSize: number = 10,
) {
  return qb.limit(pageSize).offset(page * pageSize);
}

const query = db.select().from(users).where(eq(users.id, 1));
withPagination(query, 1); // ❌ 类型错误 - 查询构建器未处于 dynamic 模式

const dynamicQuery = query.$dynamic();
withPagination(dynamicQuery, 1); // ✅ OK
```

请注意，withPagination 函数是泛型的，这允许你在其中修改查询构建器的结果类型，例如通过添加 join：

```ts copy {2}
function withFriends<T extends PgSelect>(qb: T) {
  return qb.leftJoin(friends, eq(friends.userId, users.id));
}

let query = db.select().from(users).where(eq(users.id, 1)).$dynamic();
query = withFriends(query);
```

### 🎉 可为主键和外键指定名称

当约束名称超过数据库 64 字符限制时会存在问题。这会导致数据库引擎截断名称，可能引发问题。从 `0.29.0` 开始，你可以为 `primaryKey()` 和 `foreignKey()` 指定自定义名称。我们还弃用了旧的 `primaryKey()` 语法，它仍然可以使用，但将在未来的版本中移除

```ts copy {5,7}
const table = pgTable('table', {
  id: integer('id'),
  name: text('name'),
}, (table) => ({
  cpk: primaryKey({ name: 'composite_key', columns: [table.id, table.name] }),
  cfk: foreignKey({
    name: 'fkName',
    columns: [table.id],
    foreignColumns: [table.name],
  }),
}));
```

在 [文档](/docs/indexes-constraints#composite-primary-key) 中阅读更多内容

### 🎉 支持只读副本

你现在可以使用 Drizzle 的 `withReplica` 函数为读副本和用于写操作的主实例指定不同的数据库连接。默认情况下，`withReplicas` 将为读操作使用一个随机的读副本，为所有其它数据修改操作使用主实例。你还可以指定自定义逻辑来选择使用哪个读副本连接。你可以自由地为此做出任何加权、自定义的决策。以下是一些用法示例：

```ts copy {5}
const primaryDb = drizzle({ client });
const read1 = drizzle({ client });
const read2 = drizzle({ client });

const db = withReplicas(primaryDb, [read1, read2]);

// 从主库读取
db.$primary.select().from(usersTable);

// 从 read1 连接或 read2 连接读取
db.select().from(usersTable)

// 对 delete 操作使用主数据库
db.delete(usersTable).where(eq(usersTable.id, 1))
```

选择读副本的自定义逻辑实现示例，其中第一个副本有 70% 的概率被选中，第二个副本有 30% 的概率被选中。请注意，你可以为读副本实现任何类型的随机选择

```ts copy
const db = withReplicas(primaryDb, [read1, read2], (replicas) => {
    const weight = [0.7, 0.3];
    let cumulativeProbability = 0;
    const rand = Math.random();

    for (const [i, replica] of replicas.entries()) {
      cumulativeProbability += weight[i]!;
      if (rand < cumulativeProbability) return replica;
    }
    return replicas[0]!
});
```

`withReplicas` 函数在 Drizzle ORM 的所有方言中都可用

在 [文档](/docs/read-replicas) 中阅读更多内容

### 🎉 支持集合运算 (UNION, UNION ALL, INTERSECT, INTERSECT ALL, EXCEPT, EXCEPT ALL)

非常感谢 @Angelelz 做出的重大贡献，从 API 讨论到恰当的类型检查和运行时逻辑，以及一套广泛的测试。这极大地帮助我们在本版本中交付了这一特性

用法示例：
所有集合操作符都可以通过两种方式使用：`导入方式` 或 `构建器方式`

<Section>
```ts copy {2,7}
// 导入方式
import { union } from 'drizzle-orm/pg-core'

const allUsersQuery = db.select().from(users);
const allCustomersQuery = db.select().from(customers);

const result = await union(allUsersQuery, allCustomersQuery)
```

```ts copy {2}
// 构建器方式
const result = await db.select().from(users).union(db.select().from(customers));
```
</Section>

在 [文档](/docs/set-operations) 中阅读更多内容

### 🎉 新的 MySQL Proxy 驱动

我们发布了一个新驱动，允许你使用 MySQL 数据库为 HTTP 驱动创建自己的实现。你可以在 `./examples/mysql-proxy` 文件夹中找到用法示例

你需要在服务器上实现两个端点，分别用于查询和迁移（Migrate 端点是可选的，仅当你想要使用 drizzle 迁移时才需要）。服务器和驱动的实现都由你决定，因此你在任何方面都不受限制。你可以添加自定义映射、日志记录以及更多内容

你可以在 `./examples/mysql-proxy` 文件夹中找到服务器和驱动的实现示例

```ts copy {4,9}
// 驱动
import axios from 'axios';
import { eq } from 'drizzle-orm/expressions';
import { drizzle } from 'drizzle-orm/mysql-proxy';
import { migrate } from 'drizzle-orm/mysql-proxy/migrator';
import { cities, users } from './schema';

async function main() {
  const db = drizzle(async (sql, params, method) => {
    try {
      const rows = await axios.post(`${process.env.REMOTE_DRIVER}/query`, {
        sql,
        params,
        method,
      });

      return { rows: rows.data };
    } catch (e: any) {
      console.error('Error from pg proxy server:', e.response.data);
      return { rows: [] };
    }
  });

  await migrate(db, async (queries) => {
    try {
      await axios.post(`${process.env.REMOTE_DRIVER}/migrate`, { queries });
    } catch (e) {
      console.log(e);
      throw new Error('Proxy server cannot run migrations');
    }
  }, { migrationsFolder: 'drizzle' });

  await db.insert(cities).values({ id: 1, name: 'name' });

  await db.insert(users).values({
    id: 1,
    name: 'name',
    email: 'email',
    cityId: 1,
  });

  const usersToCityResponse = await db.select().from(users).leftJoin(
    cities,
    eq(users.cityId, cities.id),
  );
}
```

在 [文档](/docs/mysql/get-started-mysql#http-proxy) 中阅读更多内容

### 🎉 新的 PostgreSQL Proxy 驱动

与 MySQL 相同，你现在可以为 PostgreSQL 数据库实现自己的 http 驱动。你可以在 `./examples/pg-proxy` 文件夹中找到用法示例

你需要在服务器上实现两个端点，分别用于查询和迁移（Migrate 端点是可选的，仅当你想要使用 drizzle 迁移时才需要）。服务器和驱动的实现都由你决定，因此你在任何方面都不受限制。你可以添加自定义映射、日志记录以及更多内容

你可以在 `./examples/pg-proxy` 文件夹中找到服务器和驱动的实现示例

### 🎉 `D1` Batch API 支持

参考：https://developers.cloudflare.com/d1/platform/client-api/#dbbatch

Batch API 用法示例：

<Section>
```ts copy {1}
const batchResponse = await db.batch([
  db.insert(usersTable).values({ id: 1, name: 'John' }).returning({
    id: usersTable.id,
  }),
  db.update(usersTable).set({ name: 'Dan' }).where(eq(usersTable.id, 1)),
  db.query.usersTable.findMany({}),
  db.select().from(usersTable).where(eq(usersTable.id, 1)),
  db.select({ id: usersTable.id, invitedBy: usersTable.invitedBy }).from(
    usersTable,
  ),
]);
```

```ts
type BatchResponse = [
  {
    id: number;
  }[],
  D1Result,
  {
    id: number;
    name: string;
    verified: number;
    invitedBy: number | null;
  }[],
  {
    id: number;
    name: string;
    verified: number;
    invitedBy: number | null;
  }[],
  {
    id: number;
    invitedBy: number | null;
  }[],
];
```
</Section>

所有可以在 `db.batch` 内使用的构建器：

```ts
`db.run()`,
`db.query.<table>.findMany()`,
`db.query.<table>.findFirst()`,
`db.select()...`,
`db.update()...`,
`db.delete()...`,
`db.insert()...`,
```

更多用法示例见：[integration-tests/tests/d1-batch.test.ts](https://github.com/drizzle-team/drizzle-orm/blob/beta/integration-tests/tests/d1-batch.test.ts) 以及 [文档](/docs/batch-api)
