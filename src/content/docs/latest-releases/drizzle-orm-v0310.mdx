## 破坏性变更

> 注意：`drizzle-orm@0.31.0` 可与 `drizzle-kit@0.22.0` 或更高版本一起使用。Drizzle Kit 同理。如果你运行 Drizzle Kit 命令，它会检查并在需要时提示你升级。你可以在[下方](#drizzle-kit-更新drizzle-kit0220)查看 Drizzle Kit 的更新。

### PostgreSQL 索引 API 已更改

之前的 Drizzle+PostgreSQL 索引 API 是不正确的，并且与 PostgreSQL 文档不一致。好在它并未用于查询，而且 drizzle-kit 也不支持索引的所有属性。这意味着我们现在可以将 API 改为正确的形式，并在 drizzle-kit 中为其提供完整支持

之前的 API

- 无法在 `.on` 内部定义 SQL 表达式。
- 在我们的场景中 `.using` 和 `.on` 是同一回事，因此这里的 API 是不正确的。
- `.asc()`、`.desc()`、`.nullsFirst()` 和 `.nullsLast()` 应针对索引上的每个列或表达式指定，而不是针对索引本身。

```ts
// 索引声明参考
index('name')
  .on(table.column1, table.column2, ...) or .onOnly(table.column1, table.column2, ...)
  .concurrently()
  .using(sql``) // sql 表达式
  .asc() or .desc()
  .nullsFirst() or .nullsLast()
  .where(sql``) // sql 表达式
```

当前的 API

```ts
// 第一个示例，使用 `.on()`
index('name')
  .on(table.column1.asc(), table.column2.nullsFirst(), ...) or .onOnly(table.column1.desc().nullsLast(), table.column2, ...)
  .concurrently()
  .where(sql``)
  .with({ fillfactor: '70' })

// 第二个示例，使用 `.using()`
index('name')
  .using('btree', table.column1.asc(), sql`lower(${table.column2})`, table.column1.op('text_ops'))
  .where(sql``) // sql 表达式
  .with({ fillfactor: '70' })
```

## 新特性

### 🎉 "pg_vector" 扩展支持

> 在 Drizzle schema 中没有用于创建扩展的特定代码。我们假设如果你使用 vector 类型、索引和查询，那么你的 PostgreSQL 数据库已经安装了 `pg_vector` 扩展。

你现在可以为 `pg_vector` 指定索引，并使用 `pg_vector` 函数进行查询、排序等操作。

让我们从 `pg_vector` 文档中取几个 `pg_vector` 索引示例，并将它们翻译成 Drizzle

#### L2 距离、内积和余弦距离

```ts
// CREATE INDEX ON items USING hnsw (embedding vector_l2_ops);
// CREATE INDEX ON items USING hnsw (embedding vector_ip_ops);
// CREATE INDEX ON items USING hnsw (embedding vector_cosine_ops);

const table = pgTable('items', {
    embedding: vector('embedding', { dimensions: 3 })
}, (table) => ({
    l2: index('l2_index').using('hnsw', table.embedding.op('vector_l2_ops'))
    ip: index('ip_index').using('hnsw', table.embedding.op('vector_ip_ops'))
    cosine: index('cosine_index').using('hnsw', table.embedding.op('vector_cosine_ops'))
}))
```

#### L1 距离、汉明距离和杰卡德距离 - 在 pg_vector 0.7.0 版本中新增

```ts
// CREATE INDEX ON items USING hnsw (embedding vector_l1_ops);
// CREATE INDEX ON items USING hnsw (embedding bit_hamming_ops);
// CREATE INDEX ON items USING hnsw (embedding bit_jaccard_ops);

const table = pgTable('table', {
    embedding: vector('embedding', { dimensions: 3 })
}, (table) => ({
    l1: index('l1_index').using('hnsw', table.embedding.op('vector_l1_ops'))
    hamming: index('hamming_index').using('hnsw', table.embedding.op('bit_hamming_ops'))
    bit: index('bit_jaccard_index').using('hnsw', table.embedding.op('bit_jaccard_ops'))
}))
```

对于查询，你可以使用预定义的向量函数，或者使用 SQL 模板操作符创建自定义函数。

你也可以使用以下辅助函数：

```ts
import { l2Distance, l1Distance, innerProduct, 
          cosineDistance, hammingDistance, jaccardDistance } from 'drizzle-orm'

l2Distance(table.column, [3, 1, 2]) // table.column <-> '[3, 1, 2]'
l1Distance(table.column, [3, 1, 2]) // table.column <+> '[3, 1, 2]'

innerProduct(table.column, [3, 1, 2]) // table.column <#> '[3, 1, 2]'
cosineDistance(table.column, [3, 1, 2]) // table.column <=> '[3, 1, 2]'

hammingDistance(table.column, '101') // table.column <~> '101'
jaccardDistance(table.column, '101') // table.column <%> '101'
```

如果 `pg_vector` 还有其它需要使用的函数，你可以参照我们现有的实现来复制。具体做法如下

```ts
export function l2Distance(
  column: SQLWrapper | AnyColumn,
  value: number[] | string[] | TypedQueryBuilder<any> | string,
): SQL {
  if (is(value, TypedQueryBuilder<any>) || typeof value === 'string') {
    return sql`${column} <-> ${value}`;
  }
  return sql`${column} <-> ${JSON.stringify(value)}`;
}
```

你可以随意命名并更换操作符。这个示例支持数字数组、字符串数组、字符串，甚至是一个查询。你可以随意创建任何你想要的类型，甚至贡献代码并提交 PR

#### 示例

让我们从 `pg_vector` 文档中取几个 `pg_vector` 查询示例，并将它们翻译成 Drizzle

```ts
import { l2Distance } from 'drizzle-orm';

// SELECT * FROM items ORDER BY embedding <-> '[3,1,2]' LIMIT 5;
db.select().from(items).orderBy(l2Distance(items.embedding, [3,1,2]))

// SELECT embedding <-> '[3,1,2]' AS distance FROM items;
db.select({ distance: l2Distance(items.embedding, [3,1,2]) })

// SELECT * FROM items ORDER BY embedding <-> (SELECT embedding FROM items WHERE id = 1) LIMIT 5;
const subquery = db.select({ embedding: items.embedding }).from(items).where(eq(items.id, 1));
db.select().from(items).orderBy(l2Distance(items.embedding, subquery)).limit(5)

// SELECT (embedding <#> '[3,1,2]') * -1 AS inner_product FROM items;
db.select({ innerProduct: sql`(${maxInnerProduct(items.embedding, [3,1,2])}) * -1` }).from(items)

// 还有更多！
```

## 🎉 新的 PostgreSQL 类型：`point`、`line`

你现在可以使用来自 [PostgreSQL 几何类型](https://www.postgresql.org/docs/current/datatype-geometric.html)的 `point` 和 `line`

类型 `point` 有两种从数据库映射的模式：`tuple` 和 `xy`。

- `tuple` 将被接受用于插入，并在查询时映射为一个元组。因此，数据库中的 Point(1,2) 在 drizzle 中会被类型化为 [1,2]。

- `xy` 将被接受用于插入，并在查询时映射为一个带有 x、y 坐标的对象。因此，数据库中的 Point(1,2) 在 drizzle 中会被类型化为 `{ x: 1, y: 2 }`

```ts
const items = pgTable('items', {
 point: point('point'),
 pointObj: point('point_xy', { mode: 'xy' }),
});
```

类型 `line` 有两种从数据库映射的模式：`tuple` 和 `abc`。

- `tuple` 将被接受用于插入，并在查询时映射为一个元组。因此，数据库中的 Line{1,2,3} 在 drizzle 中会被类型化为 [1,2,3]。

- `abc` 将被接受用于插入，并在查询时映射为一个对象，其中包含方程 `Ax + By + C = 0` 中的 a、b、c 常数。因此，数据库中的 Line{1,2,3} 在 drizzle 中会被类型化为 `{ a: 1, b: 2, c: 3 }`。

```ts
const items = pgTable('items', {
 line: line('line'),
 lineObj: line('line_abc', { mode: 'abc' }),
});
```

## 🎉 基础 "postgis" 扩展支持

> 在 Drizzle schema 中没有用于创建扩展的特定代码。我们假设如果你使用 postgis 类型、索引和查询，那么你的 PostgreSQL 数据库已经安装了 `postgis` 扩展。

postgis 扩展中的 `geometry` 类型：

```ts
const items = pgTable('items', {
  geo: geometry('geo', { type: 'point' }),
  geoObj: geometry('geo_obj', { type: 'point', mode: 'xy' }),
  geoSrid: geometry('geo_options', { type: 'point', mode: 'xy', srid: 4000 }),
});
```

**mode**
类型 `geometry` 有两种从数据库映射的模式：`tuple` 和 `xy`。

- `tuple` 将被接受用于插入，并在查询时映射为一个元组。因此，数据库中的 geometry 在 drizzle 中会被类型化为 [1,2]。
- `xy` 将被接受用于插入，并在查询时映射为一个带有 x、y 坐标的对象。因此，数据库中的 geometry 在 drizzle 中会被类型化为 `{ x: 1, y: 2 }`

**type**

当前版本有一个预定义类型：`point`，它是 PostgreSQL PostGIS 扩展中的 `geometry(Point)` 类型。如果你想使用其它类型，可以在那里指定任意字符串

# Drizzle Kit 更新：`drizzle-kit@0.22.0`

> 这里的发布说明部分复制自 [drizzle-kit@0.22.0](https://github.com/drizzle-team/drizzle-kit-mirror/releases/tag/v0.22.0)

## 新特性

### 🎉 支持新类型

Drizzle Kit 现在可以处理：

- PostgreSQL 的 `point` 和 `line`
- PostgreSQL `pg_vector` 扩展的 `vector`
- PostgreSQL `PostGIS` 扩展的 `geometry`

### 🎉 drizzle.config 中的新参数 - `extensionsFilters`

PostGIS 扩展会在 `public` schema 中创建一些内部表。这意味着如果你有一个安装了 PostGIS 扩展的数据库，并使用 `push` 或 `introspect`，所有这些表都会包含在 `diff` 操作中。在这种情况下，你需要指定 `tablesFilter`，找出该扩展创建的所有表，并将它们列在这个参数中。

我们已解决此问题，因此你无需执行所有这些步骤。只需指定 `extensionsFilters` 并带上所用扩展的名称，Drizzle 就会跳过所有必要的表。

目前我们仅支持 `postgis` 选项，但如果其它扩展会在 `public` schema 中创建表，我们计划添加更多扩展支持。

`postgis` 选项将跳过 `geography_columns`、`geometry_columns` 和 `spatial_ref_sys` 表
```ts
import { defineConfig } from 'drizzle-kit'

export default defaultConfig({
  dialect: "postgresql",
  extensionsFilters: ["postgis"],
})
```

### 为 `libsql` 和 `better-sqlite3` 驱动规范化 SQLite url

这些驱动有不同的文件路径模式，Drizzle Kit 会同时接受两者，并为每个驱动创建合适的文件路径格式

### 更新了 MySQL 和 SQLite 索引作为表达式的行为

在此版本中，MySQL 和 SQLite 会将表达式正确映射到 SQL 查询中。表达式不会被转义到字符串中，但列会被转义

```ts
export const users = sqliteTable(
  'users',
  {
    id: integer('id').primaryKey(),
    email: text('email').notNull(),
  },
  (table) => ({
    emailUniqueIndex: uniqueIndex('emailUniqueIndex').on(sql`lower(${table.email})`),
  }),
);

```
```sql
-- 之前
CREATE UNIQUE INDEX `emailUniqueIndex` ON `users` (`lower("users"."email")`);

-- 现在
CREATE UNIQUE INDEX `emailUniqueIndex` ON `users` (lower("email"));
```

## `push` 和 `generate` 如何处理索引

### 限制

#### 如果索引至少包含一个表达式，你需要手动为索引指定名称

示例

```ts
index().on(table.id, table.email) // 可以正常工作，名称会自动生成
index('my_name').on(table.id, table.email) // 可以正常工作

// 但是

index().on(sql`lower(${table.email})`) // 报错
index('my_name').on(sql`lower(${table.email})`) // 可以正常工作
```

#### 如果现有索引中的这些字段（见下方列表）被更改，Push 将不会生成语句：

- `.on()` 和 `.using()` 内部的表达式
- `.where()` 语句
- 列上的操作符类 `.op()`

如果你使用 `push` 工作流并想更改索引中的这些字段，你需要：

- 注释掉该索引
- 执行 push
- 取消注释该索引并修改这些字段
- 再次执行 push

对于 `generate` 命令，在新的 drizzle 索引 API 中，索引任何属性的任何更改都会触发 `drizzle-kit`，因此这里没有限制。
