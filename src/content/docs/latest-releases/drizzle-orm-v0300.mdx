## 破坏性变更

Postgres 的 timestamp 映射已更改，以使所有驱动保持一致的行为。

❗ 我们修改了 `postgres.js` 驱动实例，使其始终返回字符串形式的日期，然后 Drizzle 会根据所选的 `mode` 为你提供映射后的日期字符串。你唯一可能遇到的问题是一旦你在 Drizzle 中传入 `postgres.js`` 驱动实例，该对象在日期方面的行为将发生变化，日期将始终是字符串。

我们以次要版本的形式做出了这一更改，仅作为提示：

- 如果你之前使用 timestamps 并期待特定的响应，现在行为将会改变。
  在映射到驱动时，无论 timestamp 是否带时区，我们都会始终使用 `.toISOString`。

- 如果你在 Drizzle 之外使用 `postgres.js` 驱动，那么所有传给 Drizzle 的 `postgres.js` 客户端在日期方面都会出现被改变的行为。响应中的所有日期都将是字符串。

为 `postgres.js` 更改的解析器。

```ts
const transparentParser = (val: any) => val;

// 覆盖 postgres.js 默认的日期解析器：https://github.com/porsager/postgres/discussions/761
for (const type of ['1184', '1082', '1083', '1114']) {
	client.options.parsers[type as any] = transparentParser;
	client.options.serializers[type as any] = transparentParser;
}
```

理想情况下，就像几乎所有其他驱动一样，我们应该能够按查询逐个修改映射，这意味着驱动客户端不会被修改。我们将联系 `postgres.js` 库的创建者，询问是否可以指定按查询的映射拦截器，从而让所有用户的这一流程变得更好。

如果我们忽略了这一能力，并且 `postgres.js`` 已经支持它，请在我们的 Discord 中告诉我们！

关于不带时区和带时区的 timestamps 的更多参考可以在我们的[文档](http://orm.drizzle.team/docs/column-types#timestamp)中找到

在[这里](/docs/get-started-postgresql#postgresjs)查看开始使用 `postgres.js` 驱动和 Drizzle 的文档

## 修复

- mode 为 string 的 timestamp 返回的是 Date 对象而不是字符串 - ([#806](https://github.com/drizzle-team/drizzle-orm/issues/806))
- 日期始终是日期（[#971](https://github.com/drizzle-team/drizzle-orm/issues/971)）
- 在 javascript 中处理 timestamps 及对应 datetime 对象时存在不一致。（[#1176](https://github.com/drizzle-team/drizzle-orm/issues/1176)）
- timestamp 列显示为 string 类型，但实际返回的是 Date 对象。（[#1185](https://github.com/drizzle-team/drizzle-orm/issues/1185)）
- postgres date 列的数据类型错误（[#1407](https://github.com/drizzle-team/drizzle-orm/issues/1407)）
- 当 PostgreSQL 的 TimeZone 设置为 UTC 时，timestamp 转换无效（[#1587](https://github.com/drizzle-team/drizzle-orm/issues/1587)）
- Postgres 插入到带时区的 timestamp 时移除了毫秒（[#1061](https://github.com/drizzle-team/drizzle-orm/issues/1061)）
- 更新 timestamp 字段（使用 AWS Data API）（[#1164](https://github.com/drizzle-team/drizzle-orm/issues/1164)）
- 关系查询返回无效日期（[#895](https://github.com/drizzle-team/drizzle-orm/issues/895)）
