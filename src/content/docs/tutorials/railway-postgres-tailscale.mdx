<ExternalLinkArrows />

本教程将你设备上的 `drizzle-kit` 连接到 [Railway](https://driz.link/railway) 上已关闭公共访问的 PostgreSQL 数据库。

你向存放数据库的项目添加一个 [Tailscale](https://tailscale.com/) 服务。之后，你 tailnet 上的每台设备都可以访问该数据库。

<Callout type="info">
如果你还想要一个位于 tailnet 上的数据库 UI，请从 [Deploy Drizzle Studio or Gateway on Railway with private access over Tailscale](/docs/tutorials/railway-studio-tailscale) 开始。它的模板自带相同的 Tailscale 服务。
</Callout>

<Prerequisites title="本指南假设以下条件：">
  - 你拥有一个 [Railway](https://driz.link/railway) 账户。

  - 你拥有一个 [Tailscale](https://tailscale.com/) 账户。

  - 你在自己的工作设备上安装了 Tailscale 客户端，并且该设备已登录你的 tailnet。你可以在 [Tailscale 网站](https://tailscale.com/download)上找到下载项。

  - 你的 tailnet 中已开启 MagicDNS，以便机器名可以解析。2022-10-20 及之后创建的 tailnet 默认开启它。如果你的 tailnet 更早，请查看 [DNS 页面](https://login.tailscale.com/admin/dns)。

  - 你已安装 Drizzle ORM 和 [Drizzle Kit](/docs/kit-overview)。
  <Npm>
      drizzle-orm@rc
      -D drizzle-kit@rc
  </Npm>
</Prerequisites>

## 工作原理

Railway 为每个服务分配一个以 `.railway.internal` 结尾的私有域名。这些域名只在项目内部可解析，因此你设备上的 `drizzle-kit` 无法使用它们。

Tailscale 服务连接这两个网络。它运行在同一个 Railway 项目中，因此可以解析这些私有域名。它同时作为一台机器加入你的 tailnet，因此你自己的设备可以通过其机器名访问它。流量从 `drizzle-kit` 经由 tailnet 到达该机器，再从那里经由 Railway 的私有网络到达数据库。

## 设置 Railway 项目

创建一个带有无公共访问的 PostgreSQL 数据库的项目。如果你的项目已经有数据库，请跳到 [Add the Tailscale service](#添加-tailscale-服务)。

<Steps>
#### 创建 Railway 项目

登录你的 [Railway 控制面板](https://railway.app/dashboard)并点击 `New Project` 按钮。

![Railway 创建菜单，已选中 Database](@/assets/images/tutorials/railway-create-service-menu.png)

#### 配置 PostgreSQL 数据库

在项目画布上，点击右上角的 `New` 按钮，然后选择 `Database` → `PostgreSQL`。你也可以使用命令面板（<Shortcut mac="⌘ K" other="Ctrl K" />）并搜索 PostgreSQL。

![Railway 数据库菜单，已选中 PostgreSQL](@/assets/images/tutorials/railway-select-postgres.png)

#### 让数据库保持在私有网络

点击 PostgreSQL 服务，进入 `Settings` 选项卡，找到 `Networking` 部分。确认公共访问已禁用。在 `Private Networking` 下你将看到该服务的私有域名，例如 `postgres.railway.internal`。

![Postgres 的 Settings 选项卡，无公共访问，私有域名为 postgres.railway.internal](@/assets/images/tutorials/railway-postgres-private-networking.png)

</Steps>

## 添加 Tailscale 服务

将 Tailscale for Drizzle 模板部署到存放你的数据库的项目中。

<Callout type="info">
如果你的项目已经运行了 `Drizzle Studio with Tailscale` 或 `Drizzle Gateway with Tailscale` 模板，那么它已经有一个 Tailscale 服务，你可以跳过本节。打开那个 Tailscale 服务，进入 `Variables` 选项卡，并设置 `TS_FORWARD_DATABASE`：输入 `${{` 并选择你的数据库服务的 `RAILWAY_PRIVATE_DOMAIN`。点击顶栏中的 `Deploy`，等待新部署日志中出现 `5432: ready`。机器名是 `open` 行中地址的第一部分，例如 `drizzle-studio`。
</Callout>

<Steps>
#### 打开模板

按下下方按钮打开 Tailscale for Drizzle 模板。

**不要立刻部署它。** 先设置变量。

<a
  href="https://railway.com/new/template/tailscale-for-drizzle?referralCode=eobqmj&utm_medium=integration&utm_source=button&utm_campaign=tailscale-for-drizzle"
  target="_blank"
  rel="nofollow noreferrer"
  style="display: inline-block; margin: 16px 0;"
>
  <img src="https://railway.com/button.svg" alt="部署到 Railway" width="183" height="40" />
</a>

打开 `Deploy to` 下拉菜单，选择存放你的数据库的项目。

![Tailscale for Drizzle 部署表单，TS_FORWARD_DATABASE 设置为 Postgres 私有域名，TS_HOSTNAME 设置为 railway-postgres](@/assets/images/tutorials/railway-tailscale-database-template-form.png)

#### 设置变量

<TableWrapper>

| 变量 | 设置为什么 |
| --- | --- |
| `TS_FORWARD_DATABASE` | 该字段为空。从列表中选择你的数据库服务，然后选择 `RAILWAY_PRIVATE_DOMAIN`。对于名为 `Postgres` 的服务，该字段随后会显示为 `${{Postgres.RAILWAY_PRIVATE_DOMAIN}}`。 |
| `TS_HOSTNAME` | 将其改为 `railway-postgres`，或为机器选择另一个名称。你通过该名称连接数据库。 |

</TableWrapper>

一些变量（例如 `TS_HOSTNAME`）位于卡片的折叠区域 `Pre-Configured Environment Variables` 中。展开它以查看或更改它们。

#### 部署模板

在服务卡片上，点击 `Save Config`。然后点击 `Review and deploy`。Railway 会在侧边面板中打开你的项目并显示该模板。在那里点击 `Deploy Template`。

#### 从部署日志登录

打开 `Tailscale` 服务，然后进入其 `Deployments` 选项卡，阅读部署日志。日志的最后几行包含一个登录链接：

```plaintext
This service is not on your tailnet yet. Open this link and sign in
with the account that owns your tailnet:
  https://login.tailscale.com/a/xxxxxxxxxxxx
```

打开该链接并登录。谁先打开该链接，这台机器就会加入谁的 tailnet，因此不要转发它。该日志仅对你的 Railway 项目成员可见。

![Tailscale 部署日志，包含登录消息和一个隐藏的链接](@/assets/images/tutorials/railway-tailscale-signin-log.png)

如果你的 tailnet 需要设备审批，日志会说明这一点，机器会一直等待，直到你在 [Machines 页面](https://login.tailscale.com/admin/machines)上批准它。

#### 检查转发规则

登录几秒后，同一份日志会打印：

```plaintext
joined tailnet: example.com
5432: ready
```

![Tailscale 部署日志，包含已加入 tailnet 和 5432 ready 的行](@/assets/images/tutorials/railway-tailscale-database-log.png)

检查 tailnet 名称是否是你的。如果不是，说明其他人先打开了登录链接，他们的 tailnet 现在可以访问此服务。要收回该服务：

1. 在项目画布上，点击 Tailscale 服务下方的卷，打开其 `Settings` 选项卡，然后点击 `Wipe volume`。
2. 输入确认文本并点击 `Wipe`。Railway 会删除该机器的密钥并重新部署该服务。
3. 你自己从新的部署日志中打开登录链接。
4. 更改数据库用户的密码。

#### 找到机器名称

打开 [Machines 页面](https://login.tailscale.com/admin/machines)。新机器使用你在 `TS_HOSTNAME` 中设置的名称。如果你的 tailnet 已经有一台同名机器，新名称会以 `-1`、`-2` 等结尾。使用 Machines 页面显示的名称。

</Steps>

## 从你的设备连接 Drizzle Kit

将 `drizzle-kit` 指向该机器名并应用你的 schema。

<Steps>
#### 设置连接字符串

在 Railway 中打开 PostgreSQL 服务，进入 `Variables` 选项卡，然后复制 `DATABASE_URL`。

![Postgres 的 Variables 选项卡，已标出 DATABASE_URL](@/assets/images/tutorials/railway-postgres-database-url.png)

将 `***.railway.internal` 主机替换为该机器名并保留字符串的其余部分。将结果放入 `.env` 文件：

```plaintext copy
DATABASE_URL=postgresql://postgres:PASSWORD@MACHINE_NAME:5432/railway
```

替换以下内容：

- `PASSWORD`：你复制的 `DATABASE_URL` 中的密码
- `MACHINE_NAME`：Machines 页面中的机器名，例如 `railway-postgres`

<Callout type="info">
Tailscale 会加密你的设备与 Tailscale 服务之间的连接，Railway 会加密 Tailscale 服务与数据库之间的一段。Railway 的 PostgreSQL 也通过 Tailscale 服务接受 TLS，因此大多数客户端使用默认设置即可连接。
</Callout>

#### 设置 Drizzle 配置文件

在你的项目根目录下创建一个 `drizzle.config.ts` 文件：

```typescript copy filename="drizzle.config.ts"
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: "./src/schema.ts",
  out: "./migrations",
  dialect: "postgresql",
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
});
```

#### 应用你的 schema

生成迁移并应用它们：

```bash copy
npx drizzle-kit generate
```

```bash copy
npx drizzle-kit migrate
```

对于快速原型设计，你可以使用 [drizzle-kit push](/docs/drizzle-kit-push) 直接推送 schema。对于生产部署，请优先使用 `generate` 和 `migrate` 工作流，以保留 schema 变更的版本化历史。详情请参阅 [Drizzle 迁移基础](/docs/migrations)页面。

#### 在 Drizzle Studio 中检查表

在 [Drizzle Studio](/docs/drizzle-kit-studio) 中打开数据库：

```bash copy
npx drizzle-kit studio
```

它运行在你的设备上并读取相同的 `DATABASE_URL`，因此它会通过 Tailscale 服务到达数据库。你的新表就在那里。

![Drizzle Studio 中显示 posts 和 users 表](@/assets/images/tutorials/drizzle-studio-posts-table.png)

</Steps>

<Callout type="info">
对于偶尔的访问，你完全不需要 Tailscale。Railway CLI 通过 `railway connect Postgres --tunnel-only` 打开到一个私有数据库的临时隧道。如果你需要一条永久路由，或需要从 tailnet 上的每台设备访问，请使用 Tailscale 服务。
</Callout>

## 使用其他端口

默认情况下，`TS_FORWARD_DATABASE` 在机器上和数据库服务上都使用端口 5432。要使用其他端口，请按 `[port:]host[:port]` 形式书写该值：

<TableWrapper>

| 值 | 机器上的端口 | 服务上的端口 |
| --- | --- | --- |
| `host` | 默认端口 | 默认端口 |
| `host:port` | `port` | `port` |
| `source_port:host:target_port` | `source_port` | `target_port` |

</TableWrapper>

例如，`5433:${{Postgres.RAILWAY_PRIVATE_DOMAIN}}:5432` 将机器上的端口 5433 转发到数据库服务的端口 5432。你的连接字符串随后使用端口 5433。

## 禁用密钥过期

通过登录加入的机器，其密钥会按你 tailnet 的计划过期，默认是 180 天。当这种情况发生时，Tailscale 服务会打印一个新的登录链接并等待。在你点击它之前，该机器不可达。

为避免这种情况，请打开一次 [Machines 页面](https://login.tailscale.com/admin/machines)，找到该机器，打开其所在行最右侧的菜单，然后选择 `Disable key expiry`。

![Tailscale Machines 页面菜单，包含 Disable key expiry](@/assets/images/tutorials/tailscale-machines-disable-key-expiry.png)

<Callout type="info">
如果你自动化部署并且完全不希望登录，请在 Tailscale 服务上设置 `TS_AUTHKEY`：

- 对于 auth key，将 `TS_AUTHKEY` 设置为该密钥。
- 对于 OAuth client secret，将 `TS_AUTHKEY` 设置为该 secret 并追加 `?ephemeral=false&preauthorized=true`。没有该后缀时，Tailscale 会在机器断开时移除它，并且机器在加入前会等待审批。同时将 `TS_TAGS` 设置为你拥有的 tag，例如 `tag:drizzle`。带 tag 的机器其密钥永远不会过期。

Tailscale 服务只在机器加入之前读取 `TS_AUTHKEY`。如果机器已经加入，请先移除该机器并清空卷。
</Callout>

## 排查 Tailscale 设置问题

打开与你所见情况匹配的条目。

<Callout>
<Fragment slot="collapsed-title">错误信息中的主机名以 `.railway.internal` 结尾</Fragment>

你从 Railway 复制的 `DATABASE_URL` 仍带有私有域名，它只在项目内部可解析。将该主机替换为 Tailscale 机器名并保留字符串的其余部分，如 [Set the connection string](#设置连接字符串) 中所述。
</Callout>

<Callout>
<Fragment slot="collapsed-title">`drizzle-kit` 无法连接</Fragment>

在你的设备上运行 `tailscale status`，并检查它是否登录了日志中命名的同一个 tailnet。然后打开 Tailscale 服务的部署日志并查找原因：

- 某一行以 `5432:` 开头并以网络错误结尾，例如 `connect: connection refused` 或 `no such host`。变量是正确的，数据库在其私有域名上不可达。检查数据库服务是否正在运行并已开启私有网络。如果数据库监听另一个端口，请将该端口添加到值中，例如 `5432:${{Postgres.RAILWAY_PRIVATE_DOMAIN}}:5433`。
- 没有任何行以 `5432:` 或 `TS_FORWARD_DATABASE` 开头。该变量为空，或其引用指向你项目之外的服务。在 Tailscale 服务的 `Variables` 选项卡上设置它，并点击顶栏中的 `Deploy`。
- 某一行以 `TS_FORWARD_DATABASE` 开头。下一条目解释了该行。
- 日志显示 `5432: ready`，但机器名无法解析。检查 MagicDNS 是否已开启，在 [DNS 页面](https://login.tailscale.com/admin/dns)上。如果已开启，请使用 Machines 页面中该机器的 `Full domain` 值作为主机。
</Callout>

<Callout>
<Fragment slot="collapsed-title">日志打印了一行以 `skipped` 结尾的内容</Fragment>

该行以变量名开头，然后给出原因：

- `does not match [port:]host[:port]`：该值包含两个以上的冒号。
- `has an empty target host`：该值有一个端口但没有主机。一个指向你项目之外服务的引用会解析为空主机。
- `still contains a Railway reference that did not resolve`：Railway 没有替换该引用。检查其中的服务名。
- `has a port outside 1-65535`：某个端口不是 1 到 65535 之间的数字。
- `reuses port`：先前的转发已经在机器上使用了该端口。
- `uses port 443, which the https listener owns`：在机器上选择另一个端口。当 HTTPS 证书开启时，数据库 UI 的地址已经使用了 443。

在 Tailscale 服务的 `Variables` 选项卡上修正该值，并点击顶栏中的 `Deploy`。
</Callout>

<Callout>
<Fragment slot="collapsed-title">日志中出现了一个新的登录链接</Fragment>

该服务重启了，例如在密钥过期或机器被移除之后。打开最新的链接。该链接只能使用一次。
</Callout>

<Callout>
<Fragment slot="collapsed-title">日志显示机器正在等待审批</Fragment>

你的 tailnet 已开启设备审批。打开 [Machines 页面](https://login.tailscale.com/admin/machines)并批准它。
</Callout>

<Callout>
<Fragment slot="collapsed-title">它正常工作了好几个月，然后停止了</Fragment>

该机器的密钥过期了。打开 Tailscale 服务的部署日志；它正在打印一个新的登录链接。点击它，然后在该机器上禁用密钥过期，以免再次发生。
</Callout>

<Callout>
<Fragment slot="collapsed-title">机器名多了一个 `-1` 后缀</Fragment>

你的 tailnet 已经有一台使用此名称的机器，例如来自更早的部署。Tailscale 会保留该后缀。如果你想要短名称，请在 Machines 页面上重命名该机器。否则，使用 Machines 页面显示的名称。
</Callout>
