本教程在 [Railway](https://driz.link/railway) 上部署一个数据库 UI 和一个 PostgreSQL 数据库，并让两者都不暴露在公网。

一个 [Tailscale](https://tailscale.com/) Forwarder 会加入你的 tailnet，并将 UI 端口转发到 Railway 的私有网络。之后，你可以从 tailnet 上的任意设备通过 HTTPS 打开该数据库 UI，两个服务都无需公网域名。

你可以使用 [Drizzle Studio](/drizzle-studio/overview) 或 Drizzle Gateway。下面完整介绍两者。

如果你希望对 `drizzle-kit` 和其他数据库客户端也提供同样的私有访问，请参阅 [Connect to a private Railway database with Tailscale](/docs/tutorials/railway-postgres-tailscale-legacy)。

<Prerequisites title="This guide assumes the following:">
  - 你拥有一个 [Railway](https://driz.link/railway) 账户。

  - 你拥有一个 [Tailscale](https://tailscale.com/) 账户。

  - 你在工作所用的机器上安装了 Tailscale 客户端，并且该机器已登录到你的 tailnet。你可以在 [Tailscale 网站](https://tailscale.com/download)上找到下载链接。

</Prerequisites>

## 工作原理

Railway 会为每个服务分配一个以 `.railway.internal` 结尾的私有域名。这些域名只在该项目内部可解析。Tailscale Forwarder 作为同一项目中的一个服务运行，因此可以访问它们。它同时以一台机器的身份加入你的 tailnet，因此你自己的设备也能访问它。

## 设置 Railway 项目

<Steps>
#### 创建 Railway 项目

登录你的 [Railway 控制台](https://railway.app/dashboard)，点击 `New Project` 按钮。

![](@/assets/images/tutorials/railway-create-service-menu.png)

#### 配置 PostgreSQL 数据库

在项目画布上，点击右上角的 `New` 按钮，然后选择 `Database` → `PostgreSQL`。你也可以使用命令面板（<Shortcut mac="⌘ K" other="Ctrl K" />）并搜索 PostgreSQL。

![](@/assets/images/tutorials/railway-select-postgres.png)

#### 让数据库保持在私有网络

点击 PostgreSQL 服务，进入 `Settings` 标签页，找到 `Networking` 部分。确认公共访问已禁用。在 `Private Networking` 下，你会看到该服务的私有域名，例如 `postgres.railway.internal`。转发器将使用该域名。

![](@/assets/images/tutorials/railway-postgres-private-networking.png)

</Steps>

## 选择 Gateway 或 Studio

Drizzle 提供两个 Railway 模板，分别面向不同的使用场景。

<TableWrapper>

| | Drizzle Studio | Drizzle Gateway |
| --- | --- | --- |
| Databases | 一个，固定为你在 Railway 中设置的 `DATABASE_URL` | 多个，你在 UI 中添加和编辑 |
| Access | 由模板生成的 `PASSCODE` | `MASTERPASS`，以及你分发的口令 |

</TableWrapper>

在以下情况选择 **Drizzle Studio**：
- tailnet 上的每个人都只能访问单个数据库

<br />

在以下情况选择 **Drizzle Gateway**：
- 你需要管理多个数据库
- 你想让其他人访问特定数据库

请记住，知道 `MASTERPASS` 的 Gateway 用户可以添加指向该服务可访问的任意数据库的连接。

<br />

<Steps>
#### 将 Studio 模板部署到同一项目中

点击下面的按钮打开 Drizzle Studio 模板。

**不要立即部署** —— 请务必先读完本步骤并设置必需的变量。

<a
  href="https://railway.com/new/template/drizzle-studio-1?referralCode=eobqmj&utm_medium=integration&utm_source=button&utm_campaign=drizzle-studio-1"
  target="_blank"
  rel="nofollow noreferrer"
  style="display: inline-block; margin: 16px 0;"
>
  <img src="https://railway.com/button.svg" alt="Deploy on Railway" width="183" height="40" />
</a>

打开 `Deploy to` 下拉菜单，选择承载你数据库的项目。两个服务必须位于同一个项目，否则 Studio 将无法通过私有网络访问数据库，因为它会被放到另一个私有网络中。

该模板带有三个变量。将 `DATABASE_URL` 设为 `${{Postgres.DATABASE_URL}}`，它会解析为数据库的私有连接字符串，这样 Drizzle Studio 就会通过 Railway 私有网络访问它。`PASSCODE` 用于保护对 UI 的访问，由模板生成。`PORT` 设为 `4983`；保持原样，因为你稍后添加的转发器映射会指向相同的端口号。点击 `Deploy`。

![](@/assets/images/tutorials/railway-deploy-drizzle-studio-env.png)

#### 移除公共域名

进入 Drizzle Studio 服务的 `Settings` 标签页，找到 `Networking` 部分。如果 Railway 生成了公网域名，将其删除。保留私有域名。完成此步骤后，UI 只能从项目内部访问，不久之后也能从你的 tailnet 访问。

![](@/assets/images/tutorials/railway-drizzle-studio-remove-public-domain.png)

#### 检查 MagicDNS 和 HTTPS 证书

在 Tailscale 管理控制台中打开 [DNS 页面](https://login.tailscale.com/admin/dns)。**MagicDNS** 和 **HTTPS Certificates** 都必须启用。每个部分提供的都是相反的操作，因此显示 `Disable MagicDNS...` 的按钮意味着 MagicDNS 已经开启。MagicDNS 为转发器提供一个稳定的机器名。HTTPS 证书则让转发器能够通过 HTTPS 提供 UI。

![](@/assets/images/tutorials/tailscale-dns-magicdns-https.png)

#### 创建可复用的认证密钥

在设置菜单中打开 [Keys 页面](https://login.tailscale.com/admin/settings/keys)，点击 `Generate auth key`。添加描述并打开 `Reusable`。其余设置保持原样。可重复使用的密钥让转发器在没有现有状态的情况下启动时能够重新注册自己。

![](@/assets/images/tutorials/tailscale-generate-auth-key.png)

点击 `Generate key`。立即复制该密钥，因为管理控制台只显示一次。

![](@/assets/images/tutorials/tailscale-auth-key-created.png)

#### 部署 Tailscale Forwarder

Tailscale Forwarder 是一个小型 TCP 代理。它以一台机器的身份加入你的 tailnet，并将该机器上的端口转发到 Railway 私有网络中的服务。Railway 发布了该模板，它运行 `brody192/tailscale-forwarder` 镜像。

<a
  href="https://railway.com/deploy/tailscale-forwarder"
  target="_blank"
  rel="nofollow noreferrer"
  style="display: inline-block; margin: 16px 0;"
>
  <img src="https://railway.com/button.svg" alt="Deploy on Railway" width="183" height="40" />
</a>

将你的 auth key 粘贴到 `TS_AUTHKEY`。然后将 `CONNECTION_MAPPING_01` 设为数据库映射。格式为 `[https:]<source port>:<target host>:<target port>`。

```plaintext copy
5432:${{Postgres.RAILWAY_PRIVATE_DOMAIN}}:${{Postgres.PGPORT}}
```

这会将转发器上的 `5432` 端口转发到你的数据库。

![](@/assets/images/tutorials/railway-tailscale-forwarder-template-config.png)

<Callout type="info">
模板设置界面只显示模板声明的变量，你无法在那里添加新变量。`CONNECTION_MAPPING_01` 是你现在唯一能设置的映射。你将在服务存在之后再添加第二个。
</Callout>

#### 部署并检查日志

点击 `Deploy`。该模板会挂载一个卷并设置 `TS_EPHEMERAL=false`，因此该机器在多次重新部署之间保持同一身份，而不会注册重复的机器。

打开 `Deployments` 标签页并阅读部署日志。有三行表明转发器已正确启动：

- `tsnet starting with hostname "..."` 给出该机器在你 tailnet 上的机器名。你在后续步骤中会用到它。
- `Starting tailscale_fwdr` 列出它解析到的内容，包括 `ts-ephemeral: false` 以及每个映射的源端口、目标地址和目标端口。
- `listening for connections` 确认转发器在该源端口上接受流量。

![](@/assets/images/tutorials/railway-tailscale-forwarder-logs.png)

#### 为 UI 添加映射

打开 Tailscale Forwarder 服务的 `Variables` 标签页，添加第二个映射。每添加一个映射就递增编号，并保持源端口唯一。

<TableWrapper>

| Variable | Value |
| --- | --- |
| `CONNECTION_MAPPING_02` | `https:4983:${{Drizzle Studio.RAILWAY_PRIVATE_DOMAIN}}:4983` |

</TableWrapper>

这会将转发器上的 `4983` 端口转发到 UI。两个数字都是 `4983`：转发器监听的端口，以及模板设置的 `PORT`。`https:` 前缀让转发器使用其自身机器名的证书来终止 TLS，这也是必须在你的 tailnet 上启用 HTTPS 证书的原因。

![](@/assets/images/tutorials/railway-tailscale-forwarder-variables.png)

点击顶部栏中的 `Deploy` 以应用更改。

![](@/assets/images/tutorials/railway-tailscale-forwarder-variables-apply.png)

#### 复制转发器域名

在 Tailscale 管理控制台中打开 [Machines 页面](https://login.tailscale.com/admin/machines)。转发器在使用有效 auth key 启动后会自行出现在那里。

![](@/assets/images/tutorials/tailscale-machines-forwarder.png)

点击该机器打开其页面。在 `Machine Details` 下，复制 `Full domain` 值。那就是你用来打开 UI 的主机。

![](@/assets/images/tutorials/tailscale-machine-full-domain.png)

#### 打开 Studio URL

取出你复制的完整域名，在前面加上 `https://`，在末尾加上 `:4983`，然后在浏览器中打开它。

```plaintext
https://<full-domain>:4983
```

<Callout type="warning">
请确保指定 `https://` —— 通过 `http://` 打开 URL 将无法正常工作，而且如果你省略协议，某些浏览器可能会将你重定向到 `http://`。
</Callout>

Drizzle Studio 在首次使用时会要求输入口令。

![](@/assets/images/tutorials/railway-drizzle-studio-passcode-request.png)

在 Railway 中打开 Drizzle Studio 服务，进入 `Variables` 标签页，复制 `PASSCODE` 的值。将其粘贴到提示框中。

![](@/assets/images/tutorials/railway-drizzle-studio-passcode.png)

#### 检查连接

Drizzle Studio 会打开 `DATABASE_URL` 所指向的数据库，因此无需手动连接。它还没有任何表，因为你尚未将 schema 应用上去。下一节介绍如何创建它们。

![](@/assets/images/tutorials/drizzle-studio-connected.png)

## 故障排查

<Callout>
<Fragment slot="collapsed-title">The URL does not open</Fragment>

在 Railway 中打开 Studio/Gateway 服务，阅读其部署日志，找到它在启动时打印的那一行。Drizzle Gateway 会打印：

```plaintext
Drizzle Gateway listening on http://0.0.0.0:4983, store at /app
```

该行中的端口必须与 `CONNECTION_MAPPING_02` 中的目标端口一致。两个数据库 UI 都监听 `PORT` 中的端口，因此如果两者不一致，请在服务上将 `PORT` 改回 `4983` 并重新部署。

如果缺少该行，说明容器根本没有在提供服务。此时转发器会报告它无法访问的目标：

```plaintext
[ERRO] failed to forward connection source_port=4983
  target_addr="drizzle-studio.railway.internal" target_port=4983
  err="failed to dial target: dial tcp 10.x.x.x:4983: connect: connection refused"
```

`connection refused` 意味着地址正确，但该端口上没有服务在监听。如果日志中显示的却是空的目标地址或字面量 `${{...}}` 目标地址，说明引用变量未被解析，因此请检查映射中的服务名。
</Callout>

<Callout>
<Fragment slot="collapsed-title">The web browser shows a certificate warning</Fragment>

证书覆盖的是该机器的完整域名。请使用机器页面中的 `Full domain` 值，而不是短名称。并检查 Tailscale 管理控制台 DNS 页面上 HTTPS 证书是否已启用。
</Callout>

<Callout>
<Fragment slot="collapsed-title">The forwarder is not in the Machines list</Fragment>

auth key 已过期，或者一个非可重复使用的密钥已被使用过。生成一个新的可重复使用密钥，更新转发器服务上的 `TS_AUTHKEY`，然后重新部署。
</Callout>

<Callout>
<Fragment slot="collapsed-title">The mapping variable is ignored</Fragment>

确认转发器服务上变量的确切名称。该模板声明的是 `CONNECTION_MAPPING_01`，带前导零。一些较旧的指南写的是 `CONNECTION_MAPPING_1`。请使用配置面板所显示的形式，并保持编号唯一。
</Callout>
