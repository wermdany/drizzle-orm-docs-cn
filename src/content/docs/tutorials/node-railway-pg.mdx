本教程演示如何将 Drizzle ORM 与 [Node.js](https://nodejs.org/) 和 PostgreSQL 数据库一起使用，并全部部署在 [Railway](https://driz.link/railway) 上。

<Prerequisites>
  - 你需要安装 [Node.js](https://nodejs.org/)。你可以按照[官方指南](https://nodejs.org/en/download/)进行安装。

  - 你需要安装 Drizzle ORM 和 [Drizzle kit](/docs/kit-overview)。你可以通过运行以下命令来完成：
  <Npm>
      drizzle-orm@rc
      -D drizzle-kit@rc
  </Npm>

  - 你需要安装 `pg` 包作为 PostgreSQL 驱动，以及 `tsx` 用于直接运行 TypeScript 文件。
  <Npm>
    pg
    -D @types/pg tsx
  </Npm>

  - 你需要有一个 [Railway](https://driz.link/railway) 账户。
</Prerequisites>

## 设置 Railway 和 Drizzle ORM

<Steps>
#### 创建 Railway 项目

登录你的 [Railway 控制面板](https://railway.app/dashboard)并点击 `New Project` 按钮。

![](@/assets/images/tutorials/railway-create-service-menu.png)

#### 配置 PostgreSQL 数据库

在项目画布上，点击右上角的 `New` 按钮，然后选择 `Database` → `PostgreSQL`。你也可以使用命令面板（<Shortcut mac="⌘ K" other="Ctrl K" />）并搜索 PostgreSQL。Railway 将为你预置一个新的 PostgreSQL 实例。

![](@/assets/images/tutorials/railway-select-postgres.png)

#### 为数据库启用公共访问

默认情况下，Railway 将数据库保持在私有网络中，因此你无法从自己的机器访问它。点击 PostgreSQL 服务，进入 `Settings` 选项卡，找到 `Networking` 部分，然后点击 `Add Public Access`。

![](@/assets/images/tutorials/railway-add-public-access.png)

然后在顶栏中点击 `Deploy` 以应用该变更。Railway 会添加一个公共主机和端口，并在该服务上设置 `DATABASE_PUBLIC_URL` 变量。

![](@/assets/images/tutorials/railway-add-public-access-apply.png)

#### 获取你的连接字符串

进入 PostgreSQL 服务的 `Variables` 选项卡，找到 `DATABASE_PUBLIC_URL` 变量。复制该值 —— 它应该类似于这样：

```bash
postgresql://postgres:password@region.railway.app:port/railway
```

![](@/assets/images/tutorials/railway-postgres-variables.png)

<Callout type="warning">
Railway 提供两种类型的数据库连接 URL：

- **Public URL** —— 可从任何地方访问（你的本地机器、外部服务）。使用 TCP 代理，形如 `postgresql://postgres:password@region.railway.app:port/railway`。
- **Private URL** —— 只能通过内部网络从同一 Railway 项目内的服务访问。使用 `*.railway.internal` 主机名。

对于**本地开发**（例如运行 `drizzle-kit push` 或 `drizzle-kit studio`），你必须使用 **public URL**。私有 `*.railway.internal` 主机名无法从你的本地机器解析。
</Callout>

#### 设置连接字符串变量

在你的项目根目录下创建一个 `.env` 文件，并添加 `DATABASE_URL` 环境变量。使用来自 Railway 的 **public** 连接字符串：

```plaintext copy
DATABASE_URL=postgresql://postgres:password@region.railway.app:port/railway
```

<Callout type="info">
  此 `.env` 文件仅用于本地开发。在部署到 Railway 时，你将
  在 Railway 控制面板中通过服务引用变量单独配置 `DATABASE_URL`
  环境变量。
</Callout>

#### 将 Drizzle ORM 连接到你的数据库

创建一个 `db.ts` 文件并配置你的数据库连接：

```typescript copy filename="src/db.ts"
import { drizzle } from "drizzle-orm/node-postgres";

export const db = drizzle(process.env.DATABASE_URL!);
```

#### 创建表

创建一个 `schema.ts` 文件并声明你的表：

```typescript copy filename="src/schema.ts"
import * as p from "drizzle-orm/pg-core";

export const usersTable = p.pgTable("users", {
  id: p.serial().primaryKey(),
  name: p.text().notNull(),
  age: p.integer().notNull(),
  email: p.text().notNull().unique(),
});

export const postsTable = p.pgTable("posts", {
  id: p.serial().primaryKey(),
  title: p.text().notNull(),
  content: p.text().notNull(),
  userId: p
    .integer()
    .notNull()
    .references(() => usersTable.id, { onDelete: "cascade" }),
  createdAt: p.timestamp().notNull().defaultNow(),
  updatedAt: p
    .timestamp()
    .notNull()
    .$onUpdate(() => new Date()),
});

export type InsertUser = typeof usersTable.$inferInsert;
export type SelectUser = typeof usersTable.$inferSelect;

export type InsertPost = typeof postsTable.$inferInsert;
export type SelectPost = typeof postsTable.$inferSelect;
```

#### 设置 Drizzle 配置文件

**Drizzle config** —— 一个由 [Drizzle Kit](/docs/kit-overview) 使用的配置文件，包含关于你的数据库连接、迁移文件夹和 schema 文件的所有信息。

在你的项目根目录下创建一个 `drizzle.config.ts` 文件，并添加以下内容：

```typescript copy filename="drizzle.config.ts"
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: "./src/schema.ts",
  out: "./migrations",
  dialect: "postgresql",
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
});
```

#### 将更改应用到数据库

你可以使用 `drizzle-kit generate` 命令生成迁移，然后使用 `drizzle-kit migrate` 命令运行它们。

生成迁移：

```bash copy
npx drizzle-kit generate
```

`generate` 命令仅根据你的 schema 创建迁移 SQL 文件 —— 它**不会**对数据库应用任何变更。这些迁移存储在 `migrations` 目录中，正如你在 `drizzle.config.ts` 中所指定的。该目录将包含更新数据库 schema 所需的 SQL 文件，以及用于存储不同迁移阶段 schema 快照的 `meta` 文件夹。

生成的迁移示例：

```sql
CREATE TABLE "posts" (
	"id" serial PRIMARY KEY NOT NULL,
	"title" text NOT NULL,
	"content" text NOT NULL,
	"userId" integer NOT NULL,
	"createdAt" timestamp DEFAULT now() NOT NULL,
	"updatedAt" timestamp NOT NULL
);
--> statement-breakpoint
CREATE TABLE "users" (
	"id" serial PRIMARY KEY NOT NULL,
	"name" text NOT NULL,
	"age" integer NOT NULL,
	"email" text NOT NULL,
	CONSTRAINT "users_email_unique" UNIQUE("email")
);
--> statement-breakpoint
ALTER TABLE "posts" ADD CONSTRAINT "posts_userId_users_id_fk" FOREIGN KEY ("userId") REFERENCES "public"."users"("id") ON DELETE cascade ON UPDATE no action;
```

将生成的迁移应用到数据库：

```bash copy
npx drizzle-kit migrate
```

<Callout type="info">
  在本教程中，迁移会在应用程序启动时通过 `drizzle-orm/node-postgres/migrator`
  中的 `migrate()` 自动应用。你也可以为了本地测试使用 `drizzle-kit migrate`
  手动应用它们。
</Callout>

或者，你可以使用 [Drizzle kit push 命令](/docs/kit-overview#prototyping-with-db-push) 将变更直接推送到数据库：

```bash copy
npx drizzle-kit push
```

<Callout type="warning">
  Push 命令适用于本地开发中的快速原型设计，允许在无需管理迁移文件的
  情况下快速迭代。对于生产部署，请优先使用 `generate` + `migrate` 工作流，
  以保留 schema 变更的版本化历史。
</Callout>

</Steps>

## 基础文件结构

这是项目的基本文件结构。在 `src` 目录中，我们有与数据库相关的文件，包括 `db.ts` 中的连接以及 `schema.ts` 中的 schema 定义。

```plaintext
📦 <project root>
 ├ 📂 src
 │  ├ 📜 db.ts
 │  ├ 📜 schema.ts
 │  └ 📜 index.ts
 ├ 📂 migrations
 │  ├ 📂 meta
 │  │  ├ 📜 _journal.json
 │  │  └ 📜 0000_snapshot.json
 │  └ 📜 0000_optimal_the_fury.sql
 ├ 📜 .env
 ├ 📜 drizzle.config.ts
 ├ 📜 package.json
 └ 📜 tsconfig.json
```

## 将应用部署到 Railway

<Steps>
#### 为部署准备你的项目

一旦你[生成了迁移](#将更改应用到数据库)，请将 `migrations` 目录提交到你的仓库 —— 这些文件将在你的应用启动时自动应用。

创建一个 `index.ts` 文件作为应用程序的入口点。此示例在启动时运行迁移，然后使用 Node.js 启动一个简单的 HTTP 服务器：

```typescript copy filename="src/index.ts"
import { createServer } from "node:http";
import { drizzle } from "drizzle-orm/node-postgres";
import { migrate } from "drizzle-orm/node-postgres/migrator";
import { usersTable } from "./schema";

const db = drizzle(process.env.DATABASE_URL!);

await migrate(db, { migrationsFolder: "./migrations" });

const server = createServer(async (req, res) => {
  const url = new URL(req.url!, `http://${req.headers.host}`);

  if (url.pathname === "/users") {
    const users = await db.select().from(usersTable);
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify(users));
    return;
  }

  res.writeHead(200);
  res.end("OK");
});

const port = process.env.PORT || 3000;
server.listen(port, () => {
  console.log(`Server running on port ${port}`);
});
```

`migrate()` 函数从你的 `migrations` 目录读取 SQL 文件，并将任何尚未应用的迁移应用到数据库。在每次启动时运行它都是安全的 —— 已应用的迁移会被跳过。

<Callout type="info">
  顶层 `await` 需要 Node.js 将该文件视为 ES 模块。请确保你的
  `package.json` 包含 `"type": "module"`。
</Callout>

请确保你的 `package.json` 具有模块类型和 start 脚本：

```json copy filename="package.json"
{
  "type": "module",
  "scripts": {
    "start": "tsx src/index.ts"
  }
}
```

#### 将你的项目推送到 GitHub

Railway 从 GitHub 仓库进行部署。初始化一个 git 仓库并推送你的代码：

```bash copy
git init
git add .
git commit -m "initial commit"
```

在 GitHub 上创建一个新仓库并将你的代码推送到其中。

#### 将你的 GitHub 仓库连接到 Railway

在你的 Railway 项目中，点击画布右上角的 `New` 按钮，然后选择 `GitHub Repo`。如果提示，请连接你的 GitHub 账户，然后选择你刚刚推送的仓库。

![](@/assets/images/tutorials/railway-canvas-postgres-add-service.png)

![](@/assets/images/tutorials/node-railway-github-repo-search.png)

#### 配置环境变量

在已部署服务的设置中，进入 `Variables` 选项卡。通过引用 PostgreSQL 服务变量来添加 `DATABASE_URL` 变量：

点击 `Add Variable`，将名称设置为 `DATABASE_URL`，并使用 Railway 变量引用 `${{Postgres.DATABASE_URL}}` 作为值。

<Callout type="info">
`${{Postgres.DATABASE_URL}}` 引用变量在运行时会自动解析为 **private** 内部连接字符串，这对于 Railway 内部的服务间通信是最优的。这与你本地 `.env` 文件中使用的 public URL 不同。
</Callout>

![](@/assets/images/tutorials/node-railway-app-set-database-url.png)

#### 部署

当你推送到已连接的分支时，Railway 会自动部署你的应用程序。你可以在 `Deployments` 选项卡中监控部署情况。

![](@/assets/images/tutorials/node-railway-deployment-successful.png)

#### 验证你的配置

部署完成后，导航到你的 Railway 项目中的 `Architecture` 选项卡。你应该会看到你的应用程序服务已连接到 PostgreSQL 数据库。

![](@/assets/images/tutorials/node-railway-canvas-app-postgres-full.png)

<Callout type="warning" title="替代方案：零停机迁移">
本教程在应用程序启动时使用 `migrate()` 应用迁移。这是最简单的方法，适用于大多数应用程序。

如果你需要**零停机部署**，你可能希望在新版本应用开始接收流量之前，将迁移作为**单独的步骤**运行。这样你就可以独立于数据库变更来回滚应用程序。

在 Railway 上，你可以使用[预部署命令](https://docs.railway.com/deployments/pre-deploy-command)来实现这一点 —— 它在构建阶段和部署阶段之间运行，可以访问你的私有网络和环境变量，并且如果它失败，部署将不会继续。

在你的服务设置中，向下滚动到 **Deploy** 部分并点击 **Add pre-deploy step**：

![](@/assets/images/tutorials/node-railway-app-predeploy-migrate.png)

输入以下命令：

```bash copy
npx drizzle-kit migrate
```

使用这种方法时，请从你的 `index.ts` 中移除 `await migrate(db, { migrationsFolder: "./migrations" })` 调用 —— 迁移改由预部署命令处理。

更多详情，请参阅 [Drizzle 迁移基础](/docs/migrations)页面。

</Callout>

</Steps>

## 将 Drizzle Studio 部署到 Railway

你可以将 [Drizzle Studio](/drizzle-studio/overview) 与你的应用程序一起部署到 Railway，以便直接从浏览器浏览和管理你的数据库。

### 选项 1：一键部署（推荐）

<a
  href="https://railway.com/new/template/drizzle-studio-1?referralCode=eobqmj&utm_medium=integration&utm_source=button&utm_campaign=drizzle-studio-1"
  target="_blank"
  rel="nofollow noreferrer"
  style="display: inline-block; margin: 16px 0;"
>
  <img src="https://railway.com/button.svg" alt="部署到 Railway" width="183" height="40" />
</a>

<Steps>
#### 选择你的 Railway 项目

打开 `Deploy to` 下拉菜单，选择存放你的 PostgreSQL 数据库的项目。部署到同一个项目可以让 Drizzle Studio 引用该数据库变量。

![](@/assets/images/tutorials/railway-deploy-drizzle-studio-project.png)

#### 设置数据库连接字符串

点击 `Configure`，将 `DATABASE_URL` 变量设置为 `${{Postgres.DATABASE_URL}}` 以引用你现有的 PostgreSQL 服务，然后点击 `Save Config`。接着点击 `Review and deploy`。

![](@/assets/images/tutorials/railway-deploy-drizzle-studio-env.png)

</Steps>

### 选项 2：手动部署

<details>
<summary style="cursor: pointer; user-select: none; margin-bottom: 16px;">显示手动步骤</summary>

<Steps>
#### 从模板添加新服务

在你的 Railway 项目中，点击画布右上角的 `New` 按钮，然后选择 `Template`。

![](@/assets/images/tutorials/node-railway-canvas-postgres-add-new-service.png)

#### 选择 Drizzle Studio 模板

搜索 `drizzle studio` 并选择由 Drizzle 提供的 **Drizzle Studio** 模板。

![](@/assets/images/tutorials/railway-template-search-drizzle-studio.png)

#### 配置环境变量并部署

该模板自带三个预配置的环境变量：

- `PASSCODE` - 用于安全访问你的 Studio 实例的密码。它默认为 `${{secret()}}`，会生成一个随机密钥。
- `DATABASE_URL` - 数据库连接字符串。将其设置为 `${{Postgres.DATABASE_URL}}` 以引用你现有的 PostgreSQL 服务。
- `PORT` - Drizzle Studio 监听的端口。它默认为 `4983`。保持原样即可。

点击 `Deploy Template` 进行部署。

![](@/assets/images/tutorials/railway-drizzle-studio-template-config.png)

</Steps>

</details>

### 部署之后

<Steps>
#### 找到你的 Drizzle Studio URL

部署完成后，在你的项目中点击 Drizzle Studio 服务，进入 `Settings` 选项卡，然后向下滚动到 `Networking` 部分。你将在 **Public Networking** 下找到你的公共域名。

![](@/assets/images/tutorials/railway-drizzle-studio-networking.png)

#### 输入访问码

在浏览器中打开 Drizzle Studio URL。首次访问时它会要求输入密码。

![](@/assets/images/tutorials/railway-drizzle-studio-passcode-request.png)

回到 Railway 中的 Drizzle Studio 服务，打开 `Variables` 选项卡，然后复制 `PASSCODE` 变量的值。该模板会为你生成它，因此每次部署的值都不同。

![](@/assets/images/tutorials/railway-drizzle-studio-passcode.png)

将该值粘贴到提示框中，然后点击 `Continue`。

#### 使用 Drizzle Studio 浏览你的数据库

现在你应该能看到你的数据库表，并可以直接浏览、筛选和编辑数据。

![](@/assets/images/tutorials/drizzle-studio-posts-table.png)

#### 验证你的配置

导航到你的 Railway 项目中的 `Architecture` 选项卡。你现在应该看到三个服务：你的应用程序、PostgreSQL 数据库和 Drizzle Studio。

![](@/assets/images/tutorials/node-railway-canvas-all-services.png)

</Steps>
