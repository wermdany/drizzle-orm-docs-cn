本教程在 [Railway](https://driz.link/railway) 上运行一个关闭了公共访问的 PostgreSQL 数据库，并从你的机器将 `drizzle-kit` 连接到它。

一个 [Tailscale](https://tailscale.com/) Forwarder 加入你的 tailnet，并将数据库端口转发到 Railway 的私有网络中。没有任何内容暴露到公共互联网，并且你 tailnet 上的每台设备都可以针对该数据库运行迁移。

<Prerequisites title="本指南假设以下条件：">
  - 你拥有一个 [Railway](https://driz.link/railway) 账户。

  - 你拥有一个 [Tailscale](https://tailscale.com/) 账户。

  - 你在自己的工作机器上安装了 Tailscale 客户端，并且该机器已登录你的 tailnet。你可以在 [Tailscale 网站](https://tailscale.com/download)上找到下载项。

  - 你已安装 Drizzle ORM 和 [Drizzle Kit](/docs/kit-overview)。
  <Npm>
      drizzle-orm@rc
      -D drizzle-kit@rc
  </Npm>
</Prerequisites>

## 工作原理

Railway 为每个服务分配一个以 `.railway.internal` 结尾的私有域名。这些域名只在项目内部可解析，因此你机器上的 `drizzle-kit` 无法使用它们。

Tailscale Forwarder 从两端解决了这个问题。它作为同一 Railway 项目中的一个服务运行，因此可以解析这些私有域名。它同时作为一台机器加入你的 tailnet，因此你自己的设备可以通过其 tailnet 名称访问它。流量从 `drizzle-kit` 经由 tailnet 到达 forwarder，再从 forwarder 经由 Railway 的私有网络到达数据库。

## 设置 Railway 项目

<Steps>
#### 创建 Railway 项目

登录你的 [Railway 控制面板](https://railway.app/dashboard)并点击 `New Project` 按钮。

![](@/assets/images/tutorials/railway-create-service-menu.png)

#### 配置 PostgreSQL 数据库

在项目画布上，点击右上角的 `New` 按钮，然后选择 `Database` → `PostgreSQL`。你也可以使用命令面板（<Shortcut mac="⌘ K" other="Ctrl K" />）并搜索 PostgreSQL。

![](@/assets/images/tutorials/railway-select-postgres.png)

#### 让数据库保持在私有网络

点击 PostgreSQL 服务，进入 `Settings` 选项卡，找到 `Networking` 部分。确认公共访问已禁用。在 `Private Networking` 下你将看到该服务的私有域名，例如 `postgres.railway.internal`。forwarder 将使用该域名。

![](@/assets/images/tutorials/railway-postgres-private-networking.png)

</Steps>

## 将数据库添加到你的 tailnet

<Steps>
#### 检查 MagicDNS 和 HTTPS 证书

在 Tailscale 管理控制台中打开 [DNS 页面](https://login.tailscale.com/admin/dns)。**MagicDNS** 和 **HTTPS Certificates** 都必须启用。每个部分都会提供相反的操作，因此一个显示为 `Disable MagicDNS...` 的按钮意味着 MagicDNS 已经开启。

MagicDNS 为 forwarder 提供一个稳定的机器名，数据库连接需要它。HTTPS 证书不是数据库连接所必需的，但要通过 forwarder 打开数据库 UI 则需要它们，而这两个设置都位于此页面上。

![](@/assets/images/tutorials/tailscale-dns-magicdns-https.png)

#### 创建可复用的认证密钥

在设置菜单中进入 [Keys 页面](https://login.tailscale.com/admin/settings/keys)并点击 `Generate auth key`。添加一个描述并开启 `Reusable`。其余设置保持原样。可复用的密钥让 forwarder 在没有现存状态时可以重新注册自己。

![](@/assets/images/tutorials/tailscale-generate-auth-key.png)

点击 `Generate key`。现在就复制该密钥，因为管理控制台只会显示它一次。

![](@/assets/images/tutorials/tailscale-auth-key-created.png)

#### 部署 Tailscale Forwarder

Tailscale Forwarder 是一个小型的 TCP 代理。它作为一台机器加入你的 tailnet，并将该机器上的端口转发到 Railway 私有网络上的服务。Railway 发布了该模板，它运行 `brody192/tailscale-forwarder` 镜像。

<a
  href="https://railway.com/deploy/tailscale-forwarder"
  target="_blank"
  rel="nofollow noreferrer"
  style="display: inline-block; margin: 16px 0;"
>
  <img src="https://railway.com/button.svg" alt="部署到 Railway" width="183" height="40" />
</a>

打开 `Deploy to` 下拉菜单，选择存放你的数据库的项目。两个服务必须位于同一个项目中，否则 forwarder 将无法通过私有网络访问数据库，因为它会被放置在不同的私有网络上。

将你的 auth key 粘贴到 `TS_AUTHKEY` 中。然后将 `CONNECTION_MAPPING_01` 设置为数据库映射。格式为 `[https:]<source port>:<target host>:<target port>`。

```plaintext copy
5432:${{Postgres.RAILWAY_PRIVATE_DOMAIN}}:${{Postgres.PGPORT}}
```

这会将 forwarder 上的端口 `5432` 转发到你的数据库。

![](@/assets/images/tutorials/railway-tailscale-forwarder-template-config.png)

<Callout type="info">
模板设置界面只显示模板声明的变量，你无法在那里添加新变量。`CONNECTION_MAPPING_01` 是你现在唯一可以设置的映射。在服务存在之后，你可以在服务本身上添加更多映射。
</Callout>

#### 部署并检查日志

点击 `Deploy`。该模板会附加一个卷并设置 `TS_EPHEMERAL=false`，因此该机器在多次重新部署之间保持相同的身份，而不会注册成重复的机器。

打开 `Deployments` 选项卡并阅读部署日志。有三行表明 forwarder 正确启动：

- `tsnet starting with hostname "..."` 给出了它在你的 tailnet 上的机器名。你在后续步骤中需要它。
- `Starting tailscale_fwdr` 列出了它解析到的内容，包括 `ts-ephemeral: false` 以及每个映射的源端口、目标地址和目标端口。
- `listening for connections` 确认 forwarder 在该源端口上接受流量。

![](@/assets/images/tutorials/railway-tailscale-forwarder-logs.png)

#### 复制转发器域名

`TS_HOSTNAME` 默认由你的项目名、环境名和服务名用短横线连接而成，例如 `my-project-production-tailscale-forwarder`。部署日志会在 `tsnet starting with hostname` 这一行打印它。

在 Tailscale 管理控制台中打开 [Machines 页面](https://login.tailscale.com/admin/machines)。forwarder 在使用有效的 auth key 启动后会自行出现在那里。

![](@/assets/images/tutorials/tailscale-machines-forwarder.png)

点击该机器以打开其页面。在 `Machine Details` 下，复制 `Full domain` 值。这就是你从自己的机器连接的主机。

![](@/assets/images/tutorials/tailscale-machine-full-domain.png)

</Steps>

## 从你的机器连接 Drizzle Kit

<Callout type="warning">
运行 `drizzle-kit` 的机器必须登录与 forwarder 相同的 tailnet，因为数据库连接是通过它进行路由的。
</Callout>

<Steps>
#### 设置连接字符串

在 Railway 中打开 PostgreSQL 服务，进入 `Variables` 选项卡，然后复制 `DATABASE_URL`。

![](@/assets/images/tutorials/railway-postgres-database-url.png)

将 `***.railway.internal` 主机替换为 [Tailscale forwarder 的域名](#复制转发器域名)并保留字符串的其余部分。`railway.internal` 无法在 Railway 之外的机器上解析，因此你需要通过 Tailscale forwarder 连接。将结果放入 `.env` 文件。

```plaintext copy
DATABASE_URL=postgresql://postgres:password@<full-domain>:5432/railway
```

<Callout type="info">
Tailscale 会加密你的机器与 forwarder 之间的连接，Railway 会加密 forwarder 与数据库之间的一段。Railway 的 PostgreSQL 也通过 forwarder 接受 TLS，因此大多数客户端使用默认设置即可连接。
</Callout>

#### 设置 Drizzle 配置文件

在你的项目根目录下创建一个 `drizzle.config.ts` 文件：

```typescript copy filename="drizzle.config.ts"
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: "./src/schema.ts",
  out: "./migrations",
  dialect: "postgresql",
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
});
```

#### 应用你的 schema

生成迁移并应用它们：

```bash copy
npx drizzle-kit generate
```

```bash copy
npx drizzle-kit migrate
```

对于快速原型设计，你可以使用 [drizzle-kit push](/docs/kit-overview#prototyping-with-db-push) 直接推送 schema。对于生产部署，请优先使用 `generate` 和 `migrate` 工作流，以保留 schema 变更的版本化历史。详情请参阅 [Drizzle 迁移基础](/docs/migrations)页面。

#### 检查结果

在 [Drizzle Studio](/docs/drizzle-kit-studio) 中打开数据库：

```bash copy
npx drizzle-kit studio
```

它运行在你的机器上并读取相同的 `DATABASE_URL`，因此它会通过 forwarder 到达数据库。你的新表就在那里。

![](@/assets/images/tutorials/drizzle-studio-posts-table.png)

</Steps>

<Callout type="info">
对于偶尔的访问，你完全不需要 Tailscale。Railway CLI 通过 `railway connect Postgres --tunnel-only` 打开到一个私有数据库的临时隧道。当你需要一条永久路由，或需要从 tailnet 上的每台设备访问时，forwarder 才是合适的工具。
</Callout>

## 故障排查

<Callout>
<Fragment slot="collapsed-title">forwarder 不在 Machines 列表中</Fragment>

auth key 已过期，或者某个不可复用的密钥已经被使用过。生成一个新的可复用密钥，更新 forwarder 服务上的 `TS_AUTHKEY`，然后重新部署。
</Callout>

<Callout>
<Fragment slot="collapsed-title">`drizzle-kit` 无法连接</Fragment>

运行 `tailscale status` 并检查你的设备是否登录了相同的 tailnet。检查你连接字符串中的端口是否与 `CONNECTION_MAPPING_01` 中的源端口匹配。Railway 的 PostgreSQL 通过 forwarder 接受 TLS，因此你无需禁用 SSL。
</Callout>

<Callout>
<Fragment slot="collapsed-title">映射变量被忽略</Fragment>

在 forwarder 服务上确认确切的变量名。该模板声明的是 `CONNECTION_MAPPING_01`，带一个前导零。一些较早的指南写的是 `CONNECTION_MAPPING_1`。使用配置面板显示给你的形式，并保持数字唯一。
</Callout>
