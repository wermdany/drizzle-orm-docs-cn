# 神奇的 `sql` 操作符 🪄

在使用 ORM 库时，你可能会遇到难以用所提供的 ORM 语法编写
某个特定查询的情况。在这种情况下，你可以求助于使用
原始查询，即把查询构建为原始字符串。然而，原始查询往往
缺乏类型安全和查询参数化带来的好处。

为解决这个问题，许多库引入了 `sql` 模板的概念。这个模板
让你可以编写更加类型安全、参数化的查询，从而提升代码整体的安全性
和灵活性。作为一个强大的 ORM 库，Drizzle 也支持 sql 模板。

使用 Drizzle 的 `sql` 模板，你可以在构建查询方面走得更远。如果你在用
库的查询构建器编写整个查询时遇到困难，你可以在 Drizzle 查询的特定部分中选择性地
使用 `sql` 模板。这种灵活性使你能够把 sql 模板用在部分 SELECT 语句、WHERE 子句、ORDER BY 子句、HAVING
子句、GROUP BY 子句中，甚至用在关系查询构建器中。

通过利用 Drizzle 中 sql 模板的能力，你可以在实现所需查询结构和复杂度的同时，
保持类型安全和查询参数化的优势。
这让你能够在应用中编写更健壮、更易维护的代码。

## sql`` 模板

你可能在其它 ORM 中也会遇到的最常见用法之一，
就是能够把 `sql` 查询原样用作原始查询。

```typescript copy
import { sql } from 'drizzle-orm' 

const id = 69;
await db.execute(sql`select * from ${usersTable} where ${usersTable.id} = ${id}`)
```

它将生成以下查询

```sql
select * from "users" where "users"."id" = $1; --> [69]
```

提供给 sql 参数的任何表和列都会被自动映射为对应的 SQL
语法，表名会被转义，并且转义后的表名会被追加到列名之前。

此外，任何动态参数（例如 `${id}`）都会被映射为 $1 占位符，
而对应的值会被移到一个单独的 values 数组中，单独传递给数据库。

这种方式有效地防止了任何潜在的 SQL 注入漏洞。

## `sql<T>`

<Callout type="info" emoji="ℹ️">
    请注意，`sql<T>` 不执行任何运行时映射。你使用 `sql<T>` 定义的类型
    纯粹只是给 Drizzle 的辅助提示。重要的是要理解，无法以可行的方式
    动态确定确切的类型，因为 SQL 查询可以极其多样且可定制。
</Callout>

你可以在 Drizzle 中定义自定义类型，用于那些要求特定类型（而非 `unknown`）的字段位置。

这个特性在部分查询中尤其有用，可以确保所选字段的类型一致：

```typescript
// 未定义 sql<T> 类型
const response: { lowerName: unknown }[] = await db.select({
    lowerName: sql`lower(${usersTable.id})`
}).from(usersTable);

// 已定义 sql<T> 类型
const response: { lowerName: string }[] = await db.select({
    lowerName: sql<string>`lower(${usersTable.id})`
}).from(usersTable);
```

## `sql``.mapWith()`

如果你需要对从数据库驱动传递给 drizzle 的值进行运行时映射，你可以使用 `.mapWith()`

这个函数接受不同的值，用于在运行时映射响应。

只要 mapWith 内部的接口与 Column 所实现的接口一致，
你就可以复刻某种特定的列映射策略。

```typescript
const usersTable = cockroachTable('users', {
    id: int4('id').primaryKey(),
    name: string('name').notNull(),
});

//  运行时这些值将按照 drizzle 中 `text` 列的映射方式进行映射
sql`...`.mapWith(usersTable.name);
```

你也可以为 `DriverValueDecoder` 接口传入你自己的实现：

```ts 
sql``.mapWith({
	mapFromDriverValue: (value: any) => {
		const mappedValue = value;
		// 你想要应用的映射
		return mappedValue;
	},
});
    
// 或
sql``.mapWith(Number);
```

## `sql``.as<T>()`

在不同情况下，有时很难确定为你想使用的自定义字段命名。
你可能会遇到需要为一个将被选中的字段显式指定别名的情况。
在处理复杂查询时，这尤其有用。

为应对这些场景，我们引入了一个有用的 `.as('alias_name')` 辅助方法，它允许
你显式地定义别名。通过使用这个特性，你可以为字段提供一个清晰且有意义的
名称，让你的查询更直观、更易读。

<Section>
```typescript
sql`lower(${usersTable.name})`.as('lower_name')
```
```sql
... "users"."name" as lower_name ...
```
</Section>

## `sql.raw()`

有些情况下，你可能不需要从输入创建参数化的值，也不需要把表/列映射为转义后的形式。
相反，你可能只想按原样生成查询。对于这类情况，我们提供了 `sql.raw()` 函数。

`sql.raw()` 函数允许你在查询中包含原始 SQL 语句，而无需任何额外处理或转义。
当你已经有预构建的 SQL 语句，或者需要把复杂或动态的 SQL 代码
直接引入查询时，这会很有用。

<Section>
```typescript
sql.raw(`select * from users where id = ${12}`);
// 对比
sql`select * from users where id = ${12}`;
```
```sql
select * from users where id = 12;
--> 对比
select * from users where id = $1; --> [12]
```
</Section>

你也可以在 sql 函数内部使用 `sql.raw()`，从而让你能够包含任何原始字符串，
而不通过主 `sql` 模板函数对其进行转义。

通过在 `sql` 函数内部使用 `sql.raw()`，你可以把未转义的原始字符串
直接引入查询。当你有一些特定的 SQL 代码或表达式
应当保持不被模板函数的自动转义或修改影响时，这会特别有用。

<Section>
```typescript
sql`select * from ${usersTable} where id = ${12}`;
// 对比
sql`select * from ${usersTable} where id = ${sql.raw(12)}`;
```
```sql
select * from "users" where id = $1; --> [12]
--> 对比
select * from "users" where id = 12;
```
</Section>

## sql.fromList()

`sql` 模板会生成 sql 块，这些块是 SQL 部分的数组，会在把 SQL 应用到数据库
或 Drizzle 中的查询之后，被拼接到查询和参数中。

在某些场景下，你可能需要使用自定义业务逻辑把这些块聚合成一个数组，
然后把它们拼接成一条可以传给数据库或查询的单一 SQL 语句。
对于这类情况，fromList 函数会非常有用。

fromList 函数让你可以把多个 SQL 块组合成一条单一的 SQL 语句。
你可以用它按照你的具体需求聚合和拼接各个 SQL 部分，
然后得到一条可以执行的统一 SQL 查询。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

	if (i === 4) continue;
	sqlChunks.push(sql` or `);
}

const finalSql: SQL = sql.fromList(sqlChunks)
```
```sql
select * from users where id = $1 or id = $2 or id = $3 or id = $4 or id = $5; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.join()

确实，`sql.join` 函数的作用与 fromList 辅助方法类似。
不过，在处理 SQL 块之间的空格，或者为拼接 SQL 块指定自定义分隔符时，
它提供了额外的灵活性。

使用 `sql.join`，你可以用指定的分隔符把 SQL 块拼接在一起。
这个分隔符可以是任何你想插入到块之间的字符串或字符。

当你对 SQL 块的格式或分隔有特定要求时，这会特别有用。
通过指定自定义分隔符，你可以在最终 SQL 查询中实现所需的结构和格式。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql`where`);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

if (i === 4) continue;
    sqlChunks.push(sql`or`);
}

const finalSql: SQL = sql.join(sqlChunks, sql.raw(' '));
```
```sql
select * from users where id = $1 or id = $2 or id = $3 or id = $4 or id = $5; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.append()

如果你已经用 `sql` 模板生成了 SQL，你可以通过 append 函数把新块直接添加到
已生成的 SQL 中，从而实现与 `fromList` 相同的行为。

通过使用 append 函数，你可以动态地向已有 SQL 字符串添加额外的 SQL 块，
有效地把它们拼接在一起。这让你能够引入自定义逻辑或业务
规则，把各个块聚合到最终的 SQL 查询中。

<Section>
```typescript 
const finalSql = sql`select * from users`;

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = $1 or id = $2 or id = $3 or id = $4 or id = $5; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.empty()

通过使用 sql.empty()，你可以从一个空的 SQL 对象开始，然后按需动态地向它追加 SQL 块。这让你可以逐步构建 SQL 查询，应用自定义逻辑或条件来决定每个块的内容。

一旦你用 sql.empty() 初始化了 SQL 对象，你就可以利用 sql 模板的全套
特性，例如参数化、组合和转义。
这使你能够以灵活且可控的方式构建 SQL 查询，
让它适配你的具体需求。

```typescript 
const finalSql = sql.empty();

// 一些逻辑

finalSql.append(sql`select * from users`);

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = $1 or id = $2 or id = $3 or id = $4 or id = $5; --> [0, 1, 2, 3, 4]
```

## 将 `sql` 转换为字符串和参数

在前面所有的示例中，你都看到了在 TypeScript 中使用 SQL 模板语法
以及生成的 SQL 输出。

如果你需要获取由 SQL 模板生成的查询字符串和对应参数，
你必须指定你打算为其生成查询的数据库方言。不同的数据库
在参数化和转义方面语法不同，因此选择合适的方言至关重要。

选择方言之后，你可以利用对应实现的功能，
把 SQL 模板转换为所需的查询字符串和参数格式。这确保了
与你所使用的特定数据库系统的兼容性。

<Section>
```typescript copy
import { CockroachDialect } from 'drizzle-orm/cockroach-core';

const cockroachDialect = new CockroachDialect();
cockroachDialect.sqlToQuery(sql`select * from ${usersTable} where ${usersTable.id} = ${12}`);
```
```sql
select * from "users" where "users"."id" = $1; --> [ 12 ]
```
</Section>

## `sql` select

你也可以在部分查询中使用 sql 功能。部分查询让你可以
从表中检索特定的字段或列，而不是获取整行。

关于部分查询的更详细信息，你可以参考 Core API
文档：**[核心 API 文档](/docs/cockroach/select#basic-and-partial-select)**。

**从表中选择不同的自定义字段**

这里你可以看到 **[`sql<T>`](/docs/cockroach/sql#sqlt)**、**[`sql``.mapWith()`](/docs/cockroach/sql#sqlmapwith)**、**[`sql``.as<T>()`](/docs/cockroach/sql#sqlast)** 的用法。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select({
    id: usersTable.id,
    lowerName: sql<string>`lower(${usersTable.name})`,
    aliasedName: sql<string>`lower(${usersTable.name})`.as('aliased_column'),
    count: sql<number>`count(*)`.mapWith(Number) 
}).from(usersTable)
```
```sql
select "id", lower("name"), lower("name") as "aliased_column", count(*) from "users";
```
</Section>

## where 中的 `sql`

确实，Drizzle 提供了一组可以在 sql 模板中使用的表达式。
然而，数据库通常确实有更广泛的可用表达式，
包括通过扩展或其它方式提供的表达式。

为确保灵活性，并使你能够使用 Drizzle 未原生支持的
任何表达式，你可以自由地直接使用 sql 函数编写 SQL 模板。
这让你能够充分利用 SQL 的强大能力，引入任何针对你的目标数据库的
表达式或功能。

通过使用 sql 模板，你不会被限制在 Drizzle 中预定义的表达式里。
相反，你可以表达复杂的查询，并引入底层数据库系统所提供的
任何受支持的表达式。

**按 `id` 过滤，但使用 sql**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

const id = 77

await db.select()
        .from(usersTable)
        .where(sql`${usersTable.id} = ${id}`)
```
```sql
select * from "users" where "users"."id" = $1; --> [ 77 ]
```
</Section>

**高级全文搜索 where 语句**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

const searchParam = "Ale"

await db.select()
        .from(usersTable)
        .where(sql`to_tsvector('simple', ${usersTable.name}) @@ to_tsquery('simple', ${searchParam})`)
```
```sql
select * from "users" where to_tsvector('simple', "users"."name") @@ to_tsquery('simple', '$1'); --> [ "Ale" ]
```
</Section>

## orderBy 中的 `sql`

当你需要某些 Drizzle 中不可用的特定排序功能，但又不希望使用原始 SQL 时，
`sql` 模板确实可以用在 ORDER BY 子句中。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select().from(usersTable).orderBy(sql`${usersTable.id} desc nulls first`)
```
```sql
select * from "users" order by "users"."id" desc nulls first;
```
</Section>

## having 和 groupBy 中的 `sql`

当你需要某些 Drizzle 中不可用的特定排序功能，但又不希望使用原始 SQL 时，
`sql` 模板确实可以用在 HAVING 和 GROUP BY 子句中。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select({ 
    projectId: usersTable.projectId,
    count: sql<number>`count(${usersTable.id})`.mapWith(Number)
}).from(usersTable)
    .groupBy(sql`${usersTable.projectId}`)
    .having(sql`count(${usersTable.id}) > 300`)
```
```sql
select "project_id", count("id") from "users" group by "users"."project_id" having count("users"."id") > 300
```
</Section>
