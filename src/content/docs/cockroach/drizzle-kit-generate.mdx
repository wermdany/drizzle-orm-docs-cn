# `drizzle-kit generate` 

<Prerequisites>
- 开始使用 Drizzle 和 `drizzle-kit` - [阅读此处](/docs/cockroach/get-started)
- Drizzle schema 基础 - [阅读此处](/docs/cockroach/sql-schema-declaration)
- 数据库连接基础 - [阅读此处](/docs/cockroach/connect-overview)
- Drizzle 迁移基础 - [阅读此处](/docs/cockroach/migrations)
- Drizzle Kit [概览](/docs/cockroach/kit-overview)和[配置文件](/docs/cockroach/drizzle-config-file)
</Prerequisites>


<br/>

`drizzle-kit generate` 让你可以基于声明时的 Drizzle schema 或后续的 schema 变更来生成 SQL 迁移。
<Callout collapsed="它的工作原理是什么？">
Drizzle Kit `generate` 命令会触发一系列事件：
1. 它会读取你的 Drizzle schema 文件，并组成一个 schema 的 json 快照
2. 它会读取你之前的迁移文件夹，并将当前的 json 快照与最近的一个进行对比
3. 基于 json 差异，它会生成 SQL 迁移
4. 在当前时间戳下，将 `migration.sql` 和 `snapshot.json` 保存到迁移文件夹中

<Section>
```typescript filename="src/schema.ts"
import * as p from "drizzle-orm/cockroach-core";

export const users = p.cockroachTable("users", {
  id: p.int4().primaryKey(),
  name: p.string(),
  email: p.string().unique(), 
});
```
```                                  
┌────────────────────────┐                  
│ $ drizzle-kit generate │                  
└─┬──────────────────────┘                  
  │                                           
  └ 1. read previous migration folders
    2. find diff between current and previous schema
    3. prompt developer for renames if necessary
  ┌ 4. generate SQL migration and persist to file
  │    ┌─┴───────────────────────────────────────┐  
  │      📂 drizzle       
  │      └ 📂 20242409125510_premium_mister_fear
  │        ├ 📜 migration.sql
  │        └ 📜 snapshot.json
  v
```
```sql
-- drizzle/20242409125510_premium_mister_fear/migration.sql

CREATE TABLE "users" (
	"id" int4 PRIMARY KEY,
	"name" string,
	"email" string,
	CONSTRAINT "users_email_key" UNIQUE("email")
);
```
</Section>
</Callout>

它的设计目标是覆盖管理 Drizzle 迁移的[代码优先](/docs/cockroach/migrations)方式。 
你可以使用 [`drizzle-kit migrate`](/docs/cockroach/drizzle-kit-migrate)、drizzle-orm 的 `migrate()`、
像 [bytebase](https://www.bytebase.com/) 这样的外部迁移工具来应用生成的迁移，或者直接在数据库上自行运行迁移。 

`drizzle-kit generate` 命令要求你同时提供 `dialect` 和 `schema` 路径选项， 
你可以通过 [drizzle.config.ts](/docs/cockroach/drizzle-config-file) 配置文件或 CLI 选项来设置它们
<CodeTabs items={["使用配置文件", "作为 CLI 选项"]}>
<Section>
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "cockroach",
  schema: "./src/schema.ts",
});
```
```shell
npx drizzle-kit generate
```
</Section>

```shell
npx drizzle-kit generate --dialect=cockroach --schema=./src/schema.ts
```
</CodeTabs>

### Schema 文件路径
你可以只有一个 `schema.ts` 文件，也可以有任意多个散布在项目中的 schema 文件。 
Drizzle Kit 要求你通过 `schema` 配置选项，以 [glob](https://www.digitalocean.com/community/tools/glob?comments=true&glob=/**/*.js&matches=false&tests=//%20This%20will%20match%20as%20it%20ends%20with%20'.js'&tests=/hello/world.js&tests=//%20This%20won't%20match!&tests=/test/some/globs) 的形式指定它们的路径。

### 自定义迁移文件名
你可以通过提供 `--name` CLI 选项来设置自定义的迁移文件名
```shell
npx drizzle-kit generate --name=init
```
```plaintext {4}
📦 <project root>
 ├ 📂 drizzle
 │ └ 📂 20242409125510_init
 │   ├ 📜 snapshot.json
 │   └ 📜 migration.sql
 ├ 📂 src
 └ …
```

### 单个项目中的多个配置文件
你可以在项目中拥有多个配置文件，当你需要多个数据库阶段，或者在同一个项目中有多个数据库或不同的数据库时，这非常有用：
<Npx>
  drizzle-kit generate --config=drizzle-dev.config.ts
  drizzle-kit generate --config=drizzle-prod.config.ts
</Npx>
```plaintext {5-6}
📦 <project root>
 ├ 📂 drizzle
 ├ 📂 src
 ├ 📜 .env
 ├ 📜 drizzle-dev.config.ts
 ├ 📜 drizzle-prod.config.ts
 ├ 📜 package.json
 └ 📜 tsconfig.json
```

### 自定义迁移
你可以生成空的迁移文件，用来编写你自己的自定义 SQL 迁移， 
以处理 Drizzle Kit 目前尚不支持的 DDL 变更或数据填充。关于自定义迁移的扩展文档 - [见此处](/docs/cockroach/kit-custom-migrations)

```shell
drizzle-kit generate --custom --name=seed-users
```
<Section>
```plaintext {5}
📦 <project root>
 ├ 📂 drizzle
 │ ├ 📂 20242409125510_init
 │ └ 📂 20242409125510_seed-users
 ├ 📂 src
 └ …
```
```sql
-- ./drizzle/20242409125510_seed/migration.sql

INSERT INTO "users" ("name") VALUES('Dan');
INSERT INTO "users" ("name") VALUES('Andrew');
INSERT INTO "users" ("name") VALUES('Dandrew');
```
</Section>

### 忽略冲突

如果你需要 `generate` 命令跳过交换性检查并绕过它，可以使用 `--ignore-conflicts`。如果你确实有需要使用它的场景，那么
很有可能 `drizzle-kit` 没有正确检查迁移，这是一个 bug。请把你的情况报告给我们，以便我们修复它

```shell
drizzle-kit generate --ignore-conflicts
```

### 可用配置的扩展列表
`drizzle-kit generate` 有一系列仅限 CLI 的选项

<rem025/>

|               |                                                      |
| :--------     | :--------------------------------------------------- |
| `custom`      | 为自定义迁移生成空的 SQL              |
| `name`        | 以自定义名称生成迁移                  |
| `ignore-conflicts` | 跳过交换性冲突检查，默认为 `false` |
<rem025/>

<Npx>
drizzle-kit generate --name=init
drizzle-kit generate --name=seed_users --custom
drizzle-kit generate --ignore-conflicts
</Npx>

<hr/>
<br/>
我们建议通过 [drizzle.config.ts](/docs/cockroach/drizzle-config-file) 文件来配置 `drizzle-kit`， 
但你也可以在必要时通过 CLI 提供所有配置选项，例如在 CI/CD 流水线中，等等。

|               |            |                                                                            |
| :------------ | :-------   | :----------------------------------------------------------------------    |
| `dialect`     | `required` | 数据库方言，取值为 <Dialects/> 之一                                       |
| `schema`      | `required` | TypeScript schema 文件或包含多个 schema 文件的文件夹的路径  |
| `out`         |            | 迁移输出文件夹，默认为 `./drizzle`                           |
| `config`      |            | 配置文件路径，默认为 `drizzle.config.ts`                    |
| `breakpoints` |            | SQL 语句断点，默认为 `true`                              |


### 扩展示例
这是一个如何创建名为 `0001_seed-users.sql` 的自定义 Cockroach 迁移文件的示例， 
其 Drizzle schema 位于 `./src/schema.ts`，迁移文件夹命名为 `./migrations` 而非默认的 `./drizzle`。

我们还会把 drizzle 配置文件放在 `configs` 文件夹中。

让我们创建配置文件：

```plaintext {4}
📦 <project root>
 ├ 📂 migrations
 ├ 📂 configs
 │ └ 📜 drizzle.config.ts
 ├ 📂 src
 └ …
```
```ts filename='drizzle.config.ts'
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "cockroach",
  schema: "./src/schema.ts",
  out: "./migrations",
});
```

现在让我们运行
```shell
npx drizzle-kit generate --config=./configs/drizzle.config.ts --name=seed-users --custom
```
它会成功生成
<Section>
```plaintext {6}
📦 <project root>
 ├ …
 ├ 📂 migrations
 │ ├ 📂 20242409125510_init
 │ └ 📂 20242409125510_seed-users
 └ …
```
```sql
-- ./drizzle/20242409125510_seed-users/migration.sql

INSERT INTO "users" ("name") VALUES('Dan');
INSERT INTO "users" ("name") VALUES('Andrew');
INSERT INTO "users" ("name") VALUES('Dandrew');
```
</Section>
