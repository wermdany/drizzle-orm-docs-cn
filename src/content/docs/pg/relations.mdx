### `one()`
以下是 drizzle 关系中 `.one()` 可用的所有字段列表

```ts {3-11}
const relations = defineRelations({ users, posts }, (r) => ({
	posts: {
		author: r.one.users({
			from: r.posts.ownerId,
			to: r.users.id,
			optional: false,
      alias: 'custom_name',
			where: {
				verified: true,
			}
		}),
	}
}))
```

- `author` 键是一个自定义键，在使用 Drizzle 关系查询时会出现在 `posts` 对象中。
- `r.one.users` 定义 `author` 将是来自 `users` 表的单个对象，而不是对象数组。
- `from: r.posts.ownerId` 指定我们建立软关系的来源表。
在本例中，关系从 `posts` 表的 `ownerId` 列开始。
- `to: r.users.id` 指定我们建立软关系的目标表。
在本例中，关系指向 `users` 表的 `id` 列。
- 类型层面的 `optional: false` 会使 posts 对象中的 `author` 键变为 `required`。
当你确定该特定实体始终存在时应使用它。
- `alias` 用于为表之间的关系添加特定别名。如果两个表之间存在多个相同的关系，应使用 `alias` 加以区分
- `where` 条件可用于多态关系。它根据 `where` 语句获取关系。
例如，在上述情况下，只会检索 `已验证的 author`。在[此处](/docs/relations-schema-declaration#多态关系)了解有关多态关系的更多信息。

### `many()`

以下是 drizzle 关系中 `.many()` 可用的所有字段列表

```ts {3-10}
const relations = defineRelations({ users, posts }, (r) => ({
	users: {
		feed: r.many.posts({
			from: r.users.id,
			to: r.posts.ownerId,
			alias: 'custom_name',
			where: {
				approved: true,
			}
		}),
	}
}))
```

- `feed` 键是一个自定义键，在使用 Drizzle 关系查询时会出现在 `users` 对象中。
- `r.many.posts` 定义 `feed` 将是来自 `posts` 表的对象数组，而不是单个对象
- `from: r.users.id` 指定我们建立软关系的来源表。
在本例中，关系从 `users` 表的 `id` 列开始。
- `to: r.posts.ownerId` 指定我们建立软关系的目标表。
在本例中，关系指向 `posts` 表的 `ownerId` 列。
- `alias` 用于为表之间的关系添加特定别名。如果两个表之间存在多个相同的关系，应使用 `alias` 加以区分
- `where` 条件可用于多态关系。它根据 `where` 语句获取关系。
例如，在上述情况下，只会检索 `已批准的 posts`。在[此处](/docs/relations-schema-declaration#多态关系)了解有关多态关系的更多信息。

### 一对一
Drizzle ORM 通过 `defineRelations` 函数为你提供了一个 API，用于定义表之间的 `one-to-one` 关系。

以下是 users 与 users 之间 `one-to-one` 关系的一个示例，其中一个用户可以邀请另一个用户（本示例使用了自引用）：

```typescript copy {10-17}
import { pgTable, text, integer } from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';

export const users = pgTable('users', {
	id: integer().primaryKey(),
	name: text(),
	invitedBy: integer('invited_by'),
});

export const relations = defineRelations({ users }, (r) => ({
	users: {
		invitee: r.one.users({
			from: r.users.invitedBy,
			to: r.users.id,
		})
	}
}));
```

另一个示例是用户的信息存储在单独的表中。在本例中，由于外键存储在 "profile_info" 表中，用户关系既没有 fields 也没有 references。这告诉 TypeScript：`user.profileInfo` 可为空：

```typescript copy {15-22}
import { pgTable, serial, text, integer, jsonb } from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';

export const users = pgTable('users', {
	id: integer().primaryKey(),
	name: text(),
});

export const profileInfo = pgTable('profile_info', {
	id: serial().primaryKey(),
	userId: integer('user_id').references(() => users.id),
	metadata: jsonb(),
});

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));

const user = await db.query.users.findFirst({ with: { profileInfo: true } });
//____^? type { id: number, name: string | null, profileInfo: { ... } | null  }
```

### 一对多
Drizzle ORM 通过 `defineRelations` 函数为你提供了一个 API，用于定义表之间的 `one-to-many` 关系。

用户与他们所写 posts 之间 `one-to-many` 关系的示例：

```typescript copy {15-25}
import { pgTable, text, integer } from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';

export const users = pgTable('users', {
	id: integer('id').primaryKey(),
	name: text('name'),
});

export const posts = pgTable('posts', {
	id: integer('id').primaryKey(),
	content: text('content'),
	authorId: integer('author_id'),
});

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```

现在给 posts 添加评论：

### 多对多
Drizzle ORM 通过所谓的 `junction` 或 `join` 表，为你提供了一个 API 来定义表之间的 `many-to-many` 关系，
这些表必须被显式定义，用于存储相关表之间的关联。

以下是 users 与 groups 之间 `many-to-many` 关系的示例，我们使用 `through` 绕过中间表的选择，直接为每个 `user` 选择多个 `groups`。
```typescript copy {27-39}
import { defineRelations } from 'drizzle-orm';
import { integer, pgTable, primaryKey, text } from 'drizzle-orm/pg-core';

export const users = pgTable('users', {
  id: integer().primaryKey(),
  name: text(),
});

export const groups = pgTable('groups', {
  id: integer().primaryKey(),
  name: text(),
});

export const usersToGroups = pgTable(
  'users_to_groups',
  {
    userId: integer('user_id')
      .notNull()
      .references(() => users.id),
    groupId: integer('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [primaryKey({ columns: [t.userId, t.groupId] })],
);

export const relations = defineRelations({ users, groups, usersToGroups },
  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),
        to: r.groups.id.through(r.usersToGroups.groupId),
      }),
    },
    groups: {
      participants: r.many.users(),
    },
  })
);
```

**查询示例：**
```ts
const res = await db.query.users.findMany({
  with: { 
    groups: true 
  },
});

// 响应类型
type Response = {
  id: number;
  name: string | null;
  groups: {
    id: number;
    name: string | null;
  }[];
}[];
```

### 预定义过滤器

Drizzle 关系定义中的预定义 `where` 语句是多态关系实现的一种形式，但并不完全是。本质上，它们允许你
不仅通过选择特定列来连接表，还可以通过自定义的 `where` 语句来连接。让我们看几个示例：

我们可以定义 `groups` 与 `users` 之间的关系，使得在查询 group 的 users 时，只检索那些 `verified` 列被设置为 `true` 的用户
<CodeTabs items={["关系", "Schema"]}>
<Section>
```ts
import { defineRelations } from "drizzle-orm";
import * as schema from './schema';

export const relations = defineRelations(schema,(r) => ({
    groups: {
      verifiedUsers: r.many.users({
        from: r.groups.id.through(r.usersToGroups.groupId),
        to: r.users.id.through(r.usersToGroups.userId),
        where: {
          verified: true,
        },
      }),
    },
  })
);

...

await db.query.groups.findMany({
    with: {
      verifiedUsers: true,
    },
});
```
</Section>
<Section>
```ts
import * as p from "drizzle-orm/pg-core";

export const users = p.pgTable("users", {
  id: p.integer().primaryKey(),
  name: p.text().notNull(),
  verified: p.boolean().notNull(),
});

export const groups = p.pgTable("groups", {
  id: p.integer().primaryKey(),
  title: p.text().notNull(),
});

export const usersToGroups = p.pgTable(
  "users_to_groups",
  {
    userId: p
      .integer("user_id")
      .notNull()
      .references(() => users.id, { onDelete: "cascade" }),
    groupId: p
      .integer("group_id")
      .notNull()
      .references(() => groups.id, { onDelete: "cascade" }),
  },
  (t) => [p.primaryKey({ columns: [t.groupId, t.userId] })]
);
```
</Section>
</CodeTabs>

<Callout type='warning'>
你只能在目标（to）表上指定过滤器。因此在本例中，where 子句只会包含 `users` 表中的列，因为我们建立的是 **指向** users 的关系

```ts {7}
export const relations = defineRelations(schema,(r) => ({
    groups: {
      verifiedUsers: r.many.users({
        from: r.groups.id.through(r.usersToGroups.groupId),
        to: r.users.id.through(r.usersToGroups.userId),
        where: {
          verified: true,
        },
      }),
    },
  })
);
```
</Callout>

### 关系组成部分

如果你需要将 relations 配置拆分成多个部分，可以使用 `defineRelationsPart` 辅助函数

```ts
import { defineRelations, defineRelationsPart } from 'drizzle-orm';
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));

export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

然后你可以将其提供给 db 实例

```ts
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })
```

<Callout type='warning'>
你需要遵循几条规则，以确保 `defineRelationsParts` 按预期工作

**规则 1**：如果你使用分段来指定关系，那么在将其传递给 drizzle db 函数时，需要按照正确的顺序指定（主关系在前）
```ts
// ✅
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })

// ❌
const db = drizzle(process.env.DB_URL, { relations: { ...part, ...relations } })
```

<Callout collapsed="为什么这很重要？">
即使不会出现类型错误或运行时错误，这也是 "..." 与对象一起工作的方式。只要主关系
递归地推断出所有表名，它就能在自动补全中使用。以下是一个示例：

```ts
export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));

export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

这里 `relations` 和 `part` 可以表示为以下对象：
```json
// relations
{
  "users": {"invitee": {...}, "posts": {...}},
  // 添加在此处，这样 schema 中的所有表都会出现在自动补全中
  "posts": {}
}

// part
{
  "posts": {"author": {...}}
}
```

使用 `{ ...relations, ...part }` 将得到
```json
{
  "users": {"invitee": {...}, "posts": {...}},
  "posts": {"author": {...}}
}
```

而使用 `{ ...relations, ...part }` 将得到
```json
{
  "users": {"invitee": {...}, "posts": {...}},
  // 如你所见，在最终对象中，posts 的关系信息将丢失
  "posts": {}
}
```

</Callout>

**规则 2**：你应当包含主关系（main relations），这样 drizzle 才能为自动补全推断出所有表。如果你只想使用分段，那么
其中一个分段应当为空，如下所示：

```ts
export const mainPart = defineRelationsPart(schema);
```

在这种情况下，所有表都会被正确推断，你将获得关于 schema 的完整信息
</Callout>

### 性能

在 Drizzle ORM 中处理关系时，尤其是在数据量较大或查询复杂的应用中，
优化数据库性能至关重要。
索引在加速数据检索方面起着至关重要的作用，尤其是在查询相关数据时。
本节概述了针对使用 Drizzle ORM 定义的每种关系类型所推荐的索引策略。

##### 一对一关系

在一对一关系中，例如 "用户邀请用户" 示例或
"用户拥有个人信息" 示例，关键的性能考虑因素是高效地连接相关表。

<Callout>
为了一对一关系中获得最佳性能，你应该在被引用的表
（关系中的 "目标" 表）的外键列上创建索引。
</Callout>

<Callout collapsed='为什么这很重要'>
当你查询带有关联的一对一信息的数据时，Drizzle 会执行 JOIN 操作。外键列上的索引允许数据库快速
定位目标表中的相关行，从而显著加快连接过程。
</Callout>

**示例：**
```typescript
import * as p from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';

export const users = p.pgTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const profileInfo = p.pgTable('profile_info', {
	id: p.integer().primaryKey(),
	userId: p.integer('user_id').references(() => users.id),
	metadata: p.jsonb(),
});

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));
```

为了优化获取用户数据及其个人信息的查询，
你应该在 `profile_info` 表的 `userId` 列上创建索引。

```typescript {13-15}
import * as p from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';

export const users = p.pgTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const profileInfo = p.pgTable('profile_info', {
	id: p.integer().primaryKey(),
	userId: p.integer('user_id').references(() => users.id),
	metadata: p.jsonb(),
}, (table) => [
  p.index('profile_info_user_id_idx').on(table.userId)
]);

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));
```
```sql
CREATE INDEX "profile_info_user_id_idx" ON "profile_info" ("user_id");
```

#### 一对多关系

与一对一关系类似，一对多关系也能从索引中显著受益，
以优化连接操作。以 "users 和 posts" 示例为例，其中一个用户可以拥有多个 posts。

<Callout>
对于一对多关系，在表示关系 "多" 一侧的表（即外键引用 "一" 一侧的表）的外键列上创建索引。
</Callout>

<Callout collapsed='为什么这很重要'>
当你获取一个用户及其 posts，或者获取 posts 及其作者时，都会执行连接。
对外键（`posts` 表中的 `authorId`）建立索引，可以让数据库高效地
检索与给定用户关联的所有 posts，或快速找到某篇 post 的作者。
</Callout>

**示例：**
```typescript
import * as p from "drizzle-orm/pg-core";
import { defineRelations } from 'drizzle-orm';

export const users = p.pgTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const posts = p.pgTable('posts', {
	id: p.integer().primaryKey(),
	content: p.text(),
	authorId: p.integer('author_id'),
});

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```

为了优化涉及 users 及其 posts 的查询，在 `posts` 表的 `authorId` 列上创建索引。

```typescript {13-15}
import * as p from "drizzle-orm/pg-core";
import { defineRelations } from 'drizzle-orm';

export const users = p.pgTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const posts = p.pgTable('posts', {
	id: p.integer().primaryKey(),
	content: p.text(),
	authorId: p.integer('author_id'),
}, (t) => [
  p.index('posts_author_id_idx').on(t.authorId)
]);

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```
```sql
CREATE INDEX "posts_author_id_idx" ON "posts" ("author_id");
```

#### 多对多关系

使用中间表实现的多对多关系，需要稍微
更细致一些的索引策略，以确保最佳的查询性能。
以带有 `usersToGroups` 中间表的 "users 和 groups" 示例为例。

<Callout>
对于多对多关系，通常建议在中间表上创建以下
索引：
1.  **为每个外键列单独建立索引：** 这会优化基于关系的
单侧进行过滤或连接的查询
（例如，查找某个用户的所有 groups，或查找某个 group 中的所有 users）。
2.  **在两个外键列上建立联合索引：** 这对于
高效地解析多对多关系本身至关重要。它能加速需要在两个实体之间查找关联的查询。
</Callout>

<Callout collapsed='为什么这很重要'>
在查询多对多关系时，尤其是在 Drizzle ORM 中使用 `through` 时，数据库需要高效地遍历中间表。

- 单个外键列上的索引（`usersToGroups` 中的 `userId`、`groupId`）有助于你从一侧查询以找到另一侧（例如，"查找某个用户的 groups"）。
- `usersToGroups` 中 `(userId, groupId)` 上的联合索引，对于快速查找中间表中定义的所有关系尤为重要。当 Drizzle ORM 解析 `many-to-many` 关系以获取相关实体时会用到它。
</Callout>

**示例：**

在 "users 和 groups" 示例中，`usersToGroups` 中间表连接了 `users` 和 `groups`。

```typescript
import { defineRelations } from 'drizzle-orm';
import * as p from 'drizzle-orm/pg-core';

export const users = p.pgTable('users', {
  id: p.integer().primaryKey(),
  name: p.text(),
});

export const groups = p.pgTable('groups', {
  id: p.integer().primaryKey(),
  name: p.text(),
});

export const usersToGroups = p.pgTable(
  'users_to_groups',
  {
    userId: p.integer('user_id')
      .notNull()
      .references(() => users.id),
    groupId: p.integer('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [p.primaryKey({ columns: [t.userId, t.groupId] })],
);

export const relations = defineRelations({ users, groups, usersToGroups },
  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),
        to: r.groups.id.through(r.usersToGroups.groupId),
      }),
    },
    groups: {
      participants: r.many.users(),
    },
```

为了优化 users 和 groups 的查询，请按以下方式在 `usersToGroups` 表上创建索引：

```typescript {26-28}
import { defineRelations } from 'drizzle-orm';

      .notNull()
      .references(() => users.id),
    groupId: p.integer('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [
    p.primaryKey({ columns: [t.userId, t.groupId] }),
    p.index('users_to_groups_user_id_idx').on(t.userId),

    p.index('users_to_groups_composite_idx').on(t.userId, t.groupId),
  ],
);

  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),

      }),
    },
    groups: {
      participants: r.many.users(),
    },
```

### 外键

你可能已经注意到，`relations` 看起来与外键类似——它们甚至有一个 `references` 属性。那么区别在哪里呢？

虽然外键具有类似的目的，即定义表之间的关系，但它们与 `relations` 工作的层级不同。

外键是数据库级别的约束，它们在每次 `insert`/`update`/`delete` 操作时都会被检查，如果违反约束就会抛出错误。
另一方面，`relations` 是更高层级的抽象，它们仅用于在应用层面定义表之间的关系。
它们不会以任何方式影响数据库 schema，也不会隐式创建外键。

这意味着 `relations` 和外键可以一起使用，但它们并不相互依赖。
你可以在不使用外键的情况下定义 `relations`（反之亦然），这使得它们可以用于不支持外键的数据库。

以下两个示例在使用 Drizzle 关系查询数据时，效果完全相同。

```ts {15}
  metadata: p.jsonb(),

    profileInfo: r.one.profileInfo({
```

### 消除关系歧义

当你定义多个位于相同两张表之间的关系时，Drizzle 还提供了 `alias` 选项来
消除歧义。例如，如果你定义一个 `posts` 表，它同时具有 `author` 和 `reviewer`
关系。

```ts {19,22,29,34}
import { pgTable, integer, text } from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';
 
export const users = pgTable('users', {
	id: integer('id').primaryKey(),
	name: text('name'),
});

export const posts = pgTable('posts', {
	id: integer('id').primaryKey(),
	content: text('content'),
	authorId: integer('author_id'),
	reviewerId: integer('reviewer_id'),
});
 
export const relations = defineRelations({ users, posts }, (r) => ({
  users: {
    posts: r.many.posts({
      alias: "author",
    }),
    reviewedPosts: r.many.posts({
      alias: "reviewer",
    }),
  },
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
      alias: "author",
    }),
    reviewer: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
      alias: "reviewer",
    }),
  },
}));
```
