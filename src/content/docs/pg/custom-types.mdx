# 自定义类型

自定义类型让你可以使用自定义的 SQL 数据类型和 JS/DB 值转换来定义自己的列类型

PostgreSQL 从 `drizzle-orm/pg-core` 中导出了 `customType`。

## 示例
了解 `customType` 定义如何工作的最佳方式，是查看如何使用 Drizzle ORM 中的 `customType` 函数来定义现有的数据类型。

#### Integer

```ts
import { customType, pgTable } from 'drizzle-orm/pg-core';

const customInteger = customType<{ data: number; }>(
  {
    dataType() {
      return 'integer';
    },
  },
);

export const users = pgTable("users", {
  id: customInteger(),
});
```

#### Text
```ts
import { customType, pgTable } from 'drizzle-orm/pg-core';

const customText = customType<{ data: string }>({
  dataType() {
    return 'text';
  },
});

export const users = pgTable('users', {
  name: customText(),
});
```

#### Timestamp
```ts
import { customType, pgTable } from 'drizzle-orm/pg-core';

const customTimestamp = customType<{
  data: Date;
  driverData: string;
  config: { withTimezone: boolean; precision?: number };
  configRequired: false;
}>({
  dataType(config) {
    const precision = typeof config?.precision !== 'undefined' ? ` (${config.precision})` : '';
    return `timestamp${precision}${config?.withTimezone ? ' with time zone' : ''}`;
  },
  fromDriver(value: string): Date {
    return new Date(value);
  },
  codec: (config) => {
    if (config?.withTimezone) return 'timestamp with time zone';

    return 'timestamp';
  },
});

export const users = pgTable('users', {
  createdAt: customTimestamp('created_at'),
});
```

所有类型的用法都将与 Drizzle ORM 中已定义的函数相同。例如：
```ts
const usersTable = pgTable('users', {
  id: customInteger().primaryKey(),
  name: customText().notNull(),
  createdAt: customTimestamp('created_at', { withTimezone: true }).notNull()
    .default(sql`now()`),
});
```

### 方法与泛型类型
<br/>

| 类型 | 是否必需 | 描述 |
|---|---|---|
| `data` | 是 | 查询/插入后列的 TypeScript 类型。 |
| `driverData` | 否 | 数据库驱动对该数据类型所接受的类型。 |
| `driverOutput` | 否 | **已弃用** — 请改用 codec（使用时会绕过 JSON codec）。驱动返回的类型（如果与 `driverData` 不同）。 |
| `jsonData` | 否 | **已弃用** — 请改用 codec（使用时会绕过 JSON codec）。聚合为 JSON 时返回的类型。 |
| `config` | 否 | 用于生成 `dataType` 的配置对象类型（例如 `{ length: number }`）。 |
| `configRequired` | 否 | config 参数是否必需。默认为 `false`。 |
| `notNull` | 否 | 如果自定义类型应默认为 `notNull`，则设为 `true`。 |
| `default` | 否 | 如果自定义类型有默认值，则设为 `true`。 |

<br/>

| 方法 | 是否必需 | 描述 |
|---|---|---|
| `dataType` | 是 | 定义 SQL 类型字符串。如果数据库数据类型需要额外参数，你可以使用 `config` 参数中的参数。 |
| `toDriver` | 否 | 将你期望在代码中使用的输入格式转换为适合驱动的格式 |
| `fromDriver` | 否 | 将驱动返回的数据转换为期望的列输出格式 |
| `codec` | 否 | 使用哪个驱动 codec（参见 [Codecs](/docs/codecs) 章节）。 |
| `fromJson` | 否 | **已弃用** — 请改用 `codec`。转换来自 JSON 上下文的值。 |
| `forJsonSelect` | 否 | **已弃用** — 请改用 `codec`。修改 JSON 函数内部列的选择方式 |

<br/>

```ts
interface CustomTypeValues {
  /**
   * 自定义列所需的类型，它将推断出正确的类型模型
   *
   * 示例：
   *
   * 如果你希望列在查询/插入时为 `string` 类型 - 使用 `data: string`。例如 `text`、`varchar`
   *
   * 如果你希望列在查询/插入时为 `number` 类型 - 使用 `data: number`。例如 `integer`
   */
  data: unknown;
  /**
   * 类型辅助工具，表示数据库驱动对特定数据库数据类型所接受的类型
   */
  driverData?: unknown;
  /**
   * @deprecated 请改用 codec
   *
   * 类型辅助工具，表示数据库驱动对特定数据库数据类型所返回的类型
   *
   * 仅在驱动的输出与输入类型不同时才需要
   *
   * 默认为 {@link driverData}
   */
  driverOutput?: unknown;
  /**
   * @deprecated 请改用 codec
   *
   * 类型辅助工具，表示字段聚合为 JSON 后返回的类型
   */
  jsonData?: unknown;
  /**
   * 生成 {@link CustomTypeParams} 的 `dataType` 时应使用何种配置类型
   */
  config?: Record<string, any>;
  /**
   * config 参数是否应为必需
   * @default false
   */
  configRequired?: boolean;
  /**
   * 如果你的自定义数据类型默认应为 notNull，可以使用 `notNull: true`
   *
   * @example
   * const customSerial = customType<{ data: number, notNull: true, default: true }>({
   * 	  dataType() {
   * 	    return 'serial';
   *    },
   * });
   */
  notNull?: boolean;
  /**
   * 如果你的自定义数据类型有默认值，可以使用 `default: true`
   *
   * @example
   * const customSerial = customType<{ data: number, notNull: true, default: true }>({
   * 	  dataType() {
   * 	    return 'serial';
   *    },
   * });
   */
  default?: boolean;
}
interface CustomTypeParams<T extends CustomTypeValues> {
  /**
   * 数据库数据类型的字符串表示形式，用于迁移
   * @example
   * ```
   * `jsonb`, `text`
   * ```
   *
   * 如果数据库数据类型需要额外参数，你可以使用 `config` 参数中的参数
   * @example
   * ```
   * `varchar(256)`, `numeric(2,3)`
   * ```
   *
   * 要使 `config` 为特定类型，请使用 {@link CustomTypeValues} 中的 config 泛型
   *
   * @example
   * 用法示例
   * ```
   *   dataType() {
   *     return 'boolean';
   *   },
   * ```
   * 或者
   * ```
   *   dataType(config) {
   * 	   return typeof config.length !== 'undefined' ? `varchar(${config.length})` : `varchar`;
   * 	 }
   * ```
   */
  dataType: (config: T['config'] | (Equal<T['configRequired'], true> extends true ? never : undefined)) => string;
  /**
   * 可选的映射函数，用于将你期望在代码中使用的输入格式转换为适合驱动的格式
   * @example
   * 例如，使用 jsonb 时，我们需要在写入数据库前将 JS/TS 对象映射为字符串
   * ```
   * toDriver(value: TData): string {
   * 	 return JSON.stringify(value);
   * }
   * ```
   */
  toDriver?: (value: T['data']) => T['driverData'] | SQL;
  /**
   * 可选的映射函数，用于将驱动返回的数据转换为期望的列输出格式
   * @example
   * 例如，使用 timestamp 时，我们需要将字符串形式的 Date 表示映射为 JS Date
   * ```
   * fromDriver(value: string): Date {
   * 	return new Date(value);
   * }
   * ```
   *
   * 它会使返回的数据从：
   * ```
   * {
   * 	customField: "2025-04-07T03:25:16.635Z";
   * }
   * ```
   * 变为：
   * ```
   * {
   * 	customField: new Date("2025-04-07T03:25:16.635Z");
   * }
   * ```
   */
  fromDriver?: (value: 'driverOutput' extends keyof T ? T['driverOutput'] : T['driverData']) => T['data'];
  /**
   * @deprecated 请改用 codec；使用时会绕过 JSON codec
   *
   * 可选的映射函数，用于将数据库中以 JSON 形式返回的数据转换为期望格式
   *
   * 由[关系查询](https://orm.drizzle.team/docs/rqb)使用
   *
   * 默认为 {@link fromDriver} 函数
   * @example
   * 例如，当通过 [RQB](https://orm.drizzle.team/docs/rqb) 或 JSON 函数查询 bigint 列时，结果字段将以其字符串表示形式返回，而不同于常规查询返回的 bigint
   * 为处理这种情况，我们需要一个单独的函数来处理此类字段的映射：
   * ```
   * fromJson(value: string): bigint {
   * 	return BigInt(value);
   * },
   * ```
   *
   * 它会使返回的数据从：
   * ```
   * {
   * 	customField: "5044565289845416380";
   * }
   * ```
   * 变为：
   * ```
   * {
   * 	customField: 5044565289845416380n;
   * }
   * ```
   */
  fromJson?: (value: T['jsonData']) => T['data'];
  /**
   * @deprecated 请改用 codec；使用时会绕过 JSON codec
   *
   * 可选的选择修饰函数，用于修改 JSON 函数内部列的选择方式
   *
   * 此类场景可能需要的额外映射可以使用 {@link fromJson} 函数处理
   *
   * 由[关系查询](https://orm.drizzle.team/docs/rqb)使用
   *
   * 以下类型默认会被转换为 text：`bytea`、`geometry`、`timestamp`、`numeric`、`bigint`
   * @example
   * 例如，使用 bigint 时，我们需要将字段转换为 text 以保留数据完整性
   * ```
   * forJsonSelect(identifier: SQL, sql: SQLGenerator, arrayDimensions?: number): SQL {
   * 	return sql`${identifier}::text`
   * },
   * ```
   *
   * 这会将查询从：
   * ```
   * SELECT
   * 	row_to_json("t".*)
   * 	FROM
   * 	(
   * 		SELECT
   * 		"table"."custom_bigint" AS "bigint"
   * 		FROM
   * 		"table"
   * 	) AS "t"
   * ```
   * 变为：
   * ```
   * SELECT
   * 	row_to_json("t".*)
   * 	FROM
   * 	(
   * 		SELECT
   * 		"table"."custom_bigint"::text AS "bigint"
   * 		FROM
   * 		"table"
   * 	) AS "t"
   * ```
   *
   * 查询对象返回的结果将从：
   * ```
   * {
   * 	bigint: 5044565289845416000; // 由于直接转换为 JSON 格式而部分数据丢失
   * }
   * ```
   * 变为：
   * ```
   * {
   * 	bigint: "5044565289845416380"; // 由于在 JSON 化之前将字段转换为 text，数据得以保留
   * }
   * ```
   */
  forJsonSelect?: (identifier: SQL, sql: SQLGenerator, arrayDimensions?: number) => SQL;
  /**
   * 选择此列将使用哪种列类型 codec
   */
  codec?: PostgresColumnType | undefined | ((config: T['config'] | (Equal<T['configRequired'], true> extends true ? never : undefined)) => PostgresColumnType | undefined);
}
```

## 转换层与执行顺序

自定义类型有两个转换层：列级（`toDriver`/`fromDriver`）和驱动级（[codecs](/docs/codecs)）。两者都按特定顺序运行。你可以在[这里](/docs/codecs#编解码器在-customtype-中如何工作)阅读更多关于如何将 codec 与 customTypes 配合使用的内容

<br/>

- **写入：**（Insert/Update）先执行 `toDriver` → 再执行 codec 的 `normalizeParam`
- **读取：**（Select）先执行 codec 的 `normalize` → 再执行 `fromDriver`
- 如果未设置 codec，则只运行 `toDriver`/`fromDriver`
- 如果未设置 `toDriver`/`fromDriver`，则只运行 codec（如果已定义）
- 如果两者都未设置，值将原样通过

<br/>

当你既需要驱动级规范化又需要列级转换时，请同时使用两者（`toDriver`/`fromDriver` 和 `codecs`）：

```ts
// 数据库以 bigint 存储，驱动返回 string，codec 将其转换为 BigInt，
// 但你希望在应用代码中使用 number
const myColumn = customType<{ data: number; driverData: string }>({
  dataType() { return 'bigint'; },
  codec: 'bigint',           // 驱动 "123" → BigInt(123n)
  fromDriver(value) {        // BigInt(123n) → Number(123)
    return Number(value);
  },
});
```

但通常你可以通过选择合适的 codec 变体来简化：

```ts
// 结果相同，无需 fromDriver
const myColumn = customType<{ data: number; driverData: string }>({
  dataType() { return 'bigint'; },
  codec: 'bigint:number',    // 驱动 "123" → 直接得到 Number(123)
});
```
