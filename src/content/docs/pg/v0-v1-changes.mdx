# v1 中的变更

本页展示了从 `drizzle-orm@0.x`、`drizzle-kit@0.x`、`drizzle-seed@0.x` 到最新的 `drizzle-orm@1.0`、`drizzle-kit@1.0`、`drizzle-seed@1.0` 之间发生的所有变更

<Callout type="info">
关于如何升级的更多内容请阅读[这里](/docs/upgrade-v1)
</Callout>

## 破坏性变更

#### 关系查询 v1 已移除

RQBv1 已被移除。请改用新的 `defineRelations()` API 以及新特性来使用 [关系查询 v2](/docs/relations)。关于从 rqb v1 迁移到 v2 的更多细节，你可以在[这里](/docs/relations-v1-v2)找到

围绕 `defineRelations()` 构建的新关系系统：

```ts
import { defineRelations } from 'drizzle-orm';

const relations = defineRelations(schema, (r) => ({
  users: {
    posts: r.many.posts(),
    profile: r.one.profiles(),
  },
  posts: {
    author: r.one.users({
      from: posts.authorId,
      to: users.id,
    }),
  },
}));
```

#### 新的 Casing API

旧版的 `drizzle({ casing: 'camelCase' })` 已被表/视图/schema 级别的 API 取代：

```ts
import { snakeCase, camelCase } from 'drizzle-orm/pg-core';

export const users = snakeCase.table('users', {
  id: serial().primaryKey(),
  fullName: text(),        // → 数据库中的 full_name
  createdAt: timestamp(),  // → 数据库中的 created_at
});

// 可用于所有实体类型：
snakeCase.table / snakeCase.view / snakeCase.materializedView / snakeCase.schema
camelCase.table / camelCase.view / camelCase.materializedView / camelCase.schema
```

#### 验证器包已合并到 `drizzle-orm`

<Callout type="warning">
你仍然可以使用 drizzle-zod/valibot/typebox/arktype 校验包，但所有新的更新都会直接加入 Drizzle ORM
</Callout>

- drizzle-zod -> [drizzle-orm/zod](/docs/zod)
- drizzle-valibot -> [drizzle-orm/valibot](/docs/valibot)
- drizzle-typebox -> [drizzle-orm/typebox-legacy](/docs/typebox-legacy)（使用 @sinclair/typebox）
- drizzle-typebox -> [drizzle-orm/typebox](/docs/typebox)（使用 typebox）
- drizzle-arktype -> [drizzle-orm/arktype](/docs/arktype)
- 新增了 `drizzle-orm/effect-schema` 包

#### `.array()` 不再可链式调用

多维数组请使用字符串语法：

```ts
// ❌ 之前
column.array().array()

// ✅ 之后
column.array('[][]')
column.array('[][][]')
```

#### `.enableRLS()` 已弃用

表上的 `.enableRLS()` 方法已废弃。请改用 `pgTable.withRLS()`：

```ts
// ❌ 之前
const users = pgTable('users', { ... }).enableRLS();

// ✅ 之后
const users = pgTable.withRLS('users', { ... });
```

#### `.generatedAlwaysAs()` 仅接受 SQL

```ts
// ❌ 之前 — 接受原始值
.generatedAlwaysAs('some expression')

// ✅ 之后 — 只接受 sql`` 或 () => sql``
.generatedAlwaysAs(sql`some expression`)
.generatedAlwaysAs(() => sql`some expression`)
```

#### `getTableColumns` 弃用

请改用 `getColumns`

```ts
// ❌ 之前
import { getTableColumns } from 'drizzle-orm';

const columns = getTableColumns(users);

// ✅ 之后
import { getColumns } from 'drizzle-orm';

const columns = getColumns(users);
```

#### 新的迁移文件夹结构（v3）

**相关讨论**：[#2832](https://github.com/drizzle-team/drizzle-orm/discussions/2832)

<br/>

- 不再有 `journal.json`
- SQL 文件和快照被分组到各自独立的迁移文件夹中
- 移除了 `drizzle-kit drop` 命令

这些变更消除了与 journal 文件之间潜在的 Git 冲突，并简化了删除或修复有冲突的迁移的流程

<Callout type="info">
关于如何升级的更多内容请阅读[这里](/docs/upgrade-v1)
</Callout>

#### `schemaFilter` 默认行为已更改

`drizzle-kit push` 和 `drizzle-kit pull` 现在默认管理**所有 schema**，而不仅仅是 `public`。它现在也支持 glob 模式。

<Callout type='warning' title='在 0.x 版本中的工作方式'>
在 0.x 中，`drizzle-kit push` 和 `drizzle-kit pull` 默认只管理 `public` schema 中的表。你必须显式配置 `schemaFilter` 才能管理其它 schema。
</Callout>

```ts
// ❌ 之前（0.x）— 默认只有 `public`，且只能显式列出
export default defineConfig({
  schemaFilter: ['public', 'analytics'],
});

// ✅ 之后（1.0）— 默认所有 schema，支持 glob 模式
export default defineConfig({
  // 如果你想管理所有 schema，则不需要 schemaFilter
});

// 要限制到特定 schema，你仍然可以使用 schemaFilter：
export default defineConfig({
  schemaFilter: ['public', 'app_*'], // 支持 glob 模式
});
```

#### `drizzle-kit push --strict` 弃用

`--strict` 标志已被移除——它的行为现在是默认行为。除非传入了 `--force` 标志，否则 `drizzle-kit push` 对会造成数据丢失的语句总是会提示确认。使用 [drizzle-kit push --explain](/docs/drizzle-kit-push) 可在执行前预览将要执行的 SQL。

{/* #### Drizzle seed：UUID 生成器升级到 v4

UUID 生成器现在生成符合 RFC 4122 v4 的 UUID，确保与 Zod v4 校验兼容。使用 `{ version: '1' }` 可保留旧行为，或使用 `{ version: '2' | '3' }` 使用较新的生成器。 */}

```ts
// select "id", "name" from "users" /*my_first_tag*/
```

#### 预编译查询

#### 完整重写 `drizzle-kit`

kit 在架构上进行了重新设计：
- 从数据库快照迁移到 DDL 快照
- 重做了差异检测与应用
- schema 内省从约 10 秒缩短到 1 秒以内
- 为 push 增加了查询提示和 explain 支持

#### `drizzle-kit pull --init`

创建 drizzle 迁移表，并把第一个拉取的迁移标记为已应用。你可以在[这里](/docs/drizzle-kit-pull)阅读更多

#### `drizzle-kit push --explain`

展示将要执行的 SQL，而不会真正运行它。你可以在[这里](/docs/drizzle-kit-push)阅读更多

#### `drizzle-kit check` — 交换性检查

检测跨分支的非可交换迁移——例如，两个分支修改同一个列，或者一个分支重命名了另一分支正在修改的表。

工作原理：
- 根据快照的 `prevIds` 构建 DAG，以理解分支结构
- 找出分支发生分叉的分叉点
- 计算从父快照到每个分支叶节点的 DDL 差异
- 使用一份「足迹映射」（footprint map）来检查冲突，该映射记录哪些 DDL 语句类型可能相互干扰

如果发现冲突，报告会确切告诉你哪些分支上的哪些迁移不兼容

#### `drizzle-kit --ignore-conflicts` 标志

当你确定这些冲突是预期之内时，用它绕过可交换性检查。

#### `drizzle-kit generate`：迁移冲突检测

`drizzle-kit generate` 现在会识别跨迁移分支的[不兼容变更](/docs/v0-v1-changes#drizzle-kit-check--交换性检查)。使用 `--ignore-conflicts` 可绕过。

#### 迁移表的更新

当你运行 `drizzle-kit up` 时，迁移表会自动升级。新增了两个列：

- **`name`** —— 完整的迁移文件夹名（例如 `20250220153045_brave_wolverine`）
- **`applied_at`** —— 迁移执行时的时间戳（已存在的行会用 `NULL` 回填）

| 列 | 类型 | v0 | v1 |
| --- | --- | --- |:---:|
| `id` | serial | 是 | 是 |
| `hash` | text | 是 | 是 |
| `created_at` | bigint | 是 | 是（旧版） |
| `name` | text | — | 新增 |
| `applied_at` | timestamp with time zone | — | 新增 |

现在迁移通过其完整的文件夹名而非时间戳进行匹配。即使两个迁移在同一秒内生成，名称后缀也能保证唯一性。

在升级过程中，已存在的行会通过多步策略回填：
1. **毫秒匹配** —— 把存储的毫秒截断到秒，与本地文件夹时间戳匹配
2. **哈希决胜** —— 如果多个迁移共享同一秒，则通过 SQL 哈希进行区分
3. **仅哈希回退** —— 如果毫秒匹配完全失败，则仅按哈希匹配

<br/>
这意味着升级能处理所有边界情况：正常的单人开发者项目、迁移时间相近的团队，甚至旧 journal 数据与新文件夹名不完全对齐的情况。

#### Migrator 应用所有缺失的迁移

此前，迁移器只查找创建日期晚于最后一次已应用迁移的本地迁移。现在它会检测并应用**每一个缺失的迁移**，无论时间戳顺序如何。所有迁移都通过完整的文件夹名（14 位 UTC 时间戳 + 名称后缀）进行匹配。

#### drizzle 配置文件中的顶层 `await`

现在在 Node.js 上支持在 `drizzle.config.ts` 和 schema 文件中使用顶层 `await`。

#### Drizzle-kit：构建系统改进

- 从 `esbuild-register` 迁移到 `tsx` loader —— 无缝支持 ESM 和 CJS
- 原生支持 Bun 和 Deno 启动

#### TS schema 文件处理

只处理具有以下扩展名的文件：`.js`、`.mjs`、`.cjs`、`.jsx`、`.ts`、`.mts`、`.cts`、`.tsx`。所有其它文件类型都会被忽略。
