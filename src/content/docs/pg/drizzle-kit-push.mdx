# `drizzle-kit push`

<Prerequisites>
- Drizzle 与 `drizzle-kit` 入门 - [阅读文档](/docs/get-started)
- Drizzle schema 基础 - [阅读文档](/docs/sql-schema-declaration) 
- 数据库连接基础 - [阅读文档](/docs/connect-overview) 
- Drizzle 迁移基础 - [阅读文档](/docs/migrations) 
- Drizzle Kit [概览](/docs/kit-overview) 与 [配置文件](/docs/drizzle-config-file) 文档
</Prerequisites>


`drizzle-kit push` 让你可以真正地将 schema 及其后续 schema 变更直接推送到
数据库，同时省略 SQL 文件的生成，它旨在覆盖 Drizzle 迁移的 [代码优先](/docs/migrations)
方式。

<Callout collapsed="底层是如何工作的？">
当你运行 Drizzle Kit 的 `push` 命令时，它会：
1. 读取你的 Drizzle schema 文件，并组合出 schema 的 json 快照
2. 拉取（内省）数据库 schema
3. 基于两者之间的差异生成 SQL 迁移
4. 将 SQL 迁移应用到数据库

<Section>
```typescript filename="src/schema.ts"
import * as p from "drizzle-orm/pg-core";

export const users = p.pgTable("users", {
  id: p.serial().primaryKey(),
  name: p.text(),
});
```
```
┌─────────────────────┐                  
│ ~ drizzle-kit push  │                  
└─┬───────────────────┘                  
  │                                           ┌──────────────────────────┐
  └ Pull current datatabase schema ---------> │                          │
                                              │                          │
  ┌ Generate alternations based on diff <---- │         DATABASE         │
  │                                           │                          │
  └ Apply migrations to the database -------> │                          │
                                       │      └──────────────────────────┘
                                       │
  ┌────────────────────────────────────┴────────────────┐
   create table users(id serial primary key, name text);
```
</Section>
</Callout>

这是快速原型开发的最佳方式，我们已经看到数十个团队
和独立开发者成功将其作为生产应用中的主要迁移流程。
它与蓝绿部署策略以及像
[Planetscale](https://planetscale.com)、[Neon](https://neon.tech)、[Turso](https://turso.tech/drizzle) 等无服务器数据库搭配得格外好。

`drizzle-kit push` 要求你指定 `dialect`、`schema` 文件的路径以及
数据库连接 `url` 或 `user:password@host:port/db` 参数，你可以
通过 [drizzle.config.ts](/docs/drizzle-config-file) 配置文件提供，也可以通过 CLI 选项提供：

<CodeTabs items={["使用配置文件", "使用 CLI 选项"]}>
<Section>
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  dbCredentials: {
    url: "postgresql://user:password@host:port/dbname",
  },
});
```
```shell
npx drizzle-kit push
```
</Section>

```shell
npx drizzle-kit push --dialect=postgresql --schema=./src/schema.ts --url=postgresql://user:password@host:port/dbname
```

</CodeTabs>

### schema 文件路径

你可以只有一个 `schema.ts` 文件，也可以有任意多个分散在项目中的 schema 文件。
Drizzle Kit 要求你通过 `schema` 配置选项以 [glob](https://www.digitalocean.com/community/tools/glob?comments=true&glob=/**/*.js&matches=false&tests=//%20This%20will%20match%20as%20it%20ends%20with%20'.js'&tests=/hello/world.js&tests=//%20This%20won't%20match!&tests=/test/some/globs) 的形式指定它们的路径。

### 单个项目中的多个配置文件

你可以在项目中拥有多个配置文件，当你存在多个数据库环境、多个数据库或同一项目下的不同数据库时，这非常有用：

<Npx>
  drizzle-kit push --config=drizzle-dev.config.ts
  drizzle-kit push --config=drizzle-prod.config.ts
</Npx>
```plaintext {5-6}
📦 <project root>
 ├ 📂 drizzle
 ├ 📂 src
 ├ 📜 .env
 ├ 📜 drizzle-dev.config.ts
 ├ 📜 drizzle-prod.config.ts
 ├ 📜 package.json
 └ 📜 tsconfig.json
```

### 指定数据库驱动
Drizzle Kit 不自带预捆绑的数据库驱动，
它会根据 `dialect` 从你当前项目中自动挑选可用的数据库驱动 - [参见讨论](https://github.com/drizzle-team/drizzle-orm/discussions/2203)。

同一方言的几乎所有驱动都共享同一组连接参数，
但对于 `aws-data-api`、`pglite` 和 `d1-http` 这类例外情况，你必须显式指定 `driver` 参数。

### 包含表、schema 和扩展
`drizzle-kit push` 默认会管理所有表和 schema。
你可以通过 `tablesFilter`、`schemaFilter` 和 `extensionFilters` 选项配置表、schema 和扩展的列表。

|                     |                                                                                               |
| :------------------ | :-------------------------------------------------------------------------------------------- |
| `tablesFilter`      | 基于 `glob` 的表名过滤器，例如 `["users", "user_info"]` 或 `"user*"`。默认值为 `"*"`          |
| `schemaFilter`      | schema 名称过滤器，例如 `["public", "drizzle"]`                                              |
| `extensionsFilters` | 已安装的数据库扩展列表，例如 `["postgis"]`。默认值为 `[]`                                     |
<br/>

让我们配置 drizzle-kit，使其只操作 **public** schema 中的 **所有表**，
并告知 drizzle-kit 已安装 **postgis** 扩展，
该扩展会在 public schema 中创建自己的表，因此 drizzle 可以忽略它们。

<Section>
```ts filename="drizzle.config.ts" {9-11}
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  dbCredentials: {
    url: "postgresql://user:password@host:port/dbname",
  },
  extensionsFilters: ["postgis"],
  schemaFilter: ["public"],
  tablesFilter: ["*"],
});
```
```shell
npx drizzle-kit push
```
</Section>

### 扩展配置列表

`drizzle-kit push` 有一系列仅 CLI 可用的选项

<rem025/>

|           |                                                                 |
| :-------- | :---------------------------------------------------------------|
| `verbose` | 在执行前打印所有 SQL 语句                                       |
| `explain` | 打印计划中的 SQL 变更，但不应用它们（试运行）                   |
| `force`   | 自动接受所有数据丢失语句                                        |
<br/>
<Npx>
drizzle-kit push --explain --verbose --force
</Npx>

<br/>
<hr/>
<br/>
我们推荐通过 [drizzle.config.ts](/docs/drizzle-config-file) 文件来配置 `drizzle-kit`，
但如果需要（例如在 CI/CD 流水线等场景中），你也可以通过 CLI 提供所有配置选项。

|                     |            |                                                                           |
| :------------------ | :--------- | :------------------------------------------------------------------------ |
| `dialect`           | `required` | 数据库方言，取值为 <Dialects/> 之一                                       |
| `schema`            | `required` | TypeScript schema 文件或包含多个 schema 文件的文件夹的路径                  |
| `driver`            |            | 驱动例外，例如 `aws-data-api`、`pglite`                                    |
| `tablesFilter`      |            | 表名过滤器                                                                |
| `schemaFilter`      |            | schema 名称过滤器。默认：`["*"]`                                          |
| `extensionsFilters` |            | 数据库扩展的内部数据库过滤器                                              |
| `url`               |            | 数据库连接字符串                                                          |
| `user`              |            | 数据库用户                                                                |
| `password`          |            | 数据库密码                                                                |
| `host`              |            | 主机                                                                      |
| `port`              |            | 端口                                                                      |
| `database`          |            | 数据库名称                                                                |
| `config`            |            | 配置文件路径，默认=`drizzle.config.ts`                                     |

<Npx>
drizzle-kit push dialect=postgresql schema=src/schema.ts url=postgresql://user:password@host:port/dbname
drizzle-kit push dialect=postgresql schema=src/schema.ts driver=pglite url=database/
drizzle-kit push dialect=postgresql schema=src/schema.ts --tablesFilter='user*' --extensionsFilters=postgis url=postgresql://user:password@host:port/dbname
</Npx>

```plaintext
 │ └ 📜 index.ts
 ├ 📜 drizzle.config.ts
 └ …
```

```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  dbCredentials: {
    url: "postgresql://user:password@host:port/dbname"
  },
});
```
```ts 
import * as p from "drizzle-orm/pg-core";

export const users = p.pgTable("users", {
  id: p.serial().primaryKey(),
  name: p.text(),
})
```
</CodeTabs>

```shell
npx drizzle-kit push
```

它会在底层从数据库拉取现有的（空）schema，生成 SQL 迁移并应用它
```sql
CREATE TABLE "users"(
  id serial primary key,
  name text
)
```
