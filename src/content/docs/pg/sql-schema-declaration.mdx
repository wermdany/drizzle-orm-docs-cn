# Drizzle schema

Drizzle 让你可以用 TypeScript 定义 schema，支持底层数据库所支持的各种模型和属性。
当你定义 schema 时，它就成为后续查询修改（使用 Drizzle-ORM）
和迁移（使用 Drizzle-Kit）的真相来源。

<Callout> 
如果你使用 Drizzle-Kit 进行迁移流程，请确保导出 schema 文件中定义的所有模型，以便 Drizzle-Kit 能够导入它们并在迁移差异流程中使用它们。
</Callout>

<CodeTabs items={["使用 import", "使用回调", "使用 import *"]}>
```ts
import { integer, pgTable, varchar } from "drizzle-orm/pg-core";

export const usersTable = pgTable("users", {
  id: integer().primaryKey().generatedAlwaysAsIdentity(),
  name: varchar().notNull(),
  age: integer().notNull(),
  email: varchar().notNull().unique(),
});
```
```ts
import { pgTable } from "drizzle-orm/pg-core";

export const usersTable = pgTable("users", (t) => ({
  id: t.integer().primaryKey().generatedAlwaysAsIdentity(),
  name: t.varchar().notNull(),
  age: t.integer().notNull(),
  email: t.varchar().notNull().unique(),
}));
```
```ts
import * as p from "drizzle-orm/pg-core";

export const usersTable = p.pgTable("users", {
  id: p.integer().primaryKey().generatedAlwaysAsIdentity(),
  name: p.varchar().notNull(),
  age: p.integer().notNull(),
  email: p.varchar().notNull().unique(),
});
```
</CodeTabs>

## 组织你的 schema 文件 
你可以直接在 TypeScript 中声明 SQL schema，既可以放在单个 `schema.ts` 文件中，
也可以分散到各处——随你喜欢，完全自由！

#### 单个文件中的 schema
用 Drizzle 声明 schema 最常见的方式是把所有表放进一个 `schema.ts` 文件中。

> 注意：你可以随意命名你的 schema 文件。例如，它可以叫 `models.ts`，或其它名字。

如果你没有定义太多表模型，或者你愿意把它们都放在一个文件中，这种方法就很适用

示例：
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📜 schema.ts
```

在 `drizzle.config.ts` 文件中，你需要指定 schema 文件的路径。使用此配置，Drizzle 将
从 `schema.ts` 文件中读取，并在迁移生成过程中使用这些信息。有关 `drizzle.config.ts`
文件和 Drizzle 迁移的更多信息，请查看：[链接](/docs/drizzle-config-file)
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'postgresql',
  schema: './src/db/schema.ts'
})
```

#### 多个文件中的 schema

你可以将 Drizzle 模型——例如表、枚举、序列等——不仅放在一个文件中，也可以放在你喜欢的任何文件中。
你唯一必须确保的是从这些文件中导出所有模型，以便 Drizzle kit 能够导入
它们并在迁移中使用。

一种用例是将每张表拆分到各自的文件中。
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 countries.ts
          ├ 📜 cities.ts
          ├ 📜 products.ts
          ├ 📜 clients.ts
          └ 📜 etc.ts
```

在 `drizzle.config.ts` 文件中，你需要指定 schema 文件夹的路径。使用此配置，Drizzle 将
从 `schema` 文件夹中读取，递归查找所有文件并从中获取所有 drizzle 表。有关 `drizzle.config.ts`
文件和 Drizzle 迁移的更多信息，请查看：[链接](/docs/drizzle-config-file)

```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'postgresql',
  schema: './src/db/schema'
})
```

你也可以按任意方式对它们进行分组，例如为用户相关表、消息相关表、产品相关表等创建分组。
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 messaging.ts
          └ 📜 products.ts
```

## 设计你的数据 schema

Drizzle schema 由你所使用的数据库中的若干模型类型组成。使用 drizzle，你可以指定：
- 带有列、约束等的表
- Schema
- 枚举
- 序列
- 视图
- 物化视图
- 等等。

让我们逐一查看如何使用 drizzle 定义 schema

#### **表和列的声明** 

Drizzle 中的表至少应定义 1 个列，与数据库中应做的相同。有一件重要的事情需要了解，
drizzle 中不存在通用表对象这样的东西。你需要选择你正在使用的方言，PostgreSQL、MySQL、SQLite 等。

![](@/assets/images/table-structure.svg)

```ts copy
import { pgTable, integer } from "drizzle-orm/pg-core"

export const users = pgTable('users', {
  id: integer()
});
```

默认情况下，Drizzle 在数据库查询中会使用 TypeScript 的键名作为列名。
因此，示例中的 schema 和查询将生成如下所示的 SQL 查询

<Callout>
此示例使用了一个 db 对象，其初始化未在本文档的这部分中介绍。要了解如何连接数据库，请参阅[连接文档](/docs/get-started-postgresql)
</Callout>

\
**TypeScript 键 = 数据库键**
<Section>
```ts
// schema.ts
import { integer, pgTable, varchar } from "drizzle-orm/pg-core";

export const users = pgTable('users', {
  id: integer(),
  first_name: varchar()
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT "id", "first_name" from users;
```
</Section>

如果你想在 TypeScript 代码和数据库中使用不同的名称，可以使用列别名

<Section>
```ts
// schema.ts
import { integer, pgTable, varchar } from "drizzle-orm/pg-core";

export const users = pgTable('users', {
  id: integer(),
  firstName: varchar('first_name')
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT "id", "first_name" from users;
```
</Section>

### 驼峰与蛇形命名

数据库模型名通常使用 `snake_case` 约定，而在 TypeScript 中，命名模型通常使用 `camelCase`。
这可能导致 schema 中出现大量的别名定义。为解决这个问题，Drizzle 提供了一种方式，通过专门的构建器
自动将 TypeScript 中的 `camelCase` 映射为数据库中的 `snake_case`。

使用来自 `drizzle-orm/pg-core` 的 `snakeCase` 或 `camelCase` 构建器声明一张表，其列键会
自动映射到所选的数据库命名约定

<Section>
```ts {2,4,11,12}
// schema.ts
import { snakeCase, camelCase } from 'drizzle-orm/pg-core';

export const users = snakeCase.table('users', {
  id: serial().primaryKey(),
  fullName: text(),        // → 数据库中的 full_name
  createdAt: timestamp(),  // → 数据库中的 created_at
});

// 可用于所有实体类型：
snakeCase.table / snakeCase.view / snakeCase.materializedView / snakeCase.schema
camelCase.table / camelCase.view / camelCase.materializedView / camelCase.schema
```
```ts
// db.ts
import { drizzle } from "drizzle-orm/node-postgres";

const db = drizzle({ connection: process.env.DATABASE_URL })
```
```ts
// query.ts
await db.select().from(users);
```
```sql
select "id", "full_name", "created_at" from "users"
```
</Section>

### 进阶

使用 Drizzle ORM 时有一些技巧可以用。只要 Drizzle 完全位于 TypeScript 文件中，
你基本上可以在你的代码里做任何在简单 TypeScript 项目里能做的事情。

一个常见的特性是将列拆分到不同的地方，然后复用它们。
例如，考虑 `updated_at`、`created_at` 和 `deleted_at` 列。许多表/模型可能需要这
三个字段来追踪和分析系统中实体的创建、删除和更新

我们可以在一个单独的文件中定义这些列，然后导入并将它们散布到你所拥有的所有表对象中

<Section>
```ts
// columns.helpers.ts
export const timestamps = {
  updated_at: timestamp(),
  created_at: timestamp().defaultNow().notNull(),
  deleted_at: timestamp(),
}
```
```ts
// users.sql.ts
export const users = pgTable('users', {
  id: integer(),
  ...timestamps
})
```
```ts
// posts.sql.ts
export const posts = pgTable('posts', {
  id: integer(),
  ...timestamps
})
```
</Section>

#### **Schemas**

\
在 PostgreSQL 中，有一种称为 `schema` 的实体（我们认为它应该被称为 `folders`）。它在 PostgreSQL 中创建了一种结构：

![](@/assets/images/postgresql-db-structure.png)

你可以使用 `pgSchema` 管理你的 PostgreSQL schema，并将任何其它模型放在其中。

使用 Drizzle 定义你想管理的 schema
```ts
import { pgSchema } from "drizzle-orm/pg-core"

export const customSchema = pgSchema('custom');
```

然后将表放在 schema 对象内
```ts {5-7}
import { integer, pgSchema } from "drizzle-orm/pg-core";

export const customSchema = pgSchema('custom');

export const users = customSchema.table('users', {
  id: integer()
})
```

### 示例

一旦你了解了基础知识，让我们为一个真实项目定义一个 schema 示例，以便更好地查看和理解

> 所有示例都会使用 `generateUniqueString`。它的实现将在所有 schema 示例之后提供

```ts copy
import type { AnyPgColumn } from "drizzle-orm/pg-core";
import { pgEnum, pgTable as table } from "drizzle-orm/pg-core";
import * as t from "drizzle-orm/pg-core";

export const rolesEnum = pgEnum("roles", ["guest", "user", "admin"]);

export const users = table(
  "users",
  {
    id: t.integer().primaryKey().generatedAlwaysAsIdentity(),
    firstName: t.varchar("first_name", { length: 256 }),
    lastName: t.varchar("last_name", { length: 256 }),
    email: t.varchar().notNull(),
    invitee: t.integer().references((): AnyPgColumn => users.id),
    role: rolesEnum().default("guest"),
  },
  (table) => [
    t.uniqueIndex("email_idx").on(table.email)
  ]
);

export const posts = table(
  "posts",
  {
    id: t.integer().primaryKey().generatedAlwaysAsIdentity(),
    slug: t.varchar().$default(() => generateUniqueString(16)),
    title: t.varchar({ length: 256 }),
    ownerId: t.integer("owner_id").references(() => users.id),
  },
  (table) => [
    t.uniqueIndex("slug_idx").on(table.slug),
    t.index("title_idx").on(table.title),
  ]
);

export const comments = table("comments", {
  id: t.integer().primaryKey().generatedAlwaysAsIdentity(),
  text: t.varchar({ length: 256 }),
  postId: t.integer("post_id").references(() => posts.id),
  ownerId: t.integer("owner_id").references(() => users.id),
});
```

**`generateUniqueString` 实现：**
```ts
function generateUniqueString(length: number = 12): string {
  const characters =
    "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789";
  let uniqueString = "";

  for (let i = 0; i < length; i++) {
    const randomIndex = Math.floor(Math.random() * characters.length);
    uniqueString += characters[randomIndex];
  }

  return uniqueString;
}
```
