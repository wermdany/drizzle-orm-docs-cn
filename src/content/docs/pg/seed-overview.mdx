# Drizzle Seed

`drizzle-seed` 是一个 TypeScript 库，帮助你生成确定性的、却又逼真的
假数据来填充你的数据库。通过利用可设定种子的伪随机数生成器（pRNG），
它确保你生成的数据在不同运行之间保持一致且可复现。
这对于测试、开发和调试尤为有用。

#### 什么是确定性数据生成？

确定性数据生成意味着相同的输入始终会产生相同的输出。
在 `drizzle-seed` 的语境中，当你用相同的种子数字初始化该库时，
它每次都会生成相同的假数据序列。这就能得到可预测、可重复的数据集。

#### 伪随机数生成器（pRNG）

伪随机数生成器是一种算法，它产生的数字序列
近似于随机数的特性。然而，由于它基于一个称为种子的
初始值，你可以控制其随机性。通过使用相同的种子，pRNG 会产生
相同的数字序列，从而使你的数据生成过程可复现。

#### 使用 pRNG 的好处：

- 一致性：确保你的测试每次都运行在相同的数据上。
- 调试：通过提供一致的数据集，让复现和修复 bug 变得更容易。
- 协作：团队成员可以共享种子数字，以使用相同的数据集。

借助 drizzle-seed，你可以两全其美：既能生成逼真的假数据，又能在需要时控制其复现。

## 安装

<Npm>drizzle-seed</Npm>

## 基本用法

在这个示例中，我们将创建 10 个具有随机姓名和 id 的用户

```ts {12}
import { pgTable, integer, text } from "drizzle-orm/pg-core";
import { drizzle } from "drizzle-orm/node-postgres";
import { seed } from "drizzle-seed";

const users = pgTable("users", {
  id: integer().primaryKey(),
  name: text().notNull(),
});

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);
  await seed(db, { users });
}

main();
```

## 选项

**`count`**

默认情况下，`seed` 函数会创建 10 个实体。
不过，如果你的测试需要更多，可以在 seed 选项对象中指定

```ts
await seed(db, schema, { count: 1000 });
```

**`seed`**

如果你需要一个种子，以便在所有后续运行中生成一组不同的值，可以在 `seed` 选项中
定义一个不同的数字。任何新的数字都会生成一组唯一的值

```ts
await seed(db, schema, { seed: 12345 });
```

## 重置数据库

借助 `drizzle-seed`，你可以轻松地重置数据库并用新值填充它，例如在你的测试套件中

```ts
// 指向你想重置的 schema 文件的路径
import * as schema from "./schema.ts";
import { reset } from "drizzle-seed";

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);
  await reset(db, schema);
}

main();
```

不同的方言在重置数据库时会采用不同的策略

对于 PostgreSQL，`drizzle-seed` 包会生成带有 `CASCADE` 选项的 `TRUNCATE` 语句，
以确保在运行 reset 函数后所有表都被清空

```sql
TRUNCATE tableName1, tableName2, ... CASCADE;
```

## 细化

如果你需要改变 `drizzle-seed` 默认使用的种子生成器函数的行为，可以指定你自己的实现，甚至可以在种子填充过程中使用你自己的值列表

`.refine` 是一个回调，它接收来自 `drizzle-seed` 的所有可用生成器函数的列表。它应返回一个对象，其键表示你想要精细化的表，并按需定义它们的行为。
每个表可以指定若干属性，以简化数据库的种子填充：

<rem025 />

- `columns`：通过指定所需的生成器函数来精细化每一列的默认行为，或通过指定 `false` 将列排除在种子填充之外。
- `count`：指定要插入数据库的行数。默认为 10。如果在 `seed()` 选项中定义了全局 count，则此处定义的 count 会针对此特定表覆盖它。
- `with`：如果你想生成关联实体，可以定义每个父表要创建多少个被引用的实体。

<Callout title='信息'>
你还可以为你想要创建的被引用值的数量指定加权随机分布。有关此 API 的详细信息，可以参考 [加权随机文档](#加权随机) 章节
</Callout>

**API**
```ts
await seed(db, schema).refine((f) => ({
  users: {
    columns: {},
    count: 10,
    with: {
        posts: 10
    }
  },
}));
```

让我们看几个示例，并解释会发生什么：


**示例 1**：仅为 `users` 表填充种子数据，生成 20 个实体，并对 `name` 列使用精细化后的种子逻辑
```ts filename='index.ts'
import { drizzle } from "drizzle-orm/node-postgres";
import { seed } from "drizzle-seed";
import * as schema from './schema.ts'

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, { users: schema.users }).refine((f) => ({
    users: {
        columns: {
            name: f.fullName(),
        },
        count: 20
    }
  }));
}

main();
```

**示例 2**：仅为 `users` 表填充种子数据，并将 `name` 列排除在种子填充之外

## 加权随机

在某些情况下，你可能需要使用多个具有不同优先级的数据集，在种子填充阶段插入到数据库中。对于这种情况，drizzle-seed 提供了名为加权随机的 API

Drizzle Seed 包有几处可以使用加权随机的地方：

- 每个表精细化配置中的列
- `with` 属性，用于确定要创建的相关实体数量

让我们看一个同时涉及两者的示例：

```ts filename="schema.ts"
import { pgTable, integer, text, varchar, doublePrecision } from "drizzle-orm/pg-core";

export const orders = pgTable(
  "orders",
  {
    id: integer().primaryKey(),
    name: text().notNull(),
    quantityPerUnit: varchar().notNull(),
    unitPrice: doublePrecision().notNull(),
    unitsInStock: integer().notNull(),
    unitsOnOrder: integer().notNull(),
    reorderLevel: integer().notNull(),
    discontinued: integer().notNull(),
  }
);

export const details = pgTable(
  "details",
  {
    unitPrice: doublePrecision().notNull(),
    quantity: integer().notNull(),
    discount: doublePrecision().notNull(),

    orderId: integer()
      .notNull()
      .references(() => orders.id, { onDelete: "cascade" }),
  }
);
```

**示例 1**：精细化 `unitPrice` 的生成逻辑，生成 `5000` 个随机价格，其中有 30% 的概率价格在 10-100 之间，70% 的概率价格在 100-300 之间

```ts filename="index.ts"
import { drizzle } from "drizzle-orm/node-postgres";
import { seed } from "drizzle-seed";
import * as schema from './schema.ts'

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, schema).refine((f) => ({
    orders: {
       count: 5000,
       columns: {
           unitPrice: f.weightedRandom(
               [
                   {
                       weight: 0.3,
                       value: funcs.int({ minValue: 10, maxValue: 100 })
                   },
                   {
                       weight: 0.7,
                       value: funcs.number({ minValue: 100, maxValue: 300, precision: 100 })
                   }
               ]
           ),
       }
    }
  }));
}

main();
```

**示例 2**：为每个 order 生成 1 到 3 个 details（60% 的概率）、5 到 7 个 details（30% 的概率）以及 8 到 10 个 details（10% 的概率）

```ts filename="index.ts"
import { drizzle } from "drizzle-orm/node-postgres";
import { seed } from "drizzle-seed";
import * as schema from './schema.ts'

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, schema).refine((f) => ({
    orders: {
       with: {
           details:
               [
                   { weight: 0.6, count: [1, 2, 3] },
                   { weight: 0.3, count: [5, 6, 7] },
                   { weight: 0.1, count: [8, 9, 10] },
               ]
       }
    }
  }));
}

main();
```

## 限制

#### `with` 的类型限制

由于 TypeScript 的某些限制以及 Drizzle 当前的 API，无法正确推断表之间的引用，尤其是当表之间存在循环依赖时。

这意味着 `with` 选项会显示 schema 中的所有表，你需要手动选择具有一对多关系的那张表

<Callout title='warning'>
`with` 选项适用于一对多关系。例如，如果你有一个 `user` 和多个 `posts`，你可以使用 users `with` posts，但不能使用 posts `with` users
</Callout>

#### 复合唯一约束
- 当两个复合唯一约束共享某一列时，不支持种子填充：
```ts
const composite = pgTable(
  "composite_example",
  {
    id: integer("id").notNull(),
    name: text("name").notNull(),
    slug: text("slug").notNull(),
  },
  (t) => [
    unique("custom_name").on(t.id, t.name),
    unique("custom_name1").on(t.name, t.slug),
  ]
);
```
这是允许的，然而，如果其中一个约束是单列唯一约束：
```ts
unique("custom_name1").on(t.name);
```
- 你不能使用在其配置中未暴露 `isUnique` 选项的生成器，除非它是始终唯一的生成器之一：`intPrimaryKey`、`email`、`phoneNumber` 或 `uuid`。
