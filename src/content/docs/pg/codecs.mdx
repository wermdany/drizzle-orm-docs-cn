# 编解码器

## 什么是编解码器？

codecs 是一层感知驱动的转换层，位于你的 JavaScript 值与数据库之间。它们解决了**不同驱动对相同列类型返回和接受的数据格式不同**的问题。

## 为什么需要它们？

1. **驱动差异** — 每个 PG 驱动（`node-postgres`、`postgres-js`、`pglite` 等）解析和序列化类型的方式都不同。codecs 会规范化这些差异，这样你的应用代码不必关心自己使用的是哪个驱动。

2. **JSON 上下文** — 当在 JSON 函数（如 `jsonAgg`、`jsonBuildObject` 或关系查询）内部选择某一列时，数据库会以 JSON 格式返回值，这可能与常规格式不同。例如，JSON 中的 `bigint` 会变成数字（丢失精度）。codecs 通过在 JSON 化之前先转换为 text（`castInJson`），然后再解析回来（`normalizeInJson`）来处理这一情况。

## 编解码器如何工作

codecs 有两层：**cast** 和 **normalize**。

```

          ┌───────────────────────────────────────┐
          │  Cast layer (DB level)                │
          │  SELECT "bigint"::text FROM "users"   │
          └───────────────────────────────────────┘
 
          ┌────────────────────────────────────┐
          │  Normalize layer (Code level)      │
          │  "123" → BigInt("123") → 123n      │
          └────────────────────────────────────┘
```

<br/>

**Cast** 在数据库层面运作——它把列包装成 SQL `::type`

**Normalize** 在代码层面运作——它把原始值转换为你的代码/驱动所期望的类型

<br/>

两层都可以针对不同的查询上下文有各自的变体：

对于读取（SELECT）：

```
SQL generation:      SELECT "col"::text FROM ...     ← cast layer modifies SQL
                            ▼
Database executes:   returns text representation
                            ▼
JS result mapping:   parseLineABC(rawValue)          ← normalize layer transforms in JS
                            ▼
Your code gets:      { a: 1, b: 2, c: 3 }
```

对于写入（INSERT/UPDATE）：

```
Your JS value:       { key: "val" }
                            ▼
JS param building:   JSON.stringify(value)            ← normalize layer transforms in JS
                            ▼
SQL generation:      INSERT ... VALUES ($1::jsonb)    ← cast layer modifies SQL
                            ▼
Database receives:   '{"key":"val"}' with type hint
```

<br/>

每一层都跨越 3 种上下文运作，每种上下文又都有标量和数组两种变体：

```
                        Cast (SQL)              Normalize (JS)
                   ┌──────────────────┐    ┌──────────────────────┐
  Regular SELECT   │ cast             │    │ normalize            │
                   │ castArray        │    │ normalizeArray       │
                   ├──────────────────┤    ├──────────────────────┤
  Inside JSON      │ castInJson       │    │ normalizeInJson      │
  (jsonAgg, RQB)   │ castArrayInJson  │    │ normalizeArrayInJson │
                   ├──────────────────┤    ├──────────────────────┤
  Params           │ castParam        │    │ normalizeParam       │
  (INSERT/UPDATE)  │ castArrayParam   │    │ normalizeParamArray  │
                   └──────────────────┘    └──────────────────────┘
```

存在 JSON 上下文是因为数据库在 JSON 内部对值的序列化方式不同——通常从驱动返回为字符串的 `bigint`，在 JSON 对象内部会变成有损的数字。因此 codecs 需要单独处理：在 JSON 包装前先在 SQL 中转换为 `::text`，之后在 JS 中再把文本解析回来。

<br/>

| 方法 | 何时 | 示例 SQL |
|---|---|:---:|
| `cast` | SELECT 中的列 | `"col"::text` |
| `castArray` | SELECT 中的数组列 | `"col"::text[]` |
| `castInJson` | JSON 函数内的列 | `"col"::text`（在 `json_agg` 内） |
| `castArrayInJson` | JSON 内的数组列 | |
| `castParam` | INSERT/UPDATE/WHERE 中的参数占位符 | `$1::date` |
| `castArrayParam` | 数组参数占位符 | `$1::date[]` |

<br/>

| 方法 | 何时 | 示例 |
|---|---|:---:|
| `normalize` | SELECT 结果 → JS 值 | `"123"` → `123n` |
| `normalizeArray` | SELECT 数组结果 → JS 数组 | `["123", "456"]` → `[123n, 456n]` |
| `normalizeInJson` | JSON 内的 SELECT 结果 → JS | JSON `bigint` → `BigInt` |
| `normalizeArrayInJson` | JSON 内的 SELECT 数组 → JS | |
| `normalizeParam` | JS 值 → 驱动参数（INSERT/UPDATE/WHERE） | `{ key: "val" }` → `'{"key":"val"}'` |
| `normalizeParamArray` | JS 数组 → 驱动数组参数 | `[1, 2]` → `{1,2}`（PG 数组字面量） |

<br/>

## 它们默认启用吗？

是的。每个驱动都自带默认 codecs。当你调用 `drizzle(client)` 时，驱动的 codecs 会自动被使用。  
你无需做任何操作来启用它们。

## 编解码器在内置列类型中如何工作

每个内置的 PG 列类都会声明一个 `codec` 字符串标识符：

```ts {3,8,11,14,19,22,27}
// pg-core/columns/integer.ts
class PgInteger extends PgColumn {
  override readonly codec = 'int';
}

// pg-core/columns/bigint.ts  
class PgBigInt53 extends PgColumn {
  override readonly codec = 'bigint:number';
}
class PgBigInt64 extends PgColumn {
  override readonly codec = 'bigint';
}
class PgBigIntString extends PgColumn {
  override readonly codec = 'bigint:string';
}

// pg-core/columns/line.ts
class PgLineABC extends PgColumn {
  override readonly codec = 'line';
}
class PgLineTuple extends PgColumn {
  override readonly codec = 'line:tuple'
}

...
```

该标识符是驱动 codec map 的一个查找键。如果驱动为该键定义了转换，它们就会被应用。如果没有，值会原样透传。

例如，`integer` 的 codec 是 `'int'`。`node-postgres` 的 codec map 中**没有** `'int'` 的条目——整数不需要任何转换。但 `bigint` 的 codec 是 `'bigint'`，而 node-postgres 定义了：

```ts
// node-postgres/codecs.ts
bigint: {
  normalize: BigInt,                           // SELECT："123" → 123n
  normalizeArray: arrayCompatNormalize(BigInt), // SELECT 数组：["123"] → [123n]
}
```

## 为内置类型覆盖编解码器

内置列（如 `integer()`、`bigint()`、`date()`、`text()` 等）有一个硬编码的 `codec` 字符串——你无法改变某个列使用哪个 codec 标识符。但你**可以**通过覆盖驱动的 codec map 来改变该 codec 标识符的行为。

每个 PG 驱动都在 `drizzle()` 中接受一个 `codecs` 选项：

```ts {3-6}
const db = drizzle(client, {
  codecs: {
    "bigint:number": {
      cast: (name) => sql`${name}::text`,
      normalize: BigInt,
    },
  },
});
```

## 编解码器在 `customType()` 中如何工作

<Callout type='info' title='注意'>
`customType` 上的 `toDriver`/`fromDriver` 与 codecs 是**相互独立的层**。
`toDriver`/`fromDriver` 是逐列实例的转换。Codecs 是驱动级的转换，两者都会被应用  
读取时 - 先执行 `codec normalize` → 再执行 `fromDriver`
写入时 - 先执行 `toDriver` → 再执行 `codec normalizeParam`
</Callout>

在[这里](/docs/custom-types)阅读更多关于自定义类型的内容

在定义自定义列类型时，你可以通过 `codec` 属性指定要使用哪个 codec：

```ts
import { customType } from 'drizzle-orm/pg-core';

// 按名称使用已有的 codec
const customBigint = customType<{ data: bigint; driverData: string }>({
  dataType() {
    return "bigint";
  },
  fromDriver(value: string) {
    return BigInt(Number(value) * 1000); // ← 额外的列映射逻辑
  },
  codec: "bigint", // ← 使用驱动的 bigint codec
});

// codec 作为函数（当 codec 依赖配置时很有用）
const customDataType = customType<{
  data: number;
  driverData: bigint | number;
  config?: { mode: "bigint" | "number" };
  configRequired: true;
}>({
  dataType() {
    return `custom_type`;
  },
  fromDriver(value: bigint | number) {
    return Number(value) / 1000; // ← 额外的列映射逻辑
  },
  codec: (config) => {
    // ← 可以基于 config 动态决定
    if (!config || config.mode === "bigint") {
      return "bigint";
    }

    return "bigint:number";
  },
});

// 无 codec — 完全跳过 codec 转换
const rawCustom = customType<{ data: string; driverData: string }>({
  dataType() {
    return 'my_type';
  },
  // codec 默认为 undefined — 不应用任何 codec 转换
});
```

`codec` 字段接受：
- 一个 `string` — PostgreSQL 类型标识符之一（例如 `'bigint'`、`'date'`、`'json'`、`'text'` 等）
- 一个 `function` `(config) => string | undefined` — 根据列的 config 动态解析 codec
- `undefined`（默认）— 无 codec，值原样透传
