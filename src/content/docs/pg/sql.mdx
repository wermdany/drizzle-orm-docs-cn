# 神奇的 `sql` 运算符 🪄

在处理 ORM 库时，你可能会发现有些情况下很难用提供的 ORM 语法来编写某个特定的查询。在这种情况下，你可以转而使用原始查询，也就是把查询构造成原始字符串。然而，原始查询往往缺乏类型安全和查询参数化带来的好处。

为了解决这个问题，许多库引入了 `sql` 模板的概念。这个模板允许你编写更类型安全、更具参数化的查询，从而提升代码的整体安全性和灵活性。Drizzle 作为一个强大的 ORM 库，同样支持 sql 模板。

借助 Drizzle 的 `sql` 模板，你可以在构造查询时走得更远。如果你发现用该库的查询构建器难以编写完整查询，你可以在 Drizzle 查询的特定部分选择性地使用 `sql` 模板。这种灵活性使你可以在局部的 SELECT 语句、WHERE 子句、ORDER BY 子句、HAVING 子句、GROUP BY 子句，甚至关系查询构建器中使用 sql 模板。

通过利用 Drizzle 中 sql 模板的能力，你可以在保持类型安全和查询参数化优势的同时，实现所需的查询结构和复杂度。这使你能够在应用中创建更健壮、更易维护的代码。

## sql`` 模板

你在其它 ORM 中最常见的用法之一，也是把 `sql` 查询原样用作原始查询的能力。

```typescript copy
import { sql } from 'drizzle-orm' 

const id = 69;
await db.execute(sql`select * from ${usersTable} where ${usersTable.id} = ${id}`)
```

它将生成如下查询

```sql
select * from "users" where "users"."id" = $1; --> [69]
```

传给 sql 参数的任何表和列都会被自动映射为对应的 SQL 语法，表名会被转义，转义后的表名会被追加到列名前。

此外，任何动态参数（如 `${id}`）都会被映射为 $1 占位符，对应的值会被移到一个值数组中，单独传给数据库。

这种方式有效地防止了潜在的 SQL 注入漏洞。

## `sql<T>`

<Callout type="info" emoji="ℹ️">
    请注意，`sql<T>` 不会执行任何运行时映射。你用 `sql<T>` 定义的类型纯粹是给 Drizzle 用的辅助信息。需要理解的是，无法可行地动态确定确切的类型，因为 SQL 查询可能非常多样且可定制。
</Callout>

你可以在 Drizzle 中定义自定义类型，用于那些需要特定类型（而非 `unknown`）的字段。

这个特性在局部查询中特别有用，可以确保所选字段的类型一致：

```typescript
// 未定义 sql<T> 类型
const response: { lowerName: unknown }[] = await db.select({
    lowerName: sql`lower(${usersTable.id})`
}).from(usersTable);

// 定义了 sql<T> 类型
const response: { lowerName: string }[] = await db.select({
    lowerName: sql<string>`lower(${usersTable.id})`
}).from(usersTable);
```

## `sql``.mapWith()`

如果你需要为从数据库驱动传给 drizzle 的值做运行时映射，可以使用 `.mapWith()`

这个函数接受不同的值，并在运行时映射响应。

只要 mapWith 内部的接口与 Column 所实现的接口相同，你就可以复刻某种列的映射策略。

```typescript
const usersTable = pgTable('users', {
    id: serial('id').primaryKey(),
    name: text('name').notNull(),
});

//  在运行时，这些值将按照 drizzle 中 `text` 列的映射方式进行映射
sql`...`.mapWith(usersTable.name);
```

你也可以为 `DriverValueDecoder` 接口传入自己的实现：

```ts 
sql``.mapWith({
	mapFromDriverValue: (value: any) => {
		const mappedValue = value;
		// 你想要应用的映射
		return mappedValue;
	},
});
    
// 或者
sql``.mapWith(Number);
```

## `sql``.as<T>()`

在不同情况下，有时很难确定你想使用的自定义字段该如何命名。你可能会遇到需要为将要查询的字段显式指定别名的情况。这在处理复杂查询时尤其有用。

为了应对这些场景，我们引入了一个有用的 `.as('alias_name')` 辅助方法，它允许你显式定义别名。通过使用这个特性，你可以为字段提供清晰且有意义的名称，使查询更直观、更易读。

<Section>
```typescript
sql`lower(${usersTable.name})`.as('lower_name')
```
```sql
... "users"."name" as lower_name ...
```
</Section>

## `sql.raw()`

有些情况下，你可能不需要根据输入创建参数化的值，也不需要把表/列映射为转义形式。相反，你可能只是想按原样生成查询。对于这类情况，我们提供了 `sql.raw()` 函数。

`sql.raw()` 函数允许你在查询中直接包含原始 SQL 语句，而不做任何额外处理或转义。当你已有预先构造好的 SQL 语句，或者需要把复杂或动态的 SQL 代码直接写进查询时，这会很有用。

<Section>
```typescript
sql.raw(`select * from users where id = ${12}`);
// 对比
sql`select * from users where id = ${12}`;
```
```sql
select * from users where id = 12;
--> 对比
select * from users where id = $1; --> [12]
```
</Section>

你也可以在 sql 函数内部使用 `sql.raw()`，这样就能通过主 `sql` 模板函数之外的方式包含任意原始字符串而不进行转义。

通过在 `sql` 函数内使用 `sql.raw()`，你可以把未转义的原始字符串直接合并进查询。当你有一些特定的 SQL 代码或表达式，希望它们不被模板函数的自动转义或修改所影响时，这会特别有用。

<Section>
```typescript
sql`select * from ${usersTable} where id = ${12}`;
// 对比
sql`select * from ${usersTable} where id = ${sql.raw(12)}`;
```
```sql
select * from "users" where id = $1; --> [12]
--> 对比
select * from "users" where id = 12;
```
</Section>

## sql.fromList()

`sql` 模板会生成 sql 片段（chunk），也就是 SQL 部分的数组，在 Drizzle 中把 SQL 应用到数据库或查询之后，这些部分会被拼接成查询和参数。

在某些场景下，你可能需要用自定义业务逻辑把这些片段聚合成一个数组，然后再拼接成一条可传给数据库或查询的 SQL 语句。对于这类情况，fromList 函数会非常有用。

fromList 函数允许你把多个 SQL 片段合并成一条 SQL 语句。你可以用它根据具体需求聚合和拼接各个 SQL 部分，然后得到一条可执行的统一 SQL 查询。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

	if (i === 4) continue;
	sqlChunks.push(sql` or `);
}

const finalSql: SQL = sql.fromList(sqlChunks)
```
```sql
select * from users where id = $1 or id = $2 or id = $3 or id = $4 or id = $5; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.join()

的确，`sql.join` 函数与 fromList 辅助方法的目的相似。不过，它在处理 SQL 片段之间的空格，或为拼接 SQL 片段指定自定义分隔符时，提供了额外的灵活性。

使用 `sql.join`，你可以用指定的分隔符把 SQL 片段拼接在一起。这个分隔符可以是任何你想插入到片段之间的字符串或字符。

当你对 SQL 片段的格式或分隔有特定要求时，这会特别有用。通过指定自定义分隔符，你可以在最终的 SQL 查询中实现所需的结构和格式。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql`where`);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

if (i === 4) continue;
    sqlChunks.push(sql`or`);
}

const finalSql: SQL = sql.join(sqlChunks, sql.raw(' '));
```
```sql
select * from users where id = $1 or id = $2 or id = $3 or id = $4 or id = $5; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.append()

如果你已经用 `sql` 模板生成了 SQL，你可以使用 append 函数直接向已生成的 SQL 添加新片段，从而实现与 `fromList` 相同的行为。

通过使用 append 函数，你可以动态地向现有 SQL 字符串添加额外的 SQL 片段，有效地把它们拼接在一起。这使你能够引入自定义逻辑或业务规则，把片段聚合到最终的 SQL 查询中。

<Section>
```typescript 
const finalSql = sql`select * from users`;

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = $1 or id = $2 or id = $3 or id = $4 or id = $5; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.empty()

通过使用 sql.empty()，你可以从一个空白的 SQL 对象开始，然后按需向它动态追加 SQL 片段。这使你能够逐步构造 SQL 查询，应用自定义逻辑或条件来决定每个片段的内容。

一旦你用 sql.empty() 初始化了 SQL 对象，你就可以利用 sql 模板的全部特性，例如参数化、组合和转义。这使你能够以灵活且可控的方式构造 SQL 查询，让它适配你的具体需求。

```typescript 
const finalSql = sql.empty();

// 一些逻辑

finalSql.append(sql`select * from users`);

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = $1 or id = $2 or id = $3 or id = $4 or id = $5; --> [0, 1, 2, 3, 4]
```

## 将 `sql` 转换为字符串和参数

在前面的所有示例中，你看到了在 TypeScript 中使用 SQL 模板语法以及生成的 SQL 输出。

如果你需要获取由 SQL 模板生成的查询字符串和对应参数，你必须指定打算为其生成查询的数据库方言。不同的数据库在参数化和转义方面语法各异，因此选择合适的方言至关重要。

选定方言后，你可以利用对应实现的功能，把 SQL 模板转换为所需的查询字符串和参数格式。这确保与你正在使用的具体数据库系统兼容。

<Section>
```typescript copy
import { PgDialect } from 'drizzle-orm/pg-core';

const pgDialect = new PgDialect();
pgDialect.sqlToQuery(sql`select * from ${usersTable} where ${usersTable.id} = ${12}`);
```
```sql
select * from "users" where "users"."id" = $1; --> [ 12 ]
```
</Section>

## `sql` select

你也可以在局部查询中使用 sql 功能。局部查询允许你从表中检索特定字段或列，而不是获取整行。

关于局部查询的更多详细信息，你可以参考 **[Core API 文档](/docs/select#basic-and-partial-select)**。

**从表中选择不同的自定义字段**

在这里，你可以看到 **[`sql<T>`](/docs/sql#sqlt)**、**[`sql``.mapWith()`](/docs/sql#sqlmapwith)** 和 **[`sql``.as<T>()`](/docs/sql#sqlast)** 的用法。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select({
    id: usersTable.id,
    lowerName: sql<string>`lower(${usersTable.name})`,
    aliasedName: sql<string>`lower(${usersTable.name})`.as('aliased_column'),
    count: sql<number>`count(*)`.mapWith(Number) 
}).from(usersTable)
```
```sql
select "id", lower("name"), lower("name") as "aliased_column", count(*) from "users";
```
</Section>

## `sql` 在 where 中

的确，Drizzle 提供了一组可以在 sql 模板中使用的表达式。然而，数据库通常有更广泛的可用表达式，包括通过扩展或其它方式提供的表达式。

为了确保灵活性，并让你能够使用 Drizzle 未原生支持的任何表达式，你可以自由地直接用 sql 函数编写 SQL 模板。这使你能够利用 SQL 的全部能力，并引入目标数据库特有的任何表达式或功能。

通过使用 sql 模板，你不会被限制在 Drizzle 预定义的表达式之内。相反，你可以表达复杂查询，并引入底层数据库系统提供的任何受支持的表达式。

**用 `id` 过滤，但通过 sql**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

const id = 77

await db.select()
        .from(usersTable)
        .where(sql`${usersTable.id} = ${id}`)
```
```sql
select * from "users" where "users"."id" = $1; --> [ 77 ]
```
</Section>

**高级全文搜索 where 语句**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

const searchParam = "Ale"

await db.select()
        .from(usersTable)
        .where(sql`to_tsvector('simple', ${usersTable.name}) @@ to_tsquery('simple', ${searchParam})`)
```
```sql
select * from "users" where to_tsvector('simple', "users"."name") @@ to_tsquery('simple', '$1'); --> [ "Ale" ]
```
</Section>

## `sql` 在 orderBy 中

当你需要 Drizzle 中不提供的特定排序功能，而又不想退回到原始 SQL 时，`sql` 模板确实可以在 ORDER BY 子句中使用。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select().from(usersTable).orderBy(sql`${usersTable.id} desc nulls first`)
```
```sql
select * from "users" order by "users"."id" desc nulls first;
```
</Section>

## `sql` 在 having 和 groupBy 中

当你需要 Drizzle 中不提供的特定排序功能，而又不想退回到原始 SQL 时，`sql` 模板确实可以在 HAVING 和 GROUP BY 子句中使用。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select({ 
    projectId: usersTable.projectId,
    count: sql<number>`count(${usersTable.id})`.mapWith(Number)
}).from(usersTable)
    .groupBy(sql`${usersTable.projectId}`)
    .having(sql`count(${usersTable.id}) > 300`)
```
```sql
select "project_id", count("id") from "users" group by "users"."project_id" having count("users"."id") > 300
```
</Section>
