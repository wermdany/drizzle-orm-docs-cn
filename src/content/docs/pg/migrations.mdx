# Drizzle 迁移基础

SQL 数据库要求你预先指定要存储实体的**严格 schema**，如果（当）你需要改变这些实体的形态——你就需要通过 **schema 迁移**来完成。

有多种生产级的数据库迁移管理方式。无论你采用**数据库优先**还是**代码库优先**，Drizzle 都被设计为完美适配所有这些方式。

**数据库优先**是指你的数据库 schema 是唯一可信来源（source of truth）。你可以直接在数据库上或通过数据库迁移工具管理你的数据库 schema，然后将数据库 schema 拉取到你的代码库应用层实体中。  
 
**代码库优先**是指你代码库中的数据库 schema 是唯一可信来源并处于版本控制之下。你在 JavaScript/TypeScript 中声明和管理数据库 schema，然后通过 Drizzle、直接方式或外部迁移工具将该 schema 应用到数据库本身。

#### Drizzle 能提供什么帮助？
我们构建了 [**drizzle-kit**](/docs/kit-overview) —— 用于配合 Drizzle 管理迁移的 CLI 应用。 
```shell
drizzle-kit migrate
drizzle-kit generate
drizzle-kit push
drizzle-kit pull
drizzle-kit export
```
它的设计目标是让你根据当前的业务需求来选择如何处理迁移。 

它同时适配数据库优先和代码库优先两种方式，让你可以**推送 schema**、**生成 SQL 迁移**文件，或从数据库**拉取 schema**。无论你是独自工作还是在团队中工作，它都非常合适。

<rem/>

<Tag style="font-size: 12px">**选项 1**</Tag>
> 我使用外部迁移工具或直接在数据库上运行 SQL 迁移来自行管理数据库 schema。
> 从 Drizzle 我只需要从数据库获取 schema 的当前状态，并将其保存为 TypeScript schema 文件。

<Callout collapsed="展开详情">
这是**数据库优先**的方式。你将数据库 schema 作为**唯一可信来源**，Drizzle 让你使用 [`drizzle-kit pull`](/docs/drizzle-kit-pull) 命令把数据库 schema 拉取为 TypeScript。

<Section>
```
                                  ┌────────────────────────┐      ┌─────────────────────────┐ 
                                  │                        │ <---  CREATE TABLE "users" (
┌──────────────────────────┐      │                        │        "id" SERIAL PRIMARY KEY,
│ ~ drizzle-kit pull       │      │                        │        "name" TEXT,
└─┬────────────────────────┘      │        DATABASE        │        "email" TEXT UNIQUE
  │                               │                        │       );
  └ 拉取数据库 schema ----------> │                        │
  ┌ 生成 Drizzle             <--- │                        │
  │ schema TypeScript 文件        └────────────────────────┘
  │
  v
```
```typescript
import * as p from "drizzle-orm/pg-core";

export const users = p.pgTable("users", {
  id: p.serial().primaryKey(),
  name: p.text(),
  email: p.text().unique(),
});
```
</Section>

<Tag style="font-size: 12px">**选项 2**</Tag>
> 我希望将数据库 schema 放在我的 TypeScript 代码库中， 
> 我不想处理 SQL 迁移文件。  
> 我希望 Drizzle 将我的 schema 直接“推送”到数据库

<Callout collapsed="展开详情">
这是**代码库优先**的方式。你将 TypeScript Drizzle schema 作为**唯一可信来源**，Drizzle 让你使用 [`drizzle-kit push`](/docs/drizzle-kit-push) 命令把 schema 变更推送到数据库。

这是快速原型开发的最佳方式，我们已经看到数十个团队和独立开发者成功地将它作为生产应用程序中的主要迁移流程。

<Section>
```typescript {6} filename="src/schema.ts"
import * as p from "drizzle-orm/pg-core";

export const users = p.pgTable("users", {
  id: p.serial().primaryKey(),
  name: p.text(),
  email: p.text().unique(), // <--- 新增的列
});
```
```
向 `users` 表添加列                                                                          
┌──────────────────────────┐                  
│ + email: text().unique() │                  
└─┬────────────────────────┘                  
  │                                           
  v                                           
┌──────────────────────────┐                  
│ ~ drizzle-kit push       │                  
└─┬────────────────────────┘                  
  │                                           ┌──────────────────────────┐
  └ 拉取当前数据库 schema ------------------> │                          │
                                              │                          │
  ┌ 基于差异生成变更 <----------------------- │         DATABASE         │
  │                                           │                          │
  └ 将迁移应用到数据库 ---------------------> │                          │
                                       │      └──────────────────────────┘
                                       │
  ┌────────────────────────────────────┴───────────────────────────────┐
   ALTER TABLE "users" ADD COLUMN "email" text;
   ALTER TABLE "users" ADD CONSTRAINT "users_email_key" UNIQUE("email"); 
```

<Tag style="font-size: 12px">**选项 3**</Tag>

> 我希望 Drizzle 为我生成 SQL 迁移文件并将它们应用到我的数据库

<Section>

```typescript filename="src/schema.ts"
  id: p.serial().primaryKey(),

  email: p.text().unique(),
});
```
```

│ $ drizzle-kit generate │                  
└─┬──────────────────────┘                  
  │                                           
  └ 1. 读取先前的迁移文件夹

    3. 如有必要，提示开发者进行重命名
  ┌ 4. 生成 SQL 迁移并持久化到文件
  │    ┌─┴───────────────────────────────────────┐  
  │      📂 drizzle       
  │      └ 📂 20242409125510_premium_mister_fear

  │        └ 📜 migration.sql
  v
```

<Tag style="font-size: 12px">**选项 4**</Tag>
> 我希望将数据库 schema 放在我的 TypeScript 代码库中，
> 我希望 Drizzle 为我生成 SQL 迁移文件，并且我希望 Drizzle 在运行时应用它们

<Callout collapsed="展开详情">
这是**代码库优先**的方式。你将 TypeScript Drizzle schema 作为唯一可信来源，Drizzle 让你使用 [`drizzle-kit generate`](/docs/drizzle-kit-generate) 基于你的 schema 变更生成 SQL 迁移文件，然后你可以在应用程序运行时将它们应用到数据库。

这种方式广泛用于**单体**应用，即在零停机部署期间应用数据库迁移，并在出现问题时回滚 DDL 变更。它也用于**无服务器**部署，迁移在部署过程中作为**自定义资源**运行一次。

<Section>
```typescript filename="src/schema.ts"
import * as p from "drizzle-orm/pg-core";

export const users = p.pgTable("users", {
  id: p.serial().primaryKey(),
  name: p.text(),
  email: p.text().unique(),
});
```
```                                  
┌────────────────────────┐                  
│ $ drizzle-kit generate │                  
└─┬──────────────────────┘                  
  │                                           
  └ 1. 读取先前的迁移文件夹
    2. 找出当前 schema 与先前 schema 之间的差异
    3. 如有必要，提示开发者进行重命名
  ┌ 4. 生成 SQL 迁移并持久化到文件
  │    ┌─┴───────────────────────────────────────┐  
  │      📂 drizzle       
  │      └ 📂 20242409125510_premium_mister_fear
  │        ├ 📜 snapshot.json
  │        └ 📜 migration.sql
  v
```
```sql
-- drizzle/20242409125510_premium_mister_fear/migration.sql

CREATE TABLE "users" (
 "id" SERIAL PRIMARY KEY,
 "name" TEXT,
 "email" TEXT UNIQUE
);
```
