# `drizzle-kit generate` 

<Prerequisites>
- Drizzle 与 `drizzle-kit` 入门 - [阅读文档](/docs/get-started)
- Drizzle schema 基础 - [阅读文档](/docs/sql-schema-declaration)
- 数据库连接基础 - [阅读文档](/docs/connect-overview)
- Drizzle 迁移基础 - [阅读文档](/docs/migrations)
- Drizzle Kit [概览](/docs/kit-overview) 与 [配置文件](/docs/drizzle-config-file)
</Prerequisites>


<br/>

`drizzle-kit generate` 让你可以基于 Drizzle schema 在声明时或后续 schema 变更时生成 SQL 迁移。
<Callout collapsed="底层是如何工作的？">
Drizzle Kit 的 `generate` 命令会触发一系列事件：
1. 它会读取你的 Drizzle schema 文件，并组合出 schema 的 json 快照
2. 它会读取你之前的迁移文件夹，并将当前 json 快照与最近一次的进行比对
3. 基于 json 差异，它会生成 SQL 迁移
4. 以当前时间戳为名，将 `migration.sql` 和 `snapshot.json` 保存到迁移文件夹中

<Section>
```typescript filename="src/schema.ts"
import * as p from "drizzle-orm/pg-core";

export const users = p.pgTable("users", {
  id: p.serial().primaryKey(),
  name: p.text(),
  email: p.text().unique(), 
});
```
```                                  
┌────────────────────────┐                  
│ $ drizzle-kit generate │                  
└─┬──────────────────────┘                  
  │                                           
  └ 1. read previous migration folders
    2. find diff between current and previous schema
    3. prompt developer for renames if necessary
  ┌ 4. generate SQL migration and persist to file
  │    ┌─┴───────────────────────────────────────┐  
  │      📂 drizzle       
  │      └ 📂 20242409125510_premium_mister_fear
  │        ├ 📜 migration.sql
  │        └ 📜 snapshot.json
  v
```
```sql
-- drizzle/20242409125510_premium_mister_fear/migration.sql

CREATE TABLE "users" (
 "id" SERIAL PRIMARY KEY,
 "name" TEXT,
 "email" TEXT UNIQUE
);
```
</Section>
</Callout>

它旨在覆盖管理 Drizzle 迁移的 [代码优先](/docs/migrations) 方式。
你可以使用 [`drizzle-kit migrate`](/docs/drizzle-kit-migrate)、drizzle-orm 的 `migrate()`、
像 [bytebase](https://www.bytebase.com/) 这样的外部迁移工具来应用生成的迁移，或者直接在数据库上自行运行迁移。

`drizzle-kit generate` 命令要求你同时提供 `dialect` 和 `schema` 路径选项，
你可以通过 [drizzle.config.ts](/docs/drizzle-config-file) 配置文件设置，也可以通过 CLI 选项设置
<CodeTabs items={["使用配置文件", "作为 CLI 选项"]}>
<Section>
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
});
```
```shell
npx drizzle-kit generate
```
</Section>

```shell
npx drizzle-kit generate --dialect=postgresql --schema=./src/schema.ts
```
</CodeTabs>

### schema 文件路径
你可以只有一个 `schema.ts` 文件，也可以有任意多个分散在项目中的 schema 文件。
Drizzle Kit 要求你通过 `schema` 配置选项以 [glob](https://www.digitalocean.com/community/tools/glob?comments=true&glob=/**/*.js&matches=false&tests=//%20This%20will%20match%20as%20it%20ends%20with%20'.js'&tests=/hello/world.js&tests=//%20This%20won't%20match!&tests=/test/some/globs) 的形式指定它们的路径。

### 自定义迁移文件名
你可以通过提供 `--name` CLI 选项来设置自定义迁移文件名
```shell
npx drizzle-kit generate --name=init
```
```plaintext {4}
📦 <project root>
 ├ 📂 drizzle
 │ └ 📂 20242409125510_init
 │   ├ 📜 snapshot.json
 │   └ 📜 migration.sql
 ├ 📂 src
 └ …
```

### 单个项目中的多个配置文件
你可以在项目中拥有多个配置文件，当你存在多个数据库环境、多个数据库或同一项目下的不同数据库时，这非常有用：
<Npx>
  drizzle-kit generate --config=drizzle-dev.config.ts
  drizzle-kit generate --config=drizzle-prod.config.ts
</Npx>
```plaintext {5-6}
📦 <project root>
 ├ 📂 drizzle
 ├ 📂 src
 ├ 📜 .env
 ├ 📜 drizzle-dev.config.ts
 ├ 📜 drizzle-prod.config.ts
 ├ 📜 package.json
 └ 📜 tsconfig.json
```

### 自定义迁移
你可以生成空的迁移文件，以便编写自己的自定义 SQL 迁移，
用于 Drizzle Kit 目前不支持的 DDL 变更或数据填充。关于自定义迁移的详细文档 - [请见此处](/docs/kit-custom-migrations)

```shell
drizzle-kit generate --custom --name=seed-users
```
<Section>
```plaintext {5}
📦 <project root>
 ├ 📂 drizzle
 │ ├ 📂 20242409125510_init
 │ └ 📂 20242409125510_seed-users
 ├ 📂 src
 └ …
```
```sql
-- ./drizzle/20242409125510_seed/migration.sql

INSERT INTO "users" ("name") VALUES('Dan');
INSERT INTO "users" ("name") VALUES('Andrew');
INSERT INTO "users" ("name") VALUES('Dandrew');
```
</Section>

### 忽略冲突

如果你需要让 `generate` 命令跳过可交换性检查并绕过它，可以使用 `--ignore-conflicts`。如果你遇到需要用到它的场景，
那么很有可能是 `drizzle-kit` 没有正确检查迁移，这是一个 bug。请向我们报告你的情况，以便我们修复

```shell
drizzle-kit generate --ignore-conflicts
```

### 可用配置的扩展列表
`drizzle-kit generate` 有一系列仅 CLI 可用的选项

<rem025/>

|               |                                                      |
| :--------     | :--------------------------------------------------- |
| `custom`      | 为自定义迁移生成空 SQL                               |
| `name`        | 使用自定义名称生成迁移                               |
| `ignore-conflicts` | 跳过可交换性冲突检查，默认值为 `false`         |
<rem025/>

<Npx>
drizzle-kit generate --name=init
drizzle-kit generate --name=seed_users --custom
drizzle-kit generate --ignore-conflicts
</Npx>

<br/>
我们推荐通过 [drizzle.config.ts](/docs/drizzle-config-file) 文件来配置 `drizzle-kit`，
但如果需要（例如在 CI/CD 流水线等场景中），你也可以通过 CLI 提供所有配置选项。

|               |            |                                                                            |
| :------------ | :-------   | :----------------------------------------------------------------------    |
| `dialect`     | `required` | 数据库方言，取值为 <Dialects/> 之一                                        |
| `schema`      | `required` | TypeScript schema 文件或包含多个 schema 文件的文件夹的路径                  |
| `driver`      |            | 驱动，取值为 `aws-data-api`、`pglite` 之一                                 |
| `out`         |            | 迁移输出文件夹，默认为 `./drizzle`                                          |
| `config`      |            | 配置文件路径，默认为 `drizzle.config.ts`                                    |
| `breakpoints` |            | SQL 语句断点，默认为 `true`                                                |


### 扩展示例
以下示例展示了如何创建一个名为 `0001_seed-users.sql` 的自定义 postgresql 迁移文件，
其中 Drizzle schema 位于 `./src/schema.ts`，迁移文件夹名为 `./migrations` 而非默认的 `./drizzle`。

我们还会把 drizzle 配置文件放在 `configs` 文件夹中。

让我们创建配置文件：

```plaintext {4}
📦 <project root>
 ├ 📂 migrations
 ├ 📂 configs
 │ └ 📜 drizzle.config.ts
 ├ 📂 src
 └ …
```
```ts filename='drizzle.config.ts'
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  out: "./migrations",
});
```

现在我们运行
```shell
npx drizzle-kit generate --config=./configs/drizzle.config.ts --name=seed-users --custom
```
它就会成功生成

```plaintext {6}
📦 <project root>
 ├ …
 ├ 📂 migrations
 │ ├ 📂 20242409125510_init
 │ └ 📂 20242409125510_seed-users
 └ …
```
```sql
-- ./drizzle/20242409125510_seed-users/migration.sql

INSERT INTO "users" ("name") VALUES('Dan');
INSERT INTO "users" ("name") VALUES('Andrew');
INSERT INTO "users" ("name") VALUES('Dandrew');
```
