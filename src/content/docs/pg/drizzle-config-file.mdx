Drizzle Kit 允许你在 `TypeScript` 或 `JavaScript` 配置文件中声明配置选项。

<Section>
```plaintext {5}

 ├ ...
 ├ 📂 drizzle
 ├ 📂 src
 ├ 📜 drizzle.config.ts
 └ 📜 package.json
```

<CodeTab>
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  out: "./drizzle",
});
```
</CodeTab>
<CodeTab>
```js
import { defineConfig } from "drizzle-kit";

  out: "./drizzle",
```

</CodeTab>

扩展配置文件的示例
```ts collapsable
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  out: "./drizzle",
  dialect: "postgresql",
  schema: "./src/schema.ts",

  driver: "pglite",
  dbCredentials: {
    url: "./database/",
  },

  extensionsFilters: ["postgis"],
  schemaFilter: "public",
  tablesFilter: "*",

  introspect: {
    casing: "camel",
  },

  migrations: {
    table: "__drizzle_migrations__",
    schema: "drizzle",
  },

  entities: {
    roles: {
      provider: '',
      exclude: [],
      include: []
    }
  },

  breakpoints: true,
  verbose: true,
});
```

### 多个配置文件
项目中可以有多个配置文件，当你拥有多个数据库阶段、多个数据库或同一项目下不同数据库时，这非常有用：
<Npx>
  drizzle-kit generate --config=drizzle-dev.config.ts
  drizzle-kit generate --config=drizzle-prod.config.ts
</Npx>
```plaintext {5-6}
📦 <project root>
 ├ 📂 drizzle
 ├ 📂 src
 ├ 📜 .env
 ├ 📜 drizzle-dev.config.ts
 ├ 📜 drizzle-prod.config.ts
 ├ 📜 package.json
 └ 📜 tsconfig.json
```

### 迁移文件夹
`out` 参数让你定义迁移的存放文件夹，它是可选的，默认为 `drizzle`。
这非常有用，因为你可以在同一项目中为不同数据库设置许多独立的 schema，
并为它们设置不同的迁移文件夹。
  
迁移文件夹中包含 `.sql` 迁移文件所在的文件夹，由 `drizzle-kit` 使用

<Section>
```plaintext {3}
📦 <project root>
 ├ ...
 ├ 📂 drizzle
 │ ├ 📂 20242409125510_premium_mister_fear
 │ ├ 📜 user.ts 
 │ ├ 📜 post.ts 
 │ └ 📜 comment.ts 
 ├ 📂 src
 ├ 📜 drizzle.config.ts
 └ 📜 package.json
```
```ts {6}
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema/*",
  out: "./drizzle",
});
```
</Section>

### `driver`
<rem025/>

Drizzle Kit 会根据所提供的 `dialect` 自动从你当前项目中选择可用的数据库驱动，
但某些厂商特定的数据库需要不同的连接参数子集。

`driver` 选项让你可以显式选择这些例外驱动。

|               |                      |
| :------------ | :-----------------   |
| type          | `aws-data-api`、`pglite` |
| default        | --                    |
| commands      | `push`、`migrate`、`pull`、`studio`  |

<rem025/>


<CodeTabs items={["AWS Data API", "PGLite"]}>
```ts {6}
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  driver: "aws-data-api",
  dbCredentials: {
    database: "database",
    resourceArn: "resourceArn",
    secretArn: "secretArn",
  },
});
```
```ts {6}
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  driver: "pglite",
  dbCredentials: {
    // 内存模式
    url: ":memory:"
    
    // 或数据库文件夹
    url: "./database/"
  },
});
```
</CodeTabs>

### `migrations`
<rem025/>

运行 `drizzle-kit migrate` 时 - drizzle 会在 `drizzle` schema 中名为 `__drizzle_migrations` 的日志表里
记录数据库中成功应用的迁移。

`migrations` 配置选项让你可以更改迁移日志的 `table` 名称和 `schema`。

|               |                      |
| :------------ | :-----------------   |
| type          | `{ table: string, schema: string }` |
| default       | `{ table: "__drizzle_migrations", schema: "drizzle" }`                    |
| commands      | `migrate`、`push`、`pull` |

<rem025/>

```ts
export default defineConfig({
  dialect: "postgresql",
  schema: "./src/schema.ts",
  migrations: {
    table: 'my-migrations-table', // 默认为 `__drizzle_migrations`
    schema: 'my_schema', // 默认为 `drizzle`
  },
});
```

### `tablesFilter`
<Callout>
如果你想用一个数据库运行多个项目 - 请查看[我们的指南](/docs/goodies#多项目-schema)。
</Callout>
<rem025/>
默认情况下，`drizzle-kit push` 和 `drizzle-kit pull` 会管理所有表。
你可以通过 `tablesFilters`、`schemaFilter` 和 `extensionFilters` 选项配置表、schema 和扩展的列表。

`tablesFilter` 选项让你指定基于 [`glob`](https://www.digitalocean.com/community/tools/glob?comments=true&glob=/**/*.js&matches=false&tests=//%20This%20will%20match%20as%20it%20ends%20with%20'.js'&tests=/hello/world.js&tests=//%20This%20won't%20match!&tests=/test/some/globs)
的表名过滤器，例如 `["users", "user_info"]` 或 `"user*"`

|               |                      |
| :------------ | :-----------------   |
| type          | `string` `string[]` |
| default       | --                    |
| commands      | `push` `pull`   |

<rem025/>
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  tablesFilter: ["users", "posts", "project1_*"],
});
```

### `schemaFilter`


<Callout>
如果你想用一个数据库运行多个项目 - 请查看[我们的指南](/docs/goodies#多项目-schema)。
</Callout>

默认情况下，`drizzle-kit push` 和 `drizzle-kit pull` 会管理所有 schema。

`schemaFilter` 选项让你指定基于 [`glob`](https://www.digitalocean.com/community/tools/glob?comments=true&glob=/**/*.js&matches=false&tests=//%20This%20will%20match%20as%20it%20ends%20with%20'.js'&tests=/hello/world.js&tests=//%20This%20won't%20match!&tests=/test/some/globs)
的 schema 名称过滤器，例如 `["public", "auth"]` 或 `"tenant_*"`

|               |                      |
| :------------ | :-----------------   |
| type          | `string[]` |
| commands      | `push` `pull`   |

<rem025/>

```ts
export default defineConfig({
  dialect: "postgresql",
  schemaFilter: ["public", "schema1", "schema2"],
});
```

### `extensionsFilters`
<rem025/>

某些扩展（例如 [`postgis`](https://postgis.net/)）在数据库上安装后会在 public schema 中创建自己的表。
这些表必须被 `drizzle-kit push` 或 `drizzle-kit pull` 忽略。

`extensionsFilters` 选项让你声明已安装扩展的列表，以便 drizzle kit 在 schema 中忽略它们的表。

|               |                      |
| :------------ | :-----------------   |
| type          | `["postgis"]` |
| default       | `[]`                    |
| commands      | `push` `pull`   |

<rem025/>

```ts
export default defineConfig({
  dialect: "postgresql",
  extensionsFilters: ["postgis"],
});
```

### `entities`

此配置用于设置数据库中特定 `entities` 的管理设置。

目前它仅包含 `roles`，但最终所有数据库实体都会迁移到这里，例如 `tables`、`schemas`、`extensions`、`functions`、`triggers` 等

#### `roles`

<rem025/>

如果你使用 Drizzle Kit 管理 schema，尤其是管理已定义的角色，可能会出现一些未在 Drizzle schema 中定义的角色。
在这种情况下，你可能希望 Drizzle Kit 跳过这些 `roles`，而无需在 Drizzle schema 中编写每个角色并用 `.existing()` 标记它。

`roles` 选项让你：

- 启用或禁用 Drizzle Kit 的角色管理。
- 将特定角色排除在 Drizzle Kit 的管理之外。
- 将特定角色纳入 Drizzle Kit 的管理。
- 为 `Neon` 和 `Supabase` 等不管理其特定角色的 provider 启用模式。
- 组合以上所有选项

|               |                       |
| :------------ | :-----------------    |
| type          | `boolean \| { provider: "neon" \| "supabase", include: string[], exclude: string[] }`|
| default       | `false`                  |
| commands      | `push` `pull` |

<rem025/>

默认情况下，`drizzle-kit` 不会为你管理角色，因此你需要启用它。在 `drizzle.config.ts` 中
```ts
export default defineConfig({
  dialect: "postgresql",
  entities: {
    roles: true
  }
});
```

**你有一个角色 `admin`，想将它从可管理角色列表中排除**

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      exclude: ['admin']
    }
  }
});
```

**你有一个角色 `admin`，想将它加入可管理角色列表**

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      include: ['admin']
    }
  }
});
```

**如果你使用 `Neon` 并想排除由 `Neon` 定义的角色，可以使用 provider 选项**

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      provider: 'neon'
    }
  }
});
```

**如果你使用 `Supabase` 并想排除由 `Supabase` 定义的角色，可以使用 provider 选项**

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      provider: 'supabase'
    }
  }
});
```

<Callout title='important'>
你可能会遇到 Drizzle 相比数据库 provider 新指定的角色略显过时的情况，
因此你可能需要同时使用 `provider` 选项和 `exclude` 来排除额外的角色。使用 Drizzle 可以轻松做到这一点：

```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  ...
  entities: {
    roles: {
      provider: 'supabase',
      exclude: ['new_supabase_role']
    }
  }
});
```
</Callout>

### `breakpoints`
<rem025/>

Drizzle Kit 会自动将 `--> statement-breakpoint` 嵌入到生成的 SQL 迁移文件中，
这对于不支持在一个事务中执行多个 DDL 变更语句的数据库（MySQL 和 SQLite）是必要的。

`breakpoints` 选项标志让你可以打开和关闭它

|               |                      |
| :------------ | :-----------------   |
| type          | `boolean` |
| default       | `true`                    |
| commands      | `generate` `pull`   |

<rem025/>

```ts
export default defineConfig({
  dialect: "postgresql",
  breakpoints: false,
});
```
