# 缓存

默认情况下，Drizzle 会把每个查询直接发送到你的数据库。没有隐藏操作，没有自动缓存或失效——你始终能清楚看到实际执行了什么。如果你想要缓存，必须主动启用。

默认情况下，Drizzle 使用 `explicit` 缓存策略（即 `global: false`），因此除非你主动请求，否则不会缓存任何内容。
这可以避免应用中出现意外情况或隐藏的性能陷阱。
或者，你可以开启 `all` 缓存（`global: true`），这样每次 select 都会先查询缓存。

## 快速开始

### Upstash 集成

Drizzle 开箱即用地提供了 `upstashCache()` 辅助函数。默认情况下，如果设置了环境变量，它会自动配置并使用 Upstash Redis。

```ts
import { upstashCache } from "drizzle-orm/cache/upstash";
import { drizzle } from "drizzle-orm/...";

const db = drizzle(process.env.DB_URL!, {
  cache: upstashCache({ token: process.env.UPSTASH_TOKEN, url: process.env.UPSTASH_URL }),
});
```

你也可以显式定义 Upstash 凭据、默认对所有查询启用全局缓存，或传入自定义的缓存选项：

```ts
import { upstashCache } from "drizzle-orm/cache/upstash";
import { drizzle } from "drizzle-orm/...";

const db = drizzle(process.env.DB_URL!, {
  cache: upstashCache({
    // 👇 Redis 凭据（可选——也可以从环境变量中读取）
    url: '<UPSTASH_URL>',
    token: '<UPSTASH_TOKEN>',

    // 👇 默认对所有查询启用缓存（可选）
    global: true,

    // 👇 默认缓存行为（可选）
    config: { ex: 60 }
  })
});
```

## 缓存配置参考

Drizzle 为 Upstash 支持以下缓存配置选项：

```ts
export type CacheConfig = {
  /**
   * 过期时间，以秒为单位（正整数）
   */
  ex?: number;
  /**
   * 为给定 hash key 的一个或多个字段设置过期时间（TTL 或 time to live）。
   * 用于 HEXPIRE 命令
   */
  hexOptions?: "NX" | "nx" | "XX" | "xx" | "GT" | "gt" | "LT" | "lt";
};
```

## 缓存使用示例

配置好缓存后，缓存的行为如下：

**情况 1：Drizzle 使用 `global: false`（默认，需主动启用的缓存）**

```ts
import { upstashCache } from "drizzle-orm/cache/upstash";
import { drizzle } from "drizzle-orm/...";

const db = drizzle(process.env.DB_URL!, {
  // 👇 未传入 `global: true`，默认为 false
  cache: upstashCache({ url: "", token: "" }),
});
```

在这种情况下，以下查询不会从缓存中读取

```ts
const res = await db.select().from(users);

// 任何变更操作仍会触发缓存的 onMutate 处理器
// 并尝试使所有涉及受影响表的已缓存查询失效
await db.insert(users).value({ email: "cacheman@upstash.com" });
```

要让该查询从缓存中读取，请调用 `.$withCache()`

```ts
const res = await db.select().from(users).$withCache();
```

`.$withCache` 提供了一组选项，可用于管理和配置这个特定查询的策略

```ts
// 为该特定查询重写配置
.$withCache({ config: {} })

// 为该查询指定自定义缓存键（而不是在底层对 query+params 做哈希）
.$withCache({ tag: 'custom_key' })

// 为该查询关闭自动失效
// 注意：这会导致最终一致性（下文有解释）
.$withCache({ autoInvalidate: false })
```

<Callout>
**最终一致性示例**

仅当你手动设置 `autoInvalidate: false` 时，本示例才有意义。默认情况下，`autoInvalidate` 是启用的。

在以下情况下，你可能想关闭 `autoInvalidate`：
- 你的数据不常变化，轻微的陈旧数据可以接受（例如商品列表、博客文章）
- 你手动处理缓存失效

在这些情况下，关闭它可以减少不必要的缓存失效。不过在大多数情况下，我们建议保持默认启用。

示例：假设你使用 3 秒 TTL 缓存了针对 `usersTable` 的以下查询：

``` ts
const recent = await db
  .select().from(usersTable)
  .$withCache({ config: { ex: 3 }, autoInvalidate: false });
```

如果有人执行 `db.insert(usersTable)...`，缓存不会立即失效。在最多 3 秒内，你会一直看到旧数据，直到最终达到一致。
</Callout>

**情况 2：Drizzle 使用 `global: true` 选项**

```ts
import { upstashCache } from "drizzle-orm/cache/upstash";
import { drizzle } from "drizzle-orm/...";

const db = drizzle(process.env.DB_URL!, {
  cache: upstashCache({ url: "", token: "", global: true }),
});
```

在这种情况下，以下查询会从缓存中读取

```ts
const res = await db.select().from(users);
```

如果你想为该特定查询禁用缓存，请调用 `.$withCache(false)`

```ts
// 为该查询禁用缓存
const res = await db.select().from(users).$withCache(false);
```

你也可以使用 `db` 上的 cache 实例来使特定表或标签失效

```ts
// 使所有使用 `users` 表的查询失效。你可以通过 Drizzle 实例来完成。
await db.$cache.invalidate({ tables: users });
// 或
await db.$cache.invalidate({ tables: [users, posts] });

// 使所有使用 `usersTable` 的查询失效。你可以仅使用表名来完成。
await db.$cache.invalidate({ tables: "usersTable" });
// 或
await db.$cache.invalidate({ tables: ["usersTable", "postsTable"] });

// 你也可以让之前执行过的所有 select 查询中定义的自定义标签失效。
await db.$cache.invalidate({ tags: "custom_key" });
// 或
await db.$cache.invalidate({ tags: ["custom_key", "custom_key1"] });
```

## 自定义缓存

本示例展示了如何在 Drizzle 中接入自定义 `cache`：你提供从缓存获取数据、把结果存回缓存，以及在每次变更操作运行时使条目失效的函数。

缓存扩展提供了这组配置选项
```ts
export type CacheConfig = {
  /** 过期时间，以秒为单位 */
  ex?: number;
  /** 过期时间，以毫秒为单位 */
  px?: number;
  /** key 过期时的 Unix 时间（秒） */
  exat?: number;
  /** key 过期时的 Unix 时间（毫秒） */
  pxat?: number;
  /** 更新 key 时保留现有的 TTL */
  keepTtl?: boolean;
  /** HEXPIRE（hash 字段 TTL）的选项 */
  hexOptions?: 'NX' | 'XX' | 'GT' | 'LT' | 'nx' | 'xx' | 'gt' | 'lt';
};
```

```ts
const db = drizzle(process.env.DB_URL!, { cache: new TestGlobalCache() });
```

```ts
import Keyv from "keyv";

export class TestGlobalCache extends Cache {
  private globalTtl: number = 1000;
  // 该对象用于存储某个特定表使用了哪些查询键，
  // 以便之后用于失效处理。
  private usedTablesPerKey: Record<string, string[]> = {};

  constructor(private kv: Keyv = new Keyv()) {
    super();
  }

  // 对于策略，我们有两个选项：
  // - 'explicit'：仅当查询上添加了 .$withCache() 时才使用缓存。
  // - 'all'：所有查询都进行全局缓存。
  // 默认行为是 'explicit'。
  override strategy(): "explicit" | "all" {
    return "all";
  }

  // 该函数接收已缓存为 key 参数的查询与参数，
  // 让你可以从缓存中获取该查询的响应值。
  override async get(key: string): Promise<any[] | undefined> {
    const res = (await this.kv.get(key)) ?? undefined;
    return res;
  }

  // 该函数接收若干选项，用于定义缓存数据将如何存储：
  // - 'key'：经过哈希的查询和参数。
  // - 'response'：Drizzle 从数据库返回的值数组。
  // - 'tables'：select 查询涉及的表的数组。缓存失效需要此信息。
  // - 'isTag'：一个布尔标志，表示该缓存条目是否代表基于标签的查询。
  //    为 true 时，该条目关联的是特定标签而非表级失效，
  //    从而允许你按标签名使缓存的查询失效。参见 UpstashCache：
  //    https://github.com/drizzle-team/drizzle-orm/blob/beta/drizzle-orm/src/cache/upstash/cache.ts 以了解示例
  //
  // 例如，如果某个查询使用了 "users" 和 "posts" 表，你可以存储该信息。之后当应用对这些表
  // 执行任何变更语句时，就可以从缓存中移除对应的键。
  // 如果你可以接受查询的最终一致性，可以跳过此选项。
  override async put(
    key: string,
    response: any,
    tables: string[],
    isTag: boolean = false,
    config?: CacheConfig,
  ): Promise<void> {
    const ttl = config?.px ?? (config?.ex ? config.ex * 1000 : this.globalTtl);

    await this.kv.set(key, response, ttl);

    for (const table of tables) {
      const keys = this.usedTablesPerKey[table];
      if (keys === undefined) {
        this.usedTablesPerKey[table] = [key];
      } else {
        keys.push(key);
      }
    }
  }

  // 当执行 insert、update 或 delete 语句时会调用该函数。
  // 你可以跳过这一步，也可以使使用了受影响表的查询失效。
  //
  // 该函数接收一个包含两个键的对象：
  // - 'tags'：用于带特定标签的查询，允许你按该标签进行失效。
  // - 'tables'：insert、update 或 delete 语句实际影响的表，
  //   帮助你追踪自上次缓存更新以来哪些表发生了变化。
  override async onMutate(params: {
    tags: string | string[];
    tables: string | string[] | Table<any> | Table<any>[];
  }): Promise<void> {
    const tagsArray = params.tags
      ? Array.isArray(params.tags)
        ? params.tags
        : [params.tags]
      : [];
    const tablesArray = params.tables
      ? Array.isArray(params.tables)
        ? params.tables
        : [params.tables]
      : [];

    const keysToDelete = new Set<string>();

    for (const table of tablesArray) {
      const tableName = is(table, Table)
        ? getTableName(table)
        : (table as string);
      const keys = this.usedTablesPerKey[tableName] ?? [];
      for (const key of keys) keysToDelete.add(key);
    }

    if (keysToDelete.size > 0 || tagsArray.length > 0) {
      for (const tag of tagsArray) {
        await this.kv.delete(tag);
      }

      for (const key of keysToDelete) {
        await this.kv.delete(key);
        for (const table of tablesArray) {
          const tableName = is(table, Table)
            ? getTableName(table)
            : (table as string);
          this.usedTablesPerKey[tableName] = [];
        }
      }
    }
  }
}
```

## 限制

#### 不会被 `cache` 扩展处理的查询：

- 对原始查询使用缓存，例如：

```ts
db.execute(sql`select 1`);
```

```
- 在事务中使用缓存
```ts
await db.transaction(async (tx) => {
  await tx.update(accounts).set(...).where(...);
  await tx.update...
});
```

#### 暂时存在、很快会被处理的限制：

- 对 Drizzle 关系查询使用缓存
```ts
await db.query.users.findMany();
```

- 对 AWS Data API 驱动使用缓存
- 对视图使用缓存
