# Drizzle schema

Drizzle 让你可以在 TypeScript 中使用底层数据库支持的各种模型和属性来定义 schema。
当你定义 schema 时，它将成为后续查询修改（使用 Drizzle-ORM）
和迁移（使用 Drizzle-Kit）的唯一可信来源。

<Callout> 
如果你使用 Drizzle-Kit 进行迁移流程，请确保导出 schema 文件中定义的所有模型，以便 Drizzle-Kit 可以导入它们并在迁移差异（diff）流程中使用。 
</Callout>

<CodeTabs items={["使用导入", "使用回调", "使用 import *"]}>
```ts
import { int, mssqlTable, varchar } from "drizzle-orm/mssql-core";

export const usersTable = mssqlTable("users", {
  id: int().primaryKey().identity(),
  name: varchar({ length: 256 }).notNull(),
  age: int().notNull(),
  email: varchar({ length: 256 }).notNull().unique(),
});
```
```ts
import { mssqlTable } from "drizzle-orm/mssql-core";

export const usersTable = mssqlTable("users", (t) => ({
  id: t.int().primaryKey().identity(),
  name: t.varchar({ length: 256 }).notNull(),
  age: t.int().notNull(),
  email: t.varchar({ length: 256 }).notNull().unique(),
}));
```
```ts
import * as t from "drizzle-orm/mssql-core";

export const usersTable = t.mssqlTable("users", {
  id: t.int().primaryKey().identity(),
  name: t.varchar({ length: 256 }).notNull(),
  age: t.int().notNull(),
  email: t.varchar({ length: 256 }).notNull().unique(),
});
```
</CodeTabs>

## 组织你的 schema 文件 
你可以直接在 TypeScript 中声明 SQL schema，既可以放在单个 `schema.ts` 文件中，
也可以把它们分散开 —— 随你喜欢，完全自由！

#### 单文件中的 schema
使用 Drizzle 声明 schema 最常见的方式是把所有表放到一个 `schema.ts` 文件中。

> 注意：你可以随意命名 schema 文件。例如，它可以叫 `models.ts`，或其它名字。

如果你定义的表模型不太多，或者你不介意把它们都放在一个文件里，这种方式就很适用

示例：
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📜 schema.ts
```

在 `drizzle.config.ts` 文件中，你需要指定 schema 文件的路径。使用此配置，Drizzle 将
从 `schema.ts` 文件读取，并在迁移生成过程中使用这些信息。关于 `drizzle.config.ts` 文件
以及使用 Drizzle 进行迁移的更多信息，请查看：[link](/docs/mssql/drizzle-config-file)
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'mssql',
  schema: './src/db/schema.ts'
})
```

#### 多文件中的 schema

你可以把 Drizzle 模型（例如表、枚举、序列等）不仅放在一个文件中，也可以放在任何你喜欢的文件中。
你唯一需要确保的是，从这些文件中导出所有模型，以便 Drizzle kit 可以导入
它们并在迁移中使用。

一个使用场景是将每张表分离到各自的文件中。
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 countries.ts
          ├ 📜 cities.ts
          ├ 📜 products.ts
          ├ 📜 clients.ts
          └ 📜 etc.ts
```

在 `drizzle.config.ts` 文件中，你需要指定 schema 文件夹的路径。使用此配置，Drizzle 将
从 `schema` 文件夹读取，递归地查找所有文件，并从中获取所有 drizzle 表。关于 `drizzle.config.ts`
文件以及使用 Drizzle 进行迁移的更多信息，请查看：[link](/docs/mssql/drizzle-config-file)

```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'mssql',
  schema: './src/db/schema'
})
```

你也可以按任何你喜欢的方式对它们进行分组，例如为用户相关的表、消息相关的表、产品相关的表等创建分组。
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 messaging.ts
          └ 📜 products.ts
```

## 构建你的数据 schema

Drizzle schema 由你正在使用的数据库的若干模型类型组成。使用 drizzle 你可以指定：
- 带有列、约束等的表
- Schema
- 视图
- 等等。

让我们逐一查看应该如何用 drizzle 定义 schema

#### **表和列的声明** 

在 Drizzle 中，一张表至少要用 1 个列来定义，这与数据库中应做的相同。有一点很重要：
Drizzle 中没有通用表对象这种概念。你需要选择 MSSQL 表对象。

![](@/assets/images/table-structure.svg)

```ts copy
import { mssqlTable, int } from "drizzle-orm/mssql-core"

export const users = mssqlTable('users', {
  id: int()
});
```

默认情况下，Drizzle 在数据库查询中会使用 TypeScript 的键名作为列名。
因此，示例中的 schema 和查询会生成如下所示的 SQL 查询

<Callout>
本示例使用了一个 db 对象，其初始化不在本文档的这一部分中介绍。要了解如何连接数据库，请参阅 [连接文档](/docs/mssql/get-started-mssql)
</Callout>

\
**TypeScript 键 = 数据库键**
<Section>
```ts
// schema.ts
import { int, mssqlTable, varchar } from "drizzle-orm/mssql-core";

export const users = mssqlTable('users', {
  id: int(),
  first_name: varchar({ length: 256 })
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT [id], [first_name] FROM [users];
```
</Section>

如果你想在 TypeScript 代码和数据库中使用不同的名称，可以使用列别名

<Section>
```ts
// schema.ts
import { int, mssqlTable, varchar } from "drizzle-orm/mssql-core";

export const users = mssqlTable('users', {
  id: int(),
  firstName: varchar('first_name', { length: 256 })
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT [id], [first_name] FROM [users];
```
</Section>

### 驼峰与蛇形命名

数据库模型名称常使用 `snake_case` 约定，而在 TypeScript 中，命名模型通常使用 `camelCase`。
这可能导致 schema 中出现大量别名定义。为解决这一问题，Drizzle 提供了一种通过专用构建器
自动将 TypeScript 中的 `camelCase` 映射到数据库中的 `snake_case` 的方式。

使用 `drizzle-orm/mssql-core` 中的 `snakeCase` 或 `camelCase` 构建器来声明一张表，其列键
会自动映射到所选的数据库命名约定

<Section>
```ts {2,4,11,12}
// schema.ts
import { snakeCase, camelCase } from 'drizzle-orm/mssql-core';

export const users = snakeCase.table('users', {
  id: int().primaryKey(),
  fullName: text(), // → 数据库中的 full_name
  createdAt: datetime2(), // → 数据库中的 created_at
});

// 可用于所有实体类型：
snakeCase.table / snakeCase.view / snakeCase.schema
camelCase.table / camelCase.view / camelCase.schema
```
```ts
// db.ts
import { drizzle } from "drizzle-orm/node-mssql";

const db = drizzle({ connection: process.env.DATABASE_URL })
```
```ts
// query.ts
await db.select().from(users);
```
```sql
select [id], [full_name], [created_at] from [users]
```
</Section>

### 进阶

有一些技巧可以在 Drizzle ORM 中使用。只要 Drizzle 完全由 TypeScript 文件构成，
你基本上可以做任何在简单 TypeScript 项目中会做的事情。

一个常见的特性是把列分离到不同的地方然后复用它们。
例如，考虑 `updated_at`、`created_at` 和 `deleted_at` 这三列。许多表/模型都可能需要
这三个字段来追踪和分析系统中实体的创建、删除和更新

我们可以把这些列定义在单独的文件中，然后导入并将它们展开到你所拥有的所有表对象中

<Section>
```ts
// columns.helpers.ts
export const timestamps = {
  updated_at: datetime2(),
  created_at: datetime2()..defaultGetDate().notNull(),
  deleted_at: datetime2(),
}
```
```ts
// users.sql.ts
export const users = mssqlTable('users', {
  id: int(),
  ...timestamps
})
```
```ts
// posts.sql.ts
export const posts = mssqlTable('posts', {
  id: int(),
  ...timestamps
})
```
</Section>

#### **schema**

\
在 MSSQL 中，有一个称为 `schema` 的实体（我们认为它应该叫 `folders`）。它在 MSSQL 中创建了一种结构：

![](@/assets/images/postgresql-db-structure.png)

你可以使用 `mssqlSchema` 管理你的 PostgreSQL schema，并把任何其它模型放在其中。

使用 Drizzle 定义你想要管理的 schema
```ts
import { mssqlSchema } from "drizzle-orm/mssql-core"

export const customSchema = mssqlSchema('custom');
```

然后把表放到 schema 对象内部
```ts {5-7}
import { int, mssqlSchema } from "drizzle-orm/mssql-core";

export const customSchema = mssqlSchema('custom');

export const users = customSchema.table('users', {
  id: int()
})
```

### 示例

了解了基础知识后，让我们为一个真实项目定义一个 schema 示例，以获得更好的视角和理解

> 所有示例都将使用 `generateUniqueString`。它的实现将在所有 schema 示例之后提供

```ts copy
import type { AnyMsSqlColumn } from "drizzle-orm/mssql-core";
import { mssqlTable as table } from "drizzle-orm/mssql-core";
import * as t from "drizzle-orm/mssql-core";

export const users = table(
  "users",
  {
    id: t.int().primaryKey().identity(),
    firstName: t.varchar("first_name", { length: 256 }),
    lastName: t.varchar("last_name", { length: 256 }),
    email: t.varchar({ length: 256 }).notNull(),
    invitee: t.int().references((): AnyMsSqlColumn => users.id),
    role: t.varchar({ length: 20, enum: ["guest", "admin", "user"] }).default("guest"),
  },
  (table) => [
    t.uniqueIndex("email_idx").on(table.email)
  ]
);

export const posts = table(
  "posts",
  {
    id: t.int().primaryKey().identity(),
    slug: t.varchar({ length: 256 }).$default(() => generateUniqueString(16)),
    title: t.varchar({ length: 256 }),
    ownerId: t.int("owner_id").references(() => users.id),
  },
  (table) => [
    t.uniqueIndex("slug_idx").on(table.slug),
    t.index("title_idx").on(table.title),
  ]
);

export const comments = table("comments", {
  id: t.int().primaryKey().identity(),
  text: t.varchar({ length: 256 }),
  postId: t.int("post_id").references(() => posts.id),
  ownerId: t.int("owner_id").references(() => users.id),
});
```

**`generateUniqueString` 实现：**
```ts
function generateUniqueString(length: number = 12): string {
  const characters =
    "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789";
  let uniqueString = "";

  for (let i = 0; i < length; i++) {
    const randomIndex = Math.floor(Math.random() * characters.length);
    uniqueString += characters[randomIndex];
  }

  return uniqueString;
}
```
