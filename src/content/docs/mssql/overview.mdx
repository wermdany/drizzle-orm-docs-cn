# Drizzle ORM

Drizzle ORM 是一个有头的无头 TypeScript ORM。🐲
> Drizzle 是一位好朋友，在你需要时陪伴你，在你需要空间时也不打扰你。

它看起来、用起来都很简单，在你项目的第 _1000_ 天依然表现良好，\
让你按自己的方式做事，并在你需要时随时待命。

**它是唯一同时提供 [关系式](/docs/mssql/rqb) 和 [类 SQL](/docs/mssql/select) 查询 API 的 ORM**，
在访问关系型数据时为你提供两全其美的方案。
Drizzle 轻量、高性能、类型安全、不含乳糖、无麸质、清醒、灵活，并且**在设计上就为无服务器做好了准备**。
Drizzle 不只是一个库，它是一种体验。🤩

[![Drizzle bestofjs](@/assets/images/bestofjs.jpg)](https://bestofjs.org/projects/drizzle-orm)

## 无头 ORM？ 
首先，Drizzle 是一个库，以及一组互补的可选工具。

**ORM** 代表 _对象关系映射_，开发者往往会把类 Django 或类 Spring 的工具称为 ORM。
我们真的认为这是基于旧式命名法的误解，我们称它们为**数据框架**。

<Callout type="error" emoji="️💔">
  使用数据框架时，你必须**围绕它们**构建项目，而不是**用它们**构建项目。
</Callout>

**Drizzle** 让你按自己想要的方式构建项目，不会干扰你的项目或结构。

使用 Drizzle，你可以用 TypeScript 定义并管理数据库 schema，以类 SQL
或关系式的方式访问数据，并利用可选工具
把你的开发体验推向 _巅峰_。🤯 

## 为什么是类 SQL 的？
**如果你懂 SQL，你就懂 Drizzle。**

其它 ORM 和数据框架往往会偏离/抽象掉 SQL，这
导致双重的学习曲线：既要了解 SQL，又要了解框架的 API。  

Drizzle 恰恰相反。
我们拥抱 SQL，并将 Drizzle 构建为在核心上就是类 SQL 的，因此你可以拥有零到几乎没有的
学习曲线，并获得 SQL 的全部能力。  

我们带来了所有熟悉的 **[SQL schema](/docs/mssql/sql-schema-declaration)**、**[查询](/docs/mssql/select)**、
**[自动迁移](/docs/mssql/migrations)** 以及 **[还有一件事](/docs/mssql/rqb)**。✨

<CodeTabs items={["index.ts", "schema.ts", "migration.sql"]}>
```typescript copy
// 访问你的数据
await db
	.select()
	.from(countries)
	.leftJoin(cities, eq(cities.countryId, countries.id))
	.where(eq(countries.id, 10))
```
```typescript copy
// 管理你的 schema
export const countries = mssqlTable('countries', {
  id: int().primaryKey().identity(),
  name: varchar({ length: 256 }),
});

export const cities = mssqlTable('cities', {
  id: int().primaryKey().identity(),
  name: varchar({ length: 256 }),
  countryId: int('country_id').references(() => countries.id),
});
```
```sql
CREATE TABLE [countries] (
	[id] int IDENTITY(1, 1),
	[name] varchar(256),
	CONSTRAINT [countries_pkey] PRIMARY KEY([id])
);

CREATE TABLE [cities] (
	[id] int IDENTITY(1, 1),
	[name] varchar(256),
	[country_id] int,
	CONSTRAINT [cities_pkey] PRIMARY KEY([id])
);

ALTER TABLE [cities] ADD CONSTRAINT [cities_country_id_countries_id_fk] FOREIGN KEY ([country_id]) REFERENCES [countries]([id]);
```
</CodeTabs>

## 为什么不是类 SQL 的？
我们始终在追求完美平衡的解决方案，虽然类 SQL 覆盖了 100% 的需求，
但在某些常见场景中，你可以用更好的方式查询数据。  

我们为你构建了 **[Queries API](/docs/mssql/rqb)**，让你能够以最便捷、最高性能的方式
从数据库中获取关系式嵌套数据，而不必再操心连接和数据映射。  

**Drizzle 始终只输出恰好 1 条 SQL 查询。** 尽可在无服务器数据库中使用它，永远不必担心性能或往返开销！

```ts
const result = await db._query.users.findMany({
	with: {
		posts: true
	},
});
```

## 无服务器？
<Callout type="info" emoji="🥳">
  最好的部分就是没有部分。**Drizzle 恰好有 0 个依赖！**
</Callout>


![Drizzle 轻量且为无服务器做好准备](@/assets/images/drizzle31kb.jpg)
  
Drizzle ORM 是方言特定的、轻量的、高性能的，并且**在设计上**为无服务器做好了准备。  

我们花了大量时间来确保你拥有同类最佳的 SQL 方言支持，包括 Postgres、MySQL 等。

Drizzle 通过行业标准的数据库驱动原生运行。我们支持所有主流的 **[PostgreSQL](/docs/get-started-postgresql)**、**[MySQL](/docs/mysql/get-started-mysql)**、**[SQLite](/docs/sqlite/get-started-sqlite)**、**[SingleStore](/docs/singlestore/get-started-singlestore)**、**[MSSQL](/docs/mssql/get-started-mssql)** 或 **[CockroachDB](/docs/cockroach/get-started-cockroach)** 驱动，并且我们正在**[非常快地](https://twitter.com/DrizzleORM/status/1653082492742647811?s=20)**添加新的驱动。
