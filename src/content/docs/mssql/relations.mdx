### 一对一
Drizzle ORM 为你提供了一个 API，可以通过 `relations` 操作符定义表之间的 `one-to-one` 关系。

下面是一个 users 与 users 之间 `one-to-one` 关系的示例，其中一个用户可以邀请另一个用户（此示例使用了自引用）：

```typescript copy {10-15}
import { mssqlTable, ntext, int } from 'drizzle-orm/mssql-core';
import { relations } from 'drizzle-orm/_relations';

export const users = mssqlTable('users', {
	id: int().identity().primaryKey(),
	name: ntext(),
	invitedBy: int('invited_by'),
});

export const usersRelations = relations(users, ({ one }) => ({
	invitee: one(users, {
		fields: [users.invitedBy],
		references: [users.id],
	}),
}));
```

另一个示例是用户拥有存储在一个单独表中的档案信息。在这种情况下，因为外键存储在 "profile_info" 表中，该 user 关系既没有 fields 也没有 references。这告诉 TypeScript `user.profileInfo` 是可空的：

```typescript copy {9-17}
import { mssqlTable, ntext, int } from 'drizzle-orm/mssql-core';
import { relations } from 'drizzle-orm/_relations';

export const users = mssqlTable('users', {
	id: int().identity().primaryKey(),
	name: ntext(),
});

export const usersRelations = relations(users, ({ one }) => ({
	profileInfo: one(profileInfo),
}));

export const profileInfo = mssqlTable('profile_info', {
	id: int().identity().primaryKey(),
	userId: int('user_id').references(() => users.id),
	metadata: ntext(),
});

export const profileInfoRelations = relations(profileInfo, ({ one }) => ({
	user: one(users, { fields: [profileInfo.userId], references: [users.id] }),
}));

const user = await queryUserWithProfileInfo();
//____^? type { id: number, profileInfo: string | null  }
```

### 一对多
Drizzle ORM 为你提供了一个 API，可以通过 `relations` 操作符定义表之间的 `one-to-many` 关系。

下面是 users 与它们所写的 posts 之间 `one-to-many` 关系的示例：

```typescript copy {9-11, 19-24}
import { mssqlTable, ntext, int } from 'drizzle-orm/mssql-core';
import { relations } from 'drizzle-orm/_relations';

export const users = mssqlTable('users', {
	id: int().identity().primaryKey(),
	name: ntext(),
});

export const usersRelations = relations(users, ({ many }) => ({
	posts: many(posts),
}));

export const posts = mssqlTable('posts', {
	id: int().identity().primaryKey(),
	content: ntext(),
	authorId: int('author_id'),
});

export const postsRelations = relations(posts, ({ one }) => ({
	author: one(users, {
		fields: [posts.authorId],
		references: [users.id],
	}),
}));
```

### 多对多
Drizzle ORM 为你提供了一个 API，可以通过所谓的 `junction` 或 `join` 表来定义表之间的 `many-to-many` 关系，
它们必须被显式定义，并存储相关表之间的关联。
  
下面是 users 与 groups 之间 `many-to-many` 关系的示例：
```typescript copy {9-11, 18-20, 37-46}
import { relations } from 'drizzle-orm/_relations';
import { int, mssqlTable, primaryKey, ntext } from 'drizzle-orm/mssql-core';

export const users = mssqlTable('users', {
  id: int().identity().primaryKey(),
  name: ntext(),
});

export const usersRelations = relations(users, ({ many }) => ({
  usersToGroups: many(usersToGroups),
}));

export const groups = mssqlTable('groups', {
  id: int().identity().primaryKey(),
  name: ntext(),
});

export const groupsRelations = relations(groups, ({ many }) => ({
  usersToGroups: many(usersToGroups),
}));

export const usersToGroups = mssqlTable(
  'users_to_groups',
  {
    userId: int('user_id')
      .notNull()
      .references(() => users.id),
    groupId: int('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [
		primaryKey({ columns: [t.userId, t.groupId] })
	],
);

export const usersToGroupsRelations = relations(usersToGroups, ({ one }) => ({
  group: one(groups, {
    fields: [usersToGroups.groupId],
    references: [groups.id],
  }),
  user: one(users, {
    fields: [usersToGroups.userId],
    references: [users.id],
  }),
}));
```

### 外键

你可能已经注意到 `relations` 看起来与外键很相似——它们甚至都有 `references` 属性。那么区别是什么呢？

虽然外键有着类似的目的，即定义表之间的关系，但它们与 `relations` 运作在不同的层面上。

外键是数据库层面的约束，它们会在每次 `insert`/`update`/`delete` 操作时被检查，如果违反约束就会抛出错误。
另一方面，`relations` 是更高层的抽象，它们仅用于在应用层面定义表之间的关系。
它们不会以任何方式影响数据库 schema，也不会隐式创建外键。

这意味着 `relations` 和外键可以一起使用，但它们彼此并不依赖。
你可以在不使用外键的情况下定义 `relations`（反之亦然），这让它们可以用于不支持外键的数据库。

下面两个示例在使用 Drizzle 关系式查询数据方面，效果完全相同。

### 外键操作

更多信息请查看 [MSSQL 外键文档](https://learn.microsoft.com/en-us/sql/relational-databases/tables/create-foreign-key-relationships?view=sql-server-ver17)

你可以指定当父表中的被引用数据被修改时应该发生的动作。这些动作被称为“外键动作”。MSSQL 为这些动作提供了若干选项。

关于删除/更新动作

- `CASCADE`：当父表中的一行被删除时，子表中所有对应的行也会被删除。这确保子表中不存在孤儿行。

- `NO ACTION`：这是默认动作。如果子表中存在相关的行，它会阻止删除父表中的行。父表中的 DELETE 操作将失败。

- `SET DEFAULT`：如果父表中的一行被删除，子表中的外键列将被设置为它的默认值（如果有的话）。如果没有默认值，DELETE 操作将失败。

- `SET NULL`：当父表中的一行被删除时，子表中的外键列将被设置为 NULL。此动作假定子表中的外键列允许 NULL 值。

> 与 ON DELETE 类似，还有 ON UPDATE，它在被引用的列发生变化（更新）时被调用。可能的动作相同，只是 SET NULL 和 SET DEFAULT 不能指定列的列表。在这种情况下，CASCADE 意味着被引用列的更新值应该被复制到引用它的行中。
在 drizzle 中，你可以使用 `references()` 的第二个参数来添加外键动作。

动作的类型

```typescript
export type UpdateDeleteAction = 'cascade' | 'no action' | 'set null' | 'set default';

// references 接口的第二个参数
actions?: {
		onUpdate?: UpdateDeleteAction;
		onDelete?: UpdateDeleteAction;
	} | undefined
```

在下面的示例中，为 `posts` schema 上的 author 字段添加 `onDelete: 'cascade'`，意味着删除 `user` 也会删除所有相关的 Post 记录。


```typescript {11}
import { mssqlTable, ntext, int } from 'drizzle-orm/mssql-core';

export const users = mssqlTable('users', {
	id: int().identity().primaryKey(),
	name: ntext(),
});

export const posts = mssqlTable('posts', {
	id: int().identity().primaryKey(),
	name: ntext(),
	author: int().references(() => users.id, {onDelete: 'cascade'}).notNull(),
});
```

对于使用 `foreignKey` 操作符指定的约束，外键动作通过以下语法定义：

```typescript {18-19}
import { foreignKey, mssqlTable, ntext, int } from 'drizzle-orm/mssql-core';

export const users = mssqlTable('users', {
	id: int().identity().primaryKey(),
	name: ntext(),
});

export const posts = mssqlTable('posts', {
	id: int().identity().primaryKey(),
	name: ntext(),
	author: int().notNull(),
}, (table) => [
	foreignKey({
		name: "author_fk",
		columns: [table.author],
		foreignColumns: [users.id],
	})
		.onDelete('cascade')
		.onUpdate('cascade')
]);
```

### 消除关系歧义

Drizzle 还提供了 `relationName` 选项，用于在你于同两个表之间定义多个关系时
消除关系歧义。例如，如果你定义了一个 `posts` 表，它同时有 `author` 和 `reviewer`
关系。

```ts {9-12, 21-32}
import { mssqlTable, ntext, int } from 'drizzle-orm/mssql-core';
import { relations } from 'drizzle-orm/_relations';
 
export const users = mssqlTable('users', {
	id: int().identity().primaryKey(),
	name: ntext(),
});
 
export const usersRelations = relations(users, ({ many }) => ({
	author: many(posts, { relationName: 'author' }),
	reviewer: many(posts, { relationName: 'reviewer' }),
}));
 
export const posts = mssqlTable('posts', {
	id: int().identity().primaryKey(),
	content: ntext(),
	authorId: int('author_id'),
	reviewerId: int('reviewer_id'),
});
 
export const postsRelations = relations(posts, ({ one }) => ({
	author: one(users, {
		fields: [posts.authorId],
		references: [users.id],
		relationName: 'author',
	}),
	reviewer: one(users, {
		fields: [posts.reviewerId],
		references: [users.id],
		relationName: 'reviewer',
	}),
}));
```
