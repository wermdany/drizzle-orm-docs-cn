# 神奇的 `sql` 操作符 🪄

在使用 ORM 库时，有时你可能会发现用所提供的 ORM 语法编写某个特定
查询很有挑战性。在这种情况下，你可以求助于原始查询，
即把查询构造成一个原始字符串。然而，原始查询往往
缺乏类型安全和查询参数化带来的好处。

为解决这个问题，许多库引入了 `sql` 模板的概念。该模板
让你可以编写更加类型安全、带参数化的查询，增强代码的整体安全性和
灵活性。Drizzle 作为强大的 ORM 库，也支持 sql 模板。

使用 Drizzle 的 `sql` 模板，你可以在编写查询时走得更远。如果你在用库的
查询构建器编写整个查询时遇到困难，可以在 Drizzle 查询的特定部分中
选择性地使用 `sql` 模板。这种灵活性使你能够在部分 SELECT 语句、WHERE 子句、ORDER BY 子句、
HAVING 子句、GROUP BY 子句，甚至关系查询构建器中使用 sql 模板。

通过利用 Drizzle 中 sql 模板的能力，你可以在保持类型安全和查询参数化优势的同时，
实现所需的查询结构和复杂度。
这使你能够在应用中创建更健壮、更易维护的代码。

## sql`` 模板

你在其它 ORM 中可能遇到的最常见用法之一，
就是能够将 `sql` 查询原样用作原始查询。

```typescript copy
import { sql } from 'drizzle-orm' 

const id = 69;
await db.execute(sql`select * from ${usersTable} where ${usersTable.id} = ${id}`)
```

它将生成以下查询

```sql
select * from [users] where [users].[id] = @par0 -- params: [69]
```

提供给 sql 参数的任何表和列都会自动映射到对应的 SQL
语法，其中表名会被转义，且转义后的表名会被附加到列名前面。

此外，任何像 `${id}` 这样的动态参数都会被映射到 @par0 占位符，
对应的值会被移动到一个单独传递给数据库的值数组中。

这种方式有效地防止了任何潜在的 SQL 注入漏洞。

## `sql<T>`

<Callout type="info" emoji="ℹ️">
    请注意，`sql<T>` 不执行任何运行时映射。你用 `sql<T>` 定义的类型
    纯粹是给 Drizzle 的辅助信息。重要的是要理解，
    由于 SQL 查询可以高度多样且可定制，动态确定精确类型是不可行的。 
</Callout>

你可以在 Drizzle 中定义自定义类型，用于那些字段需要特定类型（而非 `unknown`）的地方。

此特性在部分查询中特别有用，可确保所选字段的类型一致：

```typescript
// 未定义 sql<T> 类型
const response: { lowerName: unknown }[] = await db.select({
    lowerName: sql`lower(${usersTable.id})`
}).from(usersTable);

// 定义了 sql<T> 类型
const response: { lowerName: string }[] = await db.select({
    lowerName: sql<string>`lower(${usersTable.id})`
}).from(usersTable);
```

## `sql``.mapWith()`

如果你需要为从数据库驱动传递到 drizzle 的值做运行时映射，可以使用 `.mapWith()`

此函数接受不同的值，将在运行时映射响应。

只要 mapWith 内部的接口与 Column 所实现的接口相同，
你就可以复现特定的列映射策略。

```typescript
import { mssqlTable, int, text } from 'drizzle-orm/mssql-core';

const usersTable = mssqlTable('users', {
    id: int().primaryKey().identity(),
    name: text().notNull(),
});

//  在运行时，这些值将按照 drizzle 中 `text` 列的映射方式进行映射
sql`...`.mapWith(usersTable.name);
```

你也可以为 `DriverValueDecoder` 接口传入自己的实现：

```ts 
sql``.mapWith({
	mapFromDriverValue: (value: any) => {
		const mappedValue = value;
		// 你想应用的映射
		return mappedValue;
	},
});
    
// 或
sql``.mapWith(Number);
```

## `sql``.as<T>()`

在不同情况下，确定如何命名你想使用的自定义字段有时会很有挑战性。
你可能会遇到需要为将被选中的字段显式指定别名的情况。
这在处理复杂查询时尤其有用。

为应对这些场景，我们引入了一个有用的 `.as('alias_name')` 辅助方法，它允许
你显式定义别名。通过使用此特性，你可以为字段提供清晰且有意义的
名称，使你的查询更直观、更易读。

<Section>
```typescript
sql`lower(${usersTable.name})`.as('lower_name')
```
```sql
... [users].[name] as [lower_name] ...
```
</Section>

## `sql.raw()`

有些情况下，你可能不需要从输入创建参数化值，也不需要把表/列映射到转义后的名称。
相反，你可能只是想按原样生成查询。对于这类情况，我们提供了 `sql.raw()` 函数。

`sql.raw()` 函数允许你在查询中包含原始 SQL 语句，而不进行任何额外的处理或转义。
当你已经有预先构造好的 SQL 语句，或需要将复杂或动态的
SQL 代码直接并入查询时，这会很有用。

<Section>
```typescript
sql.raw(`select * from users where id = ${12}`);
// 对比
sql`select * from users where id = ${12}`;
```
```sql
select * from users where id = 12;
--> 对比
select * from users where id = @par0; --> [12]
```
</Section>

你也可以在 sql 函数内部使用 `sql.raw()`，从而让你可以包含任何原始字符串
而不经过主 `sql` 模板函数的转义。

通过在 `sql` 函数内部使用 `sql.raw()`，你可以将未转义的原始字符串
直接并入查询。当你有一些特定的 SQL 代码或表达式，希望不被模板函数的
自动转义或修改所影响时，这会特别有用。

<Section>
```typescript
sql`select * from ${usersTable} where id = ${12}`;
// 对比
sql`select * from ${usersTable} where id = ${sql.raw(12)}`;
```
```sql
select * from [users] where id = @par0; --> [12]
--> 对比
select * from [users] where id = 12;
```
</Section>

## sql.fromList()

`sql` 模板生成 sql 片段（chunks），它们是 SQL 部分的数组，在 Drizzle 中将 SQL 应用到数据库或查询后，
会被拼接到查询和参数中。

在某些场景中，你可能需要用自定义业务逻辑
将这些片段聚合到一个数组中，然后把它们拼成单条可传递给数据库或查询的 SQL 语句。
对于这类情况，fromList 函数会非常有用。

fromList 函数让你可以将多个 SQL 片段组合成单条 SQL 语句。
你可以用它根据特定需求
聚合和拼接各个 SQL 部分，然后得到一条可执行的统一 SQL 查询。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

	if (i === 4) continue;
	sqlChunks.push(sql` or `);
}

const finalSql: SQL = sql.fromList(sqlChunks)
```
```sql
select * from users where id = @par0 or id = @par1 or id = @par2 or id = @par3 or id = @par4; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.join()

事实上，`sql.join` 函数的作用与 fromList 辅助函数类似。
不过，在处理 SQL 片段之间的空格或为拼接 SQL 片段指定自定义分隔符时，
它提供了额外的灵活性。

使用 `sql.join`，你可以通过指定的分隔符将 SQL 片段拼接在一起。
该分隔符可以是任何你想插入到片段之间的字符串或字符。

当你对 SQL 片段的格式或分隔有特定要求时，这尤其有用。
通过指定自定义分隔符，你可以在最终的 SQL 查询中实现所需的结构和格式。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql`where`);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

if (i === 4) continue;
    sqlChunks.push(sql`or`);
}

const finalSql: SQL = sql.join(sqlChunks, sql.raw(' '));
```
```sql
select * from users where id = @par0 or id = @par1 or id = @par2 or id = @par3 or id = @par4; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.append()

如果你已经使用 `sql` 模板生成了 SQL，可以通过 append 函数直接向生成的 SQL 中
添加新片段，从而实现与 `fromList` 相同的行为。

通过使用 append 函数，你可以动态地向现有 SQL 字符串添加额外的 SQL 片段，
有效地将它们拼接在一起。这使你能为将片段聚合到最终 SQL 查询中
引入自定义逻辑或业务规则。

<Section>
```typescript 
const finalSql = sql`select * from users`;

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = @par0 or id = @par1 or id = @par2 or id = @par3 or id = @par4; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.empty()

通过使用 sql.empty()，你可以从一个空白的 SQL 对象开始，然后按需动态地向其追加 SQL 片段。这让你能够增量式地构造 SQL 查询，应用自定义逻辑或条件来决定每个片段的内容。

一旦你用 sql.empty() 初始化了 SQL 对象，就可以使用 sql 模板的全部
功能，例如参数化、组合和转义。
这使你能够以灵活且可控的方式构造 SQL 查询，
使其适应你的特定需求。

```typescript 
const finalSql = sql.empty();

// 一些逻辑

finalSql.append(sql`select * from users`);

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = @par0 or id = @par1 or id = @par2 or id = @par3 or id = @par4; --> [0, 1, 2, 3, 4]
```

## 将 `sql` 转换为字符串和参数

在前面所有示例中，你看到了 TypeScript 中 SQL 模板语法的用法以及
生成的 SQL 输出。

如果你需要获取由 SQL 模板生成的查询字符串和相应参数，
你必须指定你想要为其生成查询的数据库方言。不同数据库在
参数化和转义方面语法各异，因此选择适当的方言至关重要。

一旦你选定了方言，就可以利用对应实现的功能
将 SQL 模板转换为所需的查询字符串和参数格式。这确保了
与你正在使用的特定数据库系统兼容。

<Section>
```typescript copy
import { MsSqlDialect } from 'drizzle-orm/mssql-core';

const mssqlDialect = new MsSqlDialect();
mssqlDialect.sqlToQuery(sql`select * from ${usersTable} where ${usersTable.id} = ${12}`);
```
```sql
select * from [users] where [users].[id] = @par0; --> [ 12 ]
```
</Section>

## `sql` select

你也可以在部分查询中使用 sql 功能。部分查询允许你
从表中检索特定字段或列，而不是获取整行。

关于部分查询的更详细信息，你可以参阅
**[Core API 文档](/docs/mssql/select#basic-and-partial-select)**。

**从表中选择不同的自定义字段**

这里你可以看到 **[`sql<T>`](/docs/mssql/sql#sqlt)**、**[`sql``.mapWith()`](/docs/mssql/sql#sqlmapwith)**、**[`sql``.as<T>()`](/docs/mssql/sql#sqlast)** 的用法。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select({
    id: usersTable.id,
    lowerName: sql<string>`lower(${usersTable.name})`,
    aliasedName: sql<string>`lower(${usersTable.name})`.as('aliased_column'),
    count: sql<number>`count(*)`.mapWith(Number) 
}).from(usersTable)
```
```sql
select [id], lower([name]), lower([name]) as [aliased_column], count(*) from [users];
```
</Section>

## `sql` 在 where 中

确实，Drizzle 提供了一组可在 sql 模板中使用的可用表达式。
然而，数据库往往有更广泛的可用表达式，
包括通过扩展或其它方式提供的表达式。

为确保灵活性，使你能够使用 Drizzle 原生不支持的
任何表达式，你可以自由地
直接使用 sql 函数编写 SQL 模板。这让你能够利用
SQL 的全部能力，并入任何特定于你目标数据库的表达式或功能。

通过使用 sql 模板，你不受限于 Drizzle 中预定义的表达式。
相反，你可以表达复杂查询，并并入底层数据库系统
提供的任何受支持的表达式。

**使用 sql 按 `id` 过滤**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

const id = 77

await db.select()
        .from(usersTable)
        .where(sql`${usersTable.id} = ${id}`)
```
```sql
select * from [users] where [users].[id] = @par0; --> [ 77 ]
```
</Section>

**高级全文搜索 where 语句**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

const searchParam = "%Ale%"

await db.select()
        .from(usersTable)
        .where(sql`lower(${usersTable.name}) like lower(${searchPattern})`)
```
```sql
select * from [users] where lower([users].[name]) like lower(@par0); --> [ "%Ale%" ]
```
</Section>

## `sql` 在 orderBy 中

当你需要 Drizzle 中不提供的特定排序功能，但又不想求助于原始 SQL 时，
`sql` 模板确实可以在 ORDER BY 子句中使用。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select().from(usersTable).orderBy(sql`${usersTable.id} desc`)
```
```sql
select * from [users] order by [users].[id] desc;
```
</Section>

## `sql` 在 having 和 groupBy 中

当你需要 Drizzle 中不提供的特定排序功能，但又不想求助于原始 SQL 时，
`sql` 模板确实可以在 HAVING 和 GROUP BY 子句中使用。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select({ 
    projectId: usersTable.projectId,
    count: sql<number>`count(${usersTable.id})`.mapWith(Number)
}).from(usersTable)
    .groupBy(sql`${usersTable.projectId}`)
    .having(sql`count(${usersTable.id}) > 300`)
```
```sql
select [project_id], count([id]) from [users] group by [users].[project_id] having count([users].[id]) > 300;
```
</Section>
