# Drizzle 迁移基础

SQL 数据库要求你预先为要存储的实体指定**严格的 schema**，
如果（当）你需要改变这些实体的形态时——你就需要通过 **schema 迁移**来完成。

管理数据库迁移有多种生产级的方式。
无论你是采用**数据库优先**还是**代码库优先**，Drizzle 都被设计为完美适配所有这些方式。

**数据库优先**是指你的数据库 schema 是事实来源。你直接在数据库上、或
通过数据库迁移工具来管理数据库 schema，然后把数据库 schema 拉取到代码库中的应用层实体。  
 
**代码库优先**是指你代码库中的数据库 schema 是事实来源，并处于版本控制之下。你在 JavaScript/TypeScript 中声明并管理数据库 schema，
然后通过 Drizzle、直接应用或外部迁移工具，把该 schema 应用到数据库本身。 

#### Drizzle 能提供什么帮助？
我们构建了 [**drizzle-kit**](/docs/mssql/kit-overview)——用于配合 Drizzle 管理迁移的 CLI 应用。 
```shell
drizzle-kit migrate
drizzle-kit generate
drizzle-kit push
drizzle-kit pull
drizzle-kit export
```
它被设计为让你根据当前的业务需求来选择迁移方式。 

它同时适用于数据库优先和代码库优先两种方式，让你可以**推送 schema**、**生成 SQL 迁移**文件，或从数据库**拉取 schema**。
无论你是单打独斗还是团队协作，它都非常合适。

<Tag style="font-size: 12px">**选项 1**</Tag>
> 我自己使用外部迁移工具，或直接在数据库上运行 SQL 迁移来管理数据库 schema。
> 从 Drizzle 我只需要从数据库获取 schema 的当前状态，并将其保存为 TypeScript schema 文件。

<Callout collapsed="展开详情">
这是一种**数据库优先**的方式。你的数据库 schema 就是**事实来源**，
Drizzle 让你可以使用 [`drizzle-kit pull`](/docs/mssql/drizzle-kit-pull) 命令把数据库 schema 拉取到 TypeScript。

<Section>
```
                                  ┌────────────────────────┐      ┌───────────────────────────────┐ 
                                  │                        │ <---  CREATE TABLE [users] (
┌──────────────────────────┐      │                        │        [id] int identity primary key,
│ ~ drizzle-kit pull       │      │                        │        [name] varchar(255),
└─┬────────────────────────┘      │        数据库          │        [email] varchar(255) unique
  │                               │                        │       );
  └ 拉取数据库 schema ----------> │                        │
  ┌ 生成 Drizzle           <----- │                        │
  │ schema TypeScript 文件        └────────────────────────┘
  │
  v
```
```typescript
import * as p from "drizzle-orm/mssql-core";

export const users = p.mssqlTable("users", {
	id: p.int().identity({ seed: 1 ,increment: 1 }),
	name: p.varchar({ length: 255 }),
	email: p.varchar({ length: 255 }),
}, (table) => [
	p.primaryKey({ columns: [table.id], name: "PK__users__3213E83FFAA14405"}),
	p.unique("UQ__users__AB6E6164E0557A2A").on(table.email)
]);
```

<Tag style="font-size: 12px">**选项 2**</Tag>
> 我希望把数据库 schema 放在 TypeScript 代码库中，
> 我不想处理 SQL 迁移文件。  
> 我希望 Drizzle 把 schema 直接“推送”到数据库

<Callout collapsed="展开详情">
这是一种**代码库优先**的方式。你的 TypeScript Drizzle schema 就是**事实来源**，
Drizzle 让你可以使用 [`drizzle-kit push`](/docs/mssql/drizzle-kit-push) 命令把 schema 变更推送到数据库。

这是快速原型开发的最佳方式，我们已经看到数十个团队
和独立开发者成功将其作为生产应用的主要迁移流程。

<Section>
```typescript {6} filename="src/schema.ts"
import * as p from "drizzle-orm/mssql-core";

export const users = p.mssqlTable("users", {
  id: p.int().primaryKey().identity(),
  name: p.varchar({ length: 255 }),
  email: p.varchar({ length: 255 }).unique(), // <--- 新增的列
});
```
```
向 `users` 表添加列
┌────────────────────────────────────────────┐                  
│ + email: varchar({ length: 255 }).unique() │                  
└─┬──────────────────────────────────────────┘                  
  │                                           
  v                                           
┌──────────────────────────┐                  
│ ~ drizzle-kit push       │                  
└─┬────────────────────────┘                  
  │                                           ┌──────────────────────────┐
  └ 拉取当前数据库 schema ------------------> │                          │
                                              │                          │
  ┌ 基于差异生成变更           <------------- │          数据库          │
  │                                           │                          │
  └ 将迁移应用到数据库 ---------------------> │                          │
                                       │      └──────────────────────────┘
                                       │
  ┌────────────────────────────────────┴───────────────────────────────┐
   ALTER TABLE [users] ADD [email] varchar(255);
   ALTER TABLE [users] ADD CONSTRAINT [users_email_key] UNIQUE([email]);
```

<Tag style="font-size: 12px">**选项 3**</Tag>

<Tag style="font-size: 12px">**选项 4**</Tag>
> 我希望把数据库 schema 放在 TypeScript 代码库中，
> 我希望 Drizzle 为我生成 SQL 迁移文件，并且我希望 Drizzle 在运行时应用它们

<Callout collapsed="展开详情">
这是一种**代码库优先**的方式。你的 TypeScript Drizzle schema 就是事实来源，

这种方式广泛用于**单体**应用，用于在零停机部署期间应用数据库迁移，
并在出现问题时回滚 DDL 变更。
它也用于**无服务器**部署，迁移会在部署过程中作为**自定义资源**运行一次。

import * as p from "drizzle-orm/mssql-core";

});

  │    ┌─┴───────────────────────────────────────┐
