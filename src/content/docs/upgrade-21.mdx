## 如何迁移到 `0.21.0`

#### 1. 从你的 drizzle-kit 命令中移除所有 `:dialect` 前缀。
示例：将 `drizzle-kit push:mysql` 改为 `drizzle-kit push`。

#### 2. 更新你的 `drizzle.config.ts` 文件：
 - 向 `drizzle.config.ts` 添加 `dialect`。它现在是必填项，可以是 `postgresql`、`mysql` 或 `sqlite`。
 - 仅在使用了 `aws-data-api`、`turso`、`d1-http`（开发中）或 `expo` 时，才向 `drizzle.config.ts` 添加 `driver`。否则，你可以从 `drizzle.config.ts` 中移除 `driver`。
 - 如果你之前在 `dbCredentials` 中使用了 `connectionString` 或 `uri`，现在应改用 `url`。
    
```ts
import { defineConfig } from "drizzle-kit"

export default defineConfig({
    dialect: "sqlite", // "postgresql" | "mysql"
    driver: "turso", // 可选，仅在使用了 `aws-data-api`、`turso`、`d1-http`（开发中）或 `expo` 时使用
    dbCredentials: {
        url: ""
    }
})
```

#### 3. 如果你使用 PostgreSQL 或 SQLite，并且项目中已生成迁移，请运行 `drizzle-kit up`，以便 Drizzle 将所有快照升级到版本 6。

<Callout>
  你可以在此处查看 `0.21.0` 中所有变更的详细信息
</Callout>

## 更新日志

**❗ Snapshots Upgrade**

所有 PostgreSQL 和 SQLite 生成的快照都会升级到版本 6。系统会提示你通过运行 `drizzle-kit up` 来升级它们

**❗ Removing :dialect from `drizzle-kit` cli commands**

现在你只需使用命令即可，例如：

- `drizzle-kit generate`
- `drizzle-kit push`
- 等等。

无需指定 dialect。该参数已移到 `drizzle.config.ts`

**❗ `drizzle.config` update**

- `dialect` 现在是必填项；指定你要连接的数据库方言。可选值包括 `mysql`、`postgresql` 或 `sqlite`。
- `driver` 变为可选，且会指定一个具体的驱动，每个驱动都有不同的 `dbCredentials` 配置。可用的驱动有：
  - `aws-data-api`
  - `turso`
  - `d1-http` —— 目前开发中
  - `expo`
- `url` —— 一个统一参数，取代此前存在的 `connectionString` 和 `uri`。
- `migrations` —— 一个新的对象参数，用于为 migrate 命令指定自定义表和 schema：
  - `table` —— drizzle 存储迁移所用的自定义表。
  - `schema` —— drizzle 存储迁移所用的自定义 schema（仅限 Postgres）。

所有新增和更新命令的用法示例
```ts
import { defineConfig } from "drizzle-kit"

export default defineConfig({
    dialect: "sqlite", // "postgresql" | "mysql"
    driver: "turso"
    dbCredentials: {
        url: ""
    },
    migration: {
        table: "migrations",
        schema: "public"
    }
})
```

Drizzle 的驱动选择遵循当前策略：

如果指定了 `driver`，则使用该驱动进行查询。

如果未指定驱动：

- 对于 `postgresql` 方言，Drizzle 会：
  - 检查是否安装了 `pg` 驱动并使用它。
  - 如果没有，则尝试查找 `postgres` 驱动并使用它。
  - 如果仍未找到，则尝试查找 `@vercel/postgres`。
  - 然后尝试 `@neondatabase/serverless`。
  - 如果什么都没找到，将抛出错误。

- 对于 `mysql` 方言，Drizzle 会：
  - 检查是否安装了 `mysql2` 驱动并使用它。
  - 如果没有，则尝试查找 `@planetscale/database` 并使用它。
  - 如果什么都没找到，将抛出错误。

- 对于 `sqlite` 方言，Drizzle 会：
  - 检查是否安装了 `@libsql/client` 驱动并使用它。
  - 如果没有，则尝试查找 `better-sqlite3` 并使用它。
  - 如果什么都没找到，将抛出错误

**❗ MySQL schemas/database are no longer supported by drizzle-kit**

Drizzle Kit 将不再处理你的 drizzle schema 文件中针对额外 schema/数据库的任何 schema 变更

# 新特性

**🎉 Pull relations**

Drizzle 现在会从数据库中拉取 `relations`：它会提取外键信息并将其转换为一个 `relations` 对象。内省完成后，你可以在 `out` 文件夹中查看 `relations.ts` 文件

关于 relations 的更多信息，请查看[文档](/docs/rqb#declaring-relations)


**🎉 Custom name for generated migrations**

要为迁移指定名称，你应使用 `--name <name>`

用法
```
drizzle-kit generate --name init_db
```

**🎉 New command `migrate`**

现在你可以直接从 `drizzle-kit` 将生成的迁移应用到数据库

用法
```
drizzle-kit migrate
```

默认情况下，drizzle-kit 会将迁移数据条目存储在 `__drizzle_migrations` 表中，对于 PostgreSQL 则存储在 `drizzle` schema 中。如果你想更改这一点，需要在 `drizzle.config.ts` 中指定修改。

```ts
import { defineConfig } from "drizzle-kit"

export default defineConfig({
    migrations: {
        table: "migrations",
        schema: "public"
    }
})
```
