### `one()`
以下是 drizzle relations 中 `.one()` 可用的所有字段列表

```ts {3-11}
const relations = defineRelations({ users, posts }, (r) => ({
	posts: {
		author: r.one.users({
			from: r.posts.ownerId,
			to: r.users.id,
			optional: false,
      alias: 'custom_name',
			where: {
				verified: true,
			}
		}),
	}
}))
```

- `author` 键是一个自定义键，在使用 Drizzle 关系查询时会出现在 `posts` 对象中。
- `r.one.users` 定义 `author` 将是来自 `users` 表的单个对象，而不是对象数组。
- `from: r.posts.ownerId` 指定我们建立软关系所依据的表。
在本例中，该关系从 `posts` 表中的 `ownerId` 列开始。
- `to: r.users.id` 指定我们建立软关系所指向的表。
在本例中，该关系指向 `users` 表中的 `id` 列。
- `optional: false` 在类型层面将 posts 对象中的 `author` 键变为 `required`。
当你确定该实体一定存在时，应使用此选项。
- `alias` 用于为表之间的关系添加特定别名。如果两张表之间存在多个完全相同的关系，你应当
使用 `alias` 加以区分
- `where` 条件可用于多态关系。它会基于 `where` 语句获取关系。
例如在上面的情况中，只会检索 `verified authors`。在[这里](/docs/sqlite/relations-schema-declaration#多态关系)了解更多关于多态关系的内容。

### `many()`

以下是 drizzle relations 中 `.many()` 可用的所有字段列表

```ts {3-10}
const relations = defineRelations({ users, posts }, (r) => ({
	users: {
		feed: r.many.posts({
			from: r.users.id,
			to: r.posts.ownerId,
			alias: 'custom_name',
			where: {
				approved: true,
			}
		}),
	}
}))
```

- `feed` 键是一个自定义键，在使用 Drizzle 关系查询时会出现在 `users` 对象中。
- `r.many.posts` 定义 `feed` 将是来自 `posts` 表的对象数组，而不仅仅是一个对象
- `from: r.users.id` 指定我们建立软关系所依据的表。
在本例中，该关系从 `users` 表中的 `id` 列开始。
- `to: r.posts.ownerId` 指定我们建立软关系所指向的表。
在本例中，该关系指向 `posts` 表中的 `ownerId` 列。
- `alias` 用于为表之间的关系添加特定别名。如果两张表之间存在多个完全相同的关系，你应当
使用 `alias` 加以区分
- `where` 条件可用于多态关系。它会基于 `where` 语句获取关系。
例如在上面的情况中，只会检索 `approved posts`。在[这里](/docs/sqlite/relations-schema-declaration#多态关系)了解更多关于多态关系的内容。

### 一对一
Drizzle ORM 为你提供了一套 API，可通过 `defineRelations` 函数定义表之间的 `one-to-one` 关系。

下面是一个 users 与 users 之间 `one-to-one` 关系的示例，其中一个用户可以邀请另一个用户（此示例使用了自引用）：

```typescript copy {10-17}
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core';
import { defineRelations } from 'drizzle-orm';

export const users = sqliteTable('users', {
	id: integer().primaryKey(),
	name: text(),
	invitedBy: integer('invited_by'),
});

export const relations = defineRelations({ users }, (r) => ({
	users: {
		invitee: r.one.users({
			from: r.users.invitedBy,
			to: r.users.id,
		})
	}
}));
```

另一个示例是用户的信息存储在单独的表中。在这种情况下，由于外键存储在 "profile_info" 表中，用户关系既没有 fields 也没有 references，这会告诉 TypeScript `user.profileInfo` 是可空的：

```typescript copy {15-22}
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core';
import { defineRelations } from 'drizzle-orm';

export const users = sqliteTable('users', {
	id: integer().primaryKey(),
	name: text(),
});

export const profileInfo = sqliteTable('profile_info', {
	id: integer().primaryKey({ autoIncrement: true }),
	userId: integer('user_id').references(() => users.id),
	metadata: text({ mode: 'json' }),
});

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));

const user = await db.query.users.findFirst({ with: { profileInfo: true } });
//____^? type { id: number, name: string | null, profileInfo: { ... } | null  }
```

### 一对多
Drizzle ORM 为你提供了一套 API，可通过 `defineRelations` 函数定义表之间的 `one-to-many` 关系。

下面是 users 与他们撰写的 posts 之间 `one-to-many` 关系的示例：

```typescript copy {15-25}
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core';
import { defineRelations } from 'drizzle-orm';

export const users = sqliteTable('users', {
	id: integer('id').primaryKey(),
	name: text('name'),
});

export const posts = sqliteTable('posts', {
	id: integer('id').primaryKey(),
	content: text('content'),
	authorId: integer('author_id'),
});

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```

现在让我们为 posts 添加 comments：

### 多对多
Drizzle ORM 为你提供了一套 API，可通过所谓的 `junction` 或 `join` 表来定义表之间的 `many-to-many` 关系，
这些表必须显式定义，并存储相关表之间的关联关系。

下面是一个 users 与 groups 之间 `many-to-many` 关系的示例，我们使用 `through` 来绕过 junction 表的选择，直接为每个 `user` 查询多个 `groups`。
```typescript copy {27-39}
import { defineRelations } from 'drizzle-orm';
import { integer, sqliteTable, primaryKey, text } from 'drizzle-orm/sqlite-core';

export const users = sqliteTable('users', {
  id: integer().primaryKey(),
  name: text(),
});

export const groups = sqliteTable('groups', {
  id: integer().primaryKey(),
  name: text(),
});

export const usersToGroups = sqliteTable(
  'users_to_groups',
  {
    userId: integer('user_id')
      .notNull()
      .references(() => users.id),
    groupId: integer('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [primaryKey({ columns: [t.userId, t.groupId] })],
);

export const relations = defineRelations({ users, groups, usersToGroups },
  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),
        to: r.groups.id.through(r.usersToGroups.groupId),
      }),
    },
    groups: {
      participants: r.many.users(),
    },
  })
);
```

**查询示例：**
```ts
const res = await db.query.users.findMany({
  with: { 
    groups: true 
  },
});

// 响应类型
type Response = {
  id: number;
  name: string | null;
  groups: {
    id: number;
    name: string | null;
  }[];
}[];
```

### 预定义过滤器

Drizzle 关系定义中预定义的 `where` 语句是多态关系实现的一种形式，但又不完全是。本质上，它们让你能够
不仅通过选择特定列来连接表，还可以通过自定义 `where` 语句来连接表。让我们看一些示例：

我们可以定义 `groups` 与 `users` 之间的关系，这样在查询某个 group 的 users 时，只检索那些 `verified` 列被设置为 `true` 的用户
<CodeTabs items={["关系", "Schema"]}>
<Section>
```ts
import { defineRelations } from "drizzle-orm";
import * as schema from './schema';

export const relations = defineRelations(schema,(r) => ({
    groups: {
      verifiedUsers: r.many.users({
        from: r.groups.id.through(r.usersToGroups.groupId),
        to: r.users.id.through(r.usersToGroups.userId),
        where: {
          verified: true,
        },
      }),
    },
  })
);

...

await db.query.groups.findMany({
    with: {
      verifiedUsers: true,
    },
});
```
</Section>
<Section>
```ts
import * as p from "drizzle-orm/sqlite-core";

export const users = p.sqliteTable("users", {
  id: p.integer().primaryKey(),
  name: p.text().notNull(),
  verified: p.integer({ mode: 'boolean' }).notNull(),
});

export const groups = p.sqliteTable("groups", {
  id: p.integer().primaryKey(),
  title: p.text().notNull(),
});

export const usersToGroups = p.sqliteTable(
  "users_to_groups",
  {
    userId: p
      .integer("user_id")
      .notNull()
      .references(() => users.id, { onDelete: "cascade" }),
    groupId: p
      .integer("group_id")
      .notNull()
      .references(() => groups.id, { onDelete: "cascade" }),
  },
  (t) => [p.primaryKey({ columns: [t.groupId, t.userId] })]
);
```
</Section>
</CodeTabs>

<Callout type='warning'>
你只能在目标（to）表上指定过滤器。因此在本例中，where 子句只会包含来自 `users` 表的列，因为我们建立的是**指向** users 的关系

```ts {7}
export const relations = defineRelations(schema,(r) => ({
    groups: {
      verifiedUsers: r.many.users({
        from: r.groups.id.through(r.usersToGroups.groupId),
        to: r.users.id.through(r.usersToGroups.userId),
        where: {
          verified: true,
        },
      }),
    },
  })
);
```
</Callout>

### 关系组成部分

如果你需要将 relations 配置拆分成多个部分，可以使用 `defineRelationsPart` 辅助函数

```ts
import { defineRelations, defineRelationsPart } from 'drizzle-orm';
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));

export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

然后你可以将其提供给 db 实例

```ts
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })
```

<Callout type='warning'>
为了让 `defineRelationsParts` 按预期工作，你需要注意几条规则

**Rule 1**：如果你使用 parts 指定了 relations，在将其传递给 drizzle db 函数时，你需要按正确的顺序指定（主 relations 放在前面）
```ts
// ✅
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })

// ❌
const db = drizzle(process.env.DB_URL, { relations: { ...part, ...relations } })
```

<Callout collapsed="为什么这很重要？">
即使不会出现类型错误或运行时错误，这就是 "..." 在对象上的工作方式。只要主 relation
递归地推断出所有表名，它就可以在自动补全中可用。下面是一个示例：

```ts
export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));

export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

这里 `relations` 和 `part` 可以表示为这个对象：
```json
// relations
{
  "users": {"invitee": {...}, "posts": {...}},
  // 添加在这里，这样 schema 中的所有表都会出现在自动补全中
  "posts": {}
}

// part
{
  "posts": {"author": {...}}
}
```

使用 `{ ...relations, ...part }` 将得到
```json
{
  "users": {"invitee": {...}, "posts": {...}},
  "posts": {"author": {...}}
}
```

而使用 `{ ...relations, ...part }` 将得到
```json
{
  "users": {"invitee": {...}, "posts": {...}},
  // 正如你在最终对象中看到的，posts 的 relations 信息将会丢失
  "posts": {}
}
```

</Callout>

**Rule 2**：你应当拥有最少的 relations，这样 drizzle 才能为自动补全推断出所有表。如果你只想使用 parts，那么
你的其中一个 part 应当为空，像这样：

```ts
export const mainPart = defineRelationsPart(schema);
```

在这种情况下，所有表都会被正确推断，你将拥有关于 schema 的完整信息
</Callout>

### 性能

在 Drizzle ORM 中使用 relations 时，尤其是在数据量大或查询复杂的应用中，
优化数据库性能至关重要。
索引在加速数据检索方面起着关键作用，尤其是在查询相关数据时。
本节概述了使用 Drizzle ORM 定义的每种关系类型所推荐的索引策略。

##### 一对一关系

在一对一关系中，例如 "user invites user" 示例或
"user has profile info" 示例，关键的性能考量是高效地 join 相关表。

<Callout>
为在一对一关系中获得最佳性能，你应当在被引用的表（关系中的 "target" 表）的外键列上创建索引。
</Callout>

<Callout collapsed='为什么这很重要'>
当你查询带有一对一关联信息的数据时，Drizzle 会执行 JOIN 操作。外键列上的索引能让数据库快速
定位目标表中的相关行，从而显著加速 join 过程。
</Callout>

**示例：**
```typescript
import * as p from 'drizzle-orm/sqlite-core';
import { defineRelations } from 'drizzle-orm';

export const users = p.sqliteTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const profileInfo = p.sqliteTable('profile_info', {
	id: p.integer().primaryKey(),
	userId: p.integer('user_id').references(() => users.id),
	metadata: p.text({ mode: 'json' }),
});

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));
```

为优化获取用户数据及其 profile 信息的查询，
你应当在 `profile_info` 表的 `userId` 列上创建索引。

```typescript {13-15}
import * as p from 'drizzle-orm/sqlite-core';
import { defineRelations } from 'drizzle-orm';

export const users = p.sqliteTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const profileInfo = p.sqliteTable('profile_info', {
	id: p.integer().primaryKey(),
	userId: p.integer('user_id').references(() => users.id),
	metadata: p.text({ mode: 'json' }),
}, (table) => [
  p.index('profile_info_user_id_idx').on(table.userId)
]);

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));
```
```sql
CREATE INDEX `profile_info_user_id_idx` ON `profile_info` (`user_id`);
```

#### 一对多关系

与一对一关系类似，一对多关系也能从索引中显著受益，
以优化 join 操作。考虑 "users and posts" 示例，其中一个用户可以有多个 posts。

<Callout>
对于一对多关系，应当在表示关系 "many" 一侧的表（即外键引用 "one" 一侧的表）的外键列上创建索引。
</Callout>

<Callout collapsed='为什么这很重要'>
当你获取一个用户及其 posts，或获取 posts 及其作者时，会执行 joins。
对作为外键的列（`posts` 表中的 `authorId`）建立索引，能让数据库高效地
检索与某个用户关联的所有 posts，或快速找到某篇 post 的作者。
</Callout>

**示例：**
```typescript
import * as p from "drizzle-orm/sqlite-core";
import { defineRelations } from 'drizzle-orm';

export const users = p.sqliteTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const posts = p.sqliteTable('posts', {
	id: p.integer().primaryKey(),
	content: p.text(),
	authorId: p.integer('author_id'),
});

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```

为优化涉及 users 及其 posts 的查询，请在 `posts` 表的 `authorId` 列上创建索引。

```typescript {13-15}
import * as p from "drizzle-orm/sqlite-core";
import { defineRelations } from 'drizzle-orm';

export const users = p.sqliteTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const posts = p.sqliteTable('posts', {
	id: p.integer().primaryKey(),
	content: p.text(),
	authorId: p.integer('author_id'),
}, (t) => [
  p.index('posts_author_id_idx').on(t.authorId)
]);

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```
```sql
CREATE INDEX `posts_author_id_idx` ON `posts` (`author_id`);
```

#### 多对多关系

使用 junction 表实现的多对多关系，需要稍微
更细致的索引策略，以确保最佳的查询性能。
考虑使用 `usersToGroups` junction 表的 "users and groups" 示例。

<Callout>
对于多对多关系，通常建议在 junction 表上创建以下
索引：
1.  **在每个外键列上单独建立索引：** 这能优化基于关系的单侧进行
过滤或 join 的查询
（例如，查找某个 user 的所有 groups，或某个 group 中的所有 users）。
2.  **在两个外键列上建立复合索引：** 这对于高效地解析多对多关系本身至关重要。它能加速那些需要查找两个实体之间连接关系的查询。
</Callout>

<Callout collapsed='为什么这很重要'>
在查询多对多 relations 时，尤其是在 Drizzle ORM 中使用 `through` 时，数据库需要高效地导航 junction 表。

- 在单个外键列上建立索引（`usersToGroups` 中的 `userId`、`groupId`），在从一侧查询另一侧时会有所帮助（例如 "查找某个 user 的 groups"）。
- `usersToGroups` 中 `(userId, groupId)` 上的复合索引，对于快速查找 junction 表中定义的所有关系尤为重要。当 Drizzle ORM 解析 `many-to-many` 关系以获取相关实体时会用到它。
</Callout>

**示例：**

在 "users and groups" 示例中，`usersToGroups` junction 表连接了 `users` 和 `groups`。

```typescript
import { defineRelations } from 'drizzle-orm';
import * as p from 'drizzle-orm/sqlite-core';

export const users = p.sqliteTable('users', {
  id: p.integer().primaryKey(),
  name: p.text(),
});

export const groups = p.sqliteTable('groups', {
  id: p.integer().primaryKey(),
  name: p.text(),
});

export const usersToGroups = p.sqliteTable(
  'users_to_groups',
  {
    userId: p.integer('user_id')
      .notNull()
      .references(() => users.id),
    groupId: p.integer('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [p.primaryKey({ columns: [t.userId, t.groupId] })],
);

export const relations = defineRelations({ users, groups, usersToGroups },
  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),
        to: r.groups.id.through(r.usersToGroups.groupId),
      }),
    },
    groups: {
      participants: r.many.users(),
    },
  })
);
```

为优化 users 和 groups 的查询，请在 `usersToGroups` 表上创建如下索引：

```typescript {26-28}
import { defineRelations } from 'drizzle-orm';
import * as p from 'drizzle-orm/sqlite-core';

export const users = p.sqliteTable('users', {
  id: p.integer().primaryKey(),
  name: p.text(),
});

export const groups = p.sqliteTable('groups', {
  id: p.integer().primaryKey(),
  name: p.text(),
});

export const usersToGroups = p.sqliteTable(
  'users_to_groups',
  {
    userId: p.integer('user_id')
      .notNull()
      .references(() => users.id),
    groupId: p.integer('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [
    p.primaryKey({ columns: [t.userId, t.groupId] }),
    p.index('users_to_groups_user_id_idx').on(t.userId),
    p.index('users_to_groups_group_id_idx').on(t.groupId),
    p.index('users_to_groups_composite_idx').on(t.userId, t.groupId),
  ],
);

export const relations = defineRelations({ users, groups, usersToGroups },
  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),
        to: r.groups.id.through(r.usersToGroups.groupId),
      }),
    },
    groups: {
      participants: r.many.users(),
    },
  })
);
```
```sql
CREATE INDEX `users_to_groups_user_id_idx` ON `users_to_groups` (`user_id`);
CREATE INDEX `users_to_groups_group_id_idx` ON `users_to_groups` (`group_id`);
CREATE INDEX `users_to_groups_composite_idx` ON `users_to_groups` (`user_id`,`group_id`);
```

通过应用这些索引策略，你可以在处理关系型数据时显著提升 Drizzle ORM 应用的性能，尤其是在数据量增长、查询变得更复杂时。记得选择最适合你特定查询模式和应用需求的索引。

### 外键

你可能已经注意到 `relations` 看起来和 foreign keys 很像——它们甚至有 `references` 属性。那么区别是什么呢？

虽然 foreign keys 有类似的目的，即定义表之间的关系，但它们与 `relations` 处于不同的层面。

Foreign keys 是数据库层面的约束，它们在每次 `insert`/`update`/`delete` 操作时都会被检查，如果违反约束就抛出错误。
另一方面，`relations` 是更高层面的抽象，它们仅用于在应用层面定义表之间的关系。
它们不会以任何方式影响数据库 schema，也不会隐式创建 foreign keys。

这意味着 `relations` 和 foreign keys 可以一起使用，但彼此并不相互依赖。
你可以在不使用 foreign keys 的情况下定义 `relations`（反之亦然），这使它们能够用于不支持 foreign keys 的数据库。

下面两个示例在使用 Drizzle 关系查询数据时表现完全相同。

```ts {15}
  userId: p.integer("user_id"),
  metadata: p.text({ mode: 'json' }),

    profileInfo: r.one.profileInfo({
```

### 消除关系歧义

Drizzle 还提供了 `alias` 选项，用于在你在相同的两张表之间定义多个关系时
区分这些 relations。例如，如果你定义了一个 `posts` 表，其中包含 `author` 和 `reviewer`
关系。

```ts {19,22,29,34}
import { sqliteTable, integer, text } from 'drizzle-orm/sqlite-core';
import { defineRelations } from 'drizzle-orm';
 
export const users = sqliteTable('users', {
	id: integer().primaryKey(),
	name: text(),
});

export const posts = sqliteTable('posts', {
	id: integer().primaryKey(),
	content: text(),
	authorId: integer('author_id'),
	reviewerId: integer('reviewer_id'),
});
 
export const relations = defineRelations({ users, posts }, (r) => ({
  users: {
    posts: r.many.posts({
      alias: "author",
    }),
    reviewedPosts: r.many.posts({
      alias: "reviewer",
    }),
  },
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
      alias: "author",
    }),
    reviewer: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
      alias: "reviewer",
    }),
  },
}));
```
