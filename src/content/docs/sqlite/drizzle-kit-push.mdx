# `drizzle-kit push`

<Prerequisites>
- Drizzle 和 `drizzle-kit` 入门 - [阅读此处](/docs/sqlite/get-started)
- Drizzle schema 基础 - [阅读此处](/docs/sqlite/sql-schema-declaration) 
- 数据库连接基础 - [阅读此处](/docs/sqlite/connect-overview) 
- Drizzle 迁移基础 - [阅读此处](/docs/sqlite/migrations) 
- Drizzle Kit [概览](/docs/sqlite/kit-overview) 和 [配置文件](/docs/sqlite/drizzle-config-file) 文档
</Prerequisites>


`drizzle-kit push` 让你可以把 schema 以及后续的 schema 变更直接推送到
数据库，同时跳过 SQL 文件的生成，它旨在覆盖 Drizzle 迁移的 [代码优先](/docs/sqlite/migrations)
方式。

<Callout collapsed="底层是如何工作的？">
当你运行 Drizzle Kit `push` 命令时，它会：
1. 读取你的 Drizzle schema 文件，并组合出你的 schema 的 json 快照
2. 拉取（introspect）数据库 schema 
3. 基于两者之间的差异生成 SQL 迁移
4. 将 SQL 迁移应用到数据库

<Section>
```typescript filename="src/schema.ts"
import * as p from "drizzle-orm/sqlite-core";

export const users = p.sqliteTable("users", {
  id: p.integer().primaryKey({ autoIncrement: true }),
  name: p.text(),
});
```
```
┌─────────────────────┐                  
│ ~ drizzle-kit push  │                  
└─┬───────────────────┘                  
  │                                           ┌──────────────────────────┐
  └ 拉取当前数据库 schema -------------------> │                          │
                                              │                          │
  ┌ 基于差异生成变更 <------------------------ │         数据库           │
  │                                           │                          │
  └ 将迁移应用到数据库 ----------------------> │                          │
                                       │      └──────────────────────────┘
                                       │
  ┌────────────────────────────────────┴───────────────────────────────────────┐
   CREATE TABLE `users` (`id` integer PRIMARY KEY AUTOINCREMENT, `name` text );
```
</Section>
</Callout>

这是快速原型开发的最佳方式，我们已经看到许多团队
和独立开发者成功地将它作为生产应用中的主要迁移流程。
它非常适合与蓝/绿部署策略以及像
[Planetscale](https://planetscale.com)、[Neon](https://neon.tech)、[Turso](https://turso.tech/drizzle) 等无服务器数据库搭配使用。

<br/>
<hr/>
<br/>


`drizzle-kit push` 要求你指定 `dialect`、`schema` 文件路径，以及
数据库连接 `url` 或 `user:password@host:port/db` 参数，你可以
通过 [drizzle.config.ts](/docs/sqlite/drizzle-config-file) 配置文件或 CLI 选项来提供：

<CodeTabs items={["使用配置文件", "使用 CLI 选项"]}>
<Section>
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "sqlite",
  schema: "./src/schema.ts",
  dbCredentials: {
    url: "./sqlite.db",
  },
});
```
```shell
npx drizzle-kit push
```
</Section>

```shell
npx drizzle-kit push --dialect=sqlite --schema=./src/schema.ts --url=./sqlite.db
```

</CodeTabs>

### schema 文件路径

你可以只有一个 `schema.ts` 文件，也可以有任意多个分散在项目中的 schema 文件。
Drizzle Kit 要求你通过 `schema` 配置选项以 [glob](https://www.digitalocean.com/community/tools/glob?comments=true&glob=/**/*.js&matches=false&tests=//%20This%20will%20match%20as%20it%20ends%20with%20'.js'&tests=/hello/world.js&tests=//%20This%20won't%20match!&tests=/test/some/globs) 的形式指定它们的路径。

### 一个项目中的多个配置文件

你可以在项目中拥有多个配置文件，当你拥有多个数据库阶段、多个数据库或同一项目中的不同数据库时，它会非常有用：

<Npx>
  drizzle-kit push --config=drizzle-dev.config.ts
  drizzle-kit push --config=drizzle-prod.config.ts
</Npx>
```plaintext {5-6}
📦 <project root>
 ├ 📂 drizzle
 ├ 📂 src
 ├ 📜 .env
 ├ 📜 drizzle-dev.config.ts
 ├ 📜 drizzle-prod.config.ts
 ├ 📜 package.json
 └ 📜 tsconfig.json
```

### 指定数据库驱动
<Callout type="warning">
**Expo SQLite** 和 **OP SQLite** 是设备端（每用户）数据库，无法将迁移 `push` 到那里。<br/>
对于嵌入式数据库，Drizzle 提供了 **embedded migrations** —— 查看我们的 [get started](/docs/get-started/expo-new) 指南。
</Callout>
Drizzle Kit 不附带预捆绑的数据库驱动， 
它会根据 `dialect` 从你当前项目中自动选择一个可用的 SQLite 驱动 - [参见讨论](https://github.com/drizzle-team/drizzle-orm/discussions/2203)。

对于 Cloudflare D1 HTTP，请显式指定 `driver: "d1-http"`。

```ts {6}
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "sqlite",
  driver: "d1-http",
  dbCredentials: {
    accountId: "accountId",
    databaseId: "databaseId",
    token: "token",
  },
});
```

### 包含表
`drizzle-kit push` 默认会管理所有 SQLite 表。
你可以通过 `tablesFilter` 配置表列表。

|                |                                                                                               |
| :------------- | :-------------------------------------------------------------------------------------------- |
| `tablesFilter` | 基于 `glob` 的表名过滤器，例如 `["users", "user_info"]` 或 `"user*"`。默认值为 `"*"` |
<br/>

让我们配置 drizzle-kit 以操作 SQLite 数据库中的**所有表**。

<Section>
```ts filename="drizzle.config.ts" {9}
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "sqlite",
  schema: "./src/schema.ts",
  dbCredentials: {
    url: "./sqlite.db",
  },
  tablesFilter: ["*"],
});
```
```shell
npx drizzle-kit push
```
</Section>

### 配置项扩展列表

`drizzle-kit push` 有一些仅限 CLI 的选项

<rem025/>

|           |                                                                 |
| :-------- | :---------------------------------------------------------------|
| `verbose` | 在执行前打印所有 SQL 语句                     |
| `explain` | 打印计划中的 SQL 变更，但不应用它们（dry run）  |
| `force`   | 自动接受所有会丢失数据的语句                            |
<br/>
<Npx>
drizzle-kit push --explain --verbose --force
</Npx>

<br/>
<hr/>
<br/>
我们建议通过 [drizzle.config.ts](/docs/sqlite/drizzle-config-file) 文件来配置 `drizzle-kit`， 
但如果需要，例如在 CI/CD 流水线中，你也可以通过 CLI 提供所有配置选项。

|                     |            |                                                                           |
| :------------------ | :--------- | :------------------------------------------------------------------------ |
| `dialect`           | `required` | 数据库方言，可选值为 <Dialects/> 之一                                      |
| `schema`            | `required` | TypeScript schema 文件或包含多个 schema 文件的文件夹的路径 |
| `driver`            |            | 驱动例外，例如 `d1-http`                                   |
| `tablesFilter`      |            | 表名过滤器                                                         |
| `url`               |            | 数据库连接字符串                                                |
| `user`              |            | 数据库用户                                                             |
| `password`          |            | 数据库密码                                                         |
| `host`              |            | 主机                                                                      |
| `port`              |            | 端口                                                                      |
| `database`          |            | 数据库名称                                                             |
| `config`            |            | 配置文件路径，默认=`drizzle.config.ts`                             |

<Npx>
drizzle-kit push dialect=sqlite schema=src/schema.ts url=./sqlite.db
drizzle-kit push dialect=sqlite schema=src/schema.ts --tablesFilter='user*' url=./sqlite.db
</Npx>

现在让我们运行
```shell
npx drizzle-kit push
```

它会在底层拉取数据库现有的（空的）schema，生成 SQL 迁移并应用它

```sql
CREATE TABLE `users`(
  `id` integer primary key autoincrement,
  `name` text
)
```
