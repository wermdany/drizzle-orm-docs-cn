# Drizzle schema

Drizzle 让你可以用 TypeScript 定义 schema，并支持底层数据库所支持的各种模型和属性。
当你定义 schema 时，它将成为后续查询（使用 Drizzle-ORM）
和迁移（使用 Drizzle-Kit）修改的唯一真实来源。

<Callout> 
如果你使用 Drizzle-Kit 进行迁移流程，请确保导出 schema 文件中定义的所有模型，以便 Drizzle-Kit 能导入它们并在迁移差异流程中使用。
</Callout>

<CodeTabs items={["使用 imports", "使用 callback", "使用 import *"]}>
```ts
import { integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const usersTable = sqliteTable("users", {
  id: integer().primaryKey({ autoIncrement: true }),
  name: text().notNull(),
  age: integer().notNull(),
  email: text().notNull().unique(),
});
```
```ts
import { sqliteTable } from "drizzle-orm/sqlite-core";

export const usersTable = sqliteTable("users", (t) => ({
  id: t.integer().primaryKey({ autoIncrement: true }),
  name: t.text().notNull(),
  age: t.integer().notNull(),
  email: t.text().notNull().unique(),
}));
```
```ts
import * as t from "drizzle-orm/sqlite-core";

export const usersTable = t.sqliteTable("users", {
  id: t.integer().primaryKey({ autoIncrement: true }),
  name: t.text().notNull(),
  age: t.integer().notNull(),
  email: t.text().notNull().unique(),
});
```
</CodeTabs>

## 组织你的 schema 文件 
你可以直接在 TypeScript 中声明你的 SQL schema，无论是放在单个 `schema.ts` 文件中，
还是分散放置——随你偏好，完全自由！

#### 单个文件中的 schema
使用 Drizzle 声明 schema 最常见的方式是把所有表放进一个 `schema.ts` 文件。

> 注意：你可以随意命名你的 schema 文件。例如，它可以是 `models.ts`，或其它名字。

如果你没有定义太多表模型，或者你不介意把它们都放在一个文件里，这种方法就很合适

示例：
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📜 schema.ts
```

在 `drizzle.config.ts` 文件中，你需要指定 schema 文件的路径。使用此配置，Drizzle 将
从 `schema.ts` 文件读取，并在迁移生成过程中使用这些信息。有关
`drizzle.config.ts` 文件以及使用 Drizzle 进行迁移的更多信息，请查看：[链接](/docs/sqlite/drizzle-config-file)
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'sqlite',
  schema: './src/db/schema.ts'
})
```

#### 多个文件中的 schema

你可以把 Drizzle 模型——例如表、enum、sequence 等——不仅放在一个文件中，也可以放在你偏好的任何文件中。
你唯一需要确保的是从这些文件中导出所有模型，以便 Drizzle kit 能导入
它们并在迁移中使用。

一种用法是把每张表分离到各自的文件中。
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 countries.ts
          ├ 📜 cities.ts
          ├ 📜 products.ts
          ├ 📜 clients.ts
          └ 📜 etc.ts
```

在 `drizzle.config.ts` 文件中，你需要指定 schema 文件夹的路径。使用此配置，Drizzle 将
从 `schema` 文件夹读取，递归地查找所有文件，并从中获取所有 drizzle 表。有关
`drizzle.config.ts` 文件以及使用 Drizzle 进行迁移的更多信息，请查看：[链接](/docs/sqlite/drizzle-config-file)

```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'sqlite',
  schema: './src/db/schema'
})
```

你也可以按任何你喜欢的方式对它们分组，例如为用户相关表、消息相关表、产品相关表等建立分组。
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 messaging.ts
          └ 📜 products.ts
```

## 塑造你的数据 schema

Drizzle schema 由你所使用数据库中的若干模型类型组成。使用 drizzle，你可以指定：
- 带列、约束等的表
- 视图
- 等。

让我们逐一检查如何使用 drizzle 定义 schema

#### **表和列的声明** 

Drizzle 中的表至少应定义 1 列，这和数据库中应当做的是一样的。有一点很重要需要知道，
Drizzle 中没有所谓通用的表对象。你需要选择你正在使用的方言，PostgreSQL、MySQL、SQLite 等。

![](@/assets/images/table-structure.svg)

```ts copy
import { sqliteTable, integer } from "drizzle-orm/sqlite-core"

export const users = sqliteTable('users', {
  id: integer()
});
```

默认情况下，Drizzle 在数据库查询中将使用 TypeScript 的键名作为列名。
因此，示例中的 schema 和查询将生成下面所示的 SQL 查询

<Callout>
本示例使用了一个 db 对象，其初始化不在本文档这一部分中涉及。要了解如何连接数据库，请参阅 [Connections 文档](/docs/sqlite/get-started-sqlite)
</Callout>

\
**TypeScript 键 = 数据库键**
<Section>
```ts
// schema.ts
import { integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const users = sqliteTable('users', {
  id: integer(),
  first_name: text()
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT "id", "first_name" from users;
```
</Section>

如果你想在 TypeScript 代码和数据库中使用不同的名称，可以使用列别名

<Section>
```ts
// schema.ts
import { integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const users = sqliteTable('users', {
  id: integer(),
  firstName: text('first_name')
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT "id", "first_name" from users;
```
</Section>

### 驼峰与蛇形命名

数据库模型名称通常使用 `snake_case` 约定，而在 TypeScript 中，常见的做法是使用 `camelCase` 命名模型。
这可能导致 schema 中出现大量别名定义。为解决这个问题，Drizzle 提供了一种方式，可以通过专门的构建器自动
将 TypeScript 中的 `camelCase` 映射到数据库中的 `snake_case`。

使用来自 `drizzle-orm/pg-core` 的 `snakeCase` 或 `camelCase` 构建器来声明一张表，其列键
会自动映射到所选的数据库命名约定

<Section>
```ts {2,4,11,12}
// schema.ts
import { snakeCase, camelCase } from 'drizzle-orm/sqlite-core';

export const users = snakeCase.table('users', {
  id: integer().primaryKey(),
  fullName: text(),        // → 数据库中为 full_name
  createdAt: integer({ mode: 'timestamp' }),  // → 数据库中为 created_at
});

// 所有实体类型均可用：
snakeCase.table / snakeCase.view
camelCase.table / camelCase.view
```
```ts
// db.ts
import { drizzle } from "drizzle-orm/better-sqlite3";

const db = drizzle({ connection: process.env.DATABASE_URL })
```
```ts
// query.ts
await db.select().from(users);
```
```sql
select "id", "full_name", "created_at" from "users";
```
</Section>

### 进阶

使用 Drizzle ORM 时，你可以运用几个技巧。只要 Drizzle 完全在 TypeScript 文件中，
你基本上可以用你的代码做任何在简单 TypeScript 项目中能做的事情。

一个常见特性是把列分离到不同位置然后复用它们。
例如，考虑 `updated_at`、`created_at` 和 `deleted_at` 这几列。许多表/模型可能都需要这
三个字段来跟踪和分析系统中实体的创建、删除和更新

我们可以在一个单独的文件中定义这些列，然后导入并将它们展开到你拥有的所有表对象中

<Section>
```ts
// columns.helpers.ts
export const timestamps = {
  updated_at: text(),
  created_at: text().$defaultFn(() => new Date().toISOString()).notNull(),
  deleted_at: text(),
}
```
```ts
// users.sql.ts
export const users = sqliteTable('users', {
  id: integer(),
  ...timestamps
})
```
```ts
// posts.sql.ts
export const posts = sqliteTable('posts', {
  id: integer(),
  ...timestamps
})
```
</Section>

### 示例

了解了基础知识后，让我们为一个真实项目定义一个 schema 示例，以便获得更好的视角和理解

> 所有示例都会使用 `generateUniqueString`。它的实现将在所有 schema 示例之后提供

```ts copy
import * as t from "drizzle-orm/sqlite-core";

export const users = t.sqliteTable(
  "users",
  {
    id: t.integer().primaryKey({ autoIncrement: true }),
    firstName: t.text("first_name"),
    lastName: t.text("last_name"),
    email: t.text().notNull(),
    invitee: t.integer().references((): t.AnySQLiteColumn => users.id),
    role: t.text().$type<"guest" | "user" | "admin">().default("guest"),
  },
  (table) => [
    t.uniqueIndex("email_idx").on(table.email)
  ]
);

export const posts = t.sqliteTable(
  "posts",
  {
    id: t.integer().primaryKey({ autoIncrement: true }),
    slug: t.text().$default(() => generateUniqueString(16)),
    title: t.text(),
    ownerId: t.integer("owner_id").references(() => users.id),
  },
  (table) => [
    t.uniqueIndex("slug_idx").on(table.slug),
    t.index("title_idx").on(table.title),
  ]
);

export const comments = t.sqliteTable("comments", {
  id: t.integer().primaryKey({ autoIncrement: true }),
  text: t.text({ length: 256 }),
  postId: t.integer("post_id").references(() => posts.id),
  ownerId: t.integer("owner_id").references(() => users.id),
});
```

**`generateUniqueString` 实现：**
```ts
function generateUniqueString(length: number = 12): string {
  const characters =
    "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789";
  let uniqueString = "";

  for (let i = 0; i < length; i++) {
    const randomIndex = Math.floor(Math.random() * characters.length);
    uniqueString += characters[randomIndex];
  }

  return uniqueString;
}
```
