# 神奇的 `sql` 操作符 🪄

在使用 ORM 库时，你可能会遇到一些情况：使用提供的 ORM 语法来编写某个
特定查询很有挑战性。在这种情况下，你可以求助于使用
原生查询，即以原始字符串的形式构造查询。然而，原生查询往往
缺乏类型安全和查询参数化带来的好处。

为解决这个问题，许多库引入了 `sql` 模板的概念。这个模板
让你能够编写更类型安全、更参数化的查询，从而增强代码整体的安全性和
灵活性。Drizzle 作为一个强大的 ORM 库，同样支持 sql 模板。

使用 Drizzle 的 `sql` 模板，你可以在构造查询时走得更远。如果你在使用
该库的查询构建器编写整个查询时遇到困难，你可以在 Drizzle 查询的特定部分
有选择地使用 `sql` 模板。这种灵活性让你能够
在部分 SELECT 语句、WHERE 子句、ORDER BY 子句、HAVING
子句、GROUP BY 子句，甚至关系查询构建器中使用 sql 模板。

通过利用 Drizzle 中 sql 模板的能力，你可以在实现所需查询结构复杂度的同时，
保持类型安全和查询参数化的优势。
这使你能在应用中创建更健壮、更易维护的代码。

## sql`` 模板

你在其它 ORM 中可能遇到的最常见用法之一，
是能够将 `sql` 查询原样用于原生查询。

```typescript copy
import { sql } from 'drizzle-orm' 

const id = 69;
await db.execute(sql`select * from ${usersTable} where ${usersTable.id} = ${id}`)
```

它将生成如下查询

```sql
select * from "users" where "users"."id" = ?; --> [69]
```

提供给 sql 参数的任何表和列都会被自动映射为对应的 SQL
语法，其中表名会被转义，并且转义后的表名会被追加到列名之前。

此外，任何动态参数（例如 `${id}`）都会被映射为 `?` 占位符，
相应的值会被移动到一个单独传递给数据库的值数组中。

这种方法有效地防止了任何潜在的 SQL 注入漏洞。

## `sql<T>`

<Callout type="info" emoji="ℹ️">
    请注意，`sql<T>` 不会执行任何运行时映射。你使用 `sql<T>` 定义的类型
    纯粹是给 Drizzle 的辅助提示。重要的是要理解，不存在可行的方式
    来动态确定确切的类型，因为 SQL 查询可以高度多样化和可定制。
</Callout>

你可以在 Drizzle 中定义自定义类型，用于那些字段需要特定类型（而非 `unknown`）的地方。

这个特性在部分选择查询中特别有用，能确保所选字段类型一致：

```typescript
// 未定义 sql<T> 类型
const response: { lowerName: unknown }[] = await db.select({
    lowerName: sql`lower(${usersTable.id})`
}).from(usersTable);

// 定义了 sql<T> 类型
const response: { lowerName: string }[] = await db.select({
    lowerName: sql<string>`lower(${usersTable.id})`
}).from(usersTable);
```

## `sql``.mapWith()`

对于需要为从数据库驱动传递到 drizzle 的值做运行时映射的情况，你可以使用 `.mapWith()`

该函数接受不同的值，这些值将在运行时映射响应。

只要 mapWith 内部的接口与 Column 所实现的接口相同，
你就可以复刻某个特定的列映射策略。

```typescript
import { sqliteTable, integer, text } from 'drizzle-orm/sqlite-core';

const usersTable = sqliteTable('users', {
    id: integer().primaryKey({ autoIncrement: true }),
    name: text().notNull(),
});

//  在运行时，这些值的映射方式将与 drizzle 中 `text` 列的映射方式相同
sql`...`.mapWith(usersTable.name);
```

你也可以为 `DriverValueDecoder` 接口传入你自己的实现：

```ts 
sql``.mapWith({
	mapFromDriverValue: (value: any) => {
		const mappedValue = value;
		// 你想应用的映射
		return mappedValue;
	},
});
    
// 或
sql``.mapWith(Number);
```

## `sql``.as<T>()`

在不同情况下，有时很难确定你想使用的自定义字段该如何命名。
你可能会遇到需要为将被选择的字段
显式指定别名的情况。在处理复杂查询时，这尤其有用。

为应对这些场景，我们引入了一个有用的 `.as('alias_name')` 辅助方法，它让你
可以显式地定义别名。通过利用这个特性，你可以为字段提供清晰且有意义的
名称，让你的查询更直观、更易读。

<Section>
```typescript
sql`lower(usersTable.name)`.as('lower_name')
```
```sql
... (usersTable.name) as lower_name ...
```
</Section>

## `sql.raw()`

有些情况下，你可能不需要根据输入创建参数化值，也不需要将表/列映射为转义后的形式。
相反，你可能只是想按原样生成查询。对于这类情况，我们提供了 `sql.raw()` 函数。

`sql.raw()` 函数让你可以在查询中包含原始 SQL 语句，而无需任何额外的处理或转义。
当你已有预先构造好的 SQL 语句，或需要将复杂或动态的
SQL 代码直接纳入查询时，这会很有用。

<Section>
```typescript
sql.raw(`select * from users where id = ${12}`);
// vs
sql`select * from users where id = ${12}`;
```
```sql
select * from users where id = 12;
--> vs
select * from users where id = ?; --> [12]
```
</Section>

你还可以在 sql 函数内部使用 `sql.raw()`，从而让你可以包含任何原始字符串，
而无需经过主 `sql` 模板函数的转义。

通过在 `sql` 函数内部使用 `sql.raw()`，你可以将未转义的原始字符串
直接纳入查询。当你有特定的 SQL 代码或表达式不应被模板函数的
自动转义或修改时，这会特别有用。

<Section>
```typescript
sql`select * from ${usersTable} where id = ${12}`;
// vs
sql`select * from ${usersTable} where id = ${sql.raw(12)}`;
```
```sql
select * from "users" where id = ?; --> [12]
--> vs
select * from "users" where id = 12;
```
</Section>

## sql.fromList()

`sql` 模板会生成 sql 块，这些块是 SQL 部分的数组，在将 SQL 应用到数据库或在 Drizzle 中执行查询后，
它们会被拼接成查询和参数。

在某些场景中，你可能需要使用自定义业务逻辑
将这些块聚合成一个数组，然后将它们拼接成可以传递给数据库或查询的单个 SQL 语句。
对于这类情况，fromList 函数会非常有用。

fromList 函数让你可以将多个 SQL 块组合成单个 SQL 语句。
你可以用它根据你的具体需求
聚合和拼接各个 SQL 部分，然后获得一个可执行的统一 SQL 查询。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

	if (i === 4) continue;
	sqlChunks.push(sql` or `);
}

const finalSql: SQL = sql.fromList(sqlChunks)
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.join()

确实，`sql.join` 函数的作用与 fromList 辅助函数类似。
不过，在处理 SQL 块之间的空格，或为拼接 SQL 块指定自定义分隔符时，
它提供了额外的灵活性。

使用 `sql.join`，你可以使用指定的分隔符将 SQL 块拼接在一起。
这个分隔符可以是任何你想插入到各块之间的字符串或字符。

当你有特定的格式化或分隔 SQL 块的需求时，这特别有用。
通过指定自定义分隔符，你可以在最终 SQL 查询中实现所需的结构和格式。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql`where`);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

if (i === 4) continue;
    sqlChunks.push(sql`or`);
}

const finalSql: SQL = sql.join(sqlChunks, sql.raw(' '));
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.append()

如果你已经使用 `sql` 模板生成了 SQL，你可以通过 append 函数直接向已生成的 SQL
添加新的块，从而实现与 `fromList` 相同的行为。

通过使用 append 函数，你可以动态地向现有 SQL 字符串添加额外的 SQL 块，
有效地将它们拼接在一起。这让你可以纳入自定义逻辑或业务
规则，将各块聚合到最终 SQL 查询中。

<Section>
```typescript 
const finalSql = sql`select * from users`;

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.empty()

通过使用 sql.empty()，你可以从一个空的 SQL 对象开始，然后按需动态地向它追加 SQL 块。这让你可以逐步构造 SQL 查询，应用自定义逻辑或条件来决定每个块的内容。

一旦你使用 sql.empty() 初始化了 SQL 对象，你就可以利用
sql 模板的全部特性，例如参数化、组合和转义。
这使你能够以灵活且可控的方式构造 SQL 查询，
使其适配你的具体需求。

```typescript 
const finalSql = sql.empty();

// 一些逻辑

finalSql.append(sql`select * from users`);

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```

## 将 `sql` 转换为字符串和参数

在前面所有示例中，你看到了在 TypeScript 中使用 SQL 模板语法
以及生成的 SQL 输出。

如果你需要获取由 SQL 模板生成的查询字符串和相应参数，
你必须指定你想为其生成查询的数据库方言。不同的数据库在
参数化和转义方面有不同的语法，因此选择恰当的方言至关重要。

一旦你选定了方言，你就可以利用相应实现的功能
将 SQL 模板转换为所需的查询字符串和参数格式。这确保
与你正在使用的具体数据库系统兼容。

<Section>
```typescript copy
import { SQLiteSyncDialect } from 'drizzle-orm/sqlite-core';

const sqliteDialect = new SQLiteSyncDialect();
sqliteDialect.sqlToQuery(sql`select * from ${usersTable} where ${usersTable.id} = ${12}`);
```
```sql
select * from "users" where "users"."id" = ?; --> [ 12 ]
```
</Section>

## `sql` select

你也可以在部分选择查询中使用 sql 功能。部分选择查询让你可以
从表中检索特定字段或列，而不是获取整行。

关于部分选择查询的更详细信息，你可以参考 Core API
文档：**[Core API docs](/docs/sqlite/select#basic-and-partial-select)**。

**从表中选择不同的自定义字段**

这里你可以看到 **[`sql<T>`](/docs/sqlite/sql#sqlt)**、**[`sql``.mapWith()`](/docs/sqlite/sql#sqlmapwith)**、**[`sql``.as<T>()`](/docs/sqlite/sql#sqlast)** 的用法。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select({
    id: usersTable.id,
    lowerName: sql<string>`lower(${usersTable.name})`,
    aliasedName: sql<string>`lower(${usersTable.name})`.as('aliased_column'),
    count: sql<number>`count(*)`.mapWith(Number) 
}).from(usersTable)
```
```sql
select `id`, lower(`name`), lower(`name`) as `aliased_column`, count(*) from `users`;
```
</Section>

## `where` 中的 `sql`

确实，Drizzle 提供了一组你可以在 sql 模板中使用的可用表达式。
然而，数据库中通常有更广泛的表达式可用，
包括通过扩展或其它方式提供的表达式。

为确保灵活性并让你能够使用 Drizzle 未原生支持的
任何表达式，你可以自由地
直接使用 sql 函数编写 SQL 模板。这让你能够利用
SQL 的全部能力，并纳入特定于你的目标数据库的任何表达式或功能。

通过使用 sql 模板，你不限于仅使用 Drizzle 中预定义的表达式。
相反，你可以表达复杂查询，并纳入底层数据库系统
所提供的任何受支持的表达式。

**按 `id` 过滤，但使用 sql**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

const id = 77

await db.select()
        .from(usersTable)
        .where(sql`${usersTable.id} = ${id}`)
```
```sql
select * from "users" where "users"."id" = ?; --> [ 77 ]
```
</Section>

**高级全文搜索 where 语句**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

const searchPattern = "%Ale%"

await db.select()
        .from(usersTable)
        .where(sql`lower(${usersTable.name}) like lower(${searchPattern})`)
```
```sql
select * from "users" where lower("users"."name") like lower(?); --> [ "%Ale%" ]
```
</Section>

## `orderBy` 中的 `sql`

当你需要 Drizzle 中不提供的特定排序功能，但又不想求助于原生 SQL 时，
`sql` 模板确实可以在 ORDER BY 子句中使用。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select().from(usersTable).orderBy(sql`${usersTable.id} desc nulls first`)
```
```sql
select * from "users" order by "users"."id" desc nulls first;
```
</Section>

## `having` 和 `groupBy` 中的 `sql`

当你需要 Drizzle 中不提供的特定排序功能，但又不想求助于原生 SQL 时，
`sql` 模板确实可以在 HAVING 和 GROUP BY 子句中使用。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from './schema'

await db.select({ 
    projectId: usersTable.projectId,
    count: sql<number>`count(${usersTable.id})`.mapWith(Number)
}).from(usersTable)
    .groupBy(sql`${usersTable.projectId}`)
    .having(sql`count(${usersTable.id}) > 300`)
```
```sql
select "project_id", count("users"."id") from users group by "users"."project_id" having count("users"."id") > 300; 
```
</Section>
