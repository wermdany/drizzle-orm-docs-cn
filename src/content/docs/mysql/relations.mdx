### `one()`
以下是 drizzle 关系中 `.one()` 可用的所有字段列表

```ts {3-11}
const relations = defineRelations({ users, posts }, (r) => ({
	posts: {
		author: r.one.users({
			from: r.posts.ownerId,
			to: r.users.id,
			optional: false,
      alias: 'custom_name',
			where: {
				verified: true,
			}
		}),
	}
}))
```

- `author` 键是一个自定义键，在使用 Drizzle 关系查询时会出现在 `posts` 对象中。
- `r.one.users` 定义 `author` 将是来自 `users` 表的单个对象，而不是对象数组。
- `from: r.posts.ownerId` 指定我们建立软关系所依据的表。
在本例中，关系从 `posts` 表的 `ownerId` 列开始。
- `to: r.users.id` 指定我们将软关系指向的表。
在本例中，关系指向 `users` 表的 `id` 列。
- 类型层面的 `optional: false` 会让 posts 对象中的 `author` 键变为 `required`。
当你确定该特定实体始终存在时，应该使用它。
- `alias` 用于为表之间的关系添加特定别名。如果两个表之间存在多个完全相同的关系，你应该
使用 `alias` 来区分它们
- `where` 条件可用于多态关系。它会基于 `where` 语句获取关系。
例如，在上面的情况中，只会检索 `已验证的作者`。在[此处](/docs/mysql/relations-schema-declaration#多态关系)了解更多关于多态关系的内容。

### `many()`

以下是 drizzle 关系中 `.many()` 可用的所有字段列表

```ts {3-10}
const relations = defineRelations({ users, posts }, (r) => ({
	users: {
		feed: r.many.posts({
			from: r.users.id,
			to: r.posts.ownerId,
			alias: 'custom_name',
			where: {
				approved: true,
			}
		}),
	}
}))
```

- `feed` 键是一个自定义键，在使用 Drizzle 关系查询时会出现在 `users` 对象中。
- `r.many.posts` 定义 `feed` 将是来自 `posts` 表的对象数组，而不只是一个对象
- `from: r.users.id` 指定我们建立软关系所依据的表。
在本例中，关系从 `users` 表的 `id` 列开始。
- `to: r.posts.ownerId` 指定我们将软关系指向的表。
在本例中，关系指向 `posts` 表的 `ownerId` 列。
- `alias` 用于为表之间的关系添加特定别名。如果两个表之间存在多个完全相同的关系，你应该
使用 `alias` 来区分它们
- `where` 条件可用于多态关系。它会基于 `where` 语句获取关系。
例如，在上面的情况中，只会检索 `已批准的帖子`。在[此处](/docs/mysql/relations-schema-declaration#多态关系)了解更多关于多态关系的内容。

### 一对一
Drizzle ORM 提供了一套 API，让你用 `defineRelations` 函数定义表之间的 `一对一` 关系。

下面是 users 与 users 之间 `一对一` 关系的一个示例，其中一个用户可以邀请另一个用户（本例使用了自引用）：

```typescript copy {10-17}
import { mysqlTable, text, int } from 'drizzle-orm/mysql-core';
import { defineRelations } from 'drizzle-orm';

export const users = mysqlTable('users', {
	id: int().autoincrement().primaryKey(),
	name: text(),
	invitedBy: int('invited_by'),
});

export const relations = defineRelations({ users }, (r) => ({
	users: {
		invitee: r.one.users({
			from: r.users.invitedBy,
			to: r.users.id,
		})
	}
}));
```

另一个示例是一个用户拥有存储在单独表中的资料信息。在这种情况下，因为外键存储在 "profile_info" 表中，user 关系既没有 fields 也没有 references。这会告诉 TypeScript `user.profileInfo` 是可空的：

```typescript copy {15-22}
import { mysqlTable, text, int, json } from 'drizzle-orm/mysql-core';
import { defineRelations } from 'drizzle-orm';

export const users = mysqlTable('users', {
  id: int().autoincrement().primaryKey(),
  name: text(),
});

export const profileInfo = mysqlTable('profile_info', {
  id: int().autoincrement().primaryKey(),
  userId: int('user_id').references(() => users.id),
  metadata: json(),
});

export const relations = defineRelations({ users, profileInfo }, (r) => ({
  users: {
    profileInfo: r.one.profileInfo({
      from: r.users.id,
      to: r.profileInfo.userId,
    }),
  },
}));

const user = await db.query.users.findFirst({ with: { profileInfo: true } });
//____^? type { id: number, name: string | null, profileInfo: { ... } | null  }
```

### 多对多
Drizzle ORM 提供了一套 API，让你通过所谓的 `junction`（联结）或 `join` 表定义表之间的 `多对多` 关系，
这些表必须被显式定义，并存储相关表之间的关联。

下面是 users 与 groups 之间 `多对多` 关系的示例，我们使用 `through` 绕过对联结表的选择，直接为每个 `user` 选择多个 `groups`。
```typescript copy {27-39}
import { defineRelations } from 'drizzle-orm';
import { int, mysqlTable, primaryKey, text } from 'drizzle-orm/mysql-core';

export const users = mysqlTable('users', {
  id: int().autoincrement().primaryKey(),
  name: text(),
});

export const groups = mysqlTable('groups', {
  id: int().autoincrement().primaryKey(),
  name: text(),
});

export const usersToGroups = mysqlTable(
  'users_to_groups',
  {
    userId: int('user_id')
      .notNull()
      .references(() => users.id),
    groupId: int('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [primaryKey({ columns: [t.userId, t.groupId] })],
);

export const relations = defineRelations({ users, groups, usersToGroups },
  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),
        to: r.groups.id.through(r.usersToGroups.groupId),
      }),
    },
    groups: {
      participants: r.many.users(),
    },
  })
);
```

**查询示例：**
```ts
const res = await db.query.users.findMany({
  with: { 
    groups: true 
  },
});

// 响应类型
type Response = {
  id: number;
  name: string | null;
  groups: {
    id: number;
    name: string | null;
  }[];
}[];
```

### 预定义过滤器

Drizzle 关系定义中的预定义 `where` 语句是多态关系实现的一种形式，但并不完全是。本质上，它们让你不仅可以通过选择特定列来
连接表，还可以通过自定义的 `where` 语句来连接。让我们看一些示例：

我们可以定义 `groups` 与 `users` 之间的关系，使得在查询组的用户时，只检索 `verified` 列为 `true` 的用户
<CodeTabs items={["关系", "Schema"]}>
<Section>
```ts

import * as schema from './schema';

export const relations = defineRelations(schema,(r) => ({
    groups: {
      verifiedUsers: r.many.users({
        from: r.groups.id.through(r.usersToGroups.groupId),
        to: r.users.id.through(r.usersToGroups.userId),
        where: {
          verified: true,
        },
      }),
    },
  })
);

...

await db.query.groups.findMany({
    with: {
      verifiedUsers: true,
    },
});
```
</Section>
<Section>
```ts
import * as p from "drizzle-orm/mysql-core";

export const users = p.mysqlTable("users", {
  id: p.int().autoincrement().primaryKey(),
  name: p.text().notNull(),
  verified: p.boolean().notNull(),
});

export const groups = p.mysqlTable("groups", {
  id: p.int().autoincrement().primaryKey(),
  title: p.text().notNull(),
});

export const usersToGroups = p.mysqlTable(
  "users_to_groups",
  {
    userId: p
      .int("user_id")
      .notNull()
      .references(() => users.id, { onDelete: "cascade" }),
    groupId: p
      .int("group_id")
      .notNull()
      .references(() => groups.id, { onDelete: "cascade" }),
  },
  (t) => [p.primaryKey({ columns: [t.groupId, t.userId] })]
);
```
</Section>
</CodeTabs>

<Callout type='warning'>
你只能在目标（to）表上指定过滤器。所以在这个示例中，由于我们建立的是 **指向** users 的关系，where 子句只会包含来自 `users` 表的列

```ts {7}
export const relations = defineRelations(schema,(r) => ({
    groups: {
      verifiedUsers: r.many.users({
        from: r.groups.id.through(r.usersToGroups.groupId),
        to: r.users.id.through(r.usersToGroups.userId),
        where: {
          verified: true,
        },
      }),
    },
  })
);
```
</Callout>

### 关系组成部分

如果你需要把关系配置拆分成多个部分，可以使用 `defineRelationsPart` 辅助函数

```ts
import { defineRelations, defineRelationsPart } from 'drizzle-orm';
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));

export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

然后你可以将它提供给 db 实例

```ts
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })
```

<Callout type='warning'>
你需要遵循一些规则，以确保 `defineRelationsParts` 按预期工作

**规则 1**：如果你用 parts 来指定关系，在将其传给 drizzle db 函数时，你需要按正确的顺序指定它们（主 relations 在前）
```ts
// ✅
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })

// ❌
const db = drizzle(process.env.DB_URL, { relations: { ...part, ...relations } })
```

<Callout collapsed="为什么这很重要？">
即使不会有类型或运行时错误，这就是 "..." 在对象上的工作方式。只要主关系
递归推断出所有表名，它们就能在自动补全中可用。下面是一个示例：

```ts
export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));

export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

这里 `relations` 和 `part` 可以表示为这些对象：
```json
// relations
{
  "users": {"invitee": {...}, "posts": {...}},
  // 在此处添加，这样 schema 中的所有表都会出现在自动补全中
  "posts": {}
}

// part
{
  "posts": {"author": {...}}
}
```

使用 `{ ...relations, ...part }` 会得到
```json
{
  "users": {"invitee": {...}, "posts": {...}},
  "posts": {"author": {...}}
}
```

而使用 `{ ...relations, ...part }` 会得到
```json
{
  "users": {"invitee": {...}, "posts": {...}},
  // 如你在最终对象中所见，posts 的关系信息会丢失
  "posts": {}
}
```

</Callout>

**规则 2**：你应该有主（main）relations，这样 drizzle 才能为自动补全推断出所有表。如果你只想使用 parts，那么
你的其中一个 part 应该是空的，就像这样：

```ts
export const mainPart = defineRelationsPart(schema);
```

在这种情况下，所有表都会被正确推断，你将拥有关于 schema 的完整信息
</Callout>

### 性能

在 Drizzle ORM 中使用关系时，尤其是在拥有
大量数据或复杂查询的应用程序中，优化数据库性能至关重要。
索引在加速数据检索方面起着关键作用，特别是在查询
关联数据时。本节概述了使用 Drizzle ORM 定义的每种
关系类型所推荐的索引策略。

##### 一对一关系

在一对一关系中，比如“用户邀请用户”示例或
“用户拥有资料信息”示例，关键的性能考量是高效地连接
相关表。

<Callout>
为在一对一关系中获得最佳性能，你应该在被引用的
表（关系中的“目标”表）的外键列上
创建索引。
</Callout>

<Callout collapsed='为什么这很重要'>
当你查询带有相关一对一信息的数据时，Drizzle 会执行 JOIN 操作。外键列上的索引让数据库能够快速
定位目标表中的相关行，从而显著加速连接过程。
</Callout>

**示例：**
```typescript
import * as p from 'drizzle-orm/mysql-core';
import { defineRelations } from 'drizzle-orm';

export const users = p.mysqlTable('users', {
	id: p.int().autoincrement().primaryKey(),
	name: p.text(),
});

export const profileInfo = p.mysqlTable('profile_info', {
	id: p.int().autoincrement().primaryKey(),
	userId: p.int('user_id').references(() => users.id),
	metadata: p.json(),
});

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));
```

为了优化获取用户数据及其资料信息的查询，
你应该在 `profile_info` 表的 `userId` 列上创建索引。

```typescript {13-15}
import * as p from 'drizzle-orm/mysql-core';
import { defineRelations } from 'drizzle-orm';

export const users = p.mysqlTable('users', {
	id: p.int().autoincrement().primaryKey(),
	name: p.text(),
});

export const profileInfo = p.mysqlTable('profile_info', {
	id: p.int().autoincrement().primaryKey(),
	userId: p.int('user_id').references(() => users.id),
	metadata: p.json(),
}, (table) => [
  p.index('profile_info_user_id_idx').on(table.userId)
]);

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));
```
```sql
CREATE INDEX `profile_info_user_id_idx` ON `profile_info` (`user_id`);
```

#### 一对多关系

与一对一关系类似，一对多关系也能通过索引显著受益，
以优化连接操作。想想“用户与帖子”的示例，其中一个用户可以拥有很多帖子。

<Callout>
对于一对多关系，在表示关系“多”的一侧的表（即带有引用“一”侧的外键的表）的外键列上创建索引。
</Callout>

<Callout collapsed='为什么这很重要'>
当你获取一个用户及其帖子，或帖子及其作者时，会执行连接。
为外键（`posts` 表中的 `authorId`）建立索引，能让数据库高效地
检索与给定用户关联的所有帖子，或快速找到某篇帖子的作者。
</Callout>

**示例：**
```typescript
import * as p from "drizzle-orm/mysql-core";
import { defineRelations } from 'drizzle-orm';

export const users = p.mysqlTable('users', {
	id: p.int().autoincrement().primaryKey(),
	name: p.text(),
});

export const posts = p.mysqlTable('posts', {
	id: p.int().autoincrement().primaryKey(),
	content: p.text(),
	authorId: p.int('author_id'),
});

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```

为了优化涉及用户及其帖子的查询，在 `posts` 表的 `authorId` 列上创建索引。

```typescript {13-15}
import * as p from "drizzle-orm/mysql-core";
import { defineRelations } from 'drizzle-orm';

export const users = p.mysqlTable('users', {
	id: p.int().autoincrement().primaryKey(),
	name: p.text(),
});

export const posts = p.mysqlTable('posts', {
	id: p.int().autoincrement().primaryKey(),
	content: p.text(),
	authorId: p.int('author_id'),
}, (t) => [
  p.index('posts_author_id_idx').on(t.authorId)
]);

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```
```sql
CREATE INDEX `posts_author_id_idx` ON `posts` (`author_id`);
```

#### 多对多关系

使用联结表实现的多对多关系，需要稍微
更细致的索引策略，以确保最佳的查询性能。
想想带有 `usersToGroups` 联结表的“用户与组”示例。

<Callout>
对于多对多关系，通常建议在联结表上创建以下
索引：
1.  **分别在每个外键列上建立索引：** 这能优化基于
关系单侧进行过滤或连接的查询
（例如，查找某个用户的所有组，或某个组中的所有用户）。
2.  **在两个外键列上共同建立复合索引：** 这对于
高效解析多对多关系本身至关重要。它能加速需要查找两个实体之间连接关系的查询。
</Callout>

<Callout collapsed='为什么这很重要'>
在查询多对多关系时，尤其是在 Drizzle ORM 中使用 `through` 时，数据库需要高效地遍历联结表。

- 在单个外键列（`usersToGroups` 中的 `userId`、`groupId`）上的索引，在你从一侧查询以找到另一侧时很有帮助（例如“查找某个用户的组”）。
- `usersToGroups` 上 `(userId, groupId)` 的复合索引，对于快速找到联结表中定义的所有关系尤为重要。当 Drizzle ORM 解析 `多对多` 关系以获取相关实体时，会用到它。
</Callout>

**示例：**

在“用户与组”示例中，`usersToGroups` 联结表连接了 `users` 和 `groups`。

```typescript
import { defineRelations } from 'drizzle-orm';
import * as p from 'drizzle-orm/mysql-core';

export const users = p.mysqlTable('users', {
  id: p.int().autoincrement().primaryKey(),
  name: p.text(),
});

export const groups = p.mysqlTable('groups', {
  id: p.int().autoincrement().primaryKey(),
  name: p.text(),
});

export const usersToGroups = p.mysqlTable(
  'users_to_groups',
  {
    userId: p.int('user_id')
      .notNull()
      .references(() => users.id),
    groupId: p.int('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [p.primaryKey({ columns: [t.userId, t.groupId] })],
);

export const relations = defineRelations({ users, groups, usersToGroups },
  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),
        to: r.groups.id.through(r.usersToGroups.groupId),
      }),
    },
    groups: {
      participants: r.many.users(),
    },
  })
);
```

为了优化用户与组的查询，按如下方式在 `usersToGroups` 表上创建索引：

```typescript {26-28}
import { defineRelations } from 'drizzle-orm';
import * as p from 'drizzle-orm/mysql-core';

export const users = p.mysqlTable('users', {
  id: p.int().autoincrement().primaryKey(),
  name: p.text(),
});

export const groups = p.mysqlTable('groups', {
  id: p.int().autoincrement().primaryKey(),
  name: p.text(),
});

export const usersToGroups = p.mysqlTable(
  'users_to_groups',
  {
    userId: p.int('user_id')
      .notNull()
      .references(() => users.id),
    groupId: p.int('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [
    p.primaryKey({ columns: [t.userId, t.groupId] }),
    p.index('users_to_groups_user_id_idx').on(t.userId),
    p.index('users_to_groups_group_id_idx').on(t.groupId),
    p.index('users_to_groups_composite_idx').on(t.userId, t.groupId),
  ],
);

export const relations = defineRelations({ users, groups, usersToGroups },
  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),
        to: r.groups.id.through(r.usersToGroups.groupId),
      }),
    },
    groups: {
      participants: r.many.users(),
    },
  })
);
```
```sql
CREATE INDEX `users_to_groups_user_id_idx` ON `users_to_groups` (`user_id`);
CREATE INDEX `users_to_groups_group_id_idx` ON `users_to_groups` (`group_id`);
CREATE INDEX `users_to_groups_composite_idx` ON `users_to_groups` (`user_id`,`group_id`);
```

通过应用这些索引策略，你在处理关系型数据时可以显著提升 Drizzle ORM 应用程序的性能，尤其是在数据量增长、查询变得更复杂时。请记住选择最适合你特定查询模式和应用需求的索引。

### 外键

你可能已经注意到 `relations` 看起来和外键很像——它们甚至都有一个 `references` 属性。那么区别是什么呢？

虽然外键有着类似的目的，即定义表之间的关系，但它们的运作层级与 `relations` 不同。

外键是数据库层面的约束，它们在每次 `insert`/`update`/`delete` 操作时都会被检查，如果违反约束就会抛出错误。
另一方面，`relations` 是更高层次的抽象，它们仅用于在应用层面定义表之间的关系。
它们不会以任何方式影响数据库 schema，也不会隐式创建外键。

这意味着 `relations` 和外键可以一起使用，但它们并不相互依赖。
你可以在不使用外键的情况下定义 `relations`（反之亦然），这使得它们可以用于不支持外键的数据库。

以下两个示例在使用 Drizzle 关系查询数据方面将完全一样地工作。

```ts {15}

  userId: p.int("user_id"),
  metadata: p.json(),

export const relations = defineRelations({ users, profileInfo }, (r) => ({
  users: {
    profileInfo: r.one.profileInfo({
```

### 消除关系歧义

Drizzle 还提供了 `alias` 选项，用于
在你于同两个表之间定义多个关系时消除歧义。例如，
如果你定义了一个 `posts` 表，它带有 `author` 和 `reviewer`
关系。

```ts {19,22,29,34}
import { mysqlTable, int, text } from 'drizzle-orm/mysql-core';
import { defineRelations } from 'drizzle-orm';
 
export const users = mysqlTable('users', {
	id: int().primaryKey(),
	name: text(),
});

export const posts = mysqlTable('posts', {
	id: int().primaryKey(),
	content: text(),
	authorId: int('author_id'),
	reviewerId: int('reviewer_id'),
});
 
export const relations = defineRelations({ users, posts }, (r) => ({
  users: {
    posts: r.many.posts({
      alias: "author",
    }),
    reviewedPosts: r.many.posts({
      alias: "reviewer",
    }),
  },
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
      alias: "author",
    }),
    reviewer: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
      alias: "reviewer",
    }),
  },
}));
```
