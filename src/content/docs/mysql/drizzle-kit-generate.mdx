# `drizzle-kit generate` 

<Prerequisites>
- Drizzle 和 `drizzle-kit` 入门 - [阅读此处](/docs/mysql/get-started)
- Drizzle schema 基础 - [阅读此处](/docs/mysql/sql-schema-declaration)
- 数据库连接基础 - [阅读此处](/docs/mysql/connect-overview)
- Drizzle 迁移基础 - [阅读此处](/docs/mysql/migrations)
- Drizzle Kit [概览](/docs/mysql/kit-overview) 和 [配置文件](/docs/mysql/drizzle-config-file)
</Prerequisites>


<br/>

`drizzle-kit generate` 让你在声明 Drizzle schema 时，或后续 schema 变更时，基于它生成 SQL 迁移。
<Callout collapsed="底层是如何工作的？">
Drizzle Kit `generate` 命令会触发一系列事件：
1. 它会读取你的 Drizzle schema 文件，并组合出你的 schema 的 json 快照
2. 它会读取你之前的迁移文件夹，并将当前 json 快照与最近的一个进行比较
3. 基于 json 差异，它会生成 SQL 迁移
4. 在当前时间戳下的迁移文件夹中保存 `migration.sql` 和 `snapshot.json`

<Section>
```typescript filename="src/schema.ts"
import * as p from "drizzle-orm/mysql-core";

export const users = p.mysqlTable("users", {
  id: p.int().primaryKey().autoincrement(),
  name: p.varchar({ length: 255 }),
  email: p.varchar({ length: 255 }).unique(), 
});
```
```                                  
┌────────────────────────┐                  
│ $ drizzle-kit generate │                  
└─┬──────────────────────┘                  
  │                                           
  └ 1. 读取之前的迁移文件夹
    2. 找出当前 schema 与之前 schema 的差异
    3. 如有必要，提示开发者进行重命名
  ┌ 4. 生成 SQL 迁移并持久化到文件
  │    ┌─┴───────────────────────────────────────┐  
  │      📂 drizzle       
  │      └ 📂 20242409125510_premium_mister_fear
  │        ├ 📜 migration.sql
  │        └ 📜 snapshot.json
  v
```
```sql
-- drizzle/20242409125510_premium_mister_fear/migration.sql

CREATE TABLE `users` (
 `id` int AUTO_INCREMENT PRIMARY KEY,
 `name` varchar(255),
 `email` varchar(255),
 CONSTRAINT `email_unique` UNIQUE INDEX(`email`)
);
```
</Section>
</Callout>

它旨在覆盖 [代码优先](/docs/mysql/migrations) 的 Drizzle 迁移管理方式。
你可以使用 [`drizzle-kit migrate`](/docs/mysql/drizzle-kit-migrate)、drizzle-orm 的 `migrate()`、
诸如 [bytebase](https://www.bytebase.com/) 的外部迁移工具来应用生成的迁移，或直接在数据库上自行运行迁移。

`drizzle-kit generate` 命令要求你同时提供 `dialect` 和 `schema` 路径选项，
你可以通过 [drizzle.config.ts](/docs/mysql/drizzle-config-file) 配置文件或 CLI 选项设置它们
<CodeTabs items={["使用配置文件", "作为 CLI 选项"]}>
<Section>
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "mysql",
  schema: "./src/schema.ts",
});
```
```shell
npx drizzle-kit generate
```
</Section>

```shell
npx drizzle-kit generate --dialect=mysql --schema=./src/schema.ts
```
</CodeTabs>

### schema 文件路径
你可以只有一个 `schema.ts` 文件，也可以在项目中分散放置任意多个 schema 文件。
Drizzle Kit 要求你通过 `schema` 配置选项以 [glob](https://www.digitalocean.com/community/tools/glob?comments=true&glob=/**/*.js&matches=false&tests=//%20This%20will%20match%20as%20it%20ends%20with%20'.js'&tests=/hello/world.js&tests=//%20This%20won't%20match!&tests=/test/some/globs) 的形式指定它们的路径。

### 自定义迁移文件名
你可以通过提供 `--name` CLI 选项来设置自定义迁移文件名
```shell
npx drizzle-kit generate --name=init
```
```plaintext {3}
📦 <project root>
 ├ 📂 drizzle
 │ └ 📂 20242409125510_init
 │   ├ 📜 snapshot.json
 │   └ 📜 migration.sql
 ├ 📂 src
 └ …
```

### 一个项目中的多个配置文件
你可以在项目中拥有多个配置文件，当你存在多个数据库阶段、多个数据库，或同一项目中有不同数据库时，这非常有用：
<Npx>
  drizzle-kit generate --config=drizzle-dev.config.ts
  drizzle-kit generate --config=drizzle-prod.config.ts
</Npx>
```plaintext {5-6}
📦 <project root>
 ├ 📂 drizzle
 ├ 📂 src
 ├ 📜 .env
 ├ 📜 drizzle-dev.config.ts
 ├ 📜 drizzle-prod.config.ts
 ├ 📜 package.json
 └ 📜 tsconfig.json
```

### 自定义迁移
你可以生成空的迁移文件，来编写自己的自定义 SQL 迁移，
用于 Drizzle Kit 目前不支持的 DDL 变更或数据填充。关于自定义迁移的扩展文档 - [参见此处](/docs/mysql/kit-custom-migrations)

```shell
drizzle-kit generate --custom --name=seed-users
```
<Section>
```plaintext {4}
📦 <project root>
 ├ 📂 drizzle
 │ ├ 📂 20242409125510_init
 │ └ 📂 20242409125510_seed-users
 ├ 📂 src
 └ …
```
```sql
-- ./drizzle/20242409125510_seed-users/migration.sql

INSERT INTO `users` (`name`) VALUES('Dan');
INSERT INTO `users` (`name`) VALUES('Andrew');
INSERT INTO `users` (`name`) VALUES('Dandrew');
```
</Section>

### 忽略冲突

如果你需要 `generate` 命令跳过交换性检查并绕过它，可以使用 `--ignore-conflicts`。如果你有想使用它的场景，那么
很有可能是 `drizzle-kit` 没有正确检查迁移，这是一个 bug。请将你的情况报告给我们，以便我们修复

```shell
drizzle-kit generate --ignore-conflicts
```

### 可用配置的扩展列表
`drizzle-kit generate` 有一系列仅限 CLI 的选项

<rem025/>

|               |                                                      |
| :--------     | :--------------------------------------------------- |
| `custom`      | 为自定义迁移生成空 SQL              |
| `name`        | 生成具有自定义名称的迁移                  |
| `ignore-conflicts` | 跳过交换性冲突检查，默认为 `false` |

<rem025/>

<Npx>
drizzle-kit generate --name=init
drizzle-kit generate --name=seed_users --custom
drizzle-kit generate --ignore-conflicts
</Npx>

<br/>
我们推荐通过 [drizzle.config.ts](/docs/mysql/drizzle-config-file) 文件配置 `drizzle-kit`，
不过如有必要，你也可以通过 CLI 提供所有配置选项，例如在 CI/CD 流水线中等。

|               |            |                                                                            |
| :------------ | :-------   | :----------------------------------------------------------------------    |
| `dialect`     | `required` | 数据库方言，为 <Dialects/> 之一                                       |
| `schema`      | `required` | typescript schema 文件或包含多个 schema 文件的文件夹的路径  |
| `out`         |            | 迁移输出文件夹，默认为 `./drizzle`                           |
| `config`      |            | 配置文件路径，默认为 `drizzle.config.ts`                    |
| `breakpoints` |            | SQL 语句断点，默认为 `true`                              |


### 扩展示例
如何创建一个名为 `0001_seed-users.sql` 的自定义 MySQL 迁移文件的示例，
其中 Drizzle schema 位于 `./src/schema.ts`，迁移文件夹命名为 `./migrations` 而不是默认的 `./drizzle`。

我们还会将 drizzle 配置文件放在 `configs` 文件夹中。

让我们创建配置文件：

```plaintext {4}
📦 <project root>
 ├ 📂 migrations
 ├ 📂 configs
 │ └ 📜 drizzle.config.ts
 ├ 📂 src
 └ …
```
```ts filename='drizzle.config.ts'
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "mysql",
  schema: "./src/schema.ts",
  out: "./migrations",
});
```

现在运行
```shell
npx drizzle-kit generate --config=./configs/drizzle.config.ts --name=seed-users --custom
```
它就会成功生成

```plaintext {5}
📦 <project root>
 ├ …
 ├ 📂 migrations
 │ ├ 📂 20242409125510_init
 │ └ 📂 20242409125510_seed-users
 └ …
```
```sql
-- ./drizzle/20242409125510_seed-users/migration.sql

INSERT INTO `users` (`name`) VALUES('Dan');
INSERT INTO `users` (`name`) VALUES('Andrew');
INSERT INTO `users` (`name`) VALUES('Dandrew');
```
