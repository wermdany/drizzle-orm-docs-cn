# Drizzle schema

Drizzle 让你用 TypeScript 定义 schema，并支持底层数据库所支持的各种模型和属性。 
当你定义 schema 时，它就充当未来查询修改（使用 Drizzle-ORM）
和迁移（使用 Drizzle-Kit）的事实来源。

<Callout> 
如果你使用 Drizzle-Kit 进行迁移流程，请确保导出 schema 文件中定义的所有模型，以便 Drizzle-Kit 能够导入它们并在迁移 diff 流程中使用它们。 
</Callout>

<CodeTabs items={["使用 imports", "使用 callback", "使用 import *"]}>
```ts
import { int, mysqlTable, varchar } from "drizzle-orm/mysql-core";

export const usersTable = mysqlTable("users", {
  id: int().primaryKey().autoincrement(),
  name: varchar({ length: 256 }).notNull(),
  age: int().notNull(),
  email: varchar({ length: 256 }).notNull().unique(),
});
```
```ts
import { mysqlTable } from "drizzle-orm/mysql-core";

export const usersTable = mysqlTable("users", (t) => ({
  id: t.int().primaryKey().autoincrement(),
  name: t.varchar({ length: 256 }).notNull(),
  age: t.int().notNull(),
  email: t.varchar({ length: 256 }).notNull().unique(),
}));
```
```ts
import * as t from "drizzle-orm/mysql-core";

export const usersTable = t.mysqlTable("users", {
  id: t.int().primaryKey().autoincrement(),
  name: t.varchar({ length: 256 }).notNull(),
  age: t.int().notNull(),
  email: t.varchar({ length: 256 }).notNull().unique(),
});
```
</CodeTabs>

## 组织你的 schema 文件 
你可以直接在 TypeScript 中声明你的 SQL schema，既可以放在单个 `schema.ts` 文件中，
也可以分散到各处——随你偏好，完全自由！

#### 单文件中的 schema
使用 Drizzle 声明 schema 最常见的方式是把所有表放入一个 `schema.ts` 文件中。

> 注意：你可以随意命名你的 schema 文件。例如，它可以叫 `models.ts`，或者别的什么。

如果你没有定义太多表模型，或者你愿意将它们全部放在一个文件中，这种方式就很合适

示例：
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📜 schema.ts
```

在 `drizzle.config.ts` 文件中，你需要指定 schema 文件的路径。使用此配置，Drizzle 将
从 `schema.ts` 文件读取，并在迁移生成过程中使用这些信息。关于 `drizzle.config.ts` 文件以及使用 Drizzle 进行迁移的更多信息，
请查看：[链接](/docs/mysql/drizzle-config-file)
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'mysql',
  schema: './src/db/schema.ts'
})
```

#### 多文件中的 schema

你可以将你的 Drizzle 模型——例如表、枚举、序列等——不仅仅放在一个文件中，而是放在你喜欢的任何文件中。 
你唯一必须确保的是从这些文件中导出所有模型，以便 Drizzle kit 能够导入它们
并在迁移中使用它们。

一个使用场景是将每个表分离到它自己的文件中。
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 countries.ts
          ├ 📜 cities.ts
          ├ 📜 products.ts
          ├ 📜 clients.ts
          └ 📜 etc.ts
```

在 `drizzle.config.ts` 文件中，你需要指定 schema 文件夹的路径。使用此配置，Drizzle 将
从 `schema` 文件夹读取，递归地查找所有文件，并从那里获取所有 drizzle 表。关于 `drizzle.config.ts` 文件以及使用 Drizzle 进行迁移的更多信息，
请查看：[链接](/docs/mysql/drizzle-config-file)

```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'mysql',
  schema: './src/db/schema'
})
```

你也可以按任何你喜欢的方式对它们进行分组，例如为用户相关表、消息相关表、产品相关表等创建分组。 
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 messaging.ts
          └ 📜 products.ts
```

## 塑造你的数据 schema

Drizzle schema 由你所用数据库中的若干模型类型组成。使用 drizzle，你可以指定：
- 带有列、约束等的表
- Schema，在 MySQL 中等价于数据库
- 枚举
- 视图
- 等等。

让我们逐一来看，检查应该如何用 drizzle 定义 schema

#### **表和列的声明** 

Drizzle 中的表至少应定义 1 列，就像在数据库中应该做的那样。有一点很重要需要了解，
drizzle 中并不存在通用表对象这样的东西。你需要选择你正在使用的方言，PostgreSQL、MySQL、SQLite 等。

![](@/assets/images/table-structure.svg)

```ts copy
import { mysqlTable, int } from "drizzle-orm/mysql-core"

export const users = mysqlTable('users', {
  id: int()
});
```

默认情况下，Drizzle 会在数据库查询中使用 TypeScript 的键名作为列名。 
因此，示例中的 schema 和查询将生成如下所示的 SQL 查询

<Callout>
此示例使用了一个 db 对象，其初始化不在本文档的这一部分中涵盖。要了解如何连接到数据库，请参阅 [Connections Docs](/docs/mysql/get-started-mysql)
</Callout>

\
**TypeScript 键 = 数据库键**
<Section>
```ts
// schema.ts
import { int, mysqlTable, varchar } from "drizzle-orm/mysql-core";

export const users = mysqlTable('users', {
  id: int(),
  first_name: varchar({ length: 256 })
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT `id`, `first_name` FROM `users`;
```
</Section>

如果你想在 TypeScript 代码和数据库中使用不同的名称，可以使用列别名

<Section>
```ts
// schema.ts
import { int, mysqlTable, varchar } from "drizzle-orm/mysql-core";

export const users = mysqlTable('users', {
  id: int(),
  firstName: varchar('first_name', { length: 256 })
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT `id`, `first_name` FROM `users`;
```
</Section>

### 驼峰命名与蛇形命名

数据库模型名称通常使用 `snake_case` 约定，而在 TypeScript 中，命名模型常见的是使用 `camelCase`。 
这可能导致 schema 中出现大量别名定义。为了解决这个问题，Drizzle 提供了一种方式，通过专门构建的构建器
自动将 TypeScript 中的 `camelCase` 映射到数据库中的 `snake_case`。

使用来自 `drizzle-orm/pg-core` 的 `snakeCase` 或 `camelCase` 构建器来声明一个表，其列键
会自动映射到所选的数据库命名约定

<Section>
```ts {2,4,11,12}
// schema.ts
import { snakeCase, camelCase } from 'drizzle-orm/mysql-core';

export const users = snakeCase.table('users', {
  id: int().primaryKey().autoincrement(),
  fullName: text(), // → 数据库中的 full_name
  createdAt: timestamp(), // → 数据库中的 created_at
});

// 可用于所有实体类型：
snakeCase.table / snakeCase.view / snakeCase.schema
camelCase.table / camelCase.view / camelCase.schema
```
```ts
// db.ts
import { drizzle } from "drizzle-orm/mysql2";

const db = drizzle({ connection: process.env.DATABASE_URL })
```
```ts
// query.ts
await db.select().from(users);
```
```sql
select `id`, `full_name`, `created_at` from `users`;
```
</Section>

### 高级

你可以使用一些技巧来配合 Drizzle ORM。只要 Drizzle 完全在 TypeScript 文件中，
你基本上可以用你的代码做任何在简单 TypeScript 项目中会做的事。

一个常见的特性是将列分离到不同的地方然后复用它们。 
例如，考虑 `updated_at`、`created_at` 和 `deleted_at` 列。许多表/模型可能需要这三个
字段来跟踪和分析系统中实体的创建、删除和更新

我们可以在单独的文件中定义这些列，然后导入并将它们展开到你所拥有的所有表对象中

<Section>
```ts
// columns.helpers.ts
export const timestamps = {
  updated_at: timestamp(),
  created_at: timestamp().defaultNow().notNull(),
  deleted_at: timestamp(),
}
```
```ts
// users.sql.ts
export const users = mysqlTable('users', {
  id: int(),
  ...timestamps
})
```
```ts
// posts.sql.ts
export const posts = mysqlTable('posts', {
  id: int(),
  ...timestamps
})
```
</Section>

#### **Schemas**


在 MySQL 中，有一个称为 `Schema` 的实体，但在 MySQL 术语中，它等价于 `Database`。 

你可以使用 `drizzle-orm` 定义它们并在查询中使用它们，但它们不会被 `drizzle-kit` 检测到，也不会被包含在迁移流程中

![](@/assets/images/mysql-db-structure.png)

使用 Drizzle 定义你想要管理的 schema
```ts
import { mysqlSchema } from "drizzle-orm/mysql-core"

export const customSchema = mysqlSchema('custom');
```

然后将表放入该 schema 对象中
```ts {5-7}
import { int, mysqlSchema } from "drizzle-orm/mysql-core";

export const customSchema = mysqlSchema('custom');

export const users = customSchema.table('users', {
  id: int()
})
```

### 示例

掌握了基础知识后，让我们为一个真实项目定义一个 schema 示例，以便更好地了解和理解

> 所有示例都将使用 `generateUniqueString`。它的实现将在所有 schema 示例之后提供

```ts copy
import { mysqlTable as table } from "drizzle-orm/mysql-core";
import * as t from "drizzle-orm/mysql-core";
import type { AnyMySqlColumn } from "drizzle-orm/mysql-core";

export const users = table(
  "users",
  {
    id: t.int().primaryKey().autoincrement(),
    firstName: t.varchar("first_name", { length: 256 }),
    lastName: t.varchar("last_name", { length: 256 }),
    email: t.varchar({ length: 256 }).notNull(),
    invitee: t.int().references((): AnyMySqlColumn => users.id),
    role: t.mysqlEnum(["guest", "user", "admin"]).default("guest"),
  },
  (table) => [
    t.uniqueIndex("email_idx").on(table.email)
  ]
);

export const posts = table(
  "posts",
  {
    id: t.int().primaryKey().autoincrement(),
    slug: t.varchar({ length: 256 }).$default(() => generateUniqueString(16)),
    title: t.varchar({ length: 256 }),
    ownerId: t.int("owner_id").references(() => users.id),
  },
  (table) => [
    t.uniqueIndex("slug_idx").on(table.slug),
    t.index("title_idx").on(table.title),
  ]
);

export const comments = table("comments", {
  id: t.int().primaryKey().autoincrement(),
  text: t.varchar({ length: 256 }),
  postId: t.int("post_id").references(() => posts.id),
  ownerId: t.int("owner_id").references(() => users.id),
});
```

**`generateUniqueString` 实现：**
```ts
function generateUniqueString(length: number = 12): string {
  const characters =
    "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789";
  let uniqueString = "";

  for (let i = 0; i < length; i++) {
    const randomIndex = Math.floor(Math.random() * characters.length);
    uniqueString += characters[randomIndex];
  }

  return uniqueString;
}
```
