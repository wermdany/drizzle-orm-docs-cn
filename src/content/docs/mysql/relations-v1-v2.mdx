### API 变更
#### 与 v1 相比有哪些不同

{/* ##### Drizzle Relations schema 定义 */}

最大的更新之一在于 **Relations Schema 定义**

第一个区别是，你不再需要为每个表在不同对象中分别指定 `relations`，
然后再把它们连同 schema 一起传给 `drizzle()`。在关系查询 v2 中，你现在有一个专门的地方来
指定你需要的所有表的所有关系。

回调中的 `r` 参数提供了全面的自动补全
功能——包括你 schema 中的所有表以及 `one`、`many` 和 `through` 等函数——基本上
提供了你指定关系所需的一切。

```ts
// relations.ts
import * as schema from "./schema"
import { defineRelations } from "drizzle-orm"

export const relations = defineRelations(schema, (r) => ({
    ...
}));
```
```ts
// index.ts
import { relations } from "./relations"
import { drizzle } from "drizzle-orm/mysql2"

const db = drizzle(process.env.DATABASE_URL, { relations })
```

##### 有什么不同？

<Callout collapsed="Schema 定义">
```ts copy
import * as p from 'drizzle-orm/mysql-core';

export const users = p.mysqlTable('users', {
  id: p.int().primaryKey(),
  name: p.text(),
  invitedBy: p.int('invited_by'),
});

export const posts = p.mysqlTable('posts', {
  id: p.int().primaryKey(),
  content: p.text(),
  authorId: p.int('author_id'),
});
```
</Callout>

**所有关系集中在一个地方**

<Callout title="❌ v1">
```ts
import { relations } from "drizzle-orm/_relations";
import { users, posts } from './schema';

export const usersRelation = relations(users, ({ one, many }) => ({
  invitee: one(users, {
    fields: [users.invitedBy],
    references: [users.id],
  }),
  posts: many(posts),
}));

export const postsRelation = relations(posts, ({ one, many }) => ({
  author: one(users, {
    fields: [posts.authorId],
    references: [users.id],
  }),
}));
```
</Callout>

<Callout title='✅ v2'>
```ts
import { defineRelations } from "drizzle-orm";
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  },
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
}));
```
</Callout>

你仍然可以把它拆分到不同的 `parts` 中，并且可以让这些 part 任意大小

```ts
import { defineRelations, defineRelationsPart } from 'drizzle-orm';
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));

export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

然后你可以将它提供给 db 实例

```ts
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })
```

**只定义 `many` 而不定义 `one`**

在 v1 中，如果你只想要关系的 `many` 一侧，你必须在另一端指定 `one` 一侧，
这带来了糟糕的开发者体验。

在 v2 中，你可以直接使用 `many` 一侧，无需任何额外步骤

<Callout title="❌ v1">
```ts
import { relations } from "drizzle-orm/_relations";
import { users, posts } from './schema';

export const usersRelation = relations(users, ({ one, many }) => ({
  posts: many(posts),
}));

export const postsRelation = relations(posts, ({ one, many }) => ({
  author: one(users, {
    fields: [posts.authorId],
    references: [users.id],
  }),
}));
```
</Callout>

<Callout title='✅ v2'>
```ts
import { defineRelations } from "drizzle-orm";
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    posts: r.many.posts({
      from: r.users.id,
      to: r.posts.authorId,
    }),
  },
}));
```
</Callout>

**新增 `optional` 选项**

类型层面的 `optional: false` 会让 `posts` 对象中的 `author` 键变为必填。
当你确定该特定实体始终存在时，应该使用它。

<Callout title="❌ v1">
v1 中不支持
</Callout>

<Callout title='✅ v2'>
```ts {9}
import { defineRelations } from "drizzle-orm";
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    posts: r.one.posts({
      from: r.users.id,
      to: r.posts.authorId,
      optional: false,
    }),
  },
}));
```
</Callout>

**`drizzle()` 中不再有 modes**

我们找到了对所有 MySQL 方言使用同一策略的方法，因此无需再指定它们

<Callout title="❌ v1">
```ts
import * as schema from './schema'

const db = drizzle(process.env.DATABASE_URL, { mode: "planetscale", schema });
// 或者
const db = drizzle(process.env.DATABASE_URL, { mode: "default", schema });
```
</Callout>

<Callout title='✅ v2'>
```ts
import { relations } from './relations'

const db = drizzle(process.env.DATABASE_URL, { relations });
```
</Callout>

**`from` 和 `to` 的升级**

我们将 `fields` 重命名为 `from`，将 `references` 重命名为 `to`，并让两者都既能接受单个值，也能接受数组

<Callout title="❌ v1">
```ts
...
author: one(users, {
  fields: [posts.authorId],
  references: [users.id],
}),
...
```
</Callout>

<Callout title='✅ v2'>
```ts
... 
author: r.one.users({
  from: r.posts.authorId,
  to: r.users.id,
}),
...
```
```ts
... 
author: r.one.users({
  from: [r.posts.authorId],
  to: [r.users.id],
}),
...
```
</Callout>

**`relationName` -> `alias`**

<Callout title="❌ v1">
```ts {8}
import { relations } from "drizzle-orm/_relations";
import { users, posts } from './schema';

export const postsRelation = relations(posts, ({ one }) => ({
  author: one(users, {
    fields: [posts.authorId],
    references: [users.id],
	  relationName: "author_post",
  }),
}));
```
</Callout>

<Callout title='✅ v2'>
```ts {9}
import { defineRelations } from "drizzle-orm";
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
      alias: "author_post",
    }),
  },
}));
```
</Callout>

**`custom types` 新增函数**

自定义类型中新增了几个函数，因此你可以控制关系查询 v2 中数据的映射方式：

<Callout collapsed='fromJson'>
可选的映射函数，用于将以 JSON 形式从数据库数据转换后返回的数据转换为期望的格式
例如，当通过 [RQB](/docs/rqb) 或 JSON 函数查询 bigint 列时，结果字段会以其字符串表示形式返回，而常规查询返回的是 bigint
为了处理这一点，我们需要一个单独的函数来处理这类字段的映射：
```ts
fromJson(value: string): bigint {
	return BigInt(value);
},
```
这会使返回的数据从：
```ts
{
	customField: "5044565289845416380";
}
```
变为：
```ts
{
	customField: 5044565289845416380n;
}
```
</Callout> 
<Callout collapsed='forJsonSelect'>
可选的选择修饰函数，用于修改 JSON 函数内部对列的选择
此类场景可能需要的额外映射可以通过 fromJson 函数来处理
由 [关系查询](/docs/rqb) 使用

例如，使用 bigint 时，我们需要将字段转换为 text 以保持数据完整性
```ts
forJsonSelect(identifier: SQL, sql: SQLGenerator, arrayDimensions?: number): SQL {
	return sql`${identifier}::text`
},
```
这会将查询从：
```sql
SELECT
	row_to_json("t".*)
	FROM
	(
		SELECT
		"table"."custom_bigint" AS "bigint"
		FROM
		"table"
	) AS "t"
```
变为：
```sql
SELECT
	row_to_json("t".*)
	FROM
	(
		SELECT
		"table"."custom_bigint"::text AS "bigint"
		FROM
		"table"
	) AS "t"
```
查询对象返回的内容将从：
```ts
{
	bigint: 5044565289845416000; // 由于直接转换为 JSON 格式导致部分数据丢失
}
```
变为：
```ts
{
	bigint: "5044565289845416380"; // 由于在 JSON 化之前将字段转换为文本，数据得以保留
}
```
</Callout>

<Callout title='✅ v2'>
```ts
const customBytes = customType<{
 	data: Buffer;
 	driverData: Buffer;
 	jsonData: string;
 }>({
 	dataType: () => 'bytea',
 	fromJson: (value) => {
 		return Buffer.from(value.slice(2, value.length), 'hex');
 	},
 	forJsonSelect: (identifier, sql, arrayDimensions) =>
 		sql`${identifier}::text${sql.raw('[]'.repeat(arrayDimensions ?? 0))}`,
 });
```

</Callout>

##### 有什么新内容？

**用于多对多关系的 `through`**

以前，你需要通过联结表查询，然后为每个响应手动映射

现在你不再需要这样做了！

<Callout collapsed='Schema'>
```ts
import * as p from 'drizzle-orm/mysql-core';

export const users = p.mysqlTable('users', {
  id: p.int().primaryKey(),
  name: p.text(),
  verified: p.boolean().notNull(),
});

export const groups = p.mysqlTable('groups', {
  id: p.int().primaryKey(),
  name: p.text(),
});

export const usersToGroups = p.mysqlTable(
  'users_to_groups',
  {
    userId: p
      .int('user_id')
      .notNull()
      .references(() => users.id),
    groupId: p
      .int('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [p.primaryKey({ columns: [t.userId, t.groupId] })],
);

```
</Callout>

<Callout title="❌ v1">
```ts
export const usersRelations = relations(users, ({ many }) => ({
  usersToGroups: many(usersToGroups),
}));

export const groupsRelations = relations(groups, ({ many }) => ({
  usersToGroups: many(usersToGroups),
}));

export const usersToGroupsRelations = relations(usersToGroups, ({ one }) => ({
  group: one(groups, {
    fields: [usersToGroups.groupId],
    references: [groups.id],
  }),
  user: one(users, {
    fields: [usersToGroups.userId],
    references: [users.id],
  }),
}));
```
```ts
// 查询示例
const response = await db.query.users.findMany({
  with: {
    usersToGroups: {
      columns: {},
      with: {
        group: true,
      },
    },
  },
});
```
</Callout>

<Callout title='✅ v2'>
```ts
import * as schema from './schema';
import { defineRelations } from 'drizzle-orm';

export const relations = defineRelations(schema, (r) => ({
  users: {
    groups: r.many.groups({
      from: r.users.id.through(r.usersToGroups.userId),
      to: r.groups.id.through(r.usersToGroups.groupId),
    }),
  },
  groups: {
    participants: r.many.users(),
  },
}));
```
```ts
// 查询示例
const response = await db.query.users.findMany({
  with: {
    groups: true,
  },
});
```
</Callout>

#### 如何将关系 schema 定义从 v1 迁移到 v2

##### **选项 1**：使用 `drizzle-kit pull`

在新版本中，`drizzle-kit pull` 支持以新语法拉取 `relations.ts` 文件：

##### 步骤 1

<Npx>
drizzle-kit pull
</Npx>

#### 步骤 2 

将生成的 relations 代码从 `drizzle/relations.ts` 传输到你在其中指定关系的文件
```plaintext {4-5}
 ├ 📂 drizzle
 │ ├ 📂 meta
 │ ├ 📜 migration.sql
 │ ├ 📜 relations.ts ────────┐
 │ └ 📜 schema.ts            |
 ├ 📂 src                    │ 
 │ ├ 📂 db                   │
 │ │ ├ 📜 relations.ts <─────┘
 │ │ └ 📜 schema.ts 
 │ └ 📜 index.ts         
 └ …
```

<Callout>
`drizzle/relations.ts` 包含从 `drizzle/schema.ts` 导入所有表的内容，看起来像这样：
```ts
import * as schema from './schema'
```

你可能需要将这个导入改为指向包含你所有 schema 表的文件。

如果有多个 schema 文件，你可以这样做：
```ts
import * as schema1 from './schema1'
import * as schema2 from './schema2'
...
```
</Callout>

#### 步骤 3

修改 drizzle 数据库实例的创建，提供 `relations` 对象而不是 `schema`

<Callout title='之前'>
```ts
import * as schema from './schema'
import { drizzle } from 'drizzle-orm/mysql2'

const db = drizzle('<url>', { schema })
```
</Callout>

<Callout title='之后'>
```ts
// 应该从 步骤 2 中的文件导入
import { relations } from './relations'
import { drizzle } from 'drizzle-orm/mysql2'

const db = drizzle('<url>', { relations })
```
</Callout>

<Callout>
如果你使用的是 MySQL 方言，可以从 `drizzle()` 中移除 `mode`，因为在版本 2 中不再需要它
</Callout>

##### **选项 2**：手动迁移

如果你想手动迁移，可以查看我们的 [Drizzle 关系章节](/docs/mysql/relations)，了解完整的 API 参考以及一对一、一对多和多对多关系的示例。

#### 如何将查询从 v1 迁移到 v2

```sql
	`d0`.`last_login` AS `lastLogin`,
	`d0`.`subscription_end` AS `subscriptionEnd`,
	`d0`.`last_activity` AS `lastActivity`,
	`d0`.`preferences` AS `preferences`,
	`d0`.`interests` AS `interests`
FROM
	`users` AS `d0`
WHERE
	(
		(
			(
				(`d0`.`name` LIKE 'john%')
				OR (`d0`.`name` LIKE 'jane%')
			)
		)
		AND (`d0`.`age` BETWEEN 25 AND 35)
	);
```
</CodeTab>
</CodeTabs>

##### 迁移 `orderBy` 语句

Order by 被简化为单个对象，你在其中指定列和排序方向（`asc` 或 `desc`）

<Callout title="❌ v1">
```ts
const response = db._query.users.findMany({
  orderBy: (users, { asc }) => [asc(users.id)],
});
```
</Callout>

<Callout title="✅ v2">
```ts
const response = db.query.users.findMany({
  orderBy: { id: "asc" },
});
```
</Callout>

##### 迁移 `many-to-many` 查询

关系查询 v1 管理多对多查询的方式非常复杂。
你必须使用联结表显式地通过它们进行查询，然后手动映射这些表，就像这样：

```ts
const response = await db.query.users.findMany({
  with: {
    usersToGroups: {
      columns: {},
      with: {
        group: true,
      },
    },
  },
});
```

升级到关系查询 v2 后，你的多对多关系会变成这样：

```ts
import * as schema from './schema';
import { defineRelations } from 'drizzle-orm';

export const relations = defineRelations(schema, (r) => ({
  users: {
    groups: r.many.groups({
      from: r.users.id.through(r.usersToGroups.userId),
      to: r.groups.id.through(r.usersToGroups.groupId),
    }),
  },
  groups: {
    participants: r.many.users(),
  },
}));
```

当你迁移查询时，它会变成这样：

```ts
// 查询示例
const response = await db.query.users.findMany({
  with: {
    groups: true,
  },
});
```
