# v1 中的变更

本页展示了从 `drizzle-orm@0.x`、`drizzle-kit@0.x`、`drizzle-seed@0.x` 到最新的 `drizzle-orm@1.0`、`drizzle-kit@1.0`、`drizzle-seed@1.0` 之间所有发生变更的内容

<Callout type="info">
阅读更多关于如何升级的内容[此处](/docs/mysql/upgrade-v1)
</Callout>

## 破坏性变更

#### 移除 Relational Queries v1

RQBv1 已被移除。请改用带有全新 `defineRelations()` API 及新特性的[关系查询 v2](/docs/mysql/relations)。你可以[此处](/docs/mysql/relations-v1-v2)找到更多关于从 rqb v1 迁移到 v2 的细节

围绕 `defineRelations()` 构建的新关系系统：

```ts
import { defineRelations } from 'drizzle-orm';

const relations = defineRelations(schema, (r) => ({
  users: {
    posts: r.many.posts(),
    profile: r.one.profiles(),
  },
  posts: {
    author: r.one.users({
      from: posts.authorId,
      to: users.id,
    }),
  },
}));
```

#### 校验器包合并进 `drizzle-orm`

<Callout type="warning">
你仍然可以使用 drizzle-zod/valibot/typebox/arktype 校验包，但所有新的更新都将直接添加到 Drizzle ORM 中
</Callout>

- drizzle-zod -> drizzle-orm/zod
- drizzle-valibot -> drizzle-orm/valibot
- drizzle-typebox -> drizzle-orm/typebox-legacy (using @sinclair/typebox)
- drizzle-typebox -> drizzle-orm/typebox (using typebox)
- drizzle-arktype -> drizzle-orm/arktype
- 新增 `drizzle-orm/effect-schema` 包

#### 新的 Casing API

旧版的 `drizzle({ casing: 'camelCase' })` 已被替换为表/视图/schema 级别的 API：

```ts
import { snakeCase, camelCase } from 'drizzle-orm/mysql-core';

export const users = snakeCase.table('users', {
  id: int().primaryKey().autoincrement(),
  fullName: text(),       // → 数据库中的 full_name
  createdAt: timestamp(), // → 数据库中的 created_at
});

// 可用于所有实体类型：
snakeCase.table / snakeCase.view / snakeCase.materializedView / snakeCase.schema
camelCase.table / camelCase.view / camelCase.materializedView / camelCase.schema
```

#### `.generatedAlwaysAs()` 仅接受 SQL

```ts
// ❌ 之前 — 接受原始值
.generatedAlwaysAs('some expression')

// ✅ 之后 — 仅接受 sql`` 或 () => sql``
.generatedAlwaysAs(sql`some expression`)
.generatedAlwaysAs(() => sql`some expression`)
```

#### `getTableColumns` 弃用

请改用 `getColumns`

```ts
// ❌ 之前
import { getTableColumns } from 'drizzle-orm';

const columns = getTableColumns(users);

// ✅ 之后
import { getColumns } from 'drizzle-orm';

const columns = getColumns(users);
```

#### 新的迁移文件夹结构（v3）

**关联讨论**：[#2832](https://github.com/drizzle-team/drizzle-orm/discussions/2832)

<br/>

- 不再有 `journal.json`
- SQL 文件和快照分组到独立的迁移文件夹中
- 移除了 `drizzle-kit drop` 命令

这些改动消除了与 journal 文件之间潜在的 Git 冲突，并简化了删除或修复冲突迁移的过程

<Callout type="info">
阅读更多关于如何升级的内容[此处](/docs/mysql/upgrade-v1)
</Callout>


#### `drizzle-kit push --strict` 弃用

`--strict` 标志已被移除 — 其行为现已成为默认行为。`drizzle-kit push` 对于会造成数据丢失的语句始终会提示确认，除非传入了 `--force` 标志。使用 [drizzle-kit push --explain](/docs/mysql/drizzle-kit-push) 可以在执行前预览将要运行的 SQL。

#### Drizzle seed：UUID 生成器升级到 v4

UUID 生成器现在会生成符合 RFC 4122 v4 的 UUID，确保与 Zod v4 校验兼容。使用 `{ version: '1' }` 可保留旧行为，或使用 `{ version: '2' | '3' }` 启用更新的生成器。

## 其他特性

#### 新的数据类型

MySQL 方言新增了列类型：`blob`、`tinyblob`、`mediumblob` 和 `longblob`。你可以[此处](/docs/mysql/column-types#blob)了解更多。

```ts
import { mysqlTable, blob, tinyblob, mediumblob, longblob } from 'drizzle-orm/mysql-core';

const files = mysqlTable('files', {
  tiny: tinyblob(),
  regular: blob(),
  medium: mediumblob(),
  large: longblob(),
});
```

#### JIT 映射器（可选启用）

即时编译的行映射器（Just-in-time compiled row mappers），让映射速度与原始驱动一样快。
你可以[此处](/docs/mysql/jit-mappers)了解更多

```ts {1}
const db = drizzle({ ..., jit: true });
```

#### 新的 MSSQL 方言

新增了对 MSSQL 方言的支持。你可以[此处](/docs/mssql/get-started-mssql)了解更多

#### 新的 CockroachDB 方言

新增了对 CockroachDB 方言的支持。你可以[此处](/docs/cockroach/get-started-cockroach)了解更多

#### 新的 NetlifyDB 驱动

新增了对 NetlifyDB 驱动的支持。你可以[此处](/docs/connect-netlify-db)了解更多

<Callout>
注意：Netlify 数据库驱动由 Netlify 团队开发和维护。
</Callout>

#### SQLcommenter 支持

为查询添加自定义标签。标签会作为 SQL 注释附加到每个查询末尾。你可以[此处](/docs/sql-comments)了解更多

```ts
db.select().from(users).comment("my_first_tag");
// select "id", "name" from "users" /*my_first_tag*/
```

#### 通过 `.as()` 设置列别名

你可以[此处](/docs/aliases)找到更多关于别名的信息
```ts
const query = db
  .select({ age: users.age.as('ageOfUser'), id: users.id.as('userId') })
  .from(users)
  .orderBy(asc(users.id.as('userId')));
```

#### 全面重写 `drizzle-kit`

该工具在架构上进行了重新设计：
- 从数据库快照迁移到 DDL 快照
- 重构了差异检测与应用
- Schema 内省从约 10 秒缩短到 1 秒以内
- 为 push 添加了查询提示和 explain 支持

#### `drizzle-kit pull --init`

创建 drizzle 迁移表并将首个拉取的迁移标记为已应用。你可以[此处](/docs/drizzle-kit-pull)了解更多

#### `drizzle-kit push --explain`

显示将要执行的 SQL，而不会真正运行它。你可以[此处](/docs/drizzle-kit-push)了解更多

#### `drizzle-kit check` — 交换性检查

检测跨分支的非可交换迁移 — 例如两个分支修改同一列，或一个分支重命名表而另一个分支在修改该表。

工作原理：
- 从快照 `prevIds` 构建 DAG，以理解分支结构
- 找出分支分叉的分叉点
- 计算从父快照到每个分支末端的 DDL 差异
- 使用一个记录哪些 DDL 语句类型可能相互干扰的足迹映射来检查冲突

如果发现冲突，报告会准确告诉你哪些分支上的哪些迁移不兼容，以及哪些语句发生碰撞。

#### `drizzle-kit --ignore-conflicts` 标志

当你知道这些冲突是预期之内时，可绕过可交换性检查。

#### `drizzle-kit generate`：迁移冲突检测

`drizzle-kit generate` 现在会识别迁移分支之间的[不兼容变更](/docs/mysql/v0-v1-changes#drizzle-kit-check--交换性检查)。使用 `--ignore-conflicts` 绕过。

#### 迁移表的更新

运行 `drizzle-kit up` 时，迁移表会自动升级。新增了两个列：

- **`name`** — 完整的迁移文件夹名称（例如 `20250220153045_brave_wolverine`）
- **`applied_at`** — 迁移执行时的时间戳（已存在的行会用 `NULL` 回填）

| 列 | 类型 | v0 | v1 |
| --- | --- | --- |:---:|
| `id` | serial | 是 | 是 |
| `hash` | text | 是 | 是 |
| `created_at` | bigint | 是 | 是（旧版） |
| `name` | text | — | 新增 |
| `applied_at` | timestamp | — | 新增 |

现在迁移通过其完整文件夹名称而非时间戳来匹配。即使两个迁移在同一秒内生成，名称后缀也能保证唯一性。

升级过程中，已存在的行会通过多步策略回填：
1. **毫秒匹配** — 将存储的毫秒截断到秒，与本地文件夹时间戳匹配
2. **哈希决胜** — 如果多个迁移共享同一秒，则通过 SQL 哈希来区分
3. **仅哈希回退** — 如果毫秒匹配完全失败，则仅通过哈希匹配

<br/>
这意味着升级能够处理所有边缘情况：正常的单人开发项目、迁移时间紧密相邻的团队，甚至旧 journal 数据与新文件夹名称并不完全对应的情况。

#### Migrator 应用所有缺失的迁移

以前，迁移器只会查找创建日期晚于最后一个已应用迁移的本地迁移。现在它会检测并应用**每一个缺失的迁移**，无论时间戳顺序如何。所有迁移都会按其完整文件夹名称（14 位 UTC 时间戳 + 名称后缀）进行匹配。

#### drizzle 配置文件中的顶层 `await`

现在在 Node.js 上的 `drizzle.config.ts` 和 schema 文件中支持顶层 `await`。

#### Drizzle-kit：构建系统改进

- 从 `esbuild-register` 迁移到 `tsx` loader — 无缝支持 ESM 和 CJS
- 原生支持 Bun 和 Deno 启动

#### TS Schema 文件处理

仅处理以下扩展名的文件：`.js`、`.mjs`、`.cjs`、`.jsx`、`.ts`、`.mts`、`.cts`、`.tsx`。所有其它文件类型都会被忽略。

#### Drizzle Seed：在 refinements 中忽略列

在填充种子数据时跳过特定列 — 转而使用数据库默认值：

```ts
await seed(db, schema).refine((f) => ({
  users: {
    count: 5,
    columns: {
      name: f.fullName(),
      photo: false, // 跳过 — 将使用数据库默认值
    },
  },
}));
```

#### `min` / `max` 参数

基于时间的生成器现在接受边界：

```ts
funcs.time({ min: '13:12:13', max: '15:12:13' })
funcs.timestamp({ min: '2024-01-01T00:00:00Z', max: '2025-01-01T00:00:00Z' })
funcs.datetime({ min: '2024-01-01', max: '2025-01-01' })
```
