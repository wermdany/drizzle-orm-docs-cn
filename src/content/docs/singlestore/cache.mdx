# 缓存

默认情况下，Drizzle 会把每个查询直接发送到你的数据库。没有隐藏行为，没有自动缓存
或失效——你始终能确切看到运行了什么。如果你想要缓存，必须显式启用。

默认情况下，Drizzle 使用 `explicit` 缓存策略（即 `global: false`），因此除非你主动要求，否则任何内容都不会被缓存。
这可以避免应用中出现意外情况或隐藏的性能陷阱。
或者，你可以开启 `all` 缓存（`global: true`），这样每个 select 都会优先查找缓存。

## 快速开始

### Upstash 集成

Drizzle 开箱即用提供了一个 `upstashCache()` 辅助函数。默认情况下，如果设置了环境变量，它会使用自动配置的 Upstash Redis。

```ts
import { upstashCache } from "drizzle-orm/cache/upstash";
import { drizzle } from "drizzle-orm/...";

const db = drizzle(process.env.DB_URL!, {
  cache: upstashCache({ token: process.env.UPSTASH_TOKEN, url: process.env.UPSTASH_URL }),
});
```

你也可以显式定义你的 Upstash 凭证、默认为所有查询启用全局缓存，或传入自定义缓存选项：

```ts
import { upstashCache } from "drizzle-orm/cache/upstash";
import { drizzle } from "drizzle-orm/...";

const db = drizzle(process.env.DB_URL!, {
  cache: upstashCache({
    // 👇 Redis 凭证（可选 —— 也可以从环境变量中读取）
    url: '<UPSTASH_URL>',
    token: '<UPSTASH_TOKEN>',

    // 👇 默认为所有查询启用缓存（可选）
    global: true,

    // 👇 默认缓存行为（可选）
    config: { ex: 60 }
  })
});
```

## 缓存配置参考

Drizzle 为 Upstash 支持以下缓存配置选项：

```ts
export type CacheConfig = {
  /**
   * 过期时间，以秒为单位（正整数）
   */
  ex?: number;
  /**
   * 为给定 hash 键的一个或多个字段设置过期时间（TTL 或 time to live）。
   * 用于 HEXPIRE 命令
   */
  hexOptions?: "NX" | "nx" | "XX" | "xx" | "GT" | "gt" | "LT" | "lt";
};
```

## 缓存用法示例

配置好缓存后，缓存的行为如下：

**情形 1：使用 `global: false` 的 Drizzle（默认，选择性启用缓存）**

```ts
import { upstashCache } from "drizzle-orm/cache/upstash";
import { drizzle } from "drizzle-orm/...";

const db = drizzle(process.env.DB_URL!, {
  // 👇 未传入 `global: true`，默认为 false
  cache: upstashCache({ url: "", token: "" }),
});
```

在这种情况下，下面的查询不会从缓存中读取

```ts
const res = await db.select().from(users);

// 任何变更操作仍会触发缓存的 onMutate 处理器
// 并尝试使任何涉及受影响表的已缓存查询失效
await db.insert(users).value({ email: "cacheman@upstash.com" });
```

要让此查询从缓存中读取，请调用 `.$withCache()`

```ts
const res = await db.select().from(users).$withCache();
```

`.$withCache` 有一组选项，可用于管理和配置这个特定查询的策略

```ts
// 为这个特定查询重写配置
.$withCache({ config: {} })

// 为这个查询提供自定义缓存键（而不是在底层对 query+params 进行哈希）
.$withCache({ tag: 'custom_key' })

// 为此查询关闭自动失效
// 注意：这会导致最终一致性（下文会说明）
.$withCache({ autoInvalidate: false })
```

<Callout>
**最终一致性示例**

此示例仅在你手动设置 `autoInvalidate: false` 时才有意义。默认情况下，`autoInvalidate` 是启用的。

在以下情况下，你可能想要关闭 `autoInvalidate`：
- 你的数据不常变化，且轻微的数据陈旧是可以接受的（例如商品列表、博客文章）
- 你手动处理缓存失效

在这些情况下，关闭它可以减少不必要的缓存失效。不过，在大多数情况下，我们建议保持默认启用状态。

示例：假设你以 3 秒的 TTL 缓存了 `usersTable` 上的以下查询：

``` ts
const recent = await db
  .select().from(usersTable)
  .$withCache({ config: { ex: 3 }, autoInvalidate: false });
```

如果某人执行了 `db.insert(usersTable)...`，缓存不会立即失效。在最多 3 秒内，你会一直看到旧数据，直到它最终变为一致。
</Callout>

**情形 2：使用 `global: true` 选项的 Drizzle**

```ts
import { upstashCache } from "drizzle-orm/cache/upstash";
import { drizzle } from "drizzle-orm/...";

const db = drizzle(process.env.DB_URL!, {
  cache: upstashCache({ url: "", token: "", global: true }),
});
```

在这种情况下，下面的查询会从缓存中读取

```ts
const res = await db.select().from(users);
```

如果你想为此特定查询禁用缓存，请调用 `.$withCache(false)`

```ts
// 为此查询禁用缓存
const res = await db.select().from(users).$withCache(false);
```

你也可以使用 `db` 上的缓存实例来使特定的表或 tag 失效

```ts
// 使所有使用 `users` 表的查询失效。你可以使用 Drizzle 实例来完成。
await db.$cache.invalidate({ tables: users });
// 或
await db.$cache.invalidate({ tables: [users, posts] });

// 使所有使用 `usersTable` 的查询失效。你只需使用表名即可。
await db.$cache.invalidate({ tables: "usersTable" });
// 或
await db.$cache.invalidate({ tables: ["usersTable", "postsTable"] });

// 你也可以使任何先前执行的 select 查询中定义的自定义 tag 失效。
await db.$cache.invalidate({ tags: "custom_key" });
// 或
await db.$cache.invalidate({ tags: ["custom_key", "custom_key1"] });
```

## 自定义缓存

此示例展示了如何在 Drizzle 中接入自定义 `cache`：你提供用于从缓存中获取数据、将结果存回缓存，以及在每次变更运行时使条目失效的函数。

缓存扩展提供了这组配置选项
```ts
export type CacheConfig = {
  /** 过期时间，以秒为单位 */
  ex?: number;
  /** 过期时间，以毫秒为单位 */
  px?: number;
  /** 该键将过期的 Unix 时间（秒） */
  exat?: number;
  /** 该键将过期的 Unix 时间（毫秒） */
  pxat?: number;
  /** 更新键时保留现有的 TTL */
  keepTtl?: boolean;
  /** HEXPIRE（hash 字段 TTL）的选项 */
  hexOptions?: 'NX' | 'XX' | 'GT' | 'LT' | 'nx' | 'xx' | 'gt' | 'lt';
};
```

```ts
const db = drizzle(process.env.DB_URL!, { cache: new TestGlobalCache() });
```

```ts
import Keyv from "keyv";

export class TestGlobalCache extends Cache {
  private globalTtl: number = 1000;
  // 此对象将用于存储某个特定表使用了哪些查询键，
  // 以便我们之后可以用它进行失效处理。
  private usedTablesPerKey: Record<string, string[]> = {};

  constructor(private kv: Keyv = new Keyv()) {
    super();
  }

  // 关于策略，我们有两个选项：
  // - 'explicit'：仅当在查询中添加 .$withCache() 时才使用缓存。
  // - 'all'：所有查询都会全局缓存。
  // 默认行为是 'explicit'。
  override strategy(): "explicit" | "all" {
    return "all";
  }

  // 此函数接收被缓存到 key 参数中的查询和参数，
  // 允许你从缓存中检索此查询的响应值。
  override async get(key: string): Promise<any[] | undefined> {
    const res = (await this.kv.get(key)) ?? undefined;
    return res;
  }

  // 此函数接收若干选项，用于定义缓存数据将如何存储：
  // - 'key'：经过哈希的查询和参数。
  // - 'response'：Drizzle 从数据库返回的值数组。
  // - 'tables'：select 查询中涉及的表数组。此信息在缓存失效时需要用到。
  // - 'isTag'：布尔标志，指示此缓存条目是否表示基于 tag 的查询。
  //    当为 true 时，该条目与特定 tag 关联，而不是与表级别的失效关联，
  //    允许你按 tag 名称使已缓存的查询失效。参见 UpstashCache：
  //    https://github.com/drizzle-team/drizzle-orm/blob/beta/drizzle-orm/src/cache/upstash/cache.ts 查看示例
  //
  // 例如，如果某个查询使用了 "users" 和 "posts" 表，你可以存储此信息。之后，当应用对这些表执行
  // 任何变更语句时，你可以从缓存中移除对应的键。
  // 如果你可以接受查询的最终一致性，则可以跳过此选项。
  override async put(
    key: string,
    response: any,
    tables: string[],
    isTag: boolean = false,
    config?: CacheConfig,
  ): Promise<void> {
    const ttl = config?.px ?? (config?.ex ? config.ex * 1000 : this.globalTtl);

    await this.kv.set(key, response, ttl);

    for (const table of tables) {
      const keys = this.usedTablesPerKey[table];
      if (keys === undefined) {
        this.usedTablesPerKey[table] = [key];
      } else {
        keys.push(key);
      }
    }
  }

  // 当执行 insert、update 或 delete 语句时会调用此函数。
  // 你可以跳过此步骤，也可以使使用受影响表的查询失效。
  //
  // 该函数接收一个带有两个键的对象：
  // - 'tags'：用于带有特定 tag 标签的查询，允许你按该 tag 进行失效。
  // - 'tables'：实际受 insert、update 或 delete 语句影响的表，
  //   帮助你追踪自上次缓存更新以来哪些表发生了变化。
  override async onMutate(params: {
    tags: string | string[];
    tables: string | string[] | Table<any> | Table<any>[];
  }): Promise<void> {
    const tagsArray = params.tags
      ? Array.isArray(params.tags)
        ? params.tags
        : [params.tags]
      : [];
    const tablesArray = params.tables
      ? Array.isArray(params.tables)
        ? params.tables
        : [params.tables]
      : [];

    const keysToDelete = new Set<string>();

    for (const table of tablesArray) {
      const tableName = is(table, Table)
        ? getTableName(table)
        : (table as string);
      const keys = this.usedTablesPerKey[tableName] ?? [];
      for (const key of keys) keysToDelete.add(key);
    }

    if (keysToDelete.size > 0 || tagsArray.length > 0) {
      for (const tag of tagsArray) {
        await this.kv.delete(tag);
      }

      for (const key of keysToDelete) {
        await this.kv.delete(key);
        for (const table of tablesArray) {
          const tableName = is(table, Table)
            ? getTableName(table)
            : (table as string);
          this.usedTablesPerKey[tableName] = [];
        }
      }
    }
  }
}
```

## 限制

#### `cache` 扩展不会处理的查询：

- 将缓存与原始查询一起使用，例如：

```ts
db.execute(sql`select 1`);
```

- 在 `d1` 和 `libsql` 中将缓存与 `batch` 功能一起使用

```ts
db.batch([
    db.insert(users).values(...),
    db.update(users).set(...).where()
])
```

- 在事务中使用缓存
```ts
await db.transaction(async (tx) => {
  await tx.update(accounts).set(...).where(...);
  await tx.update...
});
```

#### 暂时性的限制，很快会被处理：

- 将缓存与 Drizzle 关系查询一起使用
```ts
await db.query.users.findMany();
```
