# Drizzle 迁移基础

SQL 数据库要求你预先指定将要存储的实体的**严格 schema**，
如果（当）你需要改变这些实体的形态 —— 你就需要**schema 迁移**来完成。

管理数据库迁移有多种生产级别的方案。
无论你是**数据库优先（database first）**还是**代码库优先（codebase first）**，Drizzle 都被设计为能完美适配所有方案。

**数据库优先**是指你的数据库 schema 是唯一的真实来源。你可以直接在数据库上，
或通过数据库迁移工具管理数据库 schema，然后把数据库 schema 拉取到你的代码库应用层实体中。

**代码库优先**是指你代码库中的数据库 schema 是唯一的真实来源，并处于版本控制之下。你在 JavaScript/TypeScript 中声明并管理数据库 schema，
然后通过 Drizzle、直接操作或外部迁移工具将该 schema 应用到数据库本身。

#### Drizzle 能提供什么帮助？
我们构建了 [**drizzle-kit**](/docs/singlestore/kit-overview) —— 用于配合 Drizzle 管理迁移的 CLI 应用。
```shell
drizzle-kit migrate
drizzle-kit generate
drizzle-kit push
drizzle-kit pull
```
它的设计目标是让你根据当前的业务需求来选择如何管理迁移。

它同时适配数据库优先和代码库优先两种方式，让你可以**推送 schema**、**生成 SQL 迁移**文件，或从数据库**拉取 schema**。
无论你是独立开发还是团队协作，它都非常适用。

<Tag style="font-size: 12px">**选项 1**</Tag>
> 我自己通过外部迁移工具管理数据库 schema，或者直接在我的数据库上运行 SQL 迁移。
> 从 Drizzle 这边，我只需要从数据库获取 schema 的当前状态，并保存为 TypeScript schema 文件。

<Callout collapsed="展开详情">
这是**数据库优先**的方式。你的数据库 schema 是**唯一的真实来源**，
Drizzle 让你使用 [`drizzle-kit pull`](/docs/singlestore/drizzle-kit-pull) 命令将数据库 schema 拉取到 TypeScript 中。

```
│ ~ drizzle-kit pull       │      │                        │        `name` varchar(255),
└─┬────────────────────────┘      │        DATABASE        │        `email` varchar(255) unique
  │                               │                        │       );
  └ Pull datatabase schema -----> │                        │
  ┌ Generate Drizzle       <----- │                        │
  │ schema TypeScript file        └────────────────────────┘
  │
  v
```
```typescript
import * as p from "drizzle-orm/singlestore-core";

export const users = p.singlestoreTable("users", {
  id: p.int().primaryKey().autoincrement(),
  name: p.varchar({ length: 255 }),
  email: p.varchar({ length: 255 }).unique(),
});
```

<Tag style="font-size: 12px">**选项 2**</Tag>
> 我想把数据库 schema 放在我的 TypeScript 代码库中，
> 我不想处理 SQL 迁移文件。
> 我想让 Drizzle 把我的 schema 直接“推送”到数据库

<Callout collapsed="展开详情">
这是**代码库优先**的方式。你的 TypeScript Drizzle schema 是**唯一的真实来源**，
Drizzle 让你使用 [`drizzle-kit push`](/docs/singlestore/drizzle-kit-push) 命令将 schema 变更推送到数据库。

这是快速原型开发的最佳方式，我们看到许多团队
和独立开发者成功地将它作为生产应用中的主要迁移流程。

<Section>
```typescript {6} filename="src/schema.ts"
import * as p from "drizzle-orm/singlestore-core";

export const users = p.singlestoreTable("users", {
  id: p.int().primaryKey().autoincrement(),
  name: p.varchar({ length: 255 }),
  email: p.varchar({ length: 255 }).unique(), // <--- 新增的列
});
```

<Tag style="font-size: 12px">**选项 3**</Tag>
> 我想把数据库 schema 放在我的 TypeScript 代码库中，
> 我想让 Drizzle 为我生成 SQL 迁移文件并将它们应用到我的数据库

```typescript filename="src/schema.ts"
});
```
```                                  
┌────────────────────────┐                  
│ $ drizzle-kit generate │                  
└─┬──────────────────────┘                  
  │                                           
  └ 1. read previous migration folders
    2. find diff between current and previous schema
    3. prompt developer for renames if necessary
  ┌ 4. generate SQL migration and persist to file
  │    ┌─┴───────────────────────────────────────┐  
  │      📂 drizzle       
  │      └ 📂 20242409125510_premium_mister_fear
  │        ├ 📜 snapshot.json
  │        └ 📜 migration.sql
  v
```
```sql
-- drizzle/20242409125510_premium_mister_fear/migration.sql

 `id` int auto_increment primary key,
 `name` varchar(255),
 `email` varchar(255) unique
);

```

```
└─┬─────────────────────┘                  
  │                                                         ┌──────────────────────────┐                                         
  └ 1. read migration.sql files in migrations folder        │                          │
    2. fetch migration history from database -------------> │                          │
  ┌ 3. pick previously unapplied migrations <-------------- │         DATABASE         │
  └ 4. apply new migration to the database ---------------> │                          │
                                                            │                          │
                                                            └──────────────────────────┘
```

<Tag style="font-size: 12px">**选项 4**</Tag>
> 我想把数据库 schema 放在我的 TypeScript 代码库中，
> 我想让 Drizzle 为我生成 SQL 迁移文件，并且我想让 Drizzle 在运行时应用它们

<Callout collapsed="展开详情">
这是**代码库优先**的方式。你的 TypeScript Drizzle schema 是唯一的真实来源，

然后你可以在应用运行时将它们应用到数据库。

这种方式广泛用于**单体**应用，在零停机部署期间应用数据库迁移，
如果出现问题则回滚 DDL 变更。
它也用于**无服务器**部署，迁移在部署过程中作为**自定义资源**运行一次。

```typescript filename="src/schema.ts"
});

```

```                                  
  ┌ 4. generate SQL migration and persist to file

  │      📂 drizzle       
  │      └ 📂 20242409125510_premium_mister_fear
  │        ├ 📜 snapshot.json
  │        └ 📜 migration.sql
```
