# Drizzle schema

Drizzle 让你可以使用底层数据库支持的各种模型和属性在 TypeScript 中定义 schema。
当你定义 schema 时，它将成为未来查询（使用 Drizzle-ORM）
和迁移（使用 Drizzle-Kit）修改的真相来源。

<Callout> 
如果你使用 Drizzle-Kit 进行迁移流程，请确保导出 schema 文件中定义的所有模型，以便 Drizzle-Kit 可以导入它们并在迁移差异（diff）过程中使用它们。
</Callout>

<CodeTabs items={["使用 imports", "使用 callback", "使用 import *"]}>
```ts
import { int, singlestoreTable, varchar } from "drizzle-orm/singlestore-core";

export const usersTable = singlestoreTable("users", {
  id: int().primaryKey().autoincrement(),
  name: varchar({ length: 256 }).notNull(),
  age: int().notNull(),
  email: varchar({ length: 256 }).notNull().unique(),
});
```
```ts
import { singlestoreTable } from "drizzle-orm/singlestore-core";

export const usersTable = singlestoreTable("users", (t) => ({
  id: t.int().primaryKey().autoincrement(),
  name: t.varchar({ length: 256 }).notNull(),
  age: t.int().notNull(),
  email: t.varchar({ length: 256 }).notNull().unique(),
}));
```
```ts
import * as t from "drizzle-orm/singlestore-core";

export const usersTable = t.singlestoreTable("users", {
  id: t.int().primaryKey().autoincrement(),
  name: t.varchar({ length: 256 }).notNull(),
  age: t.int().notNull(),
  email: t.varchar({ length: 256 }).notNull().unique(),
});
```
</CodeTabs>

## 组织你的 schema 文件 
你可以直接在 TypeScript 中在单个 `schema.ts` 文件中声明 SQL schema，
或者将它们分散放置——随你喜欢，完全自由！

#### 单文件中的 schema
使用 Drizzle 声明 schema 最常见的方式是将所有表放入一个 `schema.ts` 文件中。

> 注意：你可以随意命名你的 schema 文件。例如，它可以叫 `models.ts` 或其他名字。

如果你没有定义太多的表模型，或者你不介意将它们都放在一个文件中，这种方法效果很好

示例：
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📜 schema.ts
```

在 `drizzle.config.ts` 文件中，你需要指定 schema 文件的路径。使用此配置，Drizzle 将
从 `schema.ts` 文件读取，并在迁移生成过程中使用这些信息。关于
`drizzle.config.ts` 文件以及使用 Drizzle 进行迁移的更多信息，请查看：[链接](/docs/singlestore/drizzle-config-file)
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'singlestore',
  schema: './src/db/schema.ts'
})
```

#### 多个文件中的 schema

你可以将你的 Drizzle 模型——例如表、enum、序列等——不仅放在一个文件中，而是放在任何你喜欢的文件中。
你唯一必须确保的是从这些文件中导出所有模型，以便 Drizzle kit 可以导入
它们并在迁移中使用。

一个用例是将每个表分离到各自的文件中。
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 countries.ts
          ├ 📜 cities.ts
          ├ 📜 products.ts
          ├ 📜 clients.ts
          └ 📜 etc.ts
```

在 `drizzle.config.ts` 文件中，你需要指定 schema 文件夹的路径。使用此配置，Drizzle 将
从 `schema` 文件夹读取，递归找到所有文件并从中获取所有 drizzle 表。关于
`drizzle.config.ts` 文件以及使用 Drizzle 进行迁移的更多信息，请查看：[链接](/docs/singlestore/drizzle-config-file)

```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: 'singlestore',
  schema: './src/db/schema'
})
```

你也可以按任何你喜欢的方式对它们进行分组，例如为用户相关的表、消息相关的表、产品相关的表等创建分组。
```plaintext
📦 <project root>
 └ 📂 src
    └ 📂 db
       └ 📂 schema
          ├ 📜 users.ts
          ├ 📜 messaging.ts
          └ 📜 products.ts
```

## 构建你的数据 schema

Drizzle schema 由你所使用数据库的若干模型类型组成。使用 drizzle 你可以指定：
- 带有列、约束等的表
- Schema，在 SingleStore 中它等同于数据库
- Enums
- Views
- 等等。

让我们逐一检查如何使用 drizzle 定义 schema

#### **表和列的声明** 

在 Drizzle 中定义表时至少需要 1 列，与在数据库中的做法相同。有一件重要的事情需要知道，
Drizzle 中没有通用表对象这种东西。你需要选择 SingleStore 表对象。

![](@/assets/images/table-structure.svg)

```ts copy
import { singlestoreTable, int } from "drizzle-orm/singlestore-core"

export const users = singlestoreTable('users', {
  id: int()
});
```

默认情况下，Drizzle 会在数据库查询中对列使用 TypeScript 键名。
因此，示例中的 schema 和查询将生成如下所示的 SQL 查询

<Callout>
此示例使用了一个 db 对象，其初始化未在本文档的这一部分中涵盖。要了解如何连接数据库，请参阅 [Connections Docs](/docs/singlestore/get-started-singlestore)
</Callout>

\
**TypeScript 键 = 数据库键**
<Section>
```ts
// schema.ts
import { int, singlestoreTable, varchar } from "drizzle-orm/singlestore-core";

export const users = singlestoreTable('users', {
  id: int(),
  first_name: varchar({ length: 256 })
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT `id`, `first_name` FROM `users`;
```
</Section>

如果你想在 TypeScript 代码和数据库中使用不同的名称，可以使用列别名

<Section>
```ts
// schema.ts
import { int, singlestoreTable, varchar } from "drizzle-orm/singlestore-core";

export const users = singlestoreTable('users', {
  id: int(),
  firstName: varchar('first_name', { length: 256 })
})
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT `id`, `first_name` FROM `users`;
```
</Section>

### 驼峰与蛇形命名

数据库模型名称通常使用 `snake_case` 约定，而在 TypeScript 中，常用 `camelCase` 来命名模型。
这可能导致 schema 中出现大量别名定义。为了解决这个问题，Drizzle 提供了一种方式，通过在 Drizzle 数据库初始化时包含一个可选参数，自动将
TypeScript 中的 `camelCase` 映射到数据库中的 `snake_case`

对于此类映射，你可以在 Drizzle DB 声明中使用 `casing` 选项。此参数将
帮助你指定数据库模型命名约定，并会尝试相应地映射所有 JavaScript 键

<Section>
```ts
// schema.ts
import { int, singlestoreTable, varchar } from "drizzle-orm/singlestore-core";

export const users = singlestoreTable('users', {
  id: int(),
  firstName: varchar({ length: 256 })
})
```
```ts
// db.ts
import { drizzle } from "drizzle-orm/singlestore";

const db = drizzle({ connection: process.env.DATABASE_URL, casing: 'snake_case' })
```
```ts
// query.ts
await db.select().from(users);
```
```sql
SELECT `id`, `first_name` FROM `users`;
```
</Section>

### 进阶

使用 Drizzle ORM 时你可以使用一些技巧。只要 Drizzle 完全位于 TypeScript 文件中，
你的代码基本上可以做在任何简单 TypeScript 项目中能做的任何事情。

一个常见的特性是将列分离到不同的地方然后复用它们。
例如，考虑 `updated_at`、`created_at` 和 `deleted_at` 列。许多表/模型可能需要这
三个字段来跟踪和分析系统中实体的创建、删除和更新

我们可以在单独的文件中定义这些列，然后导入并将它们展开到你所拥有的所有表对象中

<Section>
```ts
// columns.helpers.ts
const timestamps = {
  updated_at: timestamp(),
  created_at: timestamp().defaultNow().notNull(),
  deleted_at: timestamp(),
}
```
```ts
// users.sql.ts
export const users = singlestoreTable('users', {
  id: int(),
  ...timestamps
})
```
```ts
// posts.sql.ts
export const posts = singlestoreTable('posts', {
  id: int(),
  ...timestamps
})
```
</Section>

#### **Schema**

\
在 SingleStore 中，有一种称为 `Schema` 的实体，但在 SingleStore 术语中，它等同于 `Database`。

你可以使用 `drizzle-orm` 定义它们并在查询中使用它们，但它们不会被 `drizzle-kit` 检测到，也不会包含在迁移流程中

![](@/assets/images/mysql-db-structure.png)

使用 Drizzle 定义你想管理的 schema
```ts
import { singlestoreSchema } from "drizzle-orm/singlestore-core"

export const customSchema = singlestoreSchema('custom');
```

然后将表放入 schema 对象内
```ts {5-7}
import { int, singlestoreSchema } from "drizzle-orm/singlestore-core";

export const customSchema = singlestoreSchema('custom');

export const users = customSchema.table('users', {
  id: int()
})
```

### 示例

了解了基础知识后，让我们为一个真实项目定义一个 schema 示例，以便获得更好的视角和理解

> 所有示例都将使用 `generateUniqueString`。它的实现将在所有 schema 示例之后提供

```ts copy
import { singlestoreTable as table } from "drizzle-orm/singlestore-core";
import * as t from "drizzle-orm/singlestore-core";
import { AnyMySqlColumn } from "drizzle-orm/singlestore-core";

export const users = table(
  "users",
  {
    id: t.int().primaryKey().autoincrement(),
    firstName: t.varchar("first_name", { length: 256 }),
    lastName: t.varchar("last_name", { length: 256 }),
    email: t.varchar({ length: 256 }).notNull(),
    invitee: t.int().references((): AnyMySqlColumn => users.id),
    role: t.singlestoreEnum(["guest", "user", "admin"]).default("guest"),
  },
  (table) => [
    t.uniqueIndex("email_idx").on(table.email)
  ]
);

export const posts = table(
  "posts",
  {
    id: t.int().primaryKey().autoincrement(),
    slug: t.varchar({ length: 256 }).$default(() => generateUniqueString(16)),
    title: t.varchar({ length: 256 }),
    ownerId: t.int("owner_id").references(() => users.id),
  },
  (table) => [
    t.uniqueIndex("slug_idx").on(table.slug),
    t.index("title_idx").on(table.title),
  ]
);

export const comments = table("comments", {
  id: t.int().primaryKey().autoincrement(),
  text: t.varchar({ length: 256 }),
  postId: t.int("post_id").references(() => posts.id),
  ownerId: t.int("owner_id").references(() => users.id),
});
```

**`generateUniqueString` 实现：**
```ts
function generateUniqueString(length: number = 12): string {
  const characters =
    "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789";
  let uniqueString = "";

  for (let i = 0; i < length; i++) {
    const randomIndex = Math.floor(Math.random() * characters.length);
    uniqueString += characters[randomIndex];
  }

  return uniqueString;
}
```
