# 神奇的 `sql` 操作符 🪄

在使用 ORM 库时，有时你可能会发现使用提供的 ORM 语法很难编写
某个特定的查询。在这种情况下，你可以退而使用
原始查询，即将查询构造为原始字符串。然而，原始查询通常
缺乏类型安全和查询参数化的优势。

为了解决这个问题，许多库引入了 `sql` 模板的概念。此模板
允许你编写更类型安全、参数化的查询，增强代码的整体安全性和
灵活性。Drizzle 作为一个强大的 ORM 库，也支持 sql 模板。

使用 Drizzle 的 `sql` 模板，你可以在编写查询时走得更远。如果你在
使用库的查询构建器编写整个查询时遇到困难，你可以有选择地
在 Drizzle 查询的特定部分中使用 `sql` 模板。这种灵活性让你
能够在部分 SELECT 语句、WHERE 子句、ORDER BY 子句、HAVING
子句、GROUP BY 子句，甚至关系查询构建器中使用 sql 模板。

通过利用 Drizzle 中 sql 模板的能力，你可以在实现所需的查询结构和复杂度的同时，保持
类型安全和查询参数化的优势。
这让你能够在应用中创建更健壮、更易维护的代码。

## sql`` 模板

你在其他 ORM 中也可能遇到的最常见用法之一，
是能够直接使用 `sql` 查询作为原始查询。

```typescript copy
import { sql } from 'drizzle-orm' 

const id = 69;
await db.execute(sql`select * from ${usersTable} where ${usersTable.id} = ${id}`)
```

它将生成当前查询

```sql
select * from `users` where `users`.`id` = ?; --> [69]
```

提供给 sql 参数的任何表和列都会自动映射到它们对应的 SQL
语法，其中表名会被转义，且转义的 table 名会附加到列名上。

此外，任何动态参数（如 `${id}`）都会映射到 `?` 占位符，
相应的值会被移动到单独传递给数据库的值数组中。

这种方法有效地防止了任何潜在的 SQL 注入漏洞。

## `sql<T>`

<Callout type="info" emoji="ℹ️">
    请注意，`sql<T>` 不会执行任何运行时映射。你使用 `sql<T>` 定义的类型
    纯粹是给 Drizzle 的辅助信息。重要的是要理解，无法以可行的方式
    动态确定确切的类型，因为 SQL 查询可以高度多样且可定制。
</Callout>

你可以在 Drizzle 中定义自定义类型，用于字段需要 `unknown` 以外的特定类型的地方。

此特性在部分选择查询中特别有用，可确保所选字段的类型一致：

```typescript
// 未定义 sql<T> 类型
const response: { lowerName: unknown }[] = await db.select({
    lowerName: sql`lower(${usersTable.id})`
}).from(usersTable);

// 定义了 sql<T> 类型
const response: { lowerName: string }[] = await db.select({
    lowerName: sql<string>`lower(${usersTable.id})`
}).from(usersTable);
```

## `sql``.mapWith()`

对于需要为从数据库驱动传递到 drizzle 的值进行运行时映射的情况，你可以使用 `.mapWith()`

此函数接受不同的值，将在运行时映射响应。

只要
mapWith 内部的接口与 Column 实现的接口相同，你就可以复制特定的列映射策略。

```typescript
import { singlestoreTable, int, text } from 'drizzle-orm/singlestore-core';

const usersTable = singlestoreTable('users', {
    id: int('id').primaryKey().autoincrement(),
    name: text('name').notNull(),
});

//  在运行时，这些值将按 drizzle 中 `text` 列的映射方式被映射
sql`...`.mapWith(usersTable.name);
```

你也可以为 `DriverValueDecoder` 接口传入自己的实现：

```ts 
sql``.mapWith({
	mapFromDriverValue: (value: any) => {
		const mappedValue = value;
		// 你想应用的映射
		return mappedValue;
	},
});
    
// 或
sql``.mapWith(Number);
```

## `sql``.as<T>()`

在不同的情况下，确定如何为你想要使用的自定义字段命名有时会很有挑战性。
你可能会遇到需要为将被选择的字段显式指定别名的情况。
这在处理复杂查询时特别有用。

为了应对这些场景，我们引入了一个有用的 `.as('alias_name')` 辅助方法，它让你
可以显式地定义别名。通过利用此特性，你可以为字段提供清晰且有意义的
名称，使你的查询更直观、更易读。

<Section>
```typescript
sql`lower(usersTable.name)`.as('lower_name')
```
```sql
... `usersTable`.`name` as lower_name ...
```
</Section>

## `sql.raw()`

有些情况下，你可能不需要从输入创建参数化的值，也不需要将表/列映射为转义形式。
相反，你可能只是想要按原样生成查询。对于这种情况，我们提供了 `sql.raw()` 函数。

`sql.raw()` 函数允许你在查询中包含原始 SQL 语句，而无需任何额外的处理或转义。
当你有预先构造好的 SQL 语句，或需要将复杂或动态的
SQL 代码直接并入查询时，这会很有用。

<Section>
```typescript
sql.raw(`select * from users where id = ${12}`);
// 对比
sql`select * from users where id = ${12}`;
```
```sql
select * from users where id = 12;
--> 对比
select * from users where id = ?; --> [12]
```
</Section>

你还可以在 sql 函数内使用 `sql.raw()`，从而能够包含任何原始字符串
而不通过主 `sql` 模板函数对其进行转义。

通过在 `sql` 函数内使用 `sql.raw()`，你可以将未转义的原始字符串
直接并入查询。当你有一些特定的
SQL 代码或表达式应保持不受模板函数自动转义或修改影响时，这会特别有用。

<Section>
```typescript
sql`select * from ${usersTable} where id = ${12}`;
// 对比
sql`select * from ${usersTable} where id = ${sql.raw(12)}`;
```
```sql
select * from `users` where id = ?; --> [12]
--> 对比
select * from `users` where id = 12;
```
</Section>

## sql.fromList()

`sql` 模板会生成 sql chunks，即 SQL 部分的数组，在将 SQL 应用到 Drizzle 中的数据库或查询后，
这些部分会被拼接成查询和参数。

在某些场景中，你可能需要使用自定义业务
逻辑将这些 chunks 聚合成一个数组，然后将它们拼接成一条可以传递给数据库或查询的单一 SQL 语句。
对于这类情况，fromList 函数会非常有用。

fromList 函数允许你将多个 SQL chunks 组合成一条单一 SQL 语句。
你可以使用它按照你的特定需求
聚合并拼接各个 SQL 部分，然后获得一条可执行的统一 SQL 查询。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

	if (i === 4) continue;
	sqlChunks.push(sql` or `);
}

const finalSql: SQL = sql.fromList(sqlChunks)
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.join()

确实，`sql.join` 函数的作用与 fromList 辅助方法类似。
然而，它在处理 SQL chunks 之间的空格
或为拼接 SQL chunks 指定自定义分隔符方面提供了额外的灵活性。

使用 `sql.join`，你可以使用指定的分隔符将 SQL chunks 拼接在一起。
此分隔符可以是任何你想插入到 chunks 之间的字符串或字符。

当你在 SQL chunks 的格式化或分隔方面有特定要求时，这特别有用。
通过指定自定义分隔符，你可以在最终的 SQL 查询中实现所需的结构和格式。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql`where`);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

if (i === 4) continue;
    sqlChunks.push(sql`or`);
}

const finalSql: SQL = sql.join(sqlChunks, sql.raw(' '));
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.append()

如果你已经使用 `sql` 模板生成了 SQL，你可以通过使用 append 函数直接向生成的 SQL 添加新的 chunk，
从而实现与 `fromList` 相同的行为。

通过使用 append 函数，你可以动态地向现有 SQL 字符串添加额外的 SQL chunks，
有效地将它们拼接在一起。这让你能够并入自定义逻辑或业务
规则，以将 chunks 聚合到最终的 SQL 查询中。

<Section>
```typescript 
const finalSql = sql`select * from users`;

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.empty()

通过使用 sql.empty()，你可以从一个空白的 SQL 对象开始，然后根据需要向其中动态追加 SQL chunks。这让你能够逐步构建 SQL 查询，应用自定义逻辑或条件来确定每个 chunk 的内容。

一旦你使用 sql.empty() 初始化了 SQL 对象，你就可以利用 sql 模板的
全部特性，例如参数化、组合和转义。
这让你能够以灵活且可控的方式构建 SQL 查询，
使其适应你的特定需求。

```typescript 
const finalSql = sql.empty();

// 一些逻辑

finalSql.append(sql`select * from users`);

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```

## `sql` select

你也可以在部分选择查询中使用 sql 功能。部分选择查询让你可以
从表中检索特定字段或列，而不是获取整行。

关于部分选择查询的更详细信息，你可以参考可用的 Core API
文档：**[Core API 文档](/docs/singlestore/select#basic-and-partial-select)**。

**从表中选择不同的自定义字段**

这里你可以看到 **[`sql<T>`](/docs/singlestore/sql#sqlt)**、**[`sql``.mapWith()`](/docs/singlestore/sql#sqlmapwith)**、**[`sql``.as<T>()`](/docs/singlestore/sql#sqlast)** 的用法。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from 'schema'

await db.select({
    id: usersTable.id,
    lowerName: sql<string>`lower(${usersTable.name})`,
    aliasedName: sql<string>`lower(${usersTable.name})`.as('aliased_column'),
    count: sql<number>`count(*)`.mapWith(Number) 
}).from(usersTable)
```
```sql
select `id`, lower(`name`), lower(`name`) as `aliased_column`, count(*) from `users`;
```
</Section>

## `sql` 在 where 中

确实，Drizzle 提供了一组可在 sql 模板中使用的表达式。
然而，数据库通常有更广泛的可用表达式，
包括通过扩展或其他方式提供的表达式。

为了确保灵活性并让你能够使用 Drizzle 原生不支持的
任何表达式，你可以自由地直接使用 sql 函数
编写 SQL 模板。这让你能够充分利用
SQL 的强大功能，并并入任何特定于你目标数据库的表达式或功能。

通过使用 sql 模板，你不再局限于 Drizzle 中预定义的表达式。
相反，你可以表达复杂查询，并并入底层数据库系统
提供的任何受支持的表达式。

**使用 sql 按 `id` 过滤**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from 'schema'

const id = 77

await db.select()
        .from(usersTable)
        .where(sql`${usersTable.id} = ${id}`)
```
```sql
select * from `users` where `users`.`id` = ?; --> [ 77 ]
```
</Section>

**高级全文搜索 where 语句**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from 'schema'

const searchPattern = "%Ale%"

await db.select()
        .from(usersTable)
        .where(sql`lower(${usersTable.name}) like lower(${searchPattern})`)
```
```sql
select * from `users` where lower(`users`.`name`) like lower(?); --> [ "%Ale%" ]
```
</Section>

## `sql` 在 orderBy 中

当你需要 Drizzle 中不可用的特定排序功能，但又不愿使用原始 SQL 时，
`sql` 模板确实可以在 ORDER BY 子句中使用。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from 'schema'

await db.select().from(usersTable).orderBy(sql`${usersTable.id} desc nulls first`)
```
```sql
select * from `users` order by `users`.`id` desc nulls first;
```
</Section>

## `sql` 在 having 和 groupBy 中

当你需要 Drizzle 中不可用的特定排序功能，但又不愿使用原始 SQL 时，
`sql` 模板确实可以在 HAVING 和 GROUP BY 子句中使用。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from 'schema'

await db.select({ 
    projectId: usersTable.projectId,
    count: sql<number>`count(${usersTable.id})`.mapWith(Number)
}).from(usersTable)
    .groupBy(sql`${usersTable.projectId}`)
    .having(sql`count(${usersTable.id}) > 300`)
```
```sql
select `project_id`, count(`users`.`id`) from users group by `users`.`project_id` having count(`users`.`id`) > 300; 
```
</Section>
