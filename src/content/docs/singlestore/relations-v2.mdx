### `one()`
以下是 drizzle relations 中 `.one()` 可用的所有字段列表

```ts {3-11}
const relations = defineRelations({ users, posts }, (r) => ({
	posts: {
		author: r.one.users({
			from: r.posts.ownerId,
			to: r.users.id,
			optional: false,
      alias: 'custom_name',
			where: {
				verified: true,
			}
		}),
	}
}))
```

- `author` 键是使用 Drizzle 关系查询时出现在 `posts` 对象中的自定义键。
- `r.one.users` 定义了 `author` 将是来自 `users` 表的单个对象，而不是对象数组。
- `from: r.posts.ownerId` 指定了我们要从中建立软关系的表。
在本例中，关系从 `posts` 表中的 `ownerId` 列开始。
- `to: r.users.id` 指定了我们要向其建立软关系的表。
在本例中，关系指向 `users` 表中的 `id` 列。
- `optional: false` 在类型层面会使 posts 对象中的 `author` 键变为 `required`。
当你确定这个特定实体始终存在时，应使用它。
- `alias` 用于为表之间的关系添加特定别名。如果两个表之间存在多个相同的关系，你应该
使用 `alias` 来区分它们
- `where` 条件可用于多态关系。它基于 `where` 语句获取关系。
例如，在上述情况中，只会检索 `verified authors`。在[这里](/docs/relations-schema-declaration#多态关系)了解更多关于多态关系的信息。

### `many()`

以下是 drizzle relations 中 `.many()` 可用的所有字段列表

```ts {3-10}
const relations = defineRelations({ users, posts }, (r) => ({
	users: {
		feed: r.many.posts({
			from: r.users.id,
			to: r.posts.ownerId,
			alias: 'custom_name',
			where: {
				approved: true,
			}
		}),
	}
}))
```

- `feed` 键是使用 Drizzle 关系查询时出现在 `users` 对象中的自定义键。
- `r.many.posts` 定义了 `feed` 将是来自 `posts` 表的对象数组，而不仅仅是一个对象
- `from: r.users.id` 指定了我们要从中建立软关系的表。
在本例中，关系从 `users` 表中的 `id` 列开始。
- `to: r.posts.ownerId` 指定了我们要向其建立软关系的表。
在本例中，关系指向 `posts` 表中的 `ownerId` 列。
- `alias` 用于为表之间的关系添加特定别名。如果两个表之间存在多个相同的关系，你应该
使用 `alias` 来区分它们
- `where` 条件可用于多态关系。它基于 `where` 语句获取关系。
例如，在上述情况中，只会检索 `approved posts`。在[这里](/docs/relations-schema-declaration#多态关系)了解更多关于多态关系的信息。

### 一对一
Drizzle ORM 为你提供了使用 `defineRelations` 函数在表之间定义 `one-to-one` 关系的 API。

以下是 users 与 users 之间的 `one-to-one` 关系示例，其中一个用户可以邀请另一个用户（此示例使用了自引用）：

```typescript copy {10-17}
import { pgTable, text, integer } from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';

export const users = pgTable('users', {
	id: integer().primaryKey(),
	name: text(),
	invitedBy: integer('invited_by'),
});

export const relations = defineRelations({ users }, (r) => ({
	users: {
		invitee: r.one.users({
			from: r.users.invitedBy,
			to: r.users.id,
		})
	}
}));
```

另一个例子是将用户的个人资料信息存储在单独的表中。在这种情况下，由于外键存储在 "profile_info" 表中，user 关系既没有 fields 也没有 references。这告诉 TypeScript `user.profileInfo` 是可空的：

```typescript copy {15-22}
import { pgTable, serial, text, integer, jsonb } from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';

export const users = pgTable('users', {
	id: integer().primaryKey(),
	name: text(),
});

export const profileInfo = pgTable('profile_info', {
	id: serial().primaryKey(),
	userId: integer('user_id').references(() => users.id),
	metadata: jsonb(),
});

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));

const user = await db.query.users.findFirst({ with: { profileInfo: true } });
//____^? type { id: number, profileInfo: { ... } | null  }
```

### 一对多
Drizzle ORM 为你提供了使用 `defineRelations` 函数在表之间定义 `one-to-many` 关系的 API。

users 与他们所写 posts 之间 `one-to-many` 关系的示例：

```typescript copy {15-25}
import { pgTable, text, integer } from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';

export const users = pgTable('users', {
	id: integer('id').primaryKey(),
	name: text('name'),
});

export const posts = pgTable('posts', {
	id: integer('id').primaryKey(),
	content: text('content'),
	authorId: integer('author_id'),
});

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```

现在让我们为 posts 添加 comments：
```typescript copy {9-14,22,27-32}
...

export const posts = pgTable('posts', {

	content: text('content'),

export const comments = pgTable("comments", {

  text: text(),
  authorId: integer("author_id"),

```


### 多对多
Drizzle ORM 为你提供了通过所谓的 `junction` 或 `join` 表在表之间定义 `many-to-many` 关系的 API，
这些表必须显式定义，并存储相关表之间的关联。

users 与 groups 之间 `many-to-many` 关系的示例，我们使用 `through` 绕过中间表选择，直接为每个 `user` 查询多个 `groups`。
```typescript copy {27-39}
import { defineRelations } from 'drizzle-orm';
import { integer, pgTable, primaryKey, text } from 'drizzle-orm/pg-core';

export const users = pgTable('users', {
  id: integer().primaryKey(),
  name: text(),
});

export const groups = pgTable('groups', {
  id: integer().primaryKey(),
  name: text(),
});

export const usersToGroups = pgTable(
  'users_to_groups',
  {
    userId: integer('user_id')
      .notNull()
      .references(() => users.id),
    groupId: integer('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [primaryKey({ columns: [t.userId, t.groupId] })],
);

export const relations = defineRelations({ users, groups, usersToGroups },
  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),
        to: r.groups.id.through(r.usersToGroups.groupId),
      }),
    },
    groups: {
      participants: r.many.users(),
    },
  })
);
```

**查询示例：**
```ts
const res = await db.query.users.findMany({
  with: { 
    groups: true 
  },
});

// 响应类型
type Response = {
  id: number;
  name: string | null;
  groups: {
    id: number;
    name: string | null;
  }[];
}[];
```

### 预定义过滤器

Drizzle 关系定义中的预定义 `where` 语句是一种多态关系实现，但并不完全等同。本质上，它们让你不仅可以通过选择特定的列来连接表，还可以通过自定义的 `where` 语句来连接。让我们看一些示例：

我们可以定义 `groups` 与 `users` 之间的关系，使得在查询 group 的 users 时，只检索 `verified` 列设置为 `true` 的那些用户
<CodeTabs items={["关系", "Schema"]}>
<Section>
```ts
import { defineRelations } from "drizzle-orm";
import * as schema from './schema';

export const relations = defineRelations(schema,(r) => ({
    groups: {
      verifiedUsers: r.many.users({
        from: r.groups.id.through(r.usersToGroups.groupId),
        to: r.users.id.through(r.usersToGroups.userId),
        where: {
          verified: true,
        },
      }),
    },
  })
);

...

await db.query.groups.findMany({
    with: {
      verifiedUsers: true,
    },
});
```
</Section>
<Section>
```ts
import * as p from "drizzle-orm/pg-core";

export const users = p.pgTable("users", {
  id: p.integer().primaryKey(),
  name: p.text().notNull(),
  verified: p.boolean().notNull(),
});

export const groups = p.pgTable("groups", {
  id: p.integer().primaryKey(),
  title: p.text().notNull(),
});

export const usersToGroups = p.pgTable(
  "users_to_groups",
  {
    userId: p
      .integer("user_id")
      .notNull()
      .references(() => users.id, { onDelete: "cascade" }),
    groupId: p
      .integer("group_id")
      .notNull()
      .references(() => groups.id, { onDelete: "cascade" }),
  },
  (t) => [p.primaryKey({ columns: [t.groupId, t.userId] })]
);
```
</Section>
</CodeTabs>

<Callout type='warning'>
你只能在目标（to）表上指定过滤器。因此在本例中，由于我们建立的是 **TO** users 的关系，where 子句将只包含 `users` 表中的列

```ts {7}
export const relations = defineRelations(schema,(r) => ({
    groups: {
      verifiedUsers: r.many.users({
        from: r.groups.id.through(r.usersToGroups.groupId),
        to: r.users.id.through(r.usersToGroups.userId),
        where: {
          verified: true,
        },
      }),
    },
  })
);
```
</Callout>

### 关系组成部分

如果你需要将 relations 配置拆分为多个部分，可以使用 `defineRelationsPart` 辅助函数

```ts
import { defineRelations, defineRelationsPart } from 'drizzle-orm';
import * as schema from "./schema";

export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));

export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

然后你可以将其提供给 db 实例

```ts
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })
```

<Callout type='warning'>
为确保 `defineRelationsParts` 按预期工作，你需要遵循一些规则

**规则 1**：如果你使用 parts 指定 relations，那么在将其传递给 drizzle db 函数时，你需要按正确的顺序指定（主 relations 在前面）
```ts
// ✅
const db = drizzle(process.env.DB_URL, { relations: { ...relations, ...part } })

// ❌
const db = drizzle(process.env.DB_URL, { relations: { ...part, ...relations } })
```

<Callout collapsed="为什么这很重要？">
即使不会出现类型或运行时错误，这就是 "..." 在对象上的工作方式。只要主 relation
递归推断出所有表名，它就可以在自动补全中使用。以下是一个示例：

```ts
export const relations = defineRelations(schema, (r) => ({
  users: {
    invitee: r.one.users({
      from: r.users.invitedBy,
      to: r.users.id,
    }),
    posts: r.many.posts(),
  }
}));

export const part = defineRelationsPart(schema, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  }
}));
```

这里的 `relations` 和 `part` 可以表示为这个对象：
```json
// relations
{
  "users": {"invitee": {...}, "posts": {...}},
  // 添加在这里，这样 schema 中的所有表都会出现在自动补全中
  "posts": {}
}

// part
{
  "posts": {"author": {...}}
}
```

使用 `{ ...relations, ...part }` 会得到
```json
{
  "users": {"invitee": {...}, "posts": {...}},
  "posts": {"author": {...}}
}
```

而使用 `{ ...relations, ...part }` 会得到
```json
{
  "users": {"invitee": {...}, "posts": {...}},
  // 正如你在最终对象中看到的，posts relations 信息将丢失
  "posts": {}
}
```

</Callout>

**规则 2**：你应该有主 relations，这样 drizzle 才能推断出所有表以用于自动补全。如果你只想使用 parts，那么
你的其中一个 parts 应为空，像这样：

```ts
export const mainPart = defineRelationsPart(schema);
```

在这种情况下，所有表都会被正确推断，你将获得关于 schema 的完整信息
</Callout>

### 性能

在 Drizzle ORM 中处理关系时，尤其是在数据量大或查询复杂的应用中，
优化数据库性能至关重要。
索引在加速数据检索方面起着至关重要的作用，特别是在查询
相关数据时。本节概述了使用 Drizzle ORM 定义的每种
关系类型所推荐的索引策略。

##### 一对一关系

在一对一关系中，比如 "user invites user" 示例或
"user has profile info" 示例，关键的性能考虑因素是高效地连接
相关表。

<Callout>
为了在一对一关系中获得最佳性能，你应该在被引用的表
（关系中的 "target" 表）的外键列上创建索引。
</Callout>

<Callout collapsed='为什么这很重要'>
当你查询带有相关一对一信息的数据时，Drizzle 会执行 JOIN 操作。外键列上的索引使数据库能够快速
定位目标表中的相关行，从而显著加快连接过程。
</Callout>

**示例：**
```typescript
import * as p from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';

export const users = p.pgTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const profileInfo = p.pgTable('profile_info', {
	id: p.integer().primaryKey(),
	userId: p.integer('user_id').references(() => users.id),
	metadata: p.jsonb(),
});

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));
```

为了优化同时获取用户数据及其个人资料信息的查询，
你应该在 `profile_info` 表的 `userId` 列上创建索引。

```typescript {13-15,21}
import * as p from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';

export const users = p.pgTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const profileInfo = pgTable('profile_info', {
	id: p.integer().primaryKey(),
	userId: p.integer('user_id').references(() => users.id),
	metadata: p.jsonb(),
}, (table) => [
  p.index('profile_info_user_id_idx').on(table.userId)
]);

export const relations = defineRelations({ users, profileInfo }, (r) => ({
	users: {
		profileInfo: r.one.profileInfo({
			from: r.users.id,
			to: r.profileInfo.userId,
		})
	}
}));
```
```sql
CREATE INDEX idx_profile_info_user_id ON profile_info (user_id);
```

#### 一对多关系

与一对一关系类似，一对多关系也从索引中获益良多，
以优化连接操作。考虑 "users and posts" 示例，其中一个用户可以有多条 posts。

<Callout>
对于一对多关系，请在表示关系 "many" 一侧的表（即引用 "one" 一侧的外键所在的表）的外键列上创建索引。
</Callout>

<Callout collapsed='为什么这很重要'>
当你获取用户及其 posts，或获取 posts 及其作者时，会执行连接操作。
对(`posts` 表中的 `authorId`)外键建立索引，使数据库能够高效地
检索与给定用户关联的所有 posts，或快速找到某条 post 的作者。
</Callout>

**示例：**
```typescript
import * as p from "drizzle-orm/pg-core";
import { defineRelations } from 'drizzle-orm';

export const users = p.pgTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const posts = p.pgTable('posts', {
	id: p.integer().primaryKey(),
	content: p.text(),
	authorId: p.integer('author_id'),
});

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```

为了优化涉及用户及其 posts 的查询，请在 `posts` 表的 `authorId` 列上创建索引。

```typescript {13-15}
import * as p from "drizzle-orm/pg-core";
import { defineRelations } from 'drizzle-orm';

export const users = p.pgTable('users', {
	id: p.integer().primaryKey(),
	name: p.text(),
});

export const posts = p.pgTable('posts', {
	id: p.integer().primaryKey(),
	content: p.text(),
	authorId: p.integer('author_id'),
}, (t) => [
  index('posts_author_id_idx').on(table.authorId)
]);

export const relations = defineRelations({ users, posts }, (r) => ({
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
    }),
  },
  users: {
    posts: r.many.posts(),
  },
}));
```
```sql
CREATE INDEX idx_posts_author_id ON posts (author_id);
```

#### 多对多关系

多对多关系使用中间表实现，需要稍微
更细致的索引策略来确保最佳的查询性能。
考虑带有 `usersToGroups` 中间表的 "users and groups" 示例。

<Callout>
对于多对多关系，通常建议在中间表上创建以下
索引：
1.  **分别对每个外键列建立索引：** 这样可以优化基于关系单侧进行
过滤或连接的查询
（例如，查找某个用户的所有 groups，或某个 group 中的所有 users）。
2.  **同时对两个外键列建立复合索引：** 这对
高效解析多对多关系本身至关重要。它可以加速需要查找两个实体之间连接的查询。
</Callout>

<Callout collapsed='为什么这很重要'>
在查询多对多关系时，尤其是在 Drizzle ORM 中使用 `through` 时，数据库需要高效地遍历中间表。

- 对单个外键列（`usersToGroups` 中的 `userId`、`groupId`）建立索引，在你从一侧查询以找到另一侧时会有所帮助（例如，"查找某个用户的 groups"）。
- `usersToGroups` 中 `(userId, groupId)` 上的复合索引对于快速找到中间表中定义的所有关系尤为重要。当 Drizzle ORM 解析 `many-to-many` 关系以获取相关实体时会用到它。
</Callout>

**示例：**

在 "users and groups" 示例中，`usersToGroups` 中间表连接了 `users` 和 `groups`。

```typescript
import { defineRelations } from 'drizzle-orm';
import * as p from 'drizzle-orm/pg-core';

export const users = p.pgTable('users', {
  id: p.integer().primaryKey(),
  name: p.text(),
});

export const groups = p.pgTable('groups', {
  id: p.integer().primaryKey(),
  name: p.text(),
});

export const usersToGroups = p.pgTable(
  'users_to_groups',
  {
    userId: p.integer('user_id')
      .notNull()
      .references(() => users.id),
    groupId: p.integer('group_id')
      .notNull()
      .references(() => groups.id),
  },
  (t) => [p.primaryKey({ columns: [t.userId, t.groupId] })],
);

export const relations = defineRelations({ users, groups, usersToGroups },
  (r) => ({
    users: {
      groups: r.many.groups({
        from: r.users.id.through(r.usersToGroups.userId),
        to: r.groups.id.through(r.usersToGroups.groupId),
      }),
    },
    groups: {
      participants: r.many.users(),
    },
  })
);
```

为了优化针对 users 和 groups 的查询，请按如下方式在 `usersToGroups` 表上创建索引：

### 外键

你可能已经注意到 `relations` 看起来与外键相似——它们甚至有一个 `references` 属性。那么区别是什么呢？

虽然外键服务于类似的目的——定义表之间的关系，但它们的工作层级与 `relations` 不同。

外键是数据库级别的约束，它们在每次 `insert`/`update`/`delete` 操作时都会被检查，如果违反约束就会抛出错误。
另一方面，`relations` 是更高层次的抽象，它们仅用于在应用层面定义表之间的关系。
它们不会以任何方式影响数据库 schema，也不会隐式创建外键。

这意味着 `relations` 和外键可以一起使用，但它们并不相互依赖。
你可以在不使用外键的情况下定义 `relations`（反之亦然），这使得它们可以用于不支持外键的数据库。

以下两个示例在使用 Drizzle 关系查询数据方面将完全一样地工作。

### 区分关系

当你为同一对表定义多个关系时，Drizzle 还提供 `alias` 选项来消除
关系的歧义。例如，
如果你定义了一个 `posts` 表，其中包含 `author` 和 `reviewer`
关系。

```ts {19,22,29,34}
import { pgTable, integer, text } from 'drizzle-orm/pg-core';
import { defineRelations } from 'drizzle-orm';
 
export const users = pgTable('users', {
	id: integer('id').primaryKey(),
	name: text('name'),
});

export const posts = pgTable('posts', {
	id: integer('id').primaryKey(),
	content: text('content'),
	authorId: integer('author_id'),
	reviewerId: integer('reviewer_id'),
});
 
export const relations = defineRelations({ users, posts }, (r) => ({
  users: {
    posts: r.many.posts({
      alias: "author",
    }),
    reviewedPosts: r.many.posts({
      alias: "reviewer",
    }),
  },
  posts: {
    author: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
      alias: "author",
    }),
    reviewer: r.one.users({
      from: r.posts.authorId,
      to: r.users.id,
      alias: "reviewer",
    }),
  },
}));
```
