# `drizzle-kit export` 

<Prerequisites>
- 开始使用 Drizzle 和 `drizzle-kit` - [在此阅读](/docs/singlestore/get-started)
- Drizzle schema 基础知识 - [在此阅读](/docs/singlestore/sql-schema-declaration)
- 数据库连接基础 - [在此阅读](/docs/singlestore/connect-overview)
- Drizzle 迁移基础知识 - [在此阅读](/docs/singlestore/migrations)
- Drizzle Kit [概览](/docs/singlestore/kit-overview) 和 [配置文件](/docs/singlestore/drizzle-config-file)
</Prerequisites>


<br/>

`drizzle-kit export` 让你可以导出 Drizzle schema 的 SQL 表示形式，并在控制台中打印它的 SQL DDL 表示。
<Callout collapsed="它在底层是如何工作的？">
Drizzle Kit 的 `export` 命令会触发一系列事件：
1. 它会读取你的 Drizzle schema 文件，并组合出你的 schema 的 json 快照
3. 基于 json 的差异，它会生成 SQL DDL 语句
4. 将 SQL DDL 语句输出到控制台
</Callout>

它的设计目的是覆盖[代码库优先](/docs/singlestore/migrations)的 Drizzle 迁移管理方式。
你可以导出 Drizzle schema 的 SQL 表示形式，让像 Atlas 这样的外部工具为你处理所有迁移

`drizzle-kit export` 命令要求你同时提供 `dialect` 和 `schema` 路径选项，
你可以通过 [drizzle.config.ts](/docs/singlestore/drizzle-config-file) 配置文件或 CLI 选项来设置它们
<CodeTabs items={["使用配置文件", "作为 CLI 选项"]}>
<Section>
```ts
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "singlestore",
  schema: "./src/schema.ts",
});
```
```shell
npx drizzle-kit export
```
</Section>

```shell
npx drizzle-kit export --dialect=singlestore --schema=./src/schema.ts
```
</CodeTabs>

### schema 文件路径
你可以只有一个 `schema.ts` 文件，也可以有任意多个分散在项目各处的 schema 文件。
Drizzle Kit 要求你通过 `schema` 配置选项，以 [glob](https://www.digitalocean.com/community/tools/glob?comments=true&glob=/**/*.js&matches=false&tests=//%20This%20will%20match%20as%20it%20ends%20with%20'.js'&tests=/hello/world.js&tests=//%20This%20won't%20match!&tests=/test/some/globs) 的形式指定它们的路径。

<SchemaFilePaths/>

### 一个项目中的多个配置文件
你可以在项目中拥有多个配置文件，当你有多个数据库阶段、多个数据库，或同一项目中有不同数据库时，这非常有用：
<Npx>
  drizzle-kit export --config=drizzle-dev.config.ts
  drizzle-kit export --config=drizzle-prod.config.ts
</Npx>
```plaintext {5-6}
📦 <project root>
 ├ 📂 drizzle
 ├ 📂 src
 ├ 📜 .env
 ├ 📜 drizzle-dev.config.ts
 ├ 📜 drizzle-prod.config.ts
 ├ 📜 package.json
 └ 📜 tsconfig.json
```

### 扩展的可用配置列表
`drizzle-kit export` 有一组仅限 CLI 的选项

<rem025/>

|               |                                                      |
| :--------     | :--------------------------------------------------- |
| `--sql`       | 生成 Drizzle Schema 的 SQL 表示形式               |

默认情况下，Drizzle Kit 输出 SQL 文件，但未来我们希望能支持不同的格式

<rem025/>

<Npx>
drizzle-kit push --name=init
drizzle-kit push --name=seed_users --custom
</Npx>

<br/>
我们建议通过 [drizzle.config.ts](/docs/singlestore/drizzle-config-file) 文件来配置 `drizzle-kit`，
但如果需要，你也可以通过 CLI 提供所有配置选项，例如在 CI/CD 流水线中等。

|               |            |                                                                            |
| :------------ | :-------   | :----------------------------------------------------------------------    |
| `dialect`     | `required` | 数据库方言，<Dialects/> 之一                                       |
| `schema`      | `required` | 指向 typescript schema 文件，或包含多个 schema 文件的文件夹的路径  |
| `config`      |            | 配置文件路径，默认是 `drizzle.config.ts`                    |

### 示例
如何将位于 `./src/schema.ts` 的 Drizzle schema 导出到控制台的示例

我们还会把 drizzle 配置文件放在 `configs` 文件夹中。

让我们创建配置文件：

```plaintext {4}
📦 <project root>
 ├ 📂 configs
 │ └ 📜 drizzle.config.ts
 ├ 📂 src
 │ └ 📜 schema.ts
 └ …
```
```ts filename='drizzle.config.ts'
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "singlestore",
  schema: "./src/schema.ts",
});
```

```ts filename='schema.ts'
import { singlestoreTable, serial, text } from 'drizzle-orm/singlestore-core'

export const users = singlestoreTable('users', {
	id: int('id').primaryKey().autoincrement(),
	email: text('email').notNull(),
	name: text('name')
});
```

现在让我们运行
```shell
npx drizzle-kit export --config=./configs/drizzle.config.ts
```
它将成功输出 drizzle schema 的 SQL 表示形式
```bash
CREATE TABLE "users" (
        `id` int auto_increment primary key not null,
        `email` varchar(255) not null,
        "name" text
);
```
